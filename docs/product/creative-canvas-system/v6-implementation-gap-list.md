## 6. 建议实施顺序

1. **人工工作台收尾**：GAP-05–12、15–21、34 中明确项。优先修文字 Esc、链接输入方向、空参考、重名输入丢失、移动端撤销等与 PRD 明确相反的行为；链接/音频补原型后再完善视觉。
2. **真实节点生成闭环**：GAP-01–04；先打通一种媒体的完整路径，再补齐基础需求的其余类型。计价/授权/结果落库一起验收，不只做模型下拉框。
3. **助手可操作画布**：GAP-23、30、31；接现有画布应用命令、选区与授权。先让真实工具产生可查回执，再加表现层。
4. **助手交互与可撤销**：GAP-24–29、32–33；有序块→提问/确认→本轮改动/冲突撤销→后台提示/队列，遵循共享运行协议。
5. **整体验收与优化**：GAP-35–37。每个阶段补局部 E2E，最后串联 UF-01–11；P2 能力单独排期。

先前讨论的 OpenAI/GPT 系列接入、同一逻辑模型按 provider 优先级故障切换，是 Gateway 扩展工作，可作为第 2/3 步的依赖另立清单。**本 PRD 本身未指定该型号，也未把多 provider 故障切换作为 v6 交互验收项**；聊天模型接通不会自动交付图片/视频/音频生成。本次没有查询当前模型外部文档或尝试真实 API。

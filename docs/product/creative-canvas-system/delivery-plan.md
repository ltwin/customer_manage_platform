# 基础框架正式开发计划

本计划把已审的三批模块方案映射到[永久Epic的FND-01–13](../../../.codestable/epics/creative-workspace-system.md#当前子项契约)。**任务定义与依赖以Epic为准，执行进度只写work。** 当前交付是可审查的开发计划，没有安装依赖、运行生产迁移或开始业务实现；三批SQL探针验证的是局部协议。

## 1. 开发顺序与可体验出口

默认串行顺序为FND-01→02→03→04→05→06→13→07→08→09→10→11→12；它满足所有硬依赖，适合当前同一协作工作区。存在可并行分支不等于已授权并行开发：FND-03与04可在FND-02之后分别推进；FND-06可在01之后与人工链分开；08与09的服务端边界可拆分，但共用Agent前端必须由单一writer集成。实际并行需要隔离工作树和明确文件归属，不能同时写一个OpenAPI或迁移编号。

| 体验出口 | 需要完成的FND项 | 摄影师能实际完成什么 | 仍未覆盖 |
|---|---|---|---|
| 最小文字闭环 | 01、02 | 无项目收集文字/链接，建项目引用、修改、保存、重开 | 分组标签完整管理、复杂组/撤销、媒体、Agent |
| 人工创作主链 | 01–05 | 整理与找回素材、图文音视频引用、连线打组、替换/下载/撤销 | Agent、后台到期与全根物理清理、旧账号迁移 |
| 节点真实生成 | 01–06、13 | Prompt直接生成四类内容，历史预览/采用/保存 | Agent组任务、全根清理与迁移 |
| 三部分真实主链 | 01–09、13 | 模型/Skill选择、选区与独立附件、真实工具结果、取消恢复、断线找回 | 全部生命周期/迁移/目标环境性能与试用验收 |
| 可发布候选 | 01–13 | 核心需求、故障恢复和旧数据切换均有证据，可按授权灰度 | 后续策划、3D、RAG和社区 |

每个出口是渐进演示，不是缩减完整首期范围。人工链可用时无需等模型，但模型尚未验收不能宣布三部分完成。停用Agent必须保留人工功能；隐藏未实现菜单不代替后台权限开关。

## 4. 代码交付约定

每个FND交付包含相关服务、生成API类型、前端可用路径、正式迁移、运行配置说明与匹配的测试。允许先在项内提交小改动供检查，但项的出口必须完整，不能用后端接口返回200替代真实前端闭环。

- API变更先维护正式OpenAPI，再生成Go/TS；不在前端手写另一份领域DTO。新旧命名空间分别演进。
- schema按真实模块分组递增，已有数据只做expand/有界backfill；第三批12表是探针字段投影，不能进入生产迁移目录。River内部schema由库拥有，应用不复制其表实现。
- 关键不变量先写有意义的集成/故障测试：同key并发、取消/epoch、目标版本、引用/GC、费用差额；普通样式调整不扩成无关全量测试。
- 门禁按AGENTS影响面：前端check-frontend；引用生成schema加generate-check；跨Go包/接口/迁移check-go；部署脚本check-ops；合回develop/发布前make check。缺Docker或授权环境明确记未验证，不以跳过称通过。
- 每项独立review后修复、复验，最多按项目规定三轮；未解决blocking不完成项。任务进度/实际证据/commit仅记录work，不在本文填“已完成”。
- 工作区沿用当前创意空间worktree，先核对已有未提交改动的归属；不回主checkout顺手开发。当前提交/发布策略仍pending，不沿用此前其他改动的许可。开发前按本次明确授权记录推进方式；如保持手动提交，按项交付可审查结果，不自行commit/push。

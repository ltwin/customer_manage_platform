# 创意画布基础框架：审计意见处置

来源为[审计原稿](../../../.codestable/audits/creative-canvas-foundation-design-audit.md)（SHA-256 `44e722d6bfaa0f53545161420e9b2cb35fd30e87556e923496b5957e3b77ccc6`），其核查对象为需求 v0.1、架构/数据模型 v0.2。原稿保留，不回写历史判断；本文件记录摄影师认可核查建议后的处置及剩余验证，当前契约仍以需求、架构、数据模型和 ADR 为准。

本轮更新需求至 v0.2、架构/数据模型至 v0.3，不扩大到功能实现。A-1 的治理依据和 D-1 的 ID 一致性需要明确，但不能以此重新要求摄影师批准混合外键，或把 ID 前缀当安全边界。优先补足状态机、媒体所有权和写入不变量。

| 编号 | 处置 | 落点与理由 |
|---|---|---|
| A-1 | 部分采纳 | 新增 ADR-008，明确新业务表无外键、旧表不动及首个持久化切片的守卫/扫描/集成测试；不采用混合 FK |
| A-2 | 采纳并纠正隔离建议 | 架构 §6.3、媒体部署契约：planning 已限定前缀；旧 creative 占用了 creative/，新版独立 creative-v2/，不能扫描旧域；先并列、后按实际迁移提取平台能力 |
| A-3 | 暂不合包 | 架构 §3：按真实接口和事务耦合评估，不按包数量判定维护成本；模块设计避免纯透传层 |
| A-4 | 采纳授权细化 | 架构 §6.2 与媒体部署契约选择预签名分片 PUT；浏览器不持 STS；下载仍代理，上传/下载不是冲突决策；具体角色/权限/CORS 尚待实施验证 |
| A-5 | 采纳边界补充 | CAN-02、架构 §6.4：首期只存 HTTP/HTTPS URL 和手填信息，前端/API/工具均不自动抓取；不能把尚未存在的抓取功能记成已发生 SSRF |
| A-6 | 保留独立 worker | 队列并发不能代替进程故障隔离；同构建产物、明确迁移先行与资源预算，暂不合并到 API |
| A-7 | 暂不合并版本 | 现有读水位、结构、内容与布局各有不同冲突含义；模块阶段用实际读集合验证，再决定是否简化 |
| A-8 | 不采纳自动收藏 | LIB-06/CAN-02 与数据 §5：待绑定候选保留成功上传，摄影师可重新绑定、存入库或放弃；不能以简化实现改变“不强制收藏” |
| D-1 | 采纳一致性建议，纠正影响定级 | 数据 §1 沿用 TEXT 前缀 ID、id 主键与账号/id 唯一；ID 格式与主键形状分开论证，UUID 与前缀 ID 均可使用字符串 DTO，前缀不能替代归属校验 |
| D-2 | 补齐派生列不变量 | 数据 §4：content/revision 配对原已有守卫；统一标注资产 kind、运行 canvas 及 normalized_title 的生成/校验/扫描规则 |
| D-3 | 采纳回执归属 | 数据 §6：新命令以 creative_operation_receipts 为重放权威；changes 为变更明细，同事务提交；不扩旧白名单，旧入口不迁改 |
| D-4 | 采纳并完整定义 | 数据 §7 为唯一运行状态转换表；取消是标记，恢复是条件；补齐对账、等待、终态、槽位与迟到结果规则 |
| D-5 | 采纳并加强证据 | 架构 §6.1/12：核对 locale/collation/provider，用 show_trgm 和真实 LIKE 计划检查扫描量、重检、耗时；不能只看到 GIN 就通过；未连接目标库，不宣称 locale 缺陷已发生 |
| D-6 | 部分采纳 | normalized_title 入表并固定派生规则；LIB-06 只承诺重复引用不上传，不增加跨上传哈希去重；CAN-01 未承诺最近打开排序，last_opened_at 不是已确认需求缺口，项目列表排序留模块接口确定 |
| D-7 | 暂不缩小锁范围 | 无外键下成员创建与目录删除必须同步；资产行锁本身不能保护目录存在性。先保留短事务库根锁，后续按竞争证据及完整锁协议细化 |
| D-8 | 简化产品配置 | 首期只配置单一计价币种，不做换汇；currency 维度保留以免混算，取消跨币种首期验收。账号 slot 独立于预算周期，跨周期并发测试保留 |
| D-9 | 按语义细化 | edges.position 改 target_ordinal；可调整排列、内容修订 sequence、消息/步骤 ordinal、SSE seq 含义不同，不统一机械改名 |
| R-1 | 采纳 | 同 A-5；保存、显示、打开来源与自动抓取分开 |
| R-2 | 采纳 | CAN-01/架构 §2.2：视口按账号/画布保存在本机浏览器，首期不跨设备；缺省适配内容范围 |
| R-3 | 采纳 | 数据 §5 保留策略总表：统一起算点、期限、到期动作、未结算/异常保留与待冻结部署参数 |
| R-4 | 采纳 | AG-08、架构 §7.2、数据 §7 外发同意：首次提示供应商/用途/范围，有效同意可复用；工具结果也检查，素材权利另查，拒绝不影响人工功能 |
| R-5 | 采纳首期边界 | LIB-04 明示时间/名称排序，不承诺相关度排序；以后标题权重排序另行设计 |

## 进入模块设计时的约束

- 建立实际前缀目录、OpenAPI DTO、状态转移 SQL、派生字段写路径和保留扫描接口；契约说明已补齐不等于测试已完成。
- 首个持久化切片同时完成自己涉及的无外键关系守卫、扫描和 storetest 并发/幂等验证；随后新增关系扩展覆盖，不把所有扫描延期到最终验收。
- 目标库中文索引、新 SDK 适配、OSS CORS/RAM/分片恢复、同 bucket 新旧隔离、模型外发授权和运行故障测试仍按架构 §12 实测。具体运维权限与超时配置未冻结前不启用新版物理清理。
- 分包、独立 worker、版本计数器和库根锁是保留的方案，验证若显示实际成本/冲突问题，再带完整替代契约修订，不按审计建议自动删减。

独立契约复审进一步补齐三项边界：终态重试的来源/步骤 key 与原回执承接、选定资源外发授权固定到内容修订并使用显式关系表、ready 上传交接后释放临时 blob 保留。示意请求的版本字段也统一为十进制字符串。

本轮仅修订设计与待实施部署契约；未执行迁移、未安装依赖、未改生产配置、未提交。独立复审的目标哈希、轮次与结果由 Epic work 记录，不以本处置表代替审查证据。

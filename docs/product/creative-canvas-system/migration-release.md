# 迁移、灰度与停止恢复契约

本稿细化[架构的新旧承接](architecture.md#10-账号隔离运维与迁移)，由FND-10/11/12实施及验收。现在不运行任何回填、账号切换、生产对象复制或删除。生产变更只针对当时明确授权的环境、账号和候选版本。

## 1. 启用与发布顺序

新旧命名空间并存。功能准入来自服务端账号状态/能力，UI显示是投影：creative_read、manual_write、media_write、agent_start、node_generate、generation_apply、gc_delete代表需要独立控制的能力，不承诺这些字符串已是实际配置字段。FND-01确定与现有capability/barrier的映射，禁止建立两个相互矛盾的开关源。迁移阶段审计记录也不能成为第二份writer授权。

| 次序 | 动作与前置证据 | 可见行为 |
|---|---|---|
| Expand | 先执行向后兼容业务迁移与River自身迁移，记录版本；旧接口测试通过 | 旧板块维持原准入，新界面默认不可写；不清旧列或旧对象 |
| 部署读取能力 | 部署兼容新schema的API与前端，校验Node/Tool/Skill/事件schema manifest | 新界面仅对受信测试账号开放已完成能力；未知类型只读保留 |
| 部署Worker | Worker二进制/registry版本匹配、队列和连接预算就绪；agent/media/generation准入先暂停，必要维护另行控制 | 新job参数版本不可被旧Worker误执行；不支持版本隔离告警而非丢弃效果证据 |
| 账号演练及切换 | FND-11逐账号完成下节流程；纯新测试账号核对旧域为空后走新建路径 | 一个账号只有一个创意writer世代；旧读保留 |
| 开启媒体/人工能力 | 已验证格式、用途、API/Worker/存储配置一致，核心人工FLOW通过 | 只显示实测可用类型，不将OSS权限失败掩盖为加载中 |
| 开启节点生成 | FND-13每类真实模型/费用/任务/结果持久化与PRE-11通过；node_generate及generation_apply映射同一账号capability/barrier | 可独立于chat生成，未配置类型拒绝；状态/历史可读，Agent生成还需原Agent执行权 |
| 开启Agent | Gateway、Harness、费用/外发策略与模型真实评估通过 | 模型失效可单独关闭Agent，不影响人工库/画布 |
| 物理清理启用 | FND-10全根证明、正式恢复窗口、目标存储恢复及旧域隔离通过，并获得此次启用授权 | 仅creative-v2精确版本按宽限规则清理；否则持续只读扫描 |

阶段演示环境可以提前运行已完成组件，正式试用发布不能绕过FND-12。所有需持久异步副作用的能力启用时必须有相容Worker，不能先让入口产生无人消费的任务再补运维。前端旧版本写不支持的schema返回升级/冲突提示并保留草稿；不能用整图保存擦掉新字段。

## 2. 每账号迁移流程

每次冻结基线由服务端分配独立execution_id；执行状态、后台任务、分页/cleanup游标和控制回执均按account_id+execution_id隔离。migration_version只标识转换规则，同一版本可以在旧执行退役后创建新的execution；legacy_map继续使用account/source_kind/source_id稳定主键。每个execution的阶段/批次操作预分配并持久保存独立operation_id及请求hash，同执行恢复沿用原操作，新执行绝不复用上一轮操作回执或任务身份。保存候选构建、操作者、源指纹、对象映射清单、问题清单和每阶段时间。数据复制去重依据是当前执行已验证的legacy_map及实际目标，不能只看上一次命令输出“成功”。任何创建目标与映射的短事务都含账号/key核对；外部对象I/O在事务外，有独立可核实身份。

| 阶段 | 必须满足 / 提交动作 | 中断与失败处理 |
|---|---|---|
| 只读预检 | 明确当前旧表/卡/媒体/空间/成员/拍摄项/来源与账号准入；列全旧HTTP、后台任务及清理writer；记录映射规则、数量、内容hash和不可迁项 | 只输出报告；未知类型/权利或源文件缺失列明，不能吞项 |
| 冻结源writer | 同一账号barrier关闭旧创意写路径；使旧任务执行权失效并确认不会继续发布；旧域媒体保留/GC保护实际生效 | 不能仅隐藏菜单；旧reader继续可用；未证明所有writer受控则不能复制 |
| 固定源快照 | 在冻结后重算数据指纹和映射清单，建立必要迁移hold | 预检后到冻结前的新增/修改必须纳入；源继续变化即隔离，不继续覆盖目标 |
| 可重入复制/回填 | 旧对象复制到creative-v2新不可变位置，核对固定版本/字节/hash；按映射创建库/项目/节点及明确修订引用；每页记游标 | 已有同指纹目标复用；活动基线中同旧ID异指纹报冲突，不换ID强行新建；已放弃且旧域恢复写入后只能先完成下节重新建基线，不能直接复用旧映射；COMMIT或对象结果未知先核实 |
| 对账并开放新读 | 对比逐项清单、媒体hash、层级/引用/来源/权利与旧回跳；检查新表无错误CRM关联、无跨账号key或漏根 | 任一核心差异未解决，不启用新writer；新结果可只读检查 |
| 原子切换writer | 在账号barrier内核对源指纹/当前execution_id/迁移版本/对账通过、旧writer已停、新组件版本可写；切换有效writer世代与审计标记 | 重复动作回放同一切换结果；不运行一段时间双写来“观察” |
| 切换后观察 | 执行读回/新增/修改/附件/Agent（若开启）及旧只读回跳，保留完整迁移映射与恢复材料 | 停止条件命中先停新writer，保留两边只读与证据；不自动开启旧writer |

不可迁项必须在清单有明确处置；如果它影响本账号核心数据完整性或读取，不能以“跳过”标记该账号切换完成。未来另行接受的兼容例外应有摄影师确认和可读原数据入口，不能按缺失对象数量偷偷降低对账要求。

### 切换前放弃后的重新建基线

`legacy_map` 的稳定主键仍是account/source_kind/source_id，migration_version不是更换key的逃生口。同一冻结基线内重试复用原映射；旧writer恢复并产生新数据后，必须先退役已放弃基线，再建立新的映射，不能直接用新指纹覆盖旧目标或不断换迁移版本撞同一主键。

1. **标记放弃与围栏**：在账号barrier下将本次迁移执行标识置abandoned、失效其epoch，保持新writer关闭，确认旧迁移Worker不能再发布；恢复旧writer之前记录这一事实。迁移控制审计需持久保存每次执行的基线、target IDs及创建归属、源/目标指纹和阶段。迁移版本标明转换规则，另用execution_id区分执行基线；二者都不改变legacy_map唯一键。
2. **证明可以退役目标**：再次迁移前先检查“该账号新writer从未启用，且没有任何新域摄影师或Agent写入”的持久审计，而不是仅看目前开关关闭或编辑条数为零。每个待清目标必须由被放弃execution创建、实际指纹仍等于其发布记录、没有被另一个迁移/业务根采用或引用。账号barrier保持禁止新写；若已发生新编辑、外部采用或来源不明，则不走自动重建，按切换后修复/逐项迁回处理。
3. **退役未采用复制结果**：保留不可变审计manifest（旧source/target key、指纹、处置结果），按库/画布/内容的锁序删除本execution独占的临时业务目标及关系，释放其迁移引用/holds；先验证全部待删范围，不能删了一半才发现外部引用。跨页作业逐页有幂等回执与cleanup cursor，任何中断只恢复该cleanup，未全部结束不得开始下一基线。某页发现异常时停住，不把剩余页当孤立对象交GC。每页去除对应引用后才释放相应hold；存在合法引用或活动read pin的媒体仍受保留，物理删除独立按宽限处理。
4. **清除旧当前映射**：在目标页退役同事务中，以account/source key及旧execution归属、migration_version、fingerprint的CAS移除该页legacy_map当前映射；归属通过受信manifest验证，不仅靠客户端execution_id。审计历史是快照定位，不是新的GC根/授权源。若某映射并非该执行创建或被其他流程推进，整页回滚并报告，不覆盖它。cleanup全部完成并对账当前映射/独占目标无残留后，记录baseline_retired；保留旧版本对象的合法引用不算必须强删的残留。
5. **建立新基线**：随后重新冻结旧writer、重新取得当时源快照，分配新的execution_id，按同一稳定source key建立新目标和新指纹映射。允许旧A已变为B，使用B的实际内容，不修改旧内容修订冒充B。新映射仍唯一；原复制副本如已无引用可由新域GC回收，不要求物理删除完成才恢复迁移。新旧writer限制全程不放松。

上述退役是未采用迁移结果的清理，不是对新系统编辑做回滚。旧只读入口始终指向旧业务记录；被放弃迁移的预览链接明确标记已退役，不能作为正式业务分享链接继续使用。任何保留异常、未知对象发布或未失效Worker尚未核实，都不能开始cleanup或释放其保护。

FND-11固定验收轨迹：复制A并建映射→复制中断→放弃且围栏旧任务→恢复旧writer将A改为B→再次启动，先在cleanup页提交前/后分别注入崩溃→恢复cleanup并完成映射退役→冻结新源并迁移B→确认单一当前映射、B内容可读、历史A仅保留审计/合法引用，无重复目标或误删其他根。反例同时覆盖新域已产生编辑/目标被采用，此时必须拒绝自动退役。

## 3. 映射与历史语义

| 旧对象 | 新域或兼容目标 | 保留规则 |
|---|---|---|
| 旧inbox/账号素材 | 个人库资产及明确内容修订 | 保留真实来源/说明/权利；相同hash不合并不同声明；原卡多媒体/文字字段逐字段映射，不能只取第一张 |
| 普通创意空间/成员 | 通用项目/画布与节点引用 | 稳定legacy_map保留旧身份与顺序/来源定位；新项目不携带客户、订单、档期外键或业务链接 |
| 媒体对象 | 新前缀不可变副本及新域引用 | 旧creative/planning/avatars由旧域生命周期拥有；新GC不删除旧key；旧版本缺失/无权限时阻止该项迁移 |
| 旧拍摄项、执行事实、备忘与历史策划 | 旧业务只读记录/回跳 | 不静默转成新策划节点或把镜头表写入通用节点；如需导入后续明确业务迁移 |
| 旧CRM关联 | 旧兼容读取与来源说明 | 不删除、不复制进新项目、不自动发布新策划；新创作不依赖CRM填写 |
| 原型v4/v5浏览器数据 | 不作为默认迁移源 | 如要导入，另由摄影师明确选择并按生产内容/权限校验 |

权利声明保留来源证据，不把旧可展示权限升级为ai_analysis外发同意。新模型处理需要用途与外发同意两层检查；历史内容可读不等于获准发模型。复制旧媒体期间必须保护旧固定版本与新临时/正式引用，复制完成不自动释放旧业务仍使用的对象。

## 4. 停止与恢复

| 故障 | 立即动作 | 恢复方式 |
|---|---|---|
| 模型故障/错误路由/费用异常 | 停agent_start和新派发，失效受影响run执行权；维护继续核实已发请求 | 修复目录/配额/适配后以同request/step查询或按原恢复协议；已知结果/费用不重做 |
| 独立节点生成故障/紧急停止 | 账号barrier关闭node_generate和generation_apply，阻止新请求及尚未派发的收费请求，原子撤销相应执行的自动采用权；分批取消节点任务，先受barrier保护再扫描，不等扫描完成才生效 | 查询已派发请求、必要取件/候选入库、核算/对账继续；迟到结果不进节点版本或自动采用。修复后重开只允许新明确操作，旧执行不因开关恢复而自动发布 |
| 画布越权/静默覆盖/引用损坏 | 停受影响账号manual/media/Agent及generation_apply/node_generate writer并保留读取；保存问题操作与快照 | 修复和对账，使用已保存回执/修订恢复，不向旧库双向自动同步 |
| 媒体权限/版本读取错误 | 停新媒体发布及gc_delete，保留候选和引用保护；文字功能可继续 | 固定版本核实、权限修复与恢复验证后重试原操作，不换key重复发布 |
| 旧源冻结后、尚未切换新writer即放弃 | 先停止迁移任务/失效执行权、确认新域无摄影师编辑，保留复制结果/holds | 经账号barrier恢复旧writer；以后再迁移须先执行下节的已放弃目标/映射退役，再固定新源快照，不能沿用旧对账结论 |
| 新writer已提交任何新编辑后回滚 | 停新writer，保留新旧只读，不恢复旧writer | 优先修复前进；必要时执行明确的新数据导出/逐项迁回方案并重新对账，不能靠回退前端二进制丢掉新编辑 |
| 备份恢复 | 暂停相关writer/GC，对齐数据库恢复点与对象版本/队列/模型未知记录 | 恢复后核对未完成任务、已派发请求与幂等记录，先核实再启动Worker；不按“恢复到旧快照”盲发付费请求 |

run取消和writer停用仍遵循统一slot/epoch/同意锁序，不由发布脚本直接改几列绕过领域守卫。灰度不能只依赖内存开关：多API/Worker进程必须看到同一生效边界。

## 5. 发布前必备证据

FND-12发布候选记录：代码/构建及schema版本、功能开关、依赖/模型/Skill/配置版本摘要、账号范围、25需求/10FLOW结果、目标环境媒体/模型实测、备份恢复RPO/RTO、监测面板/告警负责人、停止命令与演练结果。凭证仅记环境变量/受控配置引用，不写值或签名URL。

初次灰度限明确授权的测试/试用账号；应用发布、账号数据切换、物理删除启用分别有可检查的动作和恢复方案，不能把一个笼统go当三项都已执行。实测范围、时间和异常记录进入work证据；未实际生产验证标记not_run，不以本地或测试OSS绿灯替代目标环境。

先导旧Epic的溯源与未完成试用事实保持；路线接管仅在实际批准/切换后单独记录，不等于旧验收完成。正式上线之前的`make check`、目标配置检查与授权不由本设计文档替代。

## 6. 独立生成的开关与维护边界

node_generate控制新执行准入和每次新的模型派发；generation_apply只控制执行器后台自动登记生成版本与自动采用。账号barrier与任务执行权共同决定有效许可，不能只停队列/隐藏按钮。生成紧急停止将两者同时关闭并撤销旧执行的发布资格，维护继续核实已派发请求、读取受控供应商结果、保存execution候选、结算费用和保护引用；维护不能调用新的生成请求或绕过停用写节点版本。已保存历史的读取/下载与人工编辑不依赖这两个生成开关。

停agent_start只影响Agent发起任务，不停止独立人工生成；全writer停用或账号迁移冻结则同时涵盖生成派发及发布，已知/未知执行必须进入切换对账。恢复开关不恢复旧任务已撤销的执行epoch/自动采用权，历史候选采用是新的显式操作。FND-13/12验证停止先提交时不再收费派发、已派发结果迟到仅保留候选、费用仍可核实、历史可读、再次开启不重放旧效果。映射字段由FND-01/13在单一能力源定义，不是新建一套运行配置授权。

### 生成开关与人工版本操作的区别

| 动作 | 必须通过的能力/事实守卫 | 关闭生成后的行为 |
|---|---|---|
| 执行器登记成功结果到节点历史（默认未采用） | 全局账号writer屏障、generation_apply、节点存活/可写与账号归属、ready结果、任务epoch/取消/期限/active归属；Agent来源另核父run/slot。不以目标/来源数据版本未变化作为登记条件 | 禁止；旧publish_operation不得借人工入口重放。生成开启时，人工改内容/选旧版不阻止符合其余资格的成果进入历史 |
| 执行器自动采用已登记结果 | 上述发布/任务资格，再核对目标与来源读集、当前采用指针 | 禁止；生成开启但读集冲突时只禁止采用，已登记历史保持未采用，不回滚其保留根 |
| 人工导入/替换媒体、复制节点 | manual_write；涉及新上传还需media_write；现有ready内容的用途/账号/版本读集校验，复制沿原闭包规则 | 继续可用；为人工来源登记版本，不要求generation_apply，不触发生成请求 |
| 人工选用已存在的历史版本 | manual_write、版本归属/ready修订/用途、目标data_revision；具名SelectNodeVersion及撤销回执 | 继续可用；预览仍只需读取权限 |

# Skill 自定义、市场与审核：灵感记录

本记录来自 2026-09-14 的产品讨论。它保存长期方向和候选交互，不代表本次实现范围，也不替代已批准 Epic。当前执行候选见[Skill 资源化与结构化输入底座方案](modules/skill-foundation.md)。

## 1. 已明确的方向

- Skill 从随二进制发布的内容转为数据库管理、OSS 存放文件的产品资源。
- 摄影师未来能够创建自定义 Skill，选择保持私有，或者申请发布到市场。
- 市场需要后台审核；内容版本、审核过程、上架状态分别管理。
- Skill 选框和 Agent 输入框的斜杠命令，最终插入同一种结构化引用。
- 对话输入可以继续扩展图片、视频等引用，资源 ID 不与普通文字混为同一个无类型字段。
- 本阶段只改造底座并预留必要字段；市场、审核后台、自定义编辑界面另行排期。

## 2. 产品对象与候选流程

| 对象 | 含义 |
|---|---|
| Skill | 长期身份及作者归属，名称可以变化 |
| 草稿 | 可持续编辑的内容，revision 用于处理并发编辑 |
| 版本 | 冻结的正文、manifest 和资源清单，具有不可变 digest |
| 审核单 | 针对一个确切版本的审核过程与结论，不直接修改该版本 |
| 市场发布 | 某个版本对市场上架的事实与历史 |
| 安装 | 摄影师选择使用某个 Skill 版本的关系，不自动获得其全部工具权限 |

候选流程：编辑草稿 → 冻结版本 → 私有使用；需要市场曝光时，针对该版本提交审核 → 通过后上架。驳回后修改草稿并生成新版本，再次送审。

私有使用无需平台人工审核，但需要基础格式、资源和工具声明校验。审核必须绑定版本 ID 与 digest；送审后编辑不能改变审核对象。

## 3. 三种状态不能合成一个 status

- 审核单候选状态：待审核、审核中、通过、驳回、作者撤回。
- 发布记录候选状态：待上架、已上架、作者下架、平台下架。
- 版本执行控制：正常、禁用；禁用阻止之后的执行，不删除历史证据。

v1 在市场上架时，v2 可以同时审核中。v2 上架只切换当前市场版本指针，既有运行仍固定 v1。历史消息、活动运行与已安装版本都不能跟随“最新版”静默漂移。

## 4. 前端输入体验

选框与 `/` 共享可访问目录查询；选中后形成可删除的 Skill 标签，内部保存 skill_id 与 skill_version_id。普通文本中的 `/名字` 本身不构成执行指令，避免名称冲突和重命名造成误调用。

输入使用有序片段：text、skill_ref、content_ref。名称与缩略图用于展示，稳定 ID 和版本用于解析。上传中的附件是草稿对象，不能将临时 OSS URL 当作永久引用。

未来多个 Skill 组合可能有价值，但指令优先级、工具交集与完成标准需要独立设计；第一版每次运行最多一个 Skill。

## 5. 后台审核候选能力

- 审核队列、版本完整预览、与上一市场版本的差异。
- 工具范围变化、外部资源与媒体预览、输出要求检查。
- 审核通过或驳回及原因，作者撤回，版本上架/下架/禁用。
- 审核人、操作人、对象版本、操作时间及原因的不可变记录。
- 默认静态检查；如支持试运行，需要隔离环境、有界权限与预算。

审核覆盖正文、manifest、参考文件与媒体；同一路径的文件不能在通过审核后被替换成另一份字节。

## 6. 尚未拍板的产品策略

以下是讨论中的建议，不写成当前交付承诺：

- 普通下架停止展示和新增安装，已有安装继续使用；平台禁用则停止后续执行。具体边界需要在市场立项时确认。
- 审核通过后立即上架，还是作者选择时机上架。
- 安装后默认固定版本并提示更新；是否提供显式订阅自动更新。
- 市场付费、作者分成、许可证、复制/派生权限、删除与保留期限。
- 审核 SLA、申诉、紧急禁用流程和已运行任务的处置。
- 多 Skill 组合、视频抽帧等多模态处理能力。

当前只保证将来加入这些规则时，不需要推翻 Skill 身份、版本引用和消息结构。

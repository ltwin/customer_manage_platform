## 1. 目标与设计基线

在图片节点工具条增加「图片编辑」入口，一期提供压缩、裁切，并让 Agent 能调用压缩能力。摄影师可以完成常见的文件减重和构图调整，观察真实结果，并恢复编辑前的图片。

本次工作为编写及修订设计文档，不包含功能实现或提交。采用方式、透明图片格式、元数据与布局按本轮评审收敛；质量档位等标为「建议」的数值仍须样张验证。本稿不表示功能已交付或修订后已通过复审。

沿用项目已有概念和设计约束：

- [创意画布基础需求](../../../.codestable/requirements/creative-canvas-foundation.md)：节点是内容的一次使用；修改节点内容不隐式改写资产及其他节点；存入个人库是独立动作。
- [节点版本设计](node-generation.md)：内容修订不可变，浏览版本与采用版本分开，已有任务读取固定输入；新结果不能覆盖后来的人工修改。
- [画布工具设计](canvas-tooling.md)：手工入口和 Agent 工具使用同一业务能力、权限校验和结果事实。
- [已有工具条设计](../../../.codestable/features/2026-10-06-node-toolbar-menu-derive/node-toolbar-menu-derive-design.md)：继承工具条及更多菜单的组织方式。该文档属于历史设计，仅作为基线，不在其中追加本功能。

上述文档提供设计约束，不表示其中所有底层能力均已在当前代码完成；实现前须核验可复用部分。

## 2. 一期范围

| 纳入 | 暂不纳入 |
|---|---|
| 单个已有图片节点的编辑入口 | 多选图片的批量编辑界面 |
| 按输出质量压缩，保持像素尺寸 | 按目标大小自动压缩、自动缩小分辨率 |
| 应用后展示实际文件大小变化，可撤销 | 应用前预览与对比、画质评分、承诺视觉无损 |
| 自由裁切和常见固定比例 | 旋转、拉直、透视、智能主体构图 |
| JPEG、PNG、静态 WebP 输入 | 动图、RAW、SVG、视频编辑及其他格式 |
| 压缩工具供 Agent 调用 | Agent 自动裁切、批量任务编排界面 |
| 可恢复的编辑结果、明确失败及冲突状态 | 重绘、扩图、抠图、高清增强 |

本功能面向主动编辑，与资产列表的缩略图性能优化独立。列表缩略图属于展示派生文件，不应成为本功能的编辑源或编辑结果。

## 3. 入口、样式与通用交互

### 3.1 工具条

建议已有图片工具条顺序为：生成视频 / 图片编辑 ▾ / 全屏 / 存入资产库 / 下载 / 更多。最终间距和响应式收纳沿用现有组件。

「图片编辑」菜单一期只显示「裁切」「压缩」，不展示尚未交付功能的占位项。更多菜单与右键菜单提供一致的图片编辑子菜单，避免只有鼠标悬浮工具条才能发现入口。

| 节点状态 | 入口行为 |
|---|---|
| 单选、图片已就绪且可编辑 | 可用 |
| 空图片节点、非图片节点、多选 | 不展示 |
| 图片加载或上传中 | 禁用，并说明正在准备图片 |
| 原文件不可读取、格式不支持 | 禁用，并说明原因 |
| 只读画布 | 禁用，并说明只读 |
| 当前节点存在会发布新内容的活动任务 | 一期建议禁用，避免并行编辑争用当前内容 |

后端始终重新校验权限和状态；前端可用状态不是授权依据。

### 3.2 参考截图的使用方式

采用截图中的「深色浮动工具条 + 下拉菜单」「画布内裁切框 + 暗色遮罩 + 三分线」交互结构。整体颜色、圆角、字号、阴影、焦点状态沿用当前项目的 v6 样式，不直接复制截图的像素值，也不增加独立皮肤。入口使用「图片编辑」，不使用含义过窄的「高清」。

进入编辑后，收起当前节点的连线把手、普通缩放把手等冲突控件。编辑期间的拖动只作用于编辑内容，不移动节点、不创建连线；点击画布空白不隐式提交或关闭编辑。

菜单可用键盘操作，控件有文字标签和焦点状态。Esc 先关闭当前展开菜单，再取消编辑；输入框内 Enter 不误触应用。窄屏时压缩采用全屏面板，裁切工具条保持在可视区域，不能让确认按钮被遮挡。

## 4. 图片压缩

### 4.1 操作流程

选中图片 → 图片编辑 → 压缩 → 选择质量 → 应用压缩 → 编码完成后当前节点采用结果，并显示实际大小变化。

压缩不做应用前预览（owner 2026-10-13）：调整质量不发起处理，只有点击「应用压缩」才编码一次。不满意时撤销，或在历史版本里切回原图后重新压缩。

打开时固定当前图片修订为本次源图，显示原文件大小、格式、像素尺寸。图片处理应使用该修订的原文件，预览缩略图不能作为编码源。

### 4.2 面板内容

| 区域 | 内容与规则 |
|---|---|
| 输出质量 | 滑杆与整数输入同步，建议范围 1–100，初始值 80 |
| 快捷档位 | 建议高质量 90、均衡 80、小文件 60；数值须用样张校准后冻结 |
| 源图信息 | 原始大小、格式、像素尺寸，以及将输出的格式（按 §4.3 规则；PNG 写明「不含透明像素转 JPEG，含透明像素转 WebP」） |
| 结果信息 | 应用成功后显示：原始大小 → 输出大小、减少比例、实际输出格式；均来自实际文件 |
| 提示 | 「质量越低，通常文件越小，但细节损失更多。像素尺寸保持不变。」 |
| 底部操作 | 取消 / 应用压缩；处理中显示「正在压缩」并禁用应用，防止重复提交 |

质量值不是画质保留百分比，也不是文件缩小比例，不使用「保留 80% 画质」等文案。大小不承诺随每个质量数值严格单调下降。质量 100 也不能称为无损。

计算减少比例时采用 `(原始字节数 - 输出字节数) / 原始字节数`。文件大小可格式化显示，是否减小必须依据实际字节数判断。

点击应用后，前端等待编码完成，再调用与裁切相同的同步采用命令。重复点击或请求重试沿用同一操作身份，不重复编码、不重复创建版本。

每次压缩以打开面板时的固定源图为准。再次压缩以节点当前采用版本为源，即在上一次结果上继续压缩；想从原图重新处理，应先切回原图版本。

### 4.3 格式策略

| 输入 | 输出 | 必须告知或保证 |
|---|---|---|
| JPEG | JPEG | 保持显示方向与像素尺寸 |
| 不含透明像素的 PNG | JPEG | 明示「PNG → JPEG」，不承诺文字、线条等内容视觉无损 |
| 静态 WebP | WebP | 保留透明效果，明确输出格式 |
| 含透明像素的 PNG | 支持透明的 WebP | 明示格式变化，不能填成黑底或白底 |

一期按上述规则自动选择格式，暂不增加格式选择器。应用前在面板说明格式规则，应用后显示实际输出格式。透明图片的编码能力、颜色表现和质量参数含义仍须实现验证；未具备能力时禁用该类输入并解释原因，不能静默改为不透明输出。

输出先校正方向并转换为 sRGB，再移除 EXIF/GPS/XMP，只保留 sRGB ICC；应用前告知输出不保留拍摄附加信息。原图及其元数据保持不变。

### 4.4 特殊状态

- 输出不小于原文件：提示「当前设置未减小文件，请尝试降低质量」，不创建结果版本；面板保留，可调低质量后再次应用。
- 准备或编码失败：面板保留参数和原图，显示可重试错误；不创建成功版本。
- 编码中点击取消或关闭面板：不采用结果，节点不变；尚未发出采用请求时丢弃候选。
- 点击应用后响应丢失：显示「正在确认结果」，查询同一操作，不重新发起压缩或重复创建版本。

保留原图及历史版本会占用存储；本功能减少的是输出文件大小，不承诺释放账号空间。编码结果在采用成功时才计入账号存储额度；取消、失败或冲突留下的结果不计额度，由系统自动回收。若采用时空间不足，明确提示，释放空间后再次应用。

## 5. 图片裁切

### 5.1 编辑状态

在画布中进入裁切模式，初始选择整张图片。顶部工具条提供取消、比例选择、重置、应用裁切。拖动期间显示三分线，选区外加深色遮罩；常驻展示输出尺寸。

比例选项为：自由、原图比例、1:1、4:3、3:4、16:9、9:16。建议默认自由；「原图比例」指固定当前源图比例，仍允许缩小选区，不等于重置整张图。

| 操作 | 规则 |
|---|---|
| 拖动角点或边缘 | 调整选区；固定比例时保持比例并限制在图片内 |
| 拖动选区内部 | 移动整个选区，不移动画布节点 |
| 切换比例 | 尽量保持选区中心，取源图内可容纳的选区，不跳回左上角 |
| 重置 | 回到整图与默认自由模式 |
| 取消 | 回到编辑前内容、节点尺寸与位置，不创建版本 |
| 应用 | 使用原文件对应区域生成真实新文件，不能只改变显示遮罩 |

裁切不填充源图外区域、不放大像素。无实质裁切时禁用应用，避免创建重复版本。最小有效选区至少覆盖一个源像素；极小结果给出尺寸提示，是否增加业务最小尺寸在可用性验证后决定。

### 5.2 输出与布局

裁切坐标依据已校正显示方向的源图片像素，不能直接使用屏幕坐标。前后端采用同一套取整规则，最终预览与输出尺寸应一致；高 DPI、画布缩放不能改变裁切范围。

建议保持源格式和透明效果。裁切后的文件大小不保证更小；JPEG/WebP 如需重编码，使用固定并经验证的高质量策略，不把裁切与可调质量压缩混为一个操作。

应用后沿用现有 `fitMediaSize`：保持节点宽度及左上角位置，按图片比例调整高度；超过现有高度上限的极长图片按既有规则等比缩小。裁切、替换和切换历史版本采用同一尺寸策略，不单设保持中心 / 长边的规则。内容与尺寸变更作为同一次可撤销操作，不自动挪动其他节点。

点击「应用裁切」后，前端等待真实候选就绪，再调用同步采用命令；等待期间关闭页面或取消编辑不会在后台自动更新画布。若采用请求已经发出，则须查询其回执，不能因页面关闭就推定未应用。

## 6. 版本、采用与保存

**采用操作在当前节点新增一个编辑结果版本并设为当前内容，保留来源版本，不默认新增节点。渲染异步完成，采用通过一个同步命令提交。**

| 事项 | 行为 |
|---|---|
| 原图 | 不覆盖原文件，不修改来源资产及其他节点 |
| 结果身份 | 新的不可变图片修订，保留来源修订与操作说明 |
| 版本文案 | 如「压缩 · 质量 80」「裁切 · 3:4」，同时可查实际尺寸、格式、大小 |
| 撤销 / 重做 | 恢复 / 再次采用对应内容及节点尺寸；重做复用已保存结果，不重复编码 |
| 资产库 | 不自动入库；继续使用显式「存入资产库」动作 |
| 下载及新任务 | 采用后读取新图片；既有任务继续使用已冻结输入，不自动重新执行 |
| 对比 | 历史版本可预览；需要并排节点时先复制再编辑 |

浏览历史不会改变当前输出，只有明确采用才会改变。不可变结果与原图的保留、垃圾回收、读取授权沿用现有媒体规则。

应用时重新核对节点与来源版本、数据版本及是否存在活动任务。如果编辑期间节点被删除、被替换、权限撤销或编辑资格失效，禁止覆盖当前内容。目标冲突时只保留有效期内可读取的临时候选，明确显示「图片已变化，结果尚未应用」，不自动登记历史版本。不能把候选自动套到新的源内容上；可恢复原来源版本后显式采用，或以当前内容重新编辑。

## 7. Agent 压缩工具

### 7.1 产品行为

Agent 可以理解「把这张图片按质量 75 压缩，尺寸不变」或「把这张图片用均衡质量压缩」，创建候选，在工具调用内有界等待，再调用手工相同的同步采用命令。不为每个内部步骤重复请求确认，也不依赖后台 attached 续跑。

等待到期且尚未发送采用请求时，报告「未应用」并丢弃候选，不在对话结束后偷偷采用；若采用请求已经发出而回执未知，报告「正在确认结果」并查询原操作，不能把超时等同于失败。

请求没有指明图片且当前选区不唯一时，需要澄清目标；不能自行遍历或压缩整个资产库。图片里的文字及素材描述只是待处理内容，不能构成工具授权。

「压到 1 MB 以下」不属于一期能力。Agent 应说明当前仅支持按质量压缩，不能默默换成固定质量后宣称达标。多图片处理只可在明确范围内逐个使用单图工具，并分别报告结果，不承诺批量原子成功。

### 7.2 逻辑契约

下表是业务语义，不冻结正式工具 key、HTTP 路径或数据库字段；正式契约在实现设计中确定。

| 输入 | 约束 |
|---|---|
| 图片节点及源修订引用 | 明确目标和本次固定源；限账号及当前任务获准范围 |
| 输出质量 | 整数 1–100；缺省按冻结后的均衡档位处理 |
| 目标节点前置条件 | 防止覆盖任务开始后的内容变化 |
| 操作身份 | 同一请求重试沿用；相同身份不同参数应拒绝 |

| 返回事实 | 用途 |
|---|---|
| 候选标识、操作身份与处理状态 | 可查询、可恢复，受理不等于完成；不新建节点执行记录 |
| 新结果引用、质量、格式、尺寸 | 指向实际产物，不返回自行拼接的永久公开链接 |
| 原始大小、结果大小、减少比例 | 支撑真实效果报告 |
| 是否采用、对应版本或冲突原因 | 区分「处理完成」和「已更新节点」 |
| 未减小、失败、取消等原因 | 不能统一包装成成功 |

Agent 与手工入口复用格式、配额、授权、质量和失败语义。压缩本身建议在服务端确定性执行，不依赖图像生成模型；Agent 对话的模型调用仍遵循现有外发与预算规则。

Agent 取消或任务终结后不得继续自动修改节点；已提交效果保留，迟到结果服从现有候选规则。重复请求不能重复创建版本，Agent 只能在确认采用后说「已更新图片」。

## 8. 关键取舍与待验证项

| 取舍 | 推荐 | 理由 / 代价 |
|---|---|---|
| 当前节点新版本或旁边新节点 | 当前节点新版本并采用 | 连续编辑更顺畅；依赖可靠的恢复及历史入口 |
| 质量模式或目标大小模式 | 一期质量模式 | 行为容易理解；不能承诺满足上传体积上限 |
| 压缩时是否同时改分辨率 | 保持尺寸 | 避免一个操作隐式改变两个维度 |
| 压缩是否先预览 | 不预览，应用后展示实际结果（owner 2026-10-13） | 交互更短，每次压缩只编码一次，不产生大量无用预览文件；代价是应用前看不到效果，靠撤销和历史版本恢复 |
| 输出格式 | 按输入自动选并明确展示，透明 PNG 压缩转 WebP | 控件简单，透明效果保留，文件扩展名可能改变 |
| 手工与 Agent 是否各做一套处理 | 复用同一能力 | 结果及权限一致，独立于 Agent 在线状态 |
| 压缩质量档位 | 90 / 80 / 60 建议值 | 需真实照片、文字图、透明图验证，不能凭数字承诺效果 |

处理必须保持正确显示方向和透明效果，尽量保持可感知颜色一致。输出转为 sRGB 并仅保留相应 ICC，移除 EXIF/GPS/XMP；不能宣称完整保留拍摄元数据。不支持或损坏的颜色配置明确报错，不能偷偷猜测颜色。

还需定向确认：现有节点历史和撤销能力的实际覆盖、WebP 编码可用性、临时候选生命周期与配额、超大图片的内存上限、移动端裁切可用性。上述未决不等于新增一期功能。

## 9. 实现影响面

| 分类 | 范围 |
|---|---|
| 必须修改 | 图片工具条及菜单、裁切交互、压缩面板；媒体处理能力；编辑结果登记与采用；压缩工具目录及 Agent 适配；正式 API 契约与生成类型 |
| 必须验证 | 节点历史、撤销 / 重做、内容来源与权限、配额和清理、执行重试及取消、下游固定输入、浏览器原图读取和预览 |
| 仍待调查 | 上节列出的编码、颜色、临时候选、版本及资源能力；具体复用模块和是否需要迁移 |

新增操作纳入既有工具、媒体及画布命令边界；渲染走现有 worker 的图片队列，采用不创建节点异步任务。耗时编码在数据库事务之外进行，版本、图变更、撤销、候选状态与采用回执在同一事务提交。技术契约见配套文档。

本次只增加设计文档，不改 API、schema、功能代码或既有需求完成状态。

## 10. 验收标准

| 编号 | 可观察结果 | 验证方式 |
|---|---|---|
| AC-01 | 符合状态的图片节点出现编辑入口，菜单、工具条、只读和空节点行为一致 | 浏览器交互 |
| AC-02 | 应用前说明将输出的格式；应用后显示原始大小 → 输出大小、减少比例与实际格式，数值来自实际文件 | 真实样张 + 文件检查 |
| AC-03 | 压缩保持像素尺寸与方向，透明图无意外底色；编码使用打开面板时的固定源图 | 文件及像素验证 |
| AC-04 | 调整质量不发起处理；重复点击应用或请求重试只编码一次、只产生一个版本；采用的字节与编码结果一致 | 重复请求与队列测试 |
| AC-05 | 输出未减小时明确提示且不创建结果版本 | 针对性测试 |
| AC-06 | 全部比例、移动、重置、取消可用；画布缩放后裁切范围仍准确 | 浏览器 + 结果像素检查 |
| AC-07 | 裁切得到实际新文件，预览、尺寸、下载及后续输入一致 | 媒体与节点集成测试 |
| AC-08 | 应用只影响当前节点；来源资产及其他节点不变；裁切及历史切换沿用同一宽度 / 左上角规则，撤销 / 重做正确 | 多引用、尺寸及撤销测试 |
| AC-09 | 应用失败、响应丢失、重试不会丢原图或产生重复版本 | 失败注入、真实存储集成测试 |
| AC-10 | 节点改变、删除、权限撤销和取消后，迟到结果不能覆盖画布；裁切等待时关闭页面不自动采用 | 并发、取消及页面关闭测试 |
| AC-11 | Agent 调用真实压缩工具并有界等待；未发送采用而等待超时报告未应用，提交未知单独核实，目标不明时不猜 | Agent 工具链验收 |
| AC-12 | 手工与 Agent 对同一输入参数遵循同一处理规则、权限和错误语义 | 契约与集成测试 |
| AC-13 | 取消、失败、超时或冲突留下的候选文件可回收且不计额度；已采用结果不被误清理 | 保留根及清理测试 |
| AC-14 | 桌面及窄屏下按钮可达、菜单不越界、焦点明确，编辑不误拖节点或连线 | 浏览器视觉与键盘验收 |

样张至少覆盖：高细节照片、肤色与渐变、含小字的截图、透明 PNG、透明 WebP、带方向信息的照片、已高度压缩的小图及较大图片。格式能力或编码默认值改变时，重新验证对应样张。

以上均为未来验收要求，本次编写文档没有执行或通过这些功能测试。

# 内容模块：身份、修订与引用保留

本模块承接[数据模型 §4–5](../data-model.md)，遵循[公共契约](common-contracts.md)。目标是让个人库、画布、Agent 使用同一份可验证内容，而各自拥有独立业务身份；此模块不查询节点坐标，也不因文件存在自动创建资产。

## 1. 内容类型与字段

| kind | 修订 payload v1 | 校验 |
|---|---|---|
| text | body | 纯文本，1–100,000 Unicode 字符；保留换行，不把每行拆成独立素材 |
| link | url, title?, description? | HTTP/HTTPS URL ≤ 4096 字符；标题 ≤ 200、描述 ≤ 2000；不抓取预览、脚本或远程页面 |
| image / video / audio | caption? | caption ≤ 2000；实际 MIME/尺寸/时长从已校验 Blob 读取，不能由 payload 决定 |

所有 payload 为严格对象，拒绝未知字段。类型配置版本与内容修订序号分开；图片替换形成新修订，新增预览渲染件不改原始内容。媒体 ID 只存在显式 content_objects 关系中，不能藏在 payload。具体媒体允许格式与资源上限见[媒体模块](media.md)。

内容身份记录 kind、created_by_kind，以及可选 origin_node_id_snapshot；后者只表示服务器核实的创作来源，不作为授权或保留根。修订包括 content_id、sequence、schema_version、payload、rights_declaration_id、provenance_snapshot、state。来源名称、旧节点/资产 ID 可以为历史快照；实际可用媒体必须通过当前合法关系验证。

## 2. 应用与事务端口

内容写入不提供任意创建后永久无引用的公开 REST 入口。个人库创建文字/链接、节点编辑及媒体发布由所属用例调用下面的受信端口；公开只读入口 `GET /api/v1/creative/content-revisions/{revision_id}` 先验证账号、合法使用入口及当前用途。

| 端口 | 输入 / 输出 | 原子规则 |
|---|---|---|
| CreateRevision | 已校验 draft、来源声明、可选已校验媒体；返回 content_id / revision_id | 创建身份、首修订、声明/对象绑定和使用方保留必须在同一用例事务完成 |
| ForkRevision | source_revision_id、新 payload、来源；返回新身份与首修订 | 同账号可用来源；保留来源摘要但不通过历史链永久保留旧修订 |
| AppendRevision | content_id、expected_source_revision_id、新 payload | 锁内容身份并分配序号，再创建不可变修订；调用方同时核对自己的采用指针，不能用序号替代节点/资产前置条件 |
| RequireUsableRevisions | 受信用途、去重后的 revision IDs | 按固定顺序锁修订、校验归属/ready/用途；调用方在同 Tx 写具体引用，不只在事务外预查 |
| ReadRevision | 当前用途及拥有该引用的业务入口 | 返回内容和授权后的媒体描述，不返回 OSS key；撤销用途实时生效 |

Append 不是把旧修订原地覆盖，也不会广播“最新版本”。节点首次编辑从共享内容分叉；原节点继续编辑自己的派生内容才追加修订。判断由画布应用服务在锁定节点及其内容来源后完成：若内容 origin_node_id_snapshot 不等于当前节点，使用 Fork；来源仅是分叉规则输入，不赋予额外权限。复制出来的新节点因此不会悄悄继续原节点的编辑流；即使追加发生，其他使用方仍固定引用原修订。

以上端口由受信应用协调，不接受浏览器指定“跳过权利校验”“已锁定”等标记。Create/Append/Fork 完成后若用例没有建立节点、资产、运行或候选等正式保留关系，则整个事务回滚。

## 3. 来源与用途

声明不可变；授权记录可撤销。每个修订显式关联声明，声明属于同账号。首期 source_class/rights_basis 沿用既有语义，新增 AI 分析用途必须与展示/生成分开核对；不能简单把老 generation_reference_granted 当 AI 外发同意。

用途分为显示/下载、AI 分析外发、生成引用（首期FND-13）。AI外发还需调用方的供应商与范围同意，Agent会话或节点Prompt各自绑定正确输入范围；内容用途允许并不代替账号同意。撤销与新读取/派发使用当前用途守卫；已发送到供应商的内容不承诺召回。

声明与授权的精确兼容矩阵由现有 planningmedia 的纯策略适配，并补充 AI 分析决策；本批未把旧素材授权扩大。矩阵未完成真实来源样例验证前，只启用可明确证明拥有所需用途的素材，拒绝含糊升级。

## 4. 引用登记和 GC 协作

保留根沿数据模型清单逐项登记：资产（含回收站）、节点、固定输入、上传候选、消息/运行/产物、撤销记录、受信 hold、未来专业文档绑定。每项登记提供所属模块、显式关系路径、创建/释放入口、检查 SQL 与测试标识；新类型缺登记则不能开启该类型的物理清理。

持有修订锁后新增引用；GC 持同一修订锁、以事务内新查询检查全部根。无根才从 ready 标记 deleting 并释放 content_objects。删除方不能根据在加锁前读到的计数继续删除，也不能把历史来源 key 当有效保留。

Blob 层同样先锁定并检查全部对象绑定、上传/校验占有和读取保留，再标记 deleting。对象删除在事务外执行；结果未知保留 deleting 并对账，不能恢复 ready 让新引用连到可能已删除的文件。

内容身份可以留下轻量来源记录，但不因此永久保留所有修订；同一 hash 不合并账号、声明或资产身份。已撤销用途优先于快照授权，不能因为历史消息留着引用就绕过撤销。

## 5. 存储与测试

本批实体/约束初稿见 [content-media-schema.sql](content-media-schema.sql)。SQL 不建外键，保留主键、唯一性、状态/长度/JSON 形状约束；跨表与用途规则必须由以上端口落实。schema 是本模块的增量草案，不是生产迁移编号，也不包含后续资产/画布/Gateway 全表族。

测试从应用端口验证：跨账号来源、错误 content/revision 配对、分叉不影响另一节点、同内容并发追加序号、撤销用途后读取/外发被拒绝、新引用与 GC 串行互斥、缺少使用方保留时回滚。数据库草案验证只证明 DDL 与显式锁协议，不代替这些尚未实现的领域测试。

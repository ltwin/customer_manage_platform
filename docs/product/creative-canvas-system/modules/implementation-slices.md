# 本批模块的实施与验证切片

本文限定公共契约、内容和媒体的模块设计承接；资产库完整管理、画布同步、Gateway 与 Harness 的详细接口继续在后续模块稿细化，不把整个基础框架写成已可开工。下表是本批局部交付切片，不替代 Epic 正式子项或继承旧 ITEM 编号/提交权限。

| 切片 | 依赖 | 可交付结果 | 验收 |
|---|---|---|---|
| CM-01 公共协议与存储适配探针 | 已对齐架构 | 错误/ID/版本/回执契约，DDL 草案；验证 TxAccountScope 与存储测试基座 | DDL 可执行、无外键；原始 SQL 可写悬空 key 的风险可观察；领域守卫测试在实现后必须拒绝它 |
| CM-02 内容及引用端口 | CM-01 | Create/Fork/Append/RequireUsable，来源/用途守卫、引用登记和只读扫描 | 双账号拒绝、分叉/序号并发、引用与 GC 的共同锁协议；无使用方引用的创建整体回滚 |
| CM-03 上传会话与适配器 | CM-01 | Local/OSS 分片、任务执行权、版本校验、阶段恢复、能力清单 | 过期签名、假 MIME、超限、完成/初始化响应丢失、旧 epoch；流式不整段载入视频 |
| CM-04 发布/候选/读取 | CM-02/03 + 最小资产/节点事务端口 | 正式发布、绑定冲突候选、采用/放弃、Range 与 read pin | 上传成功与绑定成功分开；并发采用/到期只成功一方；授权撤销、读取续租失败、中断恢复 |
| CM-05 生命周期与恢复验证 | CM-04 | 配额对账、只读孤立扫描、受保护物理清理、备份/迁移接口 | 其他合法引用仍存活；ready 会话不永久保留 Blob；新旧同 bucket 隔离；恢复与宽限验证后才开启删除 |

CM-04 依赖的最小资产/节点端口已在[个人库](library.md#5-对媒体画布与-agent-的端口)与[画布](canvas.md#5-跨模块事务端口)方案定义，实施依赖 [LC-01/02/03](library-canvas-slices.md)；不能用假节点或孤立 upload URL 算业务闭环；在后续正式开发计划中把依赖映射到实际子项。

## 契约测试矩阵

| 场景 | 层次 / 证据 | 通过标准 |
|---|---|---|
| JSON、ID、版本和错误分支 | OpenAPI 生成物 + 入口验证测试 | 服务端/前端同源；unknown 字段或错位类型明确拒绝 |
| 回执同 key 竞争 / COMMIT unknown | storetest 集成与断点注入 | 最多一次提交，同结果回放，不误清外部对象 |
| 修订绑定 / 清理竞争 | storetest 双事务、有界锁等待 | 加锁后重新查询根，新绑定不能指向已标删除的修订 |
| 目录删除与发布 | 库/内容/媒体联合事务 | 无悬空成员或隐式丢分类；不能完成则候选 |
| Upload init/complete/promote 失联 | 故障注入 + Local/OSS 同语义适配 | 查询恢复同会话/固定对象，不无限新建、重复发布或越权清理 |
| 采用 / 到期 / 重试 | 同候选多连接集成 | 只有一个状态迁移，失败不删除另一方已采用内容 |
| Range / ETag / 撤销 / read pin | HTTP 集成与浏览器媒体样本 | 206/416/HEAD 正确；授权先于304；过期保留前停止流 |
| 成本与容量 | 配额行并发测试 | 预留、发布和物理删除不双计；已失败但未清理对象仍可对账 |
| 新旧隔离 / 灾难恢复 | 授权测试存储演练 | 不扫描旧命名空间；数据库与对象版本一致恢复 |

## DDL 草案的适用范围

[content-media-schema.sql](content-media-schema.sql)包含本批13张表的结构候选，故意不建账号/资源外键。它不是完整产品迁移，尚未包含读取票据、派生任务明细及资产/画布/Agent/Gateway 的全部表；这些必须随所属切片补齐后才接真实入口。正文定义的守卫、不可变载荷、引用校验不由数据库 CHECK 冒充实现。

在正式迁移中按依赖顺序创建本批表，回填/启用独立安排；有数据后不运行破坏性 down 迁移作为业务回滚。先停新 writer，保留读和恢复证据，按既有新旧迁移方案处理。旧先导表和旧 idempotency_records 不在本批 schema 中改写。

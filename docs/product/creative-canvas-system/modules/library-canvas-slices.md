# 第二批模块：实施切片与验证

本批承接[个人库](library.md)与[画布](canvas.md)，局部 LC 编号用于模块依赖，不替代 Epic 正式子项或批准整个产品开发。

| 切片 | 依赖 | 交付 | 验收对应 |
|---|---|---|---|
| LC-01 个人库查询与整理 | CM-01/02 | 账号库、元信息、分组/标签、组合筛选、搜索水位与规范化 | LIB-01–04；FLOW-03；条件切换、同名标签竞争、删除目录/分类行为 |
| LC-02 画布图与命令 | CM-01/02 | 项目、默认画布、类型化命令、参考图、父子组、身份与版本协议 | CAN-01–05；FLOW-01/02/08；读集合、有限坐标、环/端口、跨账号与布局闭包 |
| LC-03 媒体/库/画布交接 | LC-01/02、CM-03 | 两个模块的 InTx 端口完成 CM-04 依赖；导入发布/候选、库拖入画布、节点存入库 | LIB-06；CAN-02；FLOW-02/03；同一回执、锁序、来源/修订固定、失败整体回滚 |
| LC-04 保存同步与撤销 | LC-02 | React Flow 受控适配、草稿/命令队列、版本刷新、Undo/Redo | CAN-06/07；FLOW-05/08；重复/乱序回执、删除恢复版本、跨窗口冲突与草稿保留 |
| LC-05 回收站与保留联验 | LC-01/02/03、CM-04 | 批量恢复/purge、目录删除、全部新增保留根纳入扫描，配合CM-05 | LIB-05；FLOW-06；restore/purge竞争、已有节点不失效、无标签/搜索残留 |

上述 LC-02 与 LC-01 先可各自实现最小部分，再在 LC-03 合流。完整 CM-04/05 依赖这些端口，不能把两个模块互相声明已完成以绕过集成；正式 Epic 切片将按这条依赖链重排。Agent/Gateway/Harness 的模块详细接口仍在下一批，LC-02 只提供受控命令入口。

## 必须通过的服务级场景

| 场景 | 证据 |
|---|---|
| 活跃/回收站、最爱/未归类、子树与标签组合 | 同一应用查询接口返回正确集合、数量和游标；无效过滤不静默扩大范围 |
| 新标签草稿与同名竞争 | 取消草稿零新增；两事务同名返回同一实际ID/颜色、不覆盖已有标签 |
| 归类与删组/标签竞争 | 库根锁内结果完整，无悬空关系；恢复不复活已删目录 |
| 资产/节点内容身份 | 两画布引用同修订，一处编辑分叉，另一处与原资产不变 |
| 元信息/内容/布局并发 | 纯移动不阻塞无依赖的文本应用；上游参考变化令旧 Agent 读集失效 |
| 构组/解组/跨父组/复制 | 世界坐标保持、不重复移动；内部动态引用重映射，外部动态引用清单明确 |
| 删除/撤销/重做 | 版本单调，旧请求不能借恢复后相同ID覆盖；撤销不抹掉无关编辑 |
| 连续与重叠写集撤销 | A/B两次同字段编辑连续Undo/Redo；同组两步合成终态；组外手工改回同值仍冲突；新增外部连线/孩子不可被撤销创建吞掉 |
| 连续本地结构命令与外部拓扑变化 | A拓扑7→8、B只承接8；外部拓扑9则冲突；仅无关内容变化而拓扑8可继续；纯内容命令不得推进旧结构条件 |
| A回执后、快照前发生外部写入 | object_results保持A实际版本，依赖草稿不得采纳外部新版本；无关对象变化仍可续发 |
| 同操作重复/回执未知/过期恢复 | 不重复创建；快照水位不倒退；过期命令只保留草稿 |
| 媒体发布目标变化 | 与媒体共同事务产出候选，不静默修改库分类，不丢来源声明 |
| 已归档或未知类型 | 拒绝不支持的写入；读取保留内容，不能在保存时擦除未知字段 |

## 本轮已执行：SQL 设计探针

运行 `python3 docs/product/creative-canvas-system/modules/run-schema-probe.py --scope library-canvas`。复用标准 storetest 的隔离 PostgreSQL17 空模板，先加载第一批13表，再加载本批16表；临时测试包与容器在结束后清理。查询直接执行 [library-search.sql](library-search.sql)，不在测试中手抄另一套过滤实现。

- TestLibraryFilterSQL：活跃排序、标签all/any、最爱、未归类、组直接/子树去重、回收站、字面 `%`/`_` 共10个子场景通过；另验证跨账号隔离与标签改名后的关键词查询。最终耗时0.09s。
- TestGraphSingleRowConstraints：无外键、唯一默认画布、非有限x、自引用边、双来源输入拒绝；合法节点/固定输入对照通过。最终耗时0.08s。
- TestGraphIdentityRestoreProtocol：删除后身份不复用、恢复从原版本递增、旧数据版本UPDATE影响0行。耗时0.07s。
- TestUndoStateAndReceiptProtocol：单字段组A/B连续Undo/Redo、物理版本递增、手工改回同值仍不能冒充撤销，以及回执对象/拓扑版本不随外部快照变化的SQL原型通过（拓扑7→8后外部变为9，回执仍固定8），耗时0.09s。完整组写集合成、关系闭包和真实服务Undo仍待LC-04验收。
- 最终测试包共2.911s。以上是DDL、查询与存储协议验证，不是实际服务、全部坐标变换、API授权、React Flow帧率或完整Undo验收。

尚未实施的服务/前端测试按上表跟随切片；中文搜索p95仍需目标locale、真实10,000资产及执行计划。完整端口与旧迁移共存、回收恢复仍按架构总体验收，不能用小样本SQL探针替代。

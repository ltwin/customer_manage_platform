# 订单记录：约单状态与收款收尾

> 2026-07-10 `schedule-calendar` 增量已落地：本 requirement 的主体能力保持 current；creation_mode、幂等、schedulable_at 与 order_in_use 扩展已由 `2026-07-09-schedule-calendar` 实现并验收。

## 用户故事

- 作为同时聊着多个客户的摄影师，我希望每个客户的约单都能看到现在走到哪一步，而不是翻聊天记录猜她到底是刚咨询、已定档、已拍完还是已经交付。
- 作为经常先收定金、交付前后再收尾款的摄影师，我希望每单都能标清定金和尾款是否已收，而不是月底对账时靠记忆找漏收。
- 作为把老客户搬进新系统的摄影师，我希望能把历史订单按真实状态补进去，而不是为了录一单已交付的老单假装一步步走完整个流程。
- 作为会录错或遇到坏账 / 取消单的摄影师，我希望取消和完结的订单能清楚留痕，误录的终态垃圾单也能清掉，而不是永远卡在列表和套系引用里。

## 为什么需要

订单是客户关系从"聊过"变成"成交过"的证据。没有订单记录时，拍摄进度、尾款、交付状态和客户最近一次拍摄都散在聊天窗口里，忙起来很容易漏跟进、漏收款，也很难判断一个客户是不是已经很久没有再下单。订单状态一旦不准，后面的档期、提醒和经营统计都会跟着失真。

## 怎么解决

给客户挂一条条约单记录，可以选套系、写价格和备注，把状态从咨询、定档、拍摄、选片、精修、交付推进到完结或取消。系统只记录经营事实：状态走到哪、定金 / 尾款是否已收、拍摄和交付时间是什么。客户详情里能看这个客户的订单，全局订单页能按状态和未收尾款筛选；历史订单可以一次补到真实状态，完结或取消后的误录单可以删除。

## 边界

- 不碰真实支付——定金和尾款只是人工标记，不接支付宝 / 微信支付，不做流水、退款、对账。
- 不安排档期——订单只说明一单服务存在和状态如何，具体哪天几点拍由档期能力管理。
- 不自动生成提醒或 dashboard 卡片——它只把状态和时间记准，提醒扫描和首页聚合由后续能力消费。
- 不做在线选片、云盘交付或客户自助入口——"已选片 / 已交付"只是摄影师记录的状态。
- 不做批量导入——首版支持逐单补录历史订单，CSV / 批量迁移等到真实需要时再设计。
- 新业务与历史补录必须显式区分：新业务只能引用 active 客户和套系；历史 backfill 可引用 active/archived 客户与套系以保留真实记录，但 merged 客户永不允许。
- 不提供随意回退状态——录错的进行中订单先取消再新建；只有已完结或已取消的终态订单允许删除。

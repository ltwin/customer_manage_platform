# 客户档案：多平台客户信息集中维护

## 用户故事

- 作为客户全部散在微信、QQ、Telegram 好友列表里的摄影师，我希望每个客户有一份集中档案——是谁、在哪些平台、手机、生日，而不是想找人时翻聊天记录、靠备注名回忆。
- 作为在多个平台被同一个客户加过好友的摄影师，我希望这些账号归到同一个人名下，而不是微信里一个"她"、Telegram 里又一个"她"，历史记录被拆成两个陌生人。
- 作为拍摄现场听到客户随口提到偏好的摄影师，我希望随手一句话记进她的档案（喜欢胶片感、修图别过度液化），而不是回头忘光、下次又从零开始了解。
- 作为主要靠老客转介绍接单的摄影师，我希望记下谁介绍了谁，而不是想维护介绍人时已经想不起这层关系。
- 作为在小红书、抖音、微博发作品引流的摄影师，我希望每个客户建档时就标好来自哪个渠道，而不是运营半年还说不清哪个平台真正带来了成交。

## 为什么需要

客户资产全部寄生在聊天软件里，而聊天软件只给"联系人"，不给"关系"。谁是老客、生日哪天、有什么忌讳、从哪个平台来——这些信息散在备注名、聊天记录和脑子里，客户一多就开始遗忘，遗忘的下一步就是流失。更麻烦的是同一个客户在不同平台是不同账号，信息想拼都拼不到一起；引流平台发了半年内容，也没法回答"哪个渠道值得继续投入"。

## 怎么解决

给每个客户建一份档案，把各平台社交身份、基本信息、偏好禁忌、来源渠道和转介绍关系收进同一处。建档只要 30 秒——起步只填昵称、平台，顺手标一个来源渠道（小红书 / 抖音 / 微博 / 客户介绍 / 其他），其余什么时候知道什么时候补；渠道是"客户介绍"时可以关联到具体介绍人。在系统任何地方看到这个客户，都能随手追加一句备注。档案是整个系统的地基，订单、档期、提醒都挂靠在客户上。

## 边界

- 不自动同步社媒好友——微信、QQ 没有开放接口，录入靠手工；这个能力的职责是把录入成本压到最低，不是消灭录入。
- 只管"客户是谁、从哪来"，不管"和客户发生了什么"——订单、档期、提醒是别的能力，档案只是挂靠点。
- 不做独立的线索池——咨询未成交的人一样建档，零订单的客户就是线索，不需要第二套管理入口。
- 渠道转化分析（哪个平台成交率高）不在此列——初版只负责把渠道记对，分析是数据积累之后的二期视图。
- 不是给客户用的——客户不登录系统，也看不到自己的档案。

# 提醒引擎：该找谁了，系统主动告诉你

## 用户故事

- 作为客户越积越多的摄影师，我希望客户生日前几天系统提前提醒我，而不是翻朋友圈才想起来、或者过了生日才补祝福。
- 作为拍完一单就扎进下一单的摄影师，我希望交付后过几天系统提醒我回访，问问客户对照片满不满意，而不是交付完就把人忘了。
- 作为靠老客户复购吃饭的摄影师，我希望老客户太久没来拍时系统给我预警——写真客和 cos 客的"太久"标准还不一样，而不是等她彻底流失了才发现。
- 作为每天看提醒清单的摄影师，我希望处理过的提醒能标完成或忽略，同一件事不要反复轰炸我，而不是每天被同一条生日提醒淹没。

## 为什么需要

客户、订单、档期都记进系统之后，数据还是死的——"该找谁了"仍然全靠脑子记。生日错过、回访忘掉、老客户悄悄流失，这些不是记录缺失，是没人主动盯。光有档案柜不解决遗忘，系统必须自己会找人：这是这套系统从"存东西的地方"变成"帮你经营客户的工具"的分水岭。

## 怎么解决

系统每天自动扫一遍客户和订单，按三类规则生成提醒：生日临近、交付后该回访、太久没下新单的流失预警。每条提醒带到期日，处理完标完成，不需要就忽略；反复扫描不会把同一件事生成两遍。提前几天提生日、交付几天后回访、多久算流失（可按拍摄类型分别设）都可以自己调。除了自动规则，也可以随手给某个客户记一条自定义提醒。

## 边界

- 只负责生成和管理提醒，不负责送达——Telegram 每日推送和首页今日待办是消费提醒的另外两个能力。
- 提醒的对象是摄影师自己——系统不会自动给客户发任何消息，联系客户仍然由摄影师手动进行。
- 从没成交过的线索不做流失预警——防止提醒噪音，线索跟进规则留给二期。
- 已归档、已合并的客户不参与提醒扫描。
- 用的前提：生日提醒要档案里录了生日；回访和流失预警要订单记了拍摄 / 交付时间——历史老单缺时间戳的会被跳过，不会误报。

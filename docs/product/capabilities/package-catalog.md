# 套系目录：拍摄服务的商品定义

## 用户故事

- 作为报价全靠翻备忘录和聊天记录的摄影师，我希望把常卖的套系一次定好——写真 90 分钟多少钱、含几张精修，而不是每来一个客户就重新拼一遍价格和交付说明。
- 作为按不同方式计价的摄影师，我希望一个套系能说清是按时长卖、按张数卖还是一口价，而不是把"680 元"写在那儿、张数时长全靠临场解释。
- 作为季节性调整产品的摄影师，我希望把过季或停售的套系下架、下单时不再出现；录错且没有订单引用的套系可以删除，而不是让错误商品一直留在货架上。
- 作为想让下单快起来的摄影师，我希望新约单时直接从在售套系里挑一个带出价格和参数，而不是手动誊写一遍再核对。

## 为什么需要

套系是摄影师的"货架"，但现在这个货架只存在于脑子和备忘录里。同一个写真套系,这次报 680、下次报 720，含不含精修每次讲得都不一样，客户一多就开始互相矛盾。定价方式（按时长还是按张）没有统一的表达，交付承诺（几张底片、几张精修）散在聊天记录里，事后对不上账就变成纠纷。更要命的是套系是订单和档期的引用源——货没定义清楚，下单就没法带出价格，流失预警也没法按拍摄类型分别设阈值。

## 怎么解决

给每个套系建一条定义：叫什么名字、属于哪种拍摄类型（写真 / cosplay / 其他）、怎么计价（按时长 / 按张 / 一口价）、基础价多少，再加上交付参数（时长、起拍张数范围、底片数量、精修张数）和一段自由备注（棚租说明、加拍规则这类）。定好的套系进"在售"列表，下单时直接选一个，价格和参数跟着带出来。不卖了的套系下架收起来，从选择列表里消失，但已经引用它的老订单照常显示历史套系，不受影响；录错且没有引用的套系可以删除，被订单引用时删除会被拒绝。

## 边界

- 不管库存和排期——套系是价目表不是可售数量，能不能拍、有没有档由档期能力管。
- 不管订单——套系只被订单引用，套系本身不创建订单；列表的 `orders_count` 在订单能力接通前恒为 0，销量统计是订单能力接通后长出来的读数。
- 不做促销 / 折扣 / 阶梯定价——首版只有一个基础价加计价方式，活动价临场在订单里改，不进套系定义。
- 下架不校验是否在用——过季套系随时能收起来，不因为有老订单引用就拦着；历史订单继续引用下架套系是正常状态。
- 删除受引用完整性保护——无引用时物理删除；被订单引用时拒绝删除并返回 `package_in_use`。订单域未落地前无真实订单可引用，真实引用检查随 order-tracking 接通。
- 不是给客户看的选购目录——客户不登录系统，套系目录是摄影师自己报价和下单的工作台。

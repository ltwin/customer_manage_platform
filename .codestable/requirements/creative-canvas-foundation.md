# 创意空间基础框架需求

本轮目标是把 v5 已验证的产品方向转为可落地的工程需求：**摄影师在通用画布中使用个人资产创作，Agent 能理解所选内容、检索资产并完成真实的画布操作；关闭再打开后，内容和运行结果仍然可靠。**

本文是需求设计草案，不是已批准的开发任务书。2026-09-10 最新范围包含资产库、画布、Agent真实闭环，以及节点Prompt Box、直接生成和生成版本切换；替代此前生成后置的决定，3D仍后续扩展。具体框架、数据库结构、API、模型供应商和工期在后续设计中确定。原型行为是需求输入，浏览器本地实现和演示数据不是生产实现基线。

路线与阶段出口由 [Epic](../epics/creative-workspace-system.md) 管理；长期探索见[头脑风暴](../../docs/product/creative-canvas-system/brainstorm.md)，当前交互参照 [v5 原型](../../docs/prototypes/creative-workspace/v5/README.md)。本需求只约束新的基础框架，不追溯修改旧先导版的冻结契约。

## 1. 已确认的方向

- 画布是通用创作底座，资产库与 Agent 是围绕画布工作的两项核心能力。项目不关联客户、订单、档期或任何 CRM 对象。
- 资产库使用可展开的侧栏，不恢复独立资产页面。允许没有项目时管理个人库；进入画布不是收藏的前置条件。
- 通用节点与摄影业务节点分开。策划节点展示独立策划的摘要，最大化进入其编辑视图；镜头表和现场执行事实不依赖画布图片节点。
- 连线表达参考输入，角色由目标节点类型和模式解释。连线本身不意味着自动运行，也不要求画布成为完整自动化工作流。
- 风格参考是节点可选输入，底层仍是图片/视频参考及用途说明；不引入另一套“风格连线”。详细模式设计后续展开。
- 基础节点方向包括图片、文字、视频、音频和 3D 导演台。确定扩展方向不等于首期完成全部编辑器、生成与处理能力。
- 拍摄策划 Skill 可选引用某个订单作为本次输入；产出后再选择发布到订单，默认带出来源订单。该关系不传播为项目关系，也不自动发布或进入现场。
- 个人库的分组、标签及画布节点组是不同概念；保留标签即时组合筛选、我的最爱、未归类、回收站等已经讨论的能力。

2026-09-10 补充：画布操作从基础架构起统一工具化，Agent与界面共用应用能力。节点执行按类型声明动作，内部文本执行器用于早期验证；首期还须交付文字/图片/视频/音频的真实节点生成，3D与完整策划执行器后续接入。长期逐步将个人库、策划和CRM等模块开放为同样可授权、可追踪的工具，摄影师可交由Agent组合执行；当前不直接开放全部系统权限。详见[画布工具化](../../docs/product/creative-canvas-system/canvas-tooling.md)。

## 2. 首期交付范围与细分建议

首期面向单个摄影师账号、桌面浏览器主创作、联网保存。不要求多人实时协作；同账号多窗口仍须避免静默覆盖。建议一个项目先提供一张画布，数据身份保留未来多画布的可能。

| 组成 | 首期真正可用 | 后续演进 |
|---|---|---|
| 个人资产库 | 图片、文字、链接、视频、音频导入与预览；分组、标签、检索、最爱、回收站；跨项目引用 | 多模态 RAG、相似检索、知识包、公共市场与权益 |
| 通用画布 | 项目管理；基础内容节点、参考连线、嵌套打组；编辑、撤销、保存与冲突处理；媒体预览/下载；节点Prompt、直接生成与历史版本切换 | 多画布、3D 导演台、专业媒体处理、实时协作 |
| Agent | 真实模型对话、选区上下文、模型与 Skill 选择；查个人资产、添加节点、修改指定文字、整理选区；运行记录与失败恢复 | 更多 Skill、RAG、CRM 工具、复杂长程任务 |
| 业务扩展边界 | 以独立文档的摘要/最大化往返，验证核心不绑定策划内部字段 | 完整拍摄策划工作流、订单发布、导出和现场版本闭环 |

“视频/音频支持”首期包含可靠上传、元信息、经验证格式的播放、引用、下载及节点生成；不包含完整剪辑、任意格式转码或通用逐帧理解。不把原型 5 MB/12 MB 的浏览器存储限制照搬到生产；格式与大小上限在架构阶段通过实际媒体样本、存储与传输预算确定。

2026-09-10 摄影师要求首期提供每节点Prompt Box、直接生成和媒体结果版本切换。当前按文字、图片、视频、音频每类至少一个真实可用生成模型纳入首期；组Prompt为明确范围的Agent任务，链接Prompt整理手填元信息而不抓取网页。详见[节点生成契约](../../docs/product/creative-canvas-system/node-generation.md)，必须有任务、费用、产物持久化和供应商故障验收。

3D、公共市场、完整策划交付和多模态知识库保留明确扩展位置，不以静态占位或预置回复算作交付。正式界面只呈现可用能力；必要的未来说明须清楚标注状态。

## 3. 对象边界与数据归属

以下是产品语义，不预先要求用同名表或服务实现。

| 对象 | 负责的内容 | 必须避免的混淆 |
|---|---|---|
| 项目 | 一次通用创作的名称、画布与创作上下文 | 不作为订单、客户的容器 |
| 画布 | 节点实例、层级、位置、尺寸和有向参考关系 | 不持有独立策划的镜头/现场数据 |
| 内容及修订 | 图片/视频文件版本、可编辑文字等创作内容 | 内容的改变与节点位置改变是两类变化 |
| 资产 | 账号主动收进个人库、可反复使用的内容及来源、标签等整理信息 | 底层上传文件不必自动成为库中资产 |
| 节点实例 | 内容在本画布的一次呈现、使用意图和配置 | 同一资产可以出现多次，不按资产 ID 合并节点 |
| 资产分组 | 长期整理资产的层级结构，一个资产可属于多个组 | 不控制画布父子坐标；“未归类”由普通分组成员关系推导 |
| 标签分类 | 组织标签的目录；标签使用稳定身份、名称与颜色 | 不代替资产分组；标签改名不打断筛选 |
| 画布组 | 节点的父子层级，子节点坐标相对父组 | 不是资产集合，也不直接作为媒体参考 |
| Agent 会话 | 项目内连续的对话及消息 | 会话不是一个无限延续的执行任务 |
| Agent 运行 | 一次明确请求的输入快照、模型、Skill、步骤、产出、用量及终态 | 不能用当前内容替换历史输入，不能把前端动画当服务端任务 |
| 工具 / Skill | 工具执行有边界的动作；Skill 描述方法、所需工具与产物检查 | Skill 不能自行扩大工具权限，也不是新增节点编辑器的替代品 |
| 专业文档 | 如策划，具有自身身份、修订和业务规则 | 其摘要节点被移除，不等于文档被删除 |

**建议的内容更新规则：**资产拖入画布时引用当时内容版本；节点位置、标题和参考意图属于本次使用。修改节点文字或替换媒体形成本次创作内容，不隐式改写资产或其他节点。修改资产的标签/名称不改变已用内容；资产内容有新版本时，由摄影师显式更新引用。“存入个人库”是独立动作，重复请求不创建多份资产。

删除资产、删除节点和释放文件必须分开：资产移入回收站后退出普通搜索，已有合法创作引用仍可用；彻底删除移除库条目和恢复资格，仍被节点、文档或必要快照引用的媒体保留，并在删除说明中交代。最后一个有效引用释放后，文件才进入可清理范围。用途撤销等例外单独服从既有授权规则，不能借引用绕过；详细保留与清理策略在模块设计中落实。

## 4. 核心需求

### 4.1 个人资产库

| 编号 | 需求 | 可观察的完成结果 |
|---|---|---|
| LIB-01 | 无项目也可收集，按类型填写字段；批量文件逐项呈现进度、失败与重试 | 图片描述只属于图片；多行文字保存成一份文字资产；失败项重试不重复已成功项 |
| LIB-02 | 普通分组支持层级、新建、改名、调整、删除、多重归类；最爱/未归类为固定视图 | 删除分组保留资产，子组移到上一级；未归类不受最爱和项目引用影响；禁止分组循环 |
| LIB-03 | 标签选择处即时搜索、选择或创建；管理名称、颜色、分类 | 以稳定标签身份关联；改名仍能找回；删除分类保留标签；取消素材创建不遗留该草稿临时创建的标签 |
| LIB-04 | 支持当前组/全库范围，关键词、类型、标签“同时包含/任意包含”及排序组合 | 查询结果及数量及时对应当前条件；快速切换时旧请求不能覆盖新结果；空结果可清除或扩大范围；首期按收藏时间或名称排序，不承诺相关度排序 |
| LIB-05 | 回收站支持恢复、单个/批量彻底删除、可配置到期清理 | 恢复有效分组/最爱关系；已删除分组不复活；到期清理由服务端执行，不依赖页面打开；媒体遵守引用保留规则 |
| LIB-06 | 可预览、下载、多选拖入画布，也可把画布内容保存到库 | 同一资产多次引用复用已存内容，不重复上传；不同上传会话的同哈希文件不承诺自动去重；画布本地导入及绑定冲突均不强制收藏；库内选中资产不自动更改画布选区 |

素材库首期精确检索覆盖标题、描述、文字内容、来源 URL 和标签。Agent 调用该搜索仍是精确检索，不标为语义检索或 RAG。向量索引后续作为可重建派生数据接入，不成为原始内容的唯一保存位置。

### 4.2 通用画布

| 编号 | 需求 | 可观察的完成结果 |
|---|---|---|
| CAN-01 | 项目创建、改名、归档、重新打开；建议首期一项目一画布 | 不填 CRM 信息即可创作；归档后只读并可恢复；内容状态和个人视口分开保存；首期视口按账号/画布存于本机浏览器，不跨设备同步；缺少本地视口时适配内容范围 |
| CAN-02 | 图片、文字、链接内容、视频、音频的创建、编辑、替换、复制、删除 | 空节点可补内容；上传失败不变成假成功；媒体可预览/下载；文字可连续编辑；不支持格式给出原因；上传完成但目标已变时保留待处理成果，摄影师可重新绑定、存入个人库或放弃，不自动收藏 |
| CAN-03 | 左键框选，修饰键多选，中键/空格平移，缩放；节点上方跟随工具条 | 选择、移动与编辑意图清楚；选中内容即时成为 Agent 待发送引用；附件上传不承担节点引用动作 |
| CAN-04 | 点击连接口创建节点，拖线到空白处创建或连到已有节点；参考方向明确 | 连线端点固定在节点边中心，不跟随连接口吸附动画；非法类型/方向/重复连接有明确反馈 |
| CAN-05 | 组建、解组、嵌套、组内独立移动、整组移动与复制 | 子节点相对父组定位；解组保持世界坐标；父子同时选中不重复移动；整组复制仅复制内部连线 |
| CAN-06 | 撤销/重做及自动保存覆盖节点、内容、层级与连线的合理编辑单元 | 拖动一次、批量添加一次、一次 Agent 已应用改动各为可理解的单元；撤销不回滚其后的无关编辑 |
| CAN-07 | 保存状态、重开恢复、多窗口冲突、异常恢复 | 服务端确认后才能显示已保存；断网保留待保存草稿；重连检测版本，冲突保留双方；不承诺离线完整创作同步 |
| CAN-08 | 普通节点和专业节点使用一致的选择、移动、引用、最大化/还原边界 | 专业节点读写独立内容，删除摘要不删文档；增加内部扩展节点不修改画布核心的摄影业务判断 |
| CAN-09 | 每节点有可保存的Prompt Box：参考、提示词、适配模型/参数、生成/停止 | 选中后跟随节点，切换选择/重开草稿保留；组转明确范围Agent任务，链接只整理元信息；不支持动作显示原因，引用外发与实际任务一致 |
| CAN-10 | 文字、图片、视频、音频直接真实生成，节点data与status明确分开 | 每类至少一个真实模型；空节点生成、已有内容再次生成，进度/失败不清空旧作品；幂等、取消、产物持久化、费用与未知结果可查 |
| CAN-11 | 媒体生成结果版本列表、预览、切换采用、复用参数与删除历史 | 多次生成保留独立结果；预览不改下游，采用可撤销；刷新重开保持采用版本；不随撤销/聊天期限静默清掉节点历史，迟到结果不覆盖人工选择 |

首期链接保存 HTTP/HTTPS URL、手填或Prompt整理的标题和描述；前后端与 Agent 工具均不自动抓取网页、预览图或嵌入远程页面。链接输入作为文字处理；打开来源由摄影师显式触发，拒绝脚本、文件等非 HTTP/HTTPS 协议。后续启用抓取须另设计出站地址、重定向、资源限制及 SSRF 验收。

连线是有向参考关系，不自动遍历执行。首期建议拒绝自环和引用环，避免上游上下文不确定；架构阶段定义可连接类型、上下文遍历范围和模式切换后的失效输入处置。无论采用何种画布组件，这些规则都属于产品约束。

首期移动端建议提供项目找回、内容阅读、媒体预览与基本文字编辑，不承诺与桌面等价的复杂拖拽。手机现场模式属于策划业务的后续交付，不能以画布缩小版替代。

### 4.3 Agent 与 Skill

| 编号 | 需求 | 可观察的完成结果 |
|---|---|---|
| AG-01 | 真实对话、会话保存、选择可用模型与 Skill、独立上传附件 | 模型不可用时明确失败或由摄影师选择替代；不能悄悄换模型；演示回复不得混入真实结果 |
| AG-02 | 选中节点自动成为待发送引用；发送时冻结选区、内容修订及必要参考输入 | 后续改变选区不改变正在运行任务；引用可定位来源；组引用展开其内容时显示范围；上游自动扩展有数量/容量边界 |
| AG-03 | 画布基础能力从初版统一工具化；Agent可查看获准画布/节点、创建节点、编辑/连接/组织节点，并请求执行类型已声明的动作；保留个人库检索等工具 | 界面与Agent共用真实应用能力及回执；查参考并创建节点有真实来源；内部类型及首期真实生成类型验证查看→创建→执行→核对结果；未配置/未注册动作明确拒绝；受理不冒充执行完成 |
| AG-04 | 平台维护的 Skill 有身份、版本、输入要求、工具范围、输出与完成检查 | 建议首个 Skill 为“整理参考与创作方向”；运行记录可重现采用的方法与输入，不依赖一段不可追溯提示词 |
| AG-05 | 明确状态：等待、运行、待补充、部分完成、失败、取消、完成 | 刷新仍可查询；取消停止后续步骤，已完成结果可见；未知外部结果先核实再重试；失败不留下无限转圈 |
| AG-06 | 可逆编辑遵守明确任务范围，批量/覆盖风险按实际影响处理 | 明确要求的低影响编辑可直接执行并提供撤销；模糊范围或覆盖人工内容时先给具体提案；不逐步重复确认 |
| AG-07 | 工具具备账号范围、输入校验、幂等与版本检查，运行可定位每步改动 | 伪造资源 ID 被拒绝；超时重试不重复节点；运行期间人工改动不被过期结果覆盖；未知字段不能直接落库 |
| AG-08 | 模型输入与能力匹配，用量、预算、运行上限可见 | 支持图片的模型才发送获准图片；不支持视频/音频理解时说明只读取元信息；不伪称看过内容；达到限额停止新增调用；首次外发前展示供应商、用途和内容范围并记录授权，已有覆盖相同范围的有效授权可复用；拒绝后保留草稿，人工功能仍可用 |

权限由系统校验，不由提示词承担。素材说明、导入文字和网页内容是待处理数据，不能改变工具权限。模型凭证只在服务端；首期仅注册所需受控工具，不开放任意代码执行或第三方 Skill 安装。已有外发授权与预算范围可复用，不把每一步都做成审批。外发范围覆盖摄影师输入、节点/附件和工具检索结果；授权供应商、用途或数据范围变化时重新提示。账号外发同意与素材用途权利是两项独立校验，任何一项不满足都不能发送；授权撤销阻止后续发送，不承诺召回已发出的内容。

建议首期运行不强依赖浏览器持续在线；断开后重新进入可看到任务终态及结果。是否采用独立任务进程、流式协议或其他机制属于架构阶段；必须满足的产品行为是任务有界、可取消、可查询，已产生的效果不因消息丢失而重复执行。

## 5. 三部分的贯穿验收场景

| 编号 | 场景 | 验收断言 |
|---|---|---|
| FLOW-01 | 不使用 Agent：建空项目，导入图文，连线、打组、修改、关闭重开 | 全程无需 CRM，真实服务端持久化；媒体、层级、坐标、文字与连线一致 |
| FLOW-02 | 同一资产放入两个项目，在一处替换内容，再移除节点 | 另一处引用及原资产不变；不重复上传原文件；删除节点不删除库条目 |
| FLOW-03 | 从个人库按分组与多个标签找回素材，多选放入画布 | 搜索与条件一致，引用真实资产，批量添加可整体撤销；无项目时同样可整理库 |
| FLOW-04 | 选中参考，使用真实模型和首个 Skill 查库、添加节点、写创作方向 | 返回可编辑结果、实际引用和运行记录；失败不伪造成功；无匹配不伪造素材 |
| FLOW-05 | Agent 读取文字后摄影师手工修改，同时模拟超时、取消与重试 | 过期写入被拒绝或成为可比较提案；取消后不继续写；回执丢失不重复创建；刷新可查看终态 |
| FLOW-06 | 资产移入回收站、恢复、彻底删除；删除其所在分组 | 已有创作引用保持约定行为；库条目恢复规则可预测；引用尚存的文件不被误清理 |
| FLOW-07 | 用独立文档测试扩展节点，最大化、还原、移除、重新引用 | 文档身份与内容保留，画布核心不保存镜头/订单字段；只证明扩展边界，不算完整策划交付 |
| FLOW-08 | 两个账号访问资产、节点、任务、下载；同账号两个窗口同时编辑 | 跨账号所有路径受限；同账号冲突显式处理；媒体授权失败可诊断、不显示永久假占位 |
| FLOW-09 | 选区大小或模型能力不满足任务，模型服务不可用 | 原因明确、草稿保留；可调整范围/模型再发起；人工画布与库功能持续可用 |
| FLOW-10 | 不经聊天，从节点Prompt两次生成，浏览/采用旧版、关闭重开；再由Agent执行同类动作 | 四类真实模型结果持久；草稿/采用版本不丢；结果/费用/状态可追溯；失败、取消、并发编辑和版本保留符合CAN-09–11 |

工程验收以真实前后端、数据库和授权测试对象存储为证据；生产对象存储验证单独记录。模型验收需真实供应商结果，桩测试只验证契约和故障语义。原型截图、IndexedDB、预置回复均不替代这些证据。

## 6. 质量要求与待测预算

以下是建议的验收预算，架构阶段需写清设备、浏览器、网络、媒体体积及测试数据分布，再冻结口径；当前不声称已达到。

| 方面 | 建议基线 |
|---|---|
| 资产规模 | 单账号 10,000 条资产、100 个分组、200 个标签；组合精确检索服务端 p95 ≤ 500 ms，端到端首批结果 p95 ≤ 1 s；冷启动另记，不只测暖缓存 |
| 画布规模 | 200 个节点、300 条连线、3 层组；缩略图场景下连续平移/缩放/拖动 10 分钟，帧间隔 p95 ≤ 33 ms，无连续 1 s 主线程卡死；不同时解码所有原视频 |
| 保存体验 | 普通小编辑停止后 2 s 内得到保存结果，网络异常有明确状态；上传与生成独立显示进度；明确保存成功的数据重开不丢 |
| Agent | 真实固定案例覆盖工具成功、无结果、非法输入、冲突、取消、部分失败、重复回执与限额；成功率、耗时、费用各自统计；数值预算随模型实测冻结 |
| 数据可靠性 | 上传提交、文件引用、回收、内容修订、Agent 结果具备恢复验证；多步骤部分成功可解释，不能只看 HTTP 200 |
| 可观测性 | 通过请求/运行标识关联错误、步骤与对象；日志避免凭证及不必要的私有正文；模型耗时与工具耗时分开记录 |

基础框架试用建议邀请 2–3 名摄影师，用各自真实素材完成 FLOW-01/03/04，记录完成率、卡点与是否愿意继续使用。这是试用建议，不继承旧候选 Epic 的五次实拍要求；完整策划交付另设真实现场验收。

## 7. 现有工程与原型的承接

- 项目已有账号隔离、Go/React/PostgreSQL、OpenAPI 契约与对象存储约束，沿用仓库硬规则。新业务数据必须限定账号；客户端不传账号身份作为授权依据。
- 旧先导版媒体、卡片和空间关系的历史调查见 Epic，正式架构阶段必须在确定的集成基线上重新核对；不直接把原型对象一一翻译成数据库表。
- 新旧入口、历史关联、内容与媒体引用需迁移对照和恢复演练；不以去掉唯一索引或复制旧数据的一步操作视作完成迁移。项目的新语义不要求静默删除旧 CRM 关联。
- 保持旧先导只读/停用约束；新能力准入策略单独明确，禁止通过新版入口绕过账号状态。停用 Agent 应不影响人工编辑；停止新 writer 后保留已有内容读取。
- v5 的原生资产侧栏、父子相对坐标和交互规则作为行为样例，原型源码是否复用由模块设计决定。原型浏览器资料不是默认生产迁移来源；若需导入，另做显式导入与校验。

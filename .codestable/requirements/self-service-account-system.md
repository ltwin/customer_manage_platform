# 公开自助注册与多账号登录

## 用户故事

- 作为第一次使用影约 CRM 的摄影师，我希望用自己的邮箱和密码完成注册，验证邮箱后就能进入经营台，而不是先联系管理员等待人工开通。
- 作为经常在浏览器里管理客户和档期的摄影师，我希望登录状态能安全恢复，退出后立即结束当前登录；忘记密码时也能通过自己的邮箱重新取得访问权。
- 作为已经用单账号版本积累了客户、订单、档期和头像资料的摄影师，我希望升级后认领原来的账号并继续看到全部数据，而不是创建一个空账号后重新搬资料。
- 作为准备把系统开放给更多摄影师的经营者，我希望公开注册具备验证、密码恢复、登录防护和会话撤销能力，确认安全条件齐备后再正式开放。

## 为什么需要

当前版本只适合单账号私有使用：首次启动依赖管理员预置密码，新摄影师不能自己注册，已有账号也没有邮箱验证、密码恢复和可撤销的长期登录。这样既无法公开开放，又会让旧账号升级面临数据搬迁和访问中断风险。

## 怎么解决

摄影师使用邮箱和密码创建账号，验证邮箱后进入自己的经营空间；以后可以登录、恢复浏览器登录状态、退出、找回或修改密码。每个账号的数据彼此隔离，未验证的账号不能访问经营数据。既有单账号部署通过受信的认领流程绑定 owner 邮箱，同时保留原账号和全部 CRM 数据。只有注册、恢复、登录防护和上线检查全部满足后，系统才允许正式开放公开注册。

## 边界

- 首期只支持邮箱和密码；手机号登录、短信验证码、第三方 OAuth 和 SSO 不在本能力范围内。
- 首期只面向同源 Web 浏览器；原生 App、API Key 和其他客户端凭证方式另行规划。
- 不包含修改或换绑邮箱、账号注销／删除、设备管理中心、逐设备下线、登录历史和完整安全审计中心。
- 不负责采购邮件服务、配置发件域名／DNS、制定服务条款或隐私政策；这些仍需要独立的外部决策和授权。
- 验证邮箱前不能访问客户、订单、档期、提醒、头像、设置或导出等 CRM 数据。
- 核心账号访问闭环可先在测试或封闭环境验收；完成密码恢复、持久化登录防护、监控和生产预检之前，不得开放生产公开注册。
- 真实生产迁移、旧账号 owner 邮箱绑定、旧登录切换、密钥轮换、部署和公开放量不由本 requirement 自动授权。

- 需求基线：[v6 PRD v0.2](../../../docs/product/creative-canvas-system/v6-workspace-prd.md)、[基础需求](../creative-canvas-foundation.md)、[v6 原型](../../../docs/prototypes/creative-workspace/v6/README.md)。
- 代码依据：[2026-10-05 差距分析及 E01–E15 证据](../../../docs/product/creative-canvas-system/v6-implementation-gap-list.md)，代码基线 `057e46c`。该报告作为调查快照保留，后续进度只更新本清单。
- 每项独立需求文件包含范围、当前基础、前置依赖、待定问题、可勾选 AC 和 design/验证要求；**本总表是本清单执行状态与产物链接的唯一登记处**。
- [PRD 全量追踪表](traceability.md)：PRD 222 个编号逐个对应主责条目、协作条目和验收证据。已实现的需求同样要有主责条目和验收证据；条目关闭时回填证据列。
- 当前只整理需求。全部 design/实现尚未在本清单启动；既有实现状态见条目基础，不用历史代码或前端 391 项通过冒充新需求验收完成。
- 顺序是建议，不是新增审批流程；具体设计/实施按当时任务授权及仓库流程推进。本清单没有创建或激活新 Epic，也没有重写既有批准基线。

## 如何逐项推进

1. 指定编号，例如「开始 V6-001 的 design」。先读取该条、原 PRD 和依赖，再复核实际代码。
2. 为该条写 design，覆盖 AC、未决事项、共享契约和失败恢复；把文档链接填入本表。涉及共同协议时先与相关条目对齐，不在兄弟条目复制冲突定义。
3. 设计结论明确并取得当前任务所需授权后实施；实施前满足表中硬依赖，按实际进度更新状态。
4. 验证每个 AC，记录门禁和场景证据。全部通过才标已完成；范围删减、暂缓和跳过必须记录理由，不能算完成。
5. 大小超出一次可审查交付时追加子编号（如 V6-023.1），保留父条与映射；稳定 ID 不重新编号。只在当前条目开始时创建 design/任务/验证文件，不预建空文件。V6-023、V6-038 已在条目内预拆子项；子项进度写在父条「产物」列，父条仍按完整 AC 关闭。
6. 轻量修复（如 V6-017）保留编号与 AC，可以不写完整 design 文档，修复记录和验证证据链接回本表即可。
7. 验证每个 AC 时，同时对照 [追踪表](traceability.md) 中本条主责的 PRD 原条目验收要点；通过后在追踪表回填证据。

**状态词**：待设计 → 设计中 → 待实现 → 实现中 → 待验收 → 已完成；另有「待验证」（已有基础，先核查）、「受阻」（说明具体前置）、「候选」（未定范围）、「暂缓」（记录决定）。

表中依赖是**实现/完整验收依赖**，不阻止提前设计。各条的外部资源/产品决定单独写在文件里；当前不因未来所需资源未齐而把整个清单标为受阻。

**产物**列依次填写 design / implementation / verification 的真实链接。未授权提交时 implementation 可链接工作记录及 diff，不要求为填表擅自提交。若之后由仓库工作流接管执行状态，应在此登记迁移入口并停止双写。

- **第一批：人工主链明确差距**。V6-001/002/003/004/006/007/008/017/059 可先做 design（V6-017 走轻量修复）；链接/音频 V6-009/010 先补原型，再接入 A/L；引用、版本、分组和资产库按各项依赖接续，V6-014/015 待 D-03 确定后共同 design。
- **第二批：真实生成**。先设计 V6-021/022/023，冻结供应商和报价边界，图片贯通后逐项接文字/视频/音频；公共机制服务首个图片场景，不单独堆横向基础建设。
- **第三批：助手最小可写闭环**。V6-028/029/030 → V6-032/038 的提案与变更归属 → V6-034 最小写工具；查库 V6-035 可独立设计，随后生成 V6-036、组织 V6-037。
- **第四批：助手交互完善**。结构化提问、确认/自动模式、节点联动、后台恢复、排队、会话与附件逐项推进。协议需要提前对齐，不等到 UI 做完才补持久化。
- **验收贯穿每批**。V6-019/020/046 和基线回归 V6-055/056/057 可先核查已有部分，发现缺口回流到对应交付条目；每项局部验证后再纳入 V6-048 的 UF 清单。V6-047 只代表性能验收，不替代功能验收。
- **后续范围**。V6-049–052 为 P2；V6-054 仅候选。它们不阻塞首期。V6-053、V6-058 为 P1，属于首期应有能力。

OpenAI/GPT 系列与多 provider 故障切换保留为此前讨论的 Gateway 扩展输入；本清单不把它们偷偷改成 PRD 硬要求。需要推进时另立条目并将依赖挂入相应模型接入，不用聊天模型接入替代媒体生成。

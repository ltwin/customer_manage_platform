## 目标与范围

在已有保存队列、离线与冲突处理之上，补正常编辑时可见的「保存中 / 已保存」状态。

范围外：保存队列、断网草稿与多窗口冲突的机制本身已存在，本条不重做，只验收不退化。

## 当前基础

以下是 2026-10-05 的分析依据，只取与本条相关部分；开工时复核，不将同一 GAP 内其他子需求一并带入。

- 2026-10-05 复核：已有离线、错误、恢复提示及内部 `data-sync`，但正常编辑时没有可见的「保存中 / 已保存」；没有证据表明会提前显示假成功。

## 验收标准

- [x] **AC-01**：正常编辑时可见保存状态：有未确认修改时显示「保存中」，服务端确认后才显示「已保存」，不提前显示成功。
- [x] **AC-02**：断网时显示离线并保留本机草稿，恢复后自动提交并回到正常状态。
- [x] **AC-03**：多窗口冲突时双方内容都保留，状态说明冲突而不是显示已保存。
- [x] **AC-04**：状态展示不干扰画布操作，不进入撤销栈。

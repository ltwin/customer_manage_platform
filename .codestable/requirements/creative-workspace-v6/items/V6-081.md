# V6-081 · cosplay 拍摄策划 Skill

[返回需求总表](../README.md) · 优先级：P0 · 类型：交付

**需求来源**：2026-10-15 owner 提出制作「cosplay 拍摄策划」内置 Skill，并在讨论中拍板下列各项。PRD v0.2 之外的新增范围，没有 PRD 编号。

**推进状态与产物链接以总表本条记录为准**，本文件只维护需求，不重复记录执行状态。

## 目标与范围

一个内置 Skill 包（`deploy/creative-skills/` 下），和摄影师一起完成 cosplay 拍摄策划，产出 [V6-079](V6-079.md) 的策划文档。cosplay 拍摄常常涉及垂类场景和偏门角色，好创意要靠两件事：参考头部作品，调查角色资料。

**人机协同，不自动走到底。** 对话只用来做决策，情绪板在画布上协同，结构化内容在策划文档里协同。

| 阶段 | 产出 | 是否停下来问 |
|---|---|---|
| 理解输入 | 角色身份、拍摄条件（棚拍 / 外景 / 合成）、交付要求 | 关键项缺失或有歧义（同名角色、多皮肤 / 形态）时问 |
| 角色调研（IP 拆解） | 视觉锚点（识别符号、标志动作、角色元素）、世界观与美术调性，带来源 | 资料不足时向摄影师要设定图，不编造 |
| 创意方向 | 先摸清常见拍法，再给 2–3 个方向：概念、场景、光影、色彩脚本、与常见作品的差别、执行难度 | **必停**，摄影师选择或混合 |
| 情绪板 | 按光影 / 构图透视 / 场景材质 / 色彩分组放上画布 | 摄影师直接在画布上增删，助手读画布同步 |
| 视觉设定 | 基于搜集到的或摄影师提供的角色资料与图片，生成人设三视图（正 / 侧 / 背）；基于创意方向与情绪板生成场景主图，再由主图派生几个角度 | **必停**：摄影师确认设定后才往下做；分镜以确认的设定为参考 |
| 拍摄方案 | 主光、环境光、特殊光效（给后期留接口）、肢体遮挡处理、2+4+3 镜头表、妆造道具清单 | 不停，假设标「待确认」 |
| 后期与 AI 辅助 | 从后期 SOP 挑出本次适用的步骤，标出可用 AI 的点 | 不停 |
| 分镜 | 每个镜头一张分镜图，生成时把镜头用到的人设与场景设定连为参考 | **生成前必停**：列出目标镜头、每格的参考连线（设定与版本、参考图数）、风格、模型参数与预计消耗，摄影师确认后才生成；没有确认的设定时提示先确认设定。摄影师已在镜头表里选好范围和风格时，直接按所选列出，不再重复问 |
| 汇总 | 策划文档定稿，画布上出现策划节点 | 给一页摘要 |

摄影师可以随时说「直接出初稿」（不停顿走完，所有假设标注出来），或「只做某一步」（只做那一步）。不强制走完全程。

**owner 2026-10-15 拍板**：

- 截图里的全流程 SOP 和 2+4+3 交付阵列来自 cosplay 摄影领域头部摄影师的经验，作为 Skill 的固定方法论，首版不允许摄影师修改。
- 参考来源没有主次，按摄影师意向走（见 [V6-080](V6-080.md)）。
- 分镜图由助手调用生图模型生成。风格由摄影师选择（如预演草图、写实概念图），不由 Skill 默认决定。
- 原作设定图允许作为生成参考。
- 报告目前只给摄影师看。
- 分镜之前先做视觉设定（人设图与场景设定图），否则分镜之间场景、角色不一致，后期难以复刻。策划阶段没有 coser 定妆照，人设图由助手基于搜集到的或摄影师提供的角色资料与图片生成，一般是三视图（owner 2026-10-15）。
- **生图模型与参数默认**（视觉设定、分镜都适用）：优先 `gpt-image-2.5-sunburst`，`resolution` 2K、`quality` high；不可用时依次降级 `gpt-image-2.5-flare` → `gpt-image-2` → Nano Banana 2.1。这是默认参数，Skill 直接用、不先问；以后上线 manual 模式时，助手生成前向摄影师提问确认参数，摄影师可改（owner 2026-10-15）。

**要覆盖的输入**：

| 输入 | 处理 |
|---|---|
| 只有角色名 | 从「理解输入」开始走全程 |
| 角色名加风格要求 | 创意方向收窄为围绕该风格的变体 |
| 冷门角色或原创角色（OC） | 资料不足时要设定图，查不到的项标为缺口 |
| 带参考图或链接 | 直接进情绪板，并从中提炼风格 |
| 粘贴客户需求或聊天记录 | 抽出场地、预算、交付数量等约束 |
| 已定场地的照片 | 光源逻辑、透视匹配以真实场地为准 |
| 选中画布节点后调用 | 把选中内容当输入，不重复搜集 |
| 已有策划要局部修改 | 读策划文档，只改对应章节；消息带了摘录（`quote`）或参考图（`ref_id`）时只改那一段或按那张图改，其余原样保留 |
| 拍摄条件变了（如「只剩两小时、两盏灯、不能洒水」） | 找出受影响的章节与镜头逐处改，已确认的创意不动；回复里说清改了哪几处、哪些没动，新增的准备项写进准备清单 |
| 要求「补齐镜头方案」 | 只写镜头文字：补空字段、补到 2+4+3 目标数，不生成分镜图 |
| 多角色、CP、团体 | IP 拆解按角色分开，构图考虑人物关系 |

## 当前基础

2026-10-15 静态核对的代码基础，开工时复测：

- 包格式：`manifest.json` + `SKILL.md` + 其余 UTF-8 文本资源；单文件 64 KiB、至多 20 个文件、整包 256 KiB。服务启动时自动同步进平台目录（[导入文档](../../../../docs/dev/creative-skill-import.md)）。现有种子包只有 `reference-direction.v1`。
- `tool_allowlist` 实际只约束 Skill 类工具（`load_skill` / `read_skill_resource` / `read_result`），其余工具按部署能力开放；但清单里任何一个工具未注册，整个 Skill 在目录中隐藏。
- Skill 只作用于当条消息；后续轮次模型可以用 `load_skill` 重新加载本会话用过的 Skill，是否主动加载未实测。
- 可用工具：`search_web` / `read_webpage`（Firecrawl 试点）、`search_assets`、`read_canvas` / `edit_canvas`、`read_asset`、`set_node_prompt` / `generate_node`（GPT Image 2 / 2.5，参考只来自连入的上游节点）、`update_plan`。
- 没有结构化提问，[V6-031](V6-031.md) 待设计；首版用文字提问。
- 生图模型：`set_node_prompt` 的模型参数是当前部署可用模型的枚举，不可用的模型不会出现，所以「不可用就降级」按优先顺序取第一个出现的即可。已接入 `gpt-image-2`、`gpt-image-2.5-sunburst`、`gpt-image-2.5-flare`，三者参数相同（`resolution` 1K/2K/4K 默认 2K，`quality` low/medium/high 默认 medium，需显式传 high）。Nano Banana 2.1 尚未接入，接入前降级链到 `gpt-image-2` 为止。

## 依赖与设计前置

依赖 [V6-079](V6-079.md)（策划文档）、[V6-080](V6-080.md)（网上参考图）、[V6-036](V6-036.md)（助手生成，`generate_node` 已交付）。角色调研、创意方向两步只用现有工具，可以先写先测，尽早验证内容质量。

design 时需要定：

- **包结构**：`SKILL.md` 写流程、停顿点、输入分流；references 分文件写 IP 拆解维度、差异化方法（怎么找参考做到和别人不一样）、光源逻辑、后期合成 SOP、交付标准、分镜提示词写法、报告章节说明。
- **`tool_allowlist`**：列不列网页工具。列上则未配 Firecrawl 的部署看不到这个 Skill；不列则要写清没有网页工具时的降级做法。
- **多轮连续性**：后续轮次怎么回到 Skill。进度保存在策划文档的章节状态里，不依赖对话历史；「有进行中的策划时先加载 Skill 再读策划」这条规则写在 base 指令还是 Skill 里，需要实测可靠性。策划编辑视图里的助手就是同一个会话，从编辑视图发的消息默认带本 Skill，并可带指向章节 / 设定 / 镜头的 `document_ref`（V6-079 design §7.6）；Skill 要写清收到 `document_ref` 时先读对应单元、只改这一处。
- **视觉设定**：三视图与场景主图的提示词模板；从主图派生角度时如何保持一致；设定依据（引用了哪些资料图）怎么记录。
- **分镜**：每种风格的提示词模板；参考连线规则（人设图、场景设定图、情绪板参考）；比例按交付用途。
- **模型选择与降级**：按 owner 定的顺序选模型并带 2K / high；Nano Banana 2.1 接入后参数名不同时如何对应「2K / high」。生成时失败（不是目录里不可用）要不要换下一个模型重试：换模型会改变画风，同一批设定和分镜之间最好用同一个模型，需要定规则，并在回复里说明实际用了哪个模型。
- **完成检查**：`completion_check_key` 检查哪些项。

## 验收标准

- [ ] **AC-01**：只给角色名时，能完成角色调研，给出带来源的视觉锚点与世界观；资料不足或身份有歧义时停下来问，不编造。
- [ ] **AC-02**：给出 2–3 个创意方向，每个写明概念、场景、光影、色彩、与常见作品的差别、执行难度；摄影师选择之前不往下做。
- [ ] **AC-03**：情绪板参考按维度分组放上画布；摄影师在画布上增删后，助手读画布同步，不把已删的图加回来。
- [ ] **AC-04**：拍摄方案、后期方案和 2+4+3 镜头表写入策划文档，未确认的假设标「待确认」。
- [ ] **AC-05**：分镜生成前列出目标镜头、参考连线、风格、模型参数与预计消耗，摄影师确认后才生成；能按反馈只重生成某一格；「补齐镜头方案」只写文字不生成图。
- [ ] **AC-11**：消息带摘录或参考图时只改那一处；拍摄条件变化时只改受影响的部分，已确认的创意不动，并在回复里说清改了什么、没动什么。
- [ ] **AC-10**：分镜前先生成人设三视图与场景设定图，摄影师确认后才生成分镜；每格分镜以对应设定为参考，同一场景的分镜之间空间与陈设一致。
- [ ] **AC-06**：「要覆盖的输入」表里每类输入都有一次真实对话走查记录。
- [ ] **AC-07**：中断后换会话继续，或摄影师中途手改过文档，都能按文档状态接上。
- [ ] **AC-08**：「直接出初稿」时不停顿走完且假设全部标注；「只做某一步」时只做那一步。
- [ ] **AC-09**：真实模型完整跑通一个冷门角色和一个热门角色的策划，保留调用记录。

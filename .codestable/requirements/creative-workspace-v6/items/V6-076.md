# V6-076 · 图片编辑一期：压缩、裁切与 Agent 压缩

## 目标与范围

图片节点工具条新增「图片编辑」，一期提供压缩和裁切；Agent 可以调用压缩。结果作为当前节点的新版本采用，可撤销。压缩不做应用前预览：点击应用后编码一次并直接采用，展示实际大小变化（owner 2026-10-13）。

范围、入口、交互和格式策略以[产品设计](../../../../docs/product/creative-canvas-system/image-editing.md)为准；技术方案以[后端设计第三稿](../../../../docs/product/creative-canvas-system/modules/image-editing-backend.md)为准。本文件不复制其中的定义。

## 当前基础

2026-10-12 立项时的代码基础；开工时再核对一次。

- 节点版本、选用与撤销沿用 `makeVersion` / `selectVersion` / `persistGraph`。
- Agent 的有界等待参照 `GenerateNode`。
- 媒体写入参照 `writeGeneratedMedia`。
- 镜像没有 libvips，也没有 creative-worker 构建目标。

## 依赖与设计前置

硬依赖 V6-075：媒体 GC 开启删除前不开放本功能，否则预览 blob 只增不减。

已拍板的结论（详见后端设计 §12）：

- libvips 命令行子进程。
- 采用为同步画布命令，Agent 有界等待。
- 预览是不计额度的 blob，采用时才绑定并计入额度。
- 输出只保留 sRGB ICC；透明 PNG 压缩后转为 WebP。
- 布局沿用 `fitMediaSize`。
- Agent 写入时的运行资格校验与现有工具对齐。

实现第一步是编解码穿刺，见后端设计 §11。

## 验收标准

逐条对应产品设计 §10 的 AC-01～AC-14，判定细节以产品稿为准。

- [ ] **AC-01**：编辑入口在菜单、工具条、只读与空节点上行为一致。
- [ ] **AC-02**：应用前说明将输出的格式，应用后显示真实的大小变化与格式。
- [ ] **AC-03**：压缩保持像素尺寸与方向，透明图没有意外底色，编码基于固定源图。
- [ ] **AC-04**：调整质量不发起处理；重复点击应用或重试只编码一次、只产生一个版本，采用的字节与编码结果一致。
- [ ] **AC-05**：输出未减小时明确提示，不创建版本。
- [ ] **AC-06**：裁切比例、移动、重置、取消都可用，画布缩放后裁切范围仍准确。
- [ ] **AC-07**：裁切产生实际的新文件，预览、尺寸、下载与后续输入一致。
- [ ] **AC-08**：只影响当前节点，撤销与重做正确。
- [ ] **AC-09**：失败、响应丢失和重试不丢原图，也不产生重复版本。
- [ ] **AC-10**：节点改变、删除、权限撤销或任务取消后，迟到的结果不会覆盖画布。
- [ ] **AC-11**：Agent 真实调用压缩，如实报告大小与采用状态，目标不明确时不猜。
- [ ] **AC-12**：手工与 Agent 共用同一套处理规则、权限与错误语义。
- [ ] **AC-13**：取消、失败、超时或冲突留下的候选文件由媒体 GC 回收且不计额度，已采用的结果不被误清理。
- [ ] **AC-14**：桌面与窄屏下按钮可达、焦点明确，编辑时不会误拖节点或连线。

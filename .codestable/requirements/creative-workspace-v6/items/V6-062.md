# V6-062 · 首页一句话开始

[返回需求总表](../README.md) · 优先级：P0 · 类型：交付

**需求来源**：v6 原型 `home.html` / `assets.html` / `viewer.mjs` / `side.mjs`（commit 17a9bff）与 owner 2026-10-11 拍板；PRD v0.2 之外的新增范围，没有 PRD 编号。原型说明见 [v6 原型 README](../../../../docs/prototypes/creative-workspace/v6/README.md) 的「首页」「资产库」两节。

**推进状态与产物链接以总表本条记录为准**，本文件只维护需求，不重复记录执行状态。

## 目标与范围

首页首屏中央是输入框：写一句话、可附参考图、选 Skill 和模型，按 Enter 后建好项目、把这句话交给助手并直接进入画布。「空白画布」作为次要入口。输入框下方是摄影场景 chip；页面下方一行显示资产库最近添加的素材，可加为参考。

范围外：助手在画布里的运行与展示沿用 V6-030 及后续助手条目，本条不改。

## 当前基础

2026-10-11 拆分时复核的代码基础；开工时再核对一次。

- 建项目接口 `POST /creative/projects` 已带幂等键；建对话 `POST /creative/canvases/{id}/conversations`、发消息 `POST /creative/conversations/{id}/runs` 已有，但没有一次完成三步的入口。
- 外发规则见 V6-029：每轮勾选框已经删除，发送即按本条消息的范围创建授权。首次说明和范围变化时的重新询问保留：它们是说明项，不是需要摄影师同意的条款，与「外发不做逐次授权」不冲突（owner 2026-10-11）。首页发送不另定口径，与画布内助手发送走同一套规则：从首页第一次发送时，同样先出现首次说明。
- 对话附件的规则在 V6-043：不强制建节点或入库，逐项显示上传失败并可重试或取消，发送时冻结附件修订，图片受模型能力和数量、大小约束。

## 依赖与设计前置

依赖 V6-061；外发规则依赖 V6-029；附件上传与 V6-043 共用同一套机制，哪条先做就由哪条交付共用部分。design 需定：前端顺序调用三步，还是后端提供一个组合操作。无论哪种，任何一步失败都不能留下无法解释的空项目，重试也不能重复建项目。

依赖项尚未完成时可以做设计；共享接口与语义必须对齐，不能把依赖未就绪写成验收通过。

## 验收标准

- [x] **AC-01**：输入一句话按 Enter（Shift+Enter 换行）后建好项目并进入画布，助手面板打开，首条消息已发出并开始运行；同一次提交重试不重复建项目。
- [ ] **AC-02**：可附参考图（上传、拖入、从资产库选），随首条消息进入助手上下文；可选 Skill 和模型，默认值与画布内助手一致。外发规则与画布内助手发送完全一致（V6-029），首页不另设授权步骤。
- [x] **AC-03**：参考图的交接规则与 V6-043 一致：上传的图片只作为首条消息的附件，不自动入库，也不在画布上建节点；上传完成前不能发送；失败项逐项说明，可以重试或移除；每张都可以移除；同一张图重复添加时拦截并提示；一次最多 6 张；所选模型不支持图片时，发送前提示换模型或移除图片。
- [x] **AC-04**：点场景 chip 填入示例文字并切换 Skill，不直接发送。
- [x] **AC-05**：「空白画布」建空项目并进入画布；任何一步失败时停在首页说明原因，已输入的文字和参考图保留。
- [x] **AC-06**：「最近添加」一行显示资产库最近添加的素材（等高、原比例），悬停「+ 参考」放进输入框；资产库为空时不出现这一行。

## Design 交付要求

设计按本条范围说明交互/状态、边界与异常；涉及 API/数据时说明版本、幂等、权限及恢复，复用既有模块并列出目标契约变更。对上面未决项写出结论和依据，不预设技术方案已获批准。

验收类条目先提交验证方案；发现代码缺口后更新范围并做必要设计。候选条目先确认是否纳入，不直接实现。

## 实现与验证要求

逐项关联 AC；选择与影响面匹配的仓库门禁。交互/视觉附浏览器证据，并发/幂等附真实数据库测试，模型真实性附获准供应商结果。完成后把 design、实现提交（若获准提交）和验证记录链接回总表。没有实现或证据的 AC 不勾选。

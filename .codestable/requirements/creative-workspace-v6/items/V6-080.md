# V6-080 · 助手从网上搜集参考图

[返回需求总表](../README.md) · 优先级：P0 · 类型：交付

**需求来源**：2026-10-15 owner 讨论 cosplay 拍摄策划 Skill 时拍板。拍摄策划的情绪板依赖网上的参考作品（ArtStation、Pinterest 等），一般创作同样用得上。PRD v0.2 之外的新增范围，没有 PRD 编号。

**推进状态与产物链接以总表本条记录为准**，本文件只维护需求，不重复记录执行状态。

## 目标与范围

助手能在网上找图、看图，把选中的图放上画布并记下出处。

参考从哪来**没有主次，按摄影师的意向走**（owner 2026-10-15）：摄影师给了链接就用链接，让助手去找就去找，两条路径都要好用。

- **搜图**：按关键词搜图片，返回图片地址、所在页面、标题。
- **看图**：候选图放上画布之前，模型能看到图再决定留不留，并说得出取舍理由。
- **放上画布**：按图片地址或作品页地址取图，落成图片节点，记下来源站点、作者（取得到时）和页面链接。整批放置是一个可撤销单元。
- **作品页链接**：摄影师给的 Pinterest pin、ArtStation 作品、小红书笔记等链接，能取出页面里的主图。

原作设定图、他人作品都可以作为参考，也可以作为生成参考（owner 2026-10-15 拍板）；来源记录照常保留。

范围外：需要登录才能看的内容；绕过站点反爬；视频和动图。

## 当前基础

2026-10-15 静态核对的代码基础，开工时复测：

- `edit_canvas` 的 `add_node` 只接受资产库素材（`asset_id` + `content_revision_id`）或本对话、画布里已有的内容修订，不能按地址取图。
- `read_webpage` 返回网页正文 Markdown，图片只以链接形式出现；`search_web` 只搜网页，图片来源在 [web-search design](../../../features/2026-10-14-agent-web-search/agent-web-search-design.md) 里写的是「本期不做」。两者都走 Firecrawl Cloud，节点在海外。
- 媒体已有暂存上传、格式与大小校验；生成结果取件有防 SSRF 检查（本机代理 fake-ip 会被拒，见 V6-023 记录）。
- 模型看图目前靠 `read_asset`，只能读已授权的内容修订。

## 依赖与设计前置

无硬依赖。[V6-081](V6-081.md) 的情绪板阶段依赖本条。

design 时需要定：

- **站点覆盖实测**：先用 20–30 个真实链接实测 Pinterest、ArtStation、小红书、花瓣、Lofter、米游社等，记录成功率、是否遇到登录墙、能否拿到原图尺寸，作为工具形状和文案的依据。
- **看图方式**：搜索结果直接带缩略图给模型，还是先取进暂存再 `read_asset`。要算清每张图的 token 和取件成本。
- **出处存在哪**：节点说明、内容修订的来源声明，还是新字段。策划报告的参考署名要能读到。
- **原图质量**：页面 `og:image` 常常是缩略图，怎样取到最大尺寸。
- **上限**：单次运行取图张数、单张大小、格式校验，复用上传校验。
- **工具形状**：搜图是扩展 `search_web` 还是新工具；取图放置是扩展 `edit_canvas` 还是新工具（如 `import_web_image`）。

## 验收标准

- [ ] **AC-01**：助手能按关键词搜图，结果带图片地址、所在页面和标题。
- [ ] **AC-02**：助手能先看候选图再决定是否采用，并说明取舍理由。
- [ ] **AC-03**：选中的图能落成画布图片节点，整批可撤销；节点带来源站点、作者（取得到时）和页面链接。
- [ ] **AC-04**：摄影师给出作品页链接时，助手能取出页面主图放上画布；取不到时如实说明原因（登录墙、反爬、页面无图）。
- [ ] **AC-05**：私网地址、非图片内容、超限文件被拒绝；单次运行的取图数量有上限。
- [ ] **AC-06**：站点覆盖实测结果写进验证记录。
- [ ] **AC-07**：真实模型完成「搜参考 → 看图 → 挑 3 张放上画布」，保留工具调用记录。

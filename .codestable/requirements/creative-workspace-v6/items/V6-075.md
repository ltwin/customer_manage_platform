# V6-075 · 媒体 GC 与资产库空间释放

[返回需求总表](../README.md) · 优先级：P0 · 类型：交付

**需求来源**：owner 2026-10-12 评审图片编辑后端设计时拍板。复核发现 `stored_bytes` 全仓只增不减，资产库永久删除不释放文件和额度；决定本期实现媒体 GC，并作为图片编辑（V6-076）的前置。PRD v0.2 之外的新增范围，没有 PRD 编号。

**推进状态与产物链接以总表本条记录为准**，本文件只维护需求，不重复记录执行状态。

## 目标与范围

回收不再被任何地方使用的媒体修订、blob 与对象，并在对象删除确认后释放账号额度；资产库的永久删除确认与用量展示说清空间何时释放。

范围外：

- 文本修订不占字节，一期不回收。
- 旧前缀 `creative/`、`planning/`、`avatars/` 不在清理范围。
- creative-worker 的生产镜像与部署随创意空间发布一起补齐，不在本条。

## 当前基础

2026-10-12 立项时的代码基础；开工时再核对一次。

- schema 已预留 blob 的 deleting / deleted、`delete_after`、`quota_booked_at` / `quota_released_at` 与到期索引，但没有回收程序。
- 修订的持有方已集中在 `creativereference` 的 `liveOwnerCondition`。
- `RequireCreativeCapability` 内部取账号写屏障 `LockCreativeWrite`，GC 标记可借此与该账号全部创意写入串行。
- `versionedfs.Adapter` 只有 `DeleteExact(key, version)`，会永久删除指定版本，需要补「删除当前对象」。
- `purgeAsset` 只删资产行及其关系。

## 依赖与设计前置

无硬依赖。设计见[媒体模块 §6](../../../../docs/product/creative-canvas-system/modules/media.md#6-gc恢复和上线约束)（owner 2026-10-12 拍板）：

- 宽限：已计额度 24 小时，从未绑定的预览 15 分钟。
- 本地 / 测试库只读扫描与恢复演练通过后开启删除；首次上生产时先只读 3 天。

四张原未登记的表已于 2026-10-12 定性，结论见[媒体模块 §6.2](../../../../docs/product/creative-canvas-system/modules/media.md#62-持有方登记)。由此带出两处开启删除前必须完成的代码修正：Agent dispatch 只复核本次实际发送的修订；`creative_generation_imports` 补 `updated_at`，供 GC 识别陈旧导入。

## 验收标准

- [ ] **AC-01**：所有引用修订或 blob 的创意表都登记为「持有」或「不持有」；新增未登记的列时，守卫测试失败。
- [ ] **AC-02**：资产永久删除后，若该内容不再被画布、版本、撤销记录、执行保留、上传候选、Agent 记录或读 pin 使用，宽限期后对象被删除，`stored_bytes` 恰好扣减一次；GC 重复执行不重复扣减。
- [ ] **AC-03**：仍被使用的内容不被回收；GC 标记与新增引用并发时，只有一方成功，不产生悬空引用。
- [ ] **AC-04**：删除失败或结果未知时保持 deleting 并重试，不提前释放额度；OSS 只删除当前对象，宽限期后仍可按记录的 key 与 version 恢复（恢复演练通过）。
- [ ] **AC-05**：只读模式只输出按账号的应回收统计，不做任何标记。
- [ ] **AC-06**：写入中或已存储、lease 已过期且 48 小时没有进展的生成导入被重置：预留额度退还，旧对象被回收；之后迟到的提交被 epoch 拒绝，重试会重新拉取。
- [ ] **AC-07**：资产库永久删除的确认弹窗说明空间释放条件；用量面板显示「待释放」字节。
- [ ] **AC-08**：授权批准过的某个修订被回收后，同一授权下不引用它的 Agent 运行照常 dispatch；引用它的运行如实报告内容不可用。

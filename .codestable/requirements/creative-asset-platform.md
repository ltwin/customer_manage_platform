# 创作资产分享平台与社区 PRD v0.1

## 1. 定位、文档归属与目标

让摄影师把有出处、可理解、可复用的素材与创作知识发布给其他摄影师；取得资产后，可以直接放入私有项目、交给获准使用的 Agent、组合到画布，并产出实际拍摄方案。平台长期支持免费、关注后取得与付费资产，社区围绕作者、资产版本、纠错和自愿发布的创作成果形成。

第一目标人群为 cosplay 与创作型人像摄影师；初始供给以原创拍摄素材、风格案例和经验说明为主，逐步发展角色知识包。核心判断是跨作者资产能否改善一次真实创作任务，不以注册数、浏览量或商品数量替代。

初版按同一运营主体的平台实例内多账号分享设计；发布者使用独立选择的公共资料，不能自动公开 CRM 账号资料。当前自部署方式不会自动变成互联社区；跨私有部署的身份联邦、资料同步和资产交易互通不在 v0.1，若选择集中托管市场连接私有实例，需另行设计接入与数据边界。

本文是未来产品的初版需求，所有分期均待独立立项与批准，不加入当前 M0–M4 的开发交付。已确认的是 owner 要求探索这个方向并为当前设计保留演进空间；关注语义、商业条款、公共分类运营等下文推荐值均未获实施批准。

- 探索依据：[头脑风暴](../../docs/product/creative-asset-platform/brainstorm.md)，保留备选与未验证假设。
- 当前执行候选：[创意空间完整迭代 Epic](../epics/creative-workspace-system.md)，只承接其「面向资产平台的演进约束」。
- 长期平台产品定义以本文为准；未来各期 Epic 负责获批范围、子项和验收，执行状态不写回本 PRD。本文不取代现行私有创作契约，也不启用旧 intelligence 路线。

## 2. 角色与核心场景

| 角色 | 主要任务 | 成功结果 |
|---|---|---|
| 使用者：取得资产的摄影师账号 | 找到符合题材和条件的内容，知道如何用，进入私有项目 | 少搜索、少遗漏，完成可用策划 |
| 发布者：摄影师或知识整理者账号 | 选择内容、解释用途、声明权限、发布和维护 | 内容被真实复用，获得署名、反馈及后续收益 |
| 平台运营者 | 冷启动策展、处理质量/侵权/隐私举报、维护分类 | 内容可发现，错误可修正，处置可追溯 |
| Agent | 在取得权益和用途许可内查找、解释、提出方案 | 能引用来源、遵守角色变体与实际条件，不越权取内容 |

一个账号可同时使用和发布。发布者不等于原始作者或全部权利方；市场买家/卖家不复用 CRM「客户」语义。平台不要求拍摄对象建立社区账号。

核心故事：

- 摄影师 A 搜索某角色的雨夜皮肤，预览一个知识包，确认其中的设定版本和可用内容，取得后加入私有项目，让 Agent 结合一灯条件提出分镜和布光候选。
- 摄影师 B 发布一组自己的风格作品，写明参考色彩/光线/后期思路、适用场景和允许用途；其他摄影师可以用作获准参考，但不能默认转售原图或用于模型训练。
- 整理者 C 发布角色包 v1，包内第三方图片没有再发布许可时仅提供允许公开的来源链接；v2 修订设定事实，订阅更新的账号看到差异，已有项目不自动升级。
- 摄影师 D 愿意展示一次应用成果，主动选择成片及关联资产版本；客户身份、订单价格、原始聊天、私有画布与未发布方案不会跟随公开。

## 3. 资产模型与分类

### 3.1 四个彼此独立的维度

| 维度 | 示例 | 约束 |
|---|---|---|
| 内容载体 | 图片、文字、链接；以后可增加视频等 | 载体决定预览与处理方式，不决定收费或许可 |
| 参考用途 | 素材、风格参考、设定事实、拍摄经验 | 可多选，不以三选一枚举迫使重复内容 |
| 组织形态 | 单项资产、风格作品集、知识包 | 包可包含不同用途的成员；包不是压缩文件的别名 |
| 获取条件 | 免费领取、关注后领取、单次付费 | 独立于公开范围与可使用的用途 |

「风格作品集」指创作者成品集合；「题材作品」指角色所属 IP/故事作品，两者名称与搜索字段明确区分。

### 3.2 基本资产信息

人可读的信息：名称、描述、封面/预览、分类、标签、适用任务与条件、使用限制、原始作者/整理者/发布者、来源链接、更新说明、内容清单与许可摘要。描述必须能回答“拿到它可以做什么”，不只提供关键词。

机器可用的信息：稳定资源 ID、发布版本、成员 ID/类型/顺序、角色或变体适用范围、每项来源与修订、处理/引用许可、输入输出说明、必要条件和未知项。机器描述只表达资料含义，不能携带可执行脚本、任意工具权限或绕过平台约束的指令。

类别由少量稳定分类支撑筛选，标签由发布者补充，个人备注和个人标签属于使用者私有覆盖层。取得资产不会把买方备注写回作者版本；基础分类不立即建设百科式大本体。

### 3.3 角色知识包

| 分区 | 内容 | Agent 使用规则 |
|---|---|---|
| 题材与变体定位 | 题材作品、角色、别名、皮肤/阶段、官方或衍生类型 | 默认检索精确变体；没有匹配不得无声混入其他版本 |
| 设定事实 | 服装、外观、道具、背景故事、出处与时间 | 每条保留来源；有争议的说法并列，未知不得补成事实 |
| 视觉资料 | 获准展示的设定图或允许公开的来源链接 | 每项单独判断展示、下载与模型处理许可 |
| 创作案例 | 画作、CG、摄影作品及其参考点 | 标为案例而非设定依据；保留各作者归属 |
| 风格方向 | 色彩、构图、光线、场景、后期 | 作为创作建议，不伪装成原作要求 |
| 拍摄应用 | 可用器材、场地条件、镜头建议、常见误区 | 与本次条件比对，说明替代方案与不适用条件 |
| 关联资产 | 相关素材/风格集/知识包 | 展示依赖版本和获取条件，不通过包间引用赠送权限 |

题材作品、角色、变体以后有独立稳定 ID 与别名映射；衍生关系允许跨题材或多来源，不把字符串拼接路径当身份。官方与同人标识说明来源类别，不代表平台已核实官方认可。首批人工策展维护少量实体，公共合并/纠错须保留历史映射。

**包版本是固定成员清单。** 成员包含内容版本、来源和用途许可；不能由作者更新上游文件后无声改变既有包。首版免费分享支持封闭清单（选中的素材/说明）及仅导航的外部链接；跨发布包的可执行依赖在知识包阶段再引入，并限制一层、禁止循环。必要依赖必须在领取前说明、具备完整权益；缺失则不能声称“整包可用”。可选依赖不可用时仍可领取主包并明确缺项。

## 4. 可见性、获取与使用权限

### 4.1 三层判定

1. **可见性**：私有草稿、仅链接可见的发布页、公开可检索发布页。仅链接不是访问密钥；受限正文和原图始终另做权益判断。
2. **取得权益**：账号是否按该版本的获取条件取得内容。仅收藏发布页是书签，不取得正文、原图或 Agent 使用权益。
3. **用途许可**：权益覆盖的内容可以怎样使用。观看预览、项目参考、下载、商业拍摄参考、导出原内容、模型分析、生成引用、再分发、模型训练分别说明。

默认不许可再分发或模型训练；可分享摄影成果不表示可把参考包作为自己的商品重发。Agent 使用还要满足账号对外部处理的授权。付费、关注、包作者声明均不能放宽成员本来没有的权限。平台未知的许可组合进入待确认，不自动“全部可用”。

### 4.2 获取方式建议

| 模式 | 初版建议语义 | 获得什么 | 政策变化 |
|---|---|---|---|
| 免费领取 | 登录账号主动领取指定发布版本 | 按该版本条款取得内容，不自动取得未来版本 | 后续改为付费不追溯收费 |
| 关注后领取 | 领取时需关注作者；明确称「关注后领取」 | 本次取得版本按其许可继续可用 | 取消关注不撤销旧领取；新版本重新判定；持续关注订阅另立项 |
| 单次付费 | 支付经服务端确认后授予指定版本权益 | 订单列明的版本及更新范围 | 作者涨价/下架不自动取消已购买权益；退款/争议按单独规则 |

这里采用“版本领取”而非持续关注门禁，是为避免现有拍摄项目随关注关系失效；必须在 P2 原型中验证并由 owner 确认，不冒称已满足持续关注才能访问的另一种产品语义。

### 4.3 取得、更新与失效

取得内容后，私有库新增的是对发布版本的受控引用和账号权益，不改变作者私有库的所有权，也不把包复制成无来源的自有素材。个人收藏、注释、项目使用关系与发布版本分开。文件允许下载时，下载的是对应版本文件；禁止承诺文件离开系统后仍可技术收回。

| 事件 | 对新发现/取得的影响 | 对已取得与私有项目的影响 |
|---|---|---|
| 作者修改私有源素材 | 无，直到发布新版本 | 已发布/已取得版本不变 |
| 发布 v2 | 公共页展示更新与版本差异 | 先看差异再选择升级；项目和 Agent 运行仍固定原版本 |
| 普通下架 | 停止发现及新领取/购买 | 继续提供原权益允许的版本，不由删除源素材破坏交付 |
| 举报调查/强制处置 | 可限制预览、领取、下载及外发 | 按处置范围暂停相应用途，引用标失效；不通过私有副本、文本快照、导出缓存或向量继续提供被禁内容 |
| 退款/支付争议 | 阻止重复发放或后续未授权获取 | 撤销相应服务端权益，保留交易与最小可保留的引用记录；不伪造已下载文件消失 |

权限决策先于公开搜索摘要、缩略图、正文、原图、Agent 检索和下载。暂停应实时影响服务端读路径，物理清理可异步进行；停用 AI 用途不无端删除仍许可展示的内容。既有外部文件及已完成摄影作品如何处理由具体许可/争议条款约定，平台不自动修改摄影师成片。

## 5. 发现、发布与创作流程

### 发布者流程

私有内容中选择 → 建立发布草稿 → 编辑面向他人的描述/预览 → 逐项检查来源与可公开内容 → 选择获取方式及许可 → 查看“其他账号将看到什么” → 确认发布。

发布是独立快照与显式白名单投影。默认不包含私有备注、订单/客户关联、聊天原文与批次、账号内部 ID、未选资产、拍摄对象身份、定位或原始 EXIF。确需发布的图像使用去除非必要元信息的发布副本。预览也必须有公开展示许可；能在私有空间展示不等于可公开展示。

首个分享试验采用邀请制发布者和运营审核，先选择自有或能证明可再发布的内容；缺少包内部分内容的发布许可时移除该内容，或改为获准公开的说明/来源链接。发布者不能仅凭“来源：网络”通过公开文件发布检查。

### 使用者流程

发现/搜索 → 查看封面、描述、适用条件、公开清单和许可 → 收藏书签或取得版本 → 在“已取得”中找到 → 选择加入项目 → 手动参考/获准 Agent 使用 → 完成策划 → 自愿反馈或关联公开成果。

发现入口与“我的素材”明确区分；公共搜索只检索发布投影，私有搜索可联合检索自有内容与有权使用的发布版本，结果显示来源和权限。知识包支持按题材作品、角色、变体、用途、可用设备/场景、获取方式筛选；缺少结构化条件时如实退回文本匹配。

不设置强制发布项目或成片的完成任务。公开成果是另一次显式发布，选择图片和说明，确认有权公开后再关联原资产；任何实际使用统计不自动披露谁用了哪个私有项目。

### Agent 流程

账号选定范围 → 检索元信息/已授权正文 → 确认角色变体与处理用途 → 固定输入与包版本 → 产出引用明确的候选 → 摄影师采纳到私有项目。

Agent 可建议去查看一个未取得的公开资产页，不能替账号付款、关注、领取或发布。新资产数据是待处理内容，不能授予工具权限。已有访问许可与外部模型授权任一失效，运行前和实际取内容/外发时都重新检查；运行产物含已被限制的源内容时按用途处置，不通过生成摘要泄漏锁定正文。

## 6. 分阶段目标与边界

各阶段均需另立实施 Epic；P0 是当前工具 Epic 的演进约束，P1–P4 都不在本期交付。阶段按验证结果进入，下面的编号不是自动排期许可。

| 阶段 | 可交付最小范围 | 进入条件 | 暂不做 |
|---|---|---|---|
| P0 私有创作基础 | 当前资产库、项目复用、策划、Agent、画布；本节演进约束 | 当前创意空间 Epic 获批 | 公开读写、关注、支付、资产权益 |
| P1 免费资产分享 | 邀请作者、独立发布快照、公开页/轻目录、免费领取、已取得列表、加入项目、举报与普通下架 | P0 的资产多引用/来源能力可用，分享原型/权利审核与运营负责人明确；不必等画布或 Agent 完成 | 付费、关注门禁、评论信息流、复杂依赖、正式角色知识结构 |
| P2 角色知识包与轻社区 | 分区知识包、题材/角色/变体检索、版本差异、作者页、收藏/关注、关注后领取、结构化纠错和可选成果关联 | P1 有跨作者真实复用；知识/Agent 联动使用 P0 已交付能力 | 私信、通用社交流、多作者分账、订阅制 |
| P3 精选付费市场 | 单次定价、版本权益、市场交易账本、可靠支付回调、退款/争议、卖方结算与对账、运营后台 | P2 有明确付费场景，运行地区/主体/许可、支付和退款结算方案完成专项评估 | 多币种、复杂促销、订阅、多级分销 |
| P4 平台生态 | 依据实际需求选择策展合作、更多格式、模板、订阅或更深社区 | 各方向有独立价值与供给证据 | 不把本行所有候选合成一次大开发 |

推荐先通过 P1 验证「别人做的资产能否进入我的拍摄项目」，P2 验证知识包差异化，P3 才验证交易。缺少 Agent 不阻塞 P1 的人工复用；缺少支付不阻塞免费社区。

## 7. 初版需求清单与验收

| ID | 阶段 | 需求与验收场景 |
|---|---|---|
| AP-01 | P0 | 素材 ID/修订、来源/用途和项目引用分离；相同媒体哈希不推导作者或权利相同；收集时可跳过补充描述 |
| AP-02 | P1 | 用包含客户关联、聊天批次和 EXIF 的私有项目创建发布草稿；发布预览与真实公共响应均不包含这些私有信息，未选成员不可枚举 |
| AP-03 | P1 | 发布明确内容版本，修改私有原件不改变发布页；免费领取幂等、已取得可查、加入两个项目独立注释 |
| AP-04 | P1 | 公共目录与私有库查询隔离；未取得账号只能访问获准预览；锁定正文、原图、标签推导、索引摘要均不得泄漏 |
| AP-05 | P1 | 发布者普通下架阻止新领取，原领取继续可用；举报限制能暂停对应媒体和派生内容用途；有申诉与处置记录 |
| AP-06 | P2 | 同一角色两个变体分别检索和引用；官方事实、衍生设定与作品案例不混写；无出处事实标待核实 |
| AP-07 | P2 | 包固定成员版本；必要依赖无权益时不能取得“完整包”，可选缺项有提示；关联引用不放大权限，不允许循环 |
| AP-08 | P2 | 关注领取与持续关注订阅语义明确；按推荐模式取消关注不抹除已取得版本，后续版本重新核验条件 |
| AP-09 | P2 | 版本升级需主动选择；旧项目/运行版本不变；只有主动发布成果才出现公开关联，私有使用关系不出现在作者页 |
| AP-10 | P2 | Agent 使用已取得且获准处理的成员，精确标注角色/包版本；未取得只给公开页建议，不能自动交易或绕过限制 |
| AP-11 | P3 | 重复/延迟/乱序支付回调、付款成功但响应丢失时只发一次权益；未确认支付不得依据前端成功页授权 |
| AP-12 | P3 | 退款、拒付、卖方下架与结算分别核对，交易/许可版本可查；不会写 CRM 拍摄订单的金额、客户或档期 |
| AP-13 | P3 | 定价与正文权益在购买前可核对；历史版本保留策略和更新范围明确；停服/强制处置时的交付或退款路径有运营方案 |

P1 不以建立完整支付/许可引擎为前提，但必须有最小可执行许可模板、逐项发布资格与免费版本权益。P2/P3 的复杂场景不得靠沿用“免费 = 无限制”省略。

## 8. 运营、质量与交易边界

冷启动建议邀请 5 名种子作者、10 个高质量包，覆盖少量明确主题；角色知识从少数题材开始，不承诺全题材百科。每个包有预览、使用说明、来源和可演示的应用场景；运营用实际找回/复用任务策展，重复搬运或标签堆砌不当成优质供给。

首版举报入口包含权利、隐私、错误信息和不符描述；处置可为限制预览、限制取得/下载/AI、修订、下架和恢复，记录对象版本、原因与申诉。上线前明确负责人、处理时限和紧急暂停通道，不以自动审核通过代表事实或权利已经获证实。

P3 市场交易独立于拍摄 CRM 订单，保存买方、卖方、资产/许可版本、金额币种、支付与退款事实、权益发放和结算状态。初步先单次付费，价格与平台费率须经供需验证后决定，不在本 PRD 虚构商业参数。实际运营地区、支付主体、税务/开票、知识产权与人像许可、消费者退款承诺需要在 P3 立项前完成适用规则评估；本文不是已完成的法律或交易方案。

变现候选：单包付费、平台服务费、作者专业工具订阅。优先验证资产的交易价值，再决定收费组合；不默认把收藏、查看自己已取得内容或退出平台变成收费门槛。

## 9. 评价指标与实验

北极星候选：**每周由他人发布资产支持的有效创作项目数**。有效指取得后有主动项目引用，且在观察期内采纳为方案内容或实际用于现场；一次项目只计一次，排除作者自用、测试账号和重复导入。以聚合值统计，明细不自动公开给作者。

| 阶段 | 需要回答的问题 | 建议试验出口 |
|---|---|---|
| P1 | 作者愿发、别人拿来真用吗？ | 5 名作者贡献 10 个包；10 名使用者中至少 6 名非作者；14 天内至少 6 人（其中至少 4 名非作者）用于一个真实项目；完整报告失败/放弃 |
| P2 | 知识结构与社区是否提高复用？ | 5 个角色/变体任务，至少 3 例准备耗时下降且无新增关键设定错误；至少 3 名使用者在 30 天内第二次跨项目复用；关注领取单独测更新回访 |
| P3 | 付费闭环与价值是否成立？ | 冻结包/价格/资格/窗口后至少 5 笔来自 ≥3 名非作者账号的真实交易；交付和对账无丢失；退款/争议全部报告；继续投资还需评价支付意愿与运营成本 |

技术正确性另外验收，交易数不能抵消一次越权、隐私泄漏或错误发放。P3 没发生真实退款时，以受控演练验证操作链，不能写成已有真实退款证据。

配套指标：发现→取得→引用→采纳转化、取得后首次使用时间、重复复用、作者再次发布/更新、来源纠错速度、Agent 设定错误、举报/退款/争议、单次有效复用的模型/存储/审核成本。关注数、销售额与浏览量辅助诊断，不单独代表价值。上述门槛是拟议小样本实验，不能宣称统计显著或规模化商业可行。

## 10. 与本期设计的演进接口

| 现在保留的契约 | 后续增加的能力 | 现在不建 |
|---|---|---|
| 私有账号所有权；作者/来源字段允许未知，不从上传者推定作者 | 发布者身份、公开作者资料与权利方关联 | 社交账号系统、跨账号共享私有查询 |
| 载体与用途分离，文字描述/标签和项目意图可记录 | 公共分类、风格作品集、角色知识包描述 | 新通用资产大表或复杂全局本体 |
| 稳定内容/修订、布局分离、快照有来源 | 独立发布版本、包清单、买方权益与个人覆盖层 | 发布/商品/权益表、关注/支付 API |
| 现有来源/用途不丢失、未知不升级；本期 AI/导出用途单独校验 | 发布、取得、商业使用、再分发等新许可 | 用一个 is_public 或 paid 标记承担所有权限 |
| 私有批次/CRM 信息与可选内容明确分离 | 白名单发布投影、公开预览与独立目录 | 自动把私有数据送到公共索引 |
| Agent 输入身份/版本/用途可追溯，知识范围可描述 | 受权益约束的公共检索、角色别名与实体版本 | 让第三方资产定义可执行工具或模型权限 |

私有素材库、知识库不需要现在合表。未来共享的是发布描述和许可检查语义，载荷仍由各领域持有；市场通过公共发布接口连接私有资源，不侵入所有业务查询。文件去重只是存储优化，不合并内容归属或授权历史。

本期只在当前 Epic 的 ITEM-2/4/7/10 增加上述字段归属、接口边界和验证约束；不新增阶段、资产市场入口或开发市场骨架。后续可能增加的字段不必现在全建：确定无法从历史补回的来源/原文/用途声明现在保留，获取权益、发布清单与交易事实在真正发生时再创建。

## 11. 非目标、决策与风险

本 PRD v0.1 不承诺公开社区立即开发、全网资料搬运、版权自动判定、付费后任意生图、模型训练数据市场、NFT/代币、虚拟货币、多级分销、全品类素材市场、即时聊天或所有角色资料的自动生成。其他创作者作品只能在对应发布/引用权限内进入包，不能用“知识库”名称绕过逐项限制。

在对应阶段冻结前需解决的产品决策：

- P1：首批作者与题材、允许发布的许可模板、免费版本提供期限及服务中止安排、审核与申诉负责人、聚合指标的告知与使用范围。
- P2：关注采用领取式还是持续访问式（本文推荐领取式）；公共题材分类与纠错责任；包依赖和升级价格规则。
- P3：运营地区与主体、单包/订阅取舍、价格与费率、允许售卖的内容边界、买方许可、退款争议和卖方结算。前期不把未决规则编码为难以更改的默认值。

主要风险及应对：供给不足先做少量策展；整理成本高先做模板与私有工具；收藏多使用少先改善任务匹配；角色信息错误依赖出处与变体隔离；包内权利混杂采用逐项清单与用途交集；关注领取产生短期行为则观察回访而非粉丝数；社区偏离创作则保留私有工具的默认入口；支付/审核成本过高则维持免费分享，不将市场化视为必然。

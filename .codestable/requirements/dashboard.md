# 经营台：打开系统就知道今天该干什么

## 用户故事

- 作为每天开电脑先想"今天该干嘛"的摄影师，我希望登录后直接落在一张经营台，而不是先点进客户/订单/档期四处找数。
- 作为同时盯着生日、回访和流失的摄影师，我希望近三天（含逾期）待办和流失预警分开一眼能看见，并能在台上直接标完成或忽略。
- 作为当天有拍摄安排的摄影师，我希望今日档期带客户与订单摘要，点一下就能进日历或客户档案。
- 作为刚交付完还没收齐尾款的摄影师，我希望待收尾款清单只盯"已交付未结清"，并能量到确认收讫。
- 作为偶尔想看近一个月干了多少的摄影师，我希望有近三十天新建单数、交付数和已确认收入，而不是自己翻订单表心算。

## 为什么需要

客户、订单、档期、提醒各自有页之后，"今天该行动的事"仍散落在四个列表。治忘的最后一公里是聚合：口径必须单点在服务端，移动端也不能靠五连击拼页。dashboard 是提醒引擎与档期/订单的消费面，也是 Telegram 摘要之外的 Web 兜底。

## 怎么解决

提供只读聚合端点 `GET /dashboard`，一次返回五块数据：近三天 pending 提醒、今日档期（含订单/客户摘要）、已交付未结清订单、全部 pending 流失预警、近三十天滚动统计。首页替换原型假数据，登录默认落地本页；台上对提醒/尾款的写操作复用既有提醒与订单 API，不另开写契约。

## 边界

- 不做前端自行拼五个列表——聚合口径只在服务端。
- 不做 Telegram 推送 / 绑定（telegram-digest）。
- 不做自定义看板布局、拖拽卡片、图表钻取、导出本页。
- 待收尾款口径故意窄于订单列表的 `unpaid_balance`（后者含 shot/selected/retouching）。
- 不在本条做全站空态/错误态/移动轻路径收口（v1-hardening）。

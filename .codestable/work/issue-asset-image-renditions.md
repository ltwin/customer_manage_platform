# 资产库图片缩略图与原图按需加载

## 目标

资产库列表使用低分辨率缩略图快速加载；仅在打开查看浮窗时请求当前图片的原图。owner 于 2026-10-12 决定先完成资产库功能，再推进本性能优化。

## 现场

已核对当前工作区源码：

- `frontend/src/creative-canvas/editor/LibraryTiles.tsx` 的图片卡片通过 `MediaFigure` 默认选择 `display`；`editor/media.ts` 在不存在该版本时回退 `original`。已有临近视口懒加载。
- `backend/internal/creativemedia/config.go` 的展示图最长边默认 1600px；`verify.go` 只为超过该尺寸的图片生成 JPEG 展示图。因此不超过 1600px 的图片，列表仍可能下载体积较大的原图。
- 第 4 步 `frontend/src/creative-canvas/viewer/MediaViewer.tsx` 对图片也选择 `display`，打开浮窗未切换到原图。2026-10-12 已先行修复：浮窗图片改取 `original`，`viewer-image-zoom` 回归断言浮窗为当前素材请求原图票据（修复前该断言超时失败）。缩略图占位与列表缩略图仍属本 issue。
- 媒体对象角色已有 `thumbnail` 枚举，但当前上传、生成图片导入和取图 ticket 尚未形成可用的独立缩略图链路。仅增加前端 CSS 或缩小现有展示图不能完整解决问题。

## 边界

建议方案（待实施时细化）：

1. 列表和素材抽屉加载独立缩略图，最长边约 720px，保持比例、不放大小图、保留透明度与正确方向，继续懒加载。尺寸和编码参数以实际清晰度与字节量验证后确定。
2. 保留现有 1600px 展示图供画布等场景使用，避免降低现有画布清晰度。
3. 查看浮窗先用已加载的小图占位，再加载当前图片原图；切换素材只加载当前项，下载继续使用原图。交互和样式保持与原型一致。
4. 上传与生成图片导入统一产出缩略图；覆盖鉴权、存储计量、失败清理、重试和垃圾回收。
5. 历史图片需要可重试、幂等的补齐方案；明确补齐期间的回退策略，不能宣称已有完整缩略图覆盖。是否需要迁移生成导入暂存字段，在实施设计时核实。

本 issue 不改变第 4 步代码，不执行历史数据处理，也不构成未来优化的提交授权。

## 证据

本次为源码核对，未测量真实账号下的网络传输量、首屏耗时或存储增量。已有浮窗 E2E 的媒体 mock 未区分展示图和原图字节，不能作为该性能目标已满足的证据。

## 验收

- [ ] 新上传与生成图片均可获得独立缩略图，尺寸、方向和透明度正确，原图不被修改。
- [ ] 历史图片补齐可重复执行，失败可恢复，账号隔离与存储清理正确。
- [ ] 浏览列表的网络请求使用缩略图，不批量下载原图；历史兼容阶段的例外明确记录。
- [ ] 打开或切换浮窗只请求当前图片原图；缩略图占位到原图切换不改变布局、缩放和导航行为。
- [ ] 用可区分的媒体 fixture 断言请求角色及实际文件尺寸，并对比相同图片集优化前后的传输字节与加载表现。
- [ ] 画布清晰度、素材下载、上传、生成图片导入与权限回归通过。

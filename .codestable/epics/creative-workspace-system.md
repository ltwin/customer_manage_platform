# 创意空间系统：通用画布、资产库与 Agent

## 当前路线与范围

本Epic沿用原身份，当前交付是**资产库、通用画布和Agent三部分真实可用的基础框架**，按需求设计→系统架构→模块设计→开发→验收推进。三批主要模块设计已经形成，本版将其重排为FND-01–13正式开发候选；仍为proposed，不代表已经实现或获得提交/发布许可。执行状态只在[work](../work/epic-creative-workspace-system.md)维护。

产品语义和25项需求、10条贯穿场景由[需求v0.4](../requirements/creative-canvas-foundation.md)拥有；[架构](../../docs/product/creative-canvas-system/architecture.md)、[数据模型](../../docs/product/creative-canvas-system/data-model.md)、[领域设计](../../docs/product/creative-canvas-system/domain-design.md)及[模块入口](../../docs/product/creative-canvas-system/modules/README.md)拥有工程契约。本文是当前任务ID、依赖、交付和验收出口的唯一来源；[实施计划](../../docs/product/creative-canvas-system/delivery-plan.md)负责切片映射、前置项和估算，[迁移发布](../../docs/product/creative-canvas-system/migration-release.md)与[整体验收](../../docs/product/creative-canvas-system/acceptance-plan.md)补充执行方法，不维护第二份进度。

### 目标与非目标

- 摄影师无需项目即可整理个人资产，在项目画布中引用、编辑、连线、打组、关闭再打开；修改引用不静默传播到其他作品。
- 首期包括图片、文字、链接、视频、音频导入及基础编辑/预览/引用/下载；每节点Prompt Box、文字/图片/视频/音频真实生成、历史预览与采用切换；实际启用格式按媒体样本验证。视频/音频不包含剪辑、转码或完整模型理解。
- Agent经统一LLM Gateway完成真实对话与注册的受控工具，平台Skill为“整理参考与创作方向”；保留模型/Skill选择、选区引用、独立附件、授权、取消、恢复及真实用量。Skill 是数据库与对象存储管理的产品资源，平台维护内容不必重新发布服务；身份、版本与 digest 固定，运行永不跟随“最新版”漂移。
- 通用项目不关联任何CRM业务。专业文档节点通过内部独立文档测试扩展证明边界，完整策划/镜头表/订单发布/现场模式在后续业务迭代。
- 本期不含3D导演台、RAG/向量库、公共市场/社区、CRM工具、第三方Skill安装、任意代码执行、多人实时协同、完整离线同步或摄影师商业计费。摄影师自建Skill的编辑器、市场投稿、审核后台、安装与分成同样不在本期，方向记录见[Skill市场与审核灵感](../../docs/product/creative-canvas-system/skill-marketplace-brainstorm.md)；本期只保证将来加入这些规则时不必推翻Skill身份、版本引用与消息结构。不得以这些未来能力拖延当前闭环。

### 不变的架构决策

React Flow与Zustand承接受控画布；Go模块化单体、API/Worker分进程；PostgreSQL关系记录与局部JSONB、OSS私有媒体、River持久任务；模型经Gateway，通用循环与中间件采用Eino ADK v0.9.19，Tools/Skills业务策略及执行守卫归Harness。新业务表显式账号/key关联，不建数据库外键，仍有PK/UNIQUE/CHECK/index及服务事务守卫；既有CRM与第三方内部schema不连带修改。连线表达参考，不自动执行图；画布节点、资产身份、内容修订和业务文档分开。

模型结果、领域效果、费用核算三种事实分别持久；未知不盲目重发，已知未受理重试必须重新准入；人工和Agent共用领域命令与回执。保留期、run状态机及锁序继续由数据/模块契约拥有，不在本Epic复制数值状态表。

### 新旧承接

保留旧冻结[先导Epic](creative-workspace-redesign.md)、历史审计和未完成试点证据。本次不标旧Epic验收通过或自动改为superseded。新路线批准也不自动删除旧CRM关联、对象或拍摄记录；FND-11完成显式映射、writer切换与恢复，发布前再单独记录路线接管事实。下方折叠块是完整历史候选，旧M0–M4、ITEM-1–10、AC-1–12与工期均不可执行；尤其不能沿用“先Agent后画布”。

Eino选型与隔离验证见[接入契约](../../docs/product/creative-canvas-system/eino-adoption.md)。八项实验不代表FND-01全部完成；本次不实际开放多Agent、任意脚本或模型自动切换。

基础框架按[画布工具化](../../docs/product/creative-canvas-system/canvas-tooling.md)提供共享操作入口与节点执行控制；首期新增[node-generation](../../docs/product/creative-canvas-system/node-generation.md)定义Prompt/真实生成/版本历史，未来CRM工具仍独立接入。

## 起点与本轮目标

面向个人摄影师和小型团队主创，把创意空间从「按项目收集素材的先导版」迭代为可以持续积累、找回、组合参考，并交付可执行拍摄方案的创作系统。摄影师可以只收藏，也可以只写方案；不用先填写项目资料、关联订单或完成一套流程。

产品主链：**收集素材 → 搜索与复用 → 明确本次意图和条件 → 推敲候选 → 采纳为策划内容 → 导出或带到现场 → 复盘后再次复用**。

原候选路线包括账号级资产库、项目创作空间、摄影知识支撑的 Agent、画布和独立的策划产物视图，按 **资产库 → 可人工完成的策划产物 → 知识与 Agent → 画布协作 → 完整实拍验证** 安排交付。新的长期方向建议提前验证最小画布与策划节点，具体调整以本页顶部的方向更新和关联头脑风暴为讨论依据。每一阶段必须能独立使用，后阶段失败时前阶段仍有价值。

## 共享语言与概念边界

经营侧术语沿用 `../requirements/CONTEXT.md`。以下定义属于新路线提案；批准后由 ITEM-1 同步到 canonical requirement，旧术语保留 legacy 标识。

| 术语 | 定义与事实归属 | 边界 |
|---|---|---|
| 创意空间 | 产品板块的对外名称 | 不把资产库、项目和 Agent 做成互不相通的产品 |
| 素材 | 摄影师收藏的一条图片、文字或链接，账号持有稳定身份；承接现有创意卡片 | 底层媒体文件不是业务素材；重复引用不复制文件 |
| 资产库 | 账号全部素材的浏览与查找入口，包含未归类和已用于项目的素材 | 默认私有；不等同于全网内容平台 |
| 灵感集合 | 跨项目长期积累的主题集合，如「单灯人像」「霓虹夜景」；普通集合可新建、重命名、删除 | 删除只移除该集合及其成员关系，不删素材、其他集合或项目引用 |
| 我的最爱 | 集合子版块中固定置顶、不可重命名/删除的系统集合；原“心选”统一为此名称 | 爱心是加入/移出的快捷方式，不占独立主导航，不参与普通归类判定 |
| 未归类 | 集合子版块中的自动视图，展示未加入任何普通集合的素材 | 非手工集合，不可直接增删成员；我的最爱和项目引用均不改变归类 |
| 项目空间 | 一次通用创作的参考、意图与画布上下文；既有空间身份另行兼容 | 不关联客户、订单、档期或任何 CRM 业务 |
| 项目引用 | 项目对素材的一次使用关系，持有自己的分组、顺序和「本次参考什么」 | 修改项目意图不改其他项目；移出项目不删除素材 |
| 知识条目 | 带出处、更新时间、适用条件的事实或经验，供检索和 Agent 引用 | 事实、经验、推测明确区分；知识库不与素材表强行合并 |
| 候选 | 摄影师或 Agent 提出的、尚未采纳的方案内容 | 不自动成为拍摄项、备忘或经营事实 |
| 策划产物 | 独立摄影业务文档，提供方案阅读、分镜表、清单、导出与现场入口；画布节点呈现摘要 | 内部镜头不依赖画布图片节点；没有必填完成度、ready 守卫或审批流程 |
| 拍摄项 | 单个有稳定 ID 的现场执行单元；分镜表与现场模式共同读取它 | 一条拍摄项不等于一张成片；保留既有执行事件 |
| 画布 | 通用基础节点与扩展节点的工作面，存储位置、尺寸和关系 | 策划摘要节点引用独立策划身份，不持有镜头表或执行事实 |
| 导出版本 | 对摄影师选择的策划内容、顺序和可导出媒体形成的一次冻结快照 | 后续编辑不改已导出版本；不等同于 CRM 照片交付或自动发给客户 |

端到端例子：收藏一张逆光图，加入「单灯人像」集合，又引用到项目 A、B；A 写「参考光线」，B 写「参考姿势」，两者互不覆盖。A 采纳一个候选为拍摄项后，即使原素材改备注或被归档，拍摄项仍保留已采纳内容与可保留的参考快照。A 在画布上编辑该拍摄项，分镜表读取相同版本；之前导出的 PDF 保持不变。

- 收集先选择图片、文字或链接，展示该类型对应字段。图片描述/标签/来源属于对应图片，不另建文本；多行文字（含内嵌网址）默认整篇一份，链接通过独立网址字段创建。类型切换保护未保存内容。
- 空库直接支持拖图、选图、在对应表单粘贴文本/链接；不用先建项目。上传显示逐项状态，只重试失败项，刷新或回执丢失不能造成重复写入。
- 大图详情支持连续浏览、键盘导航、返回原位置；可写「为什么收藏」，查看来源、所属集合与使用项目，加入集合或项目。
- 原候选项目提供概览、参考、策划与现场入口；概览展示本次意图/条件及方案摘要，列表以项目摘要与参考/分镜数量辨识一次创作。新方向以画布为主、策划交付为独立子版块，项目整理面不提供 CRM 绑定；订单选择属于本次 Skill 输入和策划发布两个环节。旧关联只按兼容与迁移方案保留，不自动套给项目中的所有策划。
- **原型可领先于功能实现。** 2026-09-07 owner 同意先展示项目完整形态，允许用“暂未开发”等字样屏蔽未接入能力。原型区分可操作的本地演示、只读布局预览和明确禁用的未来能力；不把静态内容伪装为 Agent 生成，不把本地保存伪装为业务成功。这不提前批准后期业务实现。正式产品默认隐藏未交付入口；若确有解释去向的价值，可保留禁用入口及可见原因，不能设置可点击的空操作。

### 搜索系统

素材浏览不设置不可维护的固定题材分类；题材与用途由标签筛选承担，载体类型（图片、文字、链接，视频待后续支持）作为独立筛选条件。工具栏统一承载类型/标签/排序/显示，管理标签与回收站放到数量栏。更细的素材分组未来另行设计，不与标签分组混为一谈。

第一版搜索覆盖自己的全部素材和当前项目两种明确范围；支持素材文字、标题/备注、来源 URL、手工标签，以及类型、集合、使用项目、时间筛选。原文/标签精确匹配优先；中文短语、组合筛选、空结果、清除条件、失效链接均有明确行为。不会因为素材已用于项目就从全库消失。

标签作为账号级可复用实体管理：固定 ID、名称、颜色和一级分组，素材关联使用 ID。支持管理页新建/改名/改色/调整分组，收集与素材详情共用就地展开的可搜索多选面板，并可在面板内新建标签，不叠加二级选择弹窗；收集时新标签随素材原子保存，取消不残留。分组只整理标签，删除分组不删标签；删除标签需说明素材关联范围，覆盖回收站而不删除素材。旧自由文本标签兼容迁移，改名不打断引用和筛选。多标签支持“同时包含/包含任意一个”，与关键词/类型/集合/项目筛选组合，并保存到 URL；标签勾选/取消即时更新结果和匹配数量，不依赖再次点击应用。原型先验证反馈，后端缓存另行设计。颜色作为名称的辅助线索，不建设公共标签本体。

语义搜索在 Agent 阶段引入：自然语言找风格、以自有或获准处理的图片寻找相似素材，仍限定账号库。检索结果说明匹配依据和处理状态；不支持的素材回落到文字/标签检索。外部 Pinterest/小红书搜索、推荐流和自动抓取另列候选，不承诺已有内容供给。

### Agent 与知识

2026-09-08 新增方向：知识库按图文多模态 RAG 探索，以向量检索结合精确条件/关键词取得可追溯证据，视频作为后续候选；原文、图片和片段定位不被自动摘要替代。详见[头脑风暴 §7](../../docs/product/creative-canvas-system/brainstorm.md)。下述文字先行范围与 ITEM-7 是原候选切片，需在新版路线中重新拆分入库、检索和多模态应用，不能直接据此声称已覆盖完整知识库；Gemini 是候选参考，尚未完成选型。

- 入口以动作表达：「找相似参考」「整理这些素材」「检查拍摄缺口」「根据条件提出方案」，同时支持围绕结果继续对话。可选输入为素材/集合、项目文字、已确认方案、器材、场地和时间条件；空库可用文字条件和获准知识完成基础检查。
- 先交付查找、归类建议和缺口检查，再交付六类产物的候选生成。「整理这些素材」首版只在项目内针对所选参考提出分组名称、分组归属和组内顺序建议；显示当前与建议布局，确认采纳才更新本项目成员关系，不改全局素材、标签、集合或其他项目。资产库不显示这一项目整理入口。默认只处理摄影师选择的范围；明确展示本次输入与可用来源，不自动吸入整个 CRM 或整库原文。
- 私有知识先行：账号主动录入事实文字、经验、来源链接和适用范围；首版不自动抓网页、不建设平台百科。平台可随版本提供少量原创基础摄影知识，来源与维护者可追溯。冷门角色没有依据时标「待核实」，不给出伪造设定或场地实勘结论。
- 每次运行持久化输入版本、来源引用、模型/提示版本、任务进度、候选结果与用量。可取消、失败可重试、已完成部分可查看；刷新不丢任务，重试/回执丢失不重复采纳。服务重启时未确认完成的模型调用标为中断，不静默再次计费。
- 候选逐条或成组采纳，可编辑、拒绝、撤销采纳。采纳绑定目标版本；并发改动需展示冲突，禁止覆盖人工修改。已经修改或执行的采纳内容不能被简单撤销删除，改为新修订并保留历史。
- 账号级授权明确外部模型处理范围；展示许可、检索分析、外部处理、生成参考分别判定。未定义用途默认拒绝外发，不能让缩略图、OCR、标签或向量成为绕过途径。既有来源未知素材不自动升级权限。
- 运行前显示输入规模、预计等待和费用区间；服务端有可配置单次及账号周期用量上限、超时和取消。第一版接入一个经选型验证的供应商，不建多 Agent 编排平台。供应商故障时人工策划与基础搜索可继续使用。

## 数据演进与不可变边界

1. **复用现有身份。** 保留空间、素材、媒体、拍摄项、备忘、来源批次与执行事件 ID；新增迁移，不回写已应用的 0036。素材内容与使用关系分别版本化，排序/分组/项目意图属于关系，原始来源与收藏备注属于素材。
2. **先解除单空间假设，再提供复用。** 同一素材在一个集合或项目最多一条成员关系，可以属于多个集合和项目。账号级详情不返回一个任意的“所属空间”；项目内接口显式携带目标空间。来源回跳优先稳定素材地址，旧地址兼容跳转。
3. **未归类语义。** 全库包含所有未归档素材；未归类指没有任何普通集合引用的素材，独立于我的最爱与项目引用。一张图可同时出现在我的最爱、未归类和某次拍摄项目中；加入普通集合才退出未归类，从最后一个普通集合移出或删除该集合后自动返回未归类。我的最爱是不可重命名/删除的系统集合，未归类是不可手工管理成员的自动视图。原未归类空间 ID 保留为兼容入口，已有素材不复制。普通空间继续是项目；原空间分组保持项目内分组，不自动转成全局集合。
4. **编辑和移除可预测。** 修改全局素材会影响其未冻结引用视图，编辑时说明作用范围；只改本次参考意图走项目引用。移出集合/项目只删关系。素材删除先进入回收站，展示影响的集合/项目范围；回收期间退出正常搜索与可用参考，停止新增引用。恢复时恢复仍存在的原关系，不重建已删除的集合/项目；已采纳文本与媒体快照仍保留，项目冻结引用按规则 5 处理。回收站默认保留 30 天，可选 7/90 天或不自动清理；支持手动恢复、彻底删除和清空，缩短期限前展示立即清理数量并确认。v4 原型先验证本地语义；生产媒体回收须在 ITEM-2 设计独立快照引用、幂等清理和恢复边界后实现，不将删除素材记录等同于删除仍被采纳内容使用的媒体。
5. **归档项目保持稳定。** 归档时冻结参考内容版本与布局；之后全库素材编辑或普通归档不改变冻结内容，素材归档时在项目参考上标明「素材已归档」。恢复项目仍保留冻结内容；仅当素材已恢复可用且摄影师显式刷新引用时，才采用当前素材版本。普通归档只是整理动作，不等于用途权限撤销：所有服务端展示、外发和下载仍检查当前用途权限，冻结版本不能绕过撤销，禁止的媒体显示占位并保留可展示的内容。已下载到系统外的文件无法自动收回；服务端后续下载重新检查用途权限。资产库仍可找到账号有权查看的原素材；CRM 关联与旧执行事实不变化。
6. **媒体与产物权限同等重要。** 账号级素材读取不以原上传空间作为唯一授权入口；权限仍在服务端限定账号。媒体 `workspace_id` 的保留/重命名或回填由 ITEM-2 设计，不能通过放宽跨账号读取实现复用。导出选择、AI 输入、缓存、索引及临时下载均沿用账号与用途检查。导出用途未明确许可的媒体以来源/占位代替，并在导出预览中说明，默认不把私有备注或整库导出。
7. **独立且单一的策划事实。** 人工、Agent 和策划节点提供的编辑入口访问同一策划业务文档，镜头直接引用素材或快照，不以画布图片节点为身份。现场读取选定版本的拍摄项；导出固定内容版本及媒体清单。工作修订不覆盖历史导出或执行依据，订单发布版本的详细规则需在新路线中设计。
8. **发布与停止。** 扩展字段和兼容读先部署，回填核对完成后再开启新写。启用多空间/策划新写后，禁止回滚到不识别新结构的旧 writer；停用新能力后保留兼容读取、人工入口和已产生数据，按 forward fix 恢复。Agent 可单独关闭，不影响素材/方案读取。
9. **经营边界明确。** 新能力继续遵守 pilot 准入与 stopped 只读规则，不以升级绕过 preflight，不复活旧策划 writer。新项目不建立 CRM 业务关联；订单信息只作为明确任务的可选输入，策划发布到订单是独立业务扩展，需在新版契约立项。历史关联按兼容方案保留，不能直接清除；引用或发布策划均不自动改价格、档期、收款、提醒、订单/客户状态或对外发送内容。

- 演进验收：落实 EV-3–6，使用同一角色的两个变体样例，检索与候选明确适用范围、来源和未知项；缺少精确变体时只能说明回落，不能把他版设定当事实。来源署名不改变账号权限，同哈希素材的不同声明仍可独立追溯；不测试尚不存在的市场 API、不借本子项建设公共本体。

M1 真实体验目标：每位参与摄影师从自己的 ≥100 条素材中完成 10 个找回任务，至少 8 个在 60 秒内完成；至少两名摄影师出现跨项目复用。记录查找意图、是否命中、时间与放弃原因，低于目标先查入口、内容质量与检索，不机械增加筛选项。

M2 目标：在同一给定材料和条件下，至少 3 名摄影师分别使用原工具与新版完成一份可用方案；报告个人前后耗时与缺漏，不用只有均值的报告掩盖失败。目标为至少两人节省 ≥30% 时间且无关键遗漏；人工产物验收不依赖 Agent。

M3 冻结案例评分：每例按约束满足、可执行性、来源诚实、编辑成本四项各 0–2 分，达到 6/8 且来源诚实非 0 视为可用；20 例中至少 16 例可用。泄漏账号数据、无授权外发、伪造来源或覆盖人工内容出现一次即修复重验，不与平均分抵消。记录失败输出与模型版本；延迟/费用预算在 ITEM-7 选型时冻结，不能仅靠增加重试提升质量而不计成本。

M4 真正价值以连续实拍判断：至少 3/5 个项目把新版策划实际用于现场，且至少两名摄影师愿意继续使用并能说明复用的具体内容。Agent 分别报告建议采纳率（采纳候选/成功产出的候选）、运行成功率（成功运行/全部运行）与拍摄项落实率（现场完成的 AI 来源拍摄项/已进入拍摄窗口的 AI 来源拍摄项）；六类候选分别计数，非镜头候选不套“已拍”口径，分母为零记无证据。

这些是方向性门槛而非统计显著性声明。工程验收可形成阶段交付；产品指标未达时给出继续改善、缩小范围或停止扩展的具体建议，由 owner 决定，不能把增加功能当作验证通过。指标不出现在摄影师界面，不形成催促与完成率考核。

## 关键决策

- **DEC-1 · Pinterest 作为资产层的交互参考**：采用视觉浏览、搜索、集合和轻收集；项目的分镜/现场保留稳定顺序，画布用于表达关系。参考 Pinterest 官方「All about Pinterest」「Search for ideas」「Visual search」说明，访问日期 2026-09-07：https://help.pinterest.com/en/guide/all-about-pinterest 、https://help.pinterest.com/en/article/search-for-ideas-on-pinterest 、https://help.pinterest.com/en/article/use-visual-search-features 。本 Epic 的私有库形态和验收为本项目设计判断，不宣称复制其内容供给或搜索质量。
- **DEC-2 · 产物先于 Agent**：先做可人工完成且能带走的内容结构，让 Agent 直接写候选、采纳进相同事实，避免做出只在聊天里成立的策划。
- **DEC-3 · 画布承接创作，不增加录入前提**：画布是最终交付的一部分，实施排在 Agent 后；摄影师始终可用素材/方案/现场视图完成任务。
- **DEC-4 · 私有库与知识优先**：第一版先保证自己的素材找得回；外部发现、平台知识运营与全网抓取分别评估，不混入搜索的最小交付。
- **DEC-5 · 延续轻创作边界**：无必填流程、经营写入、客户认领、准备项催促和默认自动执行。
- **DEC-6 · 承接旧试点而不改写历史**：批准后显式 superseded 旧路线，旧工程基线、未完成证据和真实缺陷都保留来源。

## 整体验收与遗留风险

完整演示必须从账号自己的历史素材开始：搜索参考 → 引用到新项目 → 填本次条件 → 人工或 Agent 提出六类内容 → 选择采纳 → 画布组合 → 导出 → 手机现场执行 → 回到库复用。并展示另一条完全不启用 Agent、也不进入画布的人工路径。

完成全部 AC、子项工程验证与真实项目观察后，才进入最终 owner 验收；部分阶段交付不将本 Epic 标为 accepted。发布范围、停止策略与验证版本必须可追溯。

主要风险：

1. Pinterest 式页面在素材不足时价值有限；以批量收集与 100 条真实材料验证，外部供给不能靠 UI 假装存在。
2. 多空间引用涉及媒体授权、旧回跳、归档稳定性与备份；ITEM-2 是地基，不能压缩成去掉唯一索引的一次修改。
3. 收藏素材的 AI 处理许可可能不足；有明确的文字/标签回落和人工方案路径，许可限制作为产品真实能力展示。
4. 风格和布光建议可能好看但不适合实际场地；以具体器材/场景条件、待核实标记和真实拍摄结果评估。
5. 长文档与图文导出可能比编辑器更难；ITEM-6 独立交付和逐页验证，避免到最后才发现产物带不走。
6. 画布交互可能显著扩大工期；限制节点类型与模板，并保留移动端列表/详情替代路径，不先做通用编辑器平台。
7. 当前 OSS 403 已有账号实测反馈，但具体 RAM/bucket 配置根因仍需实际配置证据；不能把“很可能缺 creative 前缀权限”记为已修复。M1 上线前需完成授权测试环境的上传/读取验证。
8. 真实拍摄频率与外部参与者不可由工程进度保证；按阶段交付、明确未完成观察，不制造通过记录。实施授权、模型费用授权和部署授权分别沿用明确范围。

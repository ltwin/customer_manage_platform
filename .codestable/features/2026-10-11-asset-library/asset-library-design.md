# 资产库第 2 期：独立页面、查看浮窗、评分、主色与画幅

## 0. 结论

- **范围**：`/creative/library` 改成独立的资产库页面，不再借用画布。布局是应用侧栏、资料库树、浏览区和检查器四栏。同期交付共用查看浮窗（V6-066）、半星评分（V6-068）、主色与画幅筛选（V6-069）。原型是 `docs/prototypes/creative-workspace/v6/assets.html` 和 `viewer.mjs`（commit 17a9bff）。
- **并入的旧条目（owner 2026-10-11）**：这几条的界面都在新页面上，分开做的话同一批组件要改两遍。
  - V6-016：标签数量随条件变化，名称排序规则写清楚。
  - V6-018：删除分组后可以在服务端撤销。
  - V6-060：文字、链接、音频、视频卡片的样式。
  - V6-020：回收站验收，放在 067.3 一起做。
- **画布内的资产库抽屉保留**，继续负责在画布里取用素材。卡片组件和 `api.ts` 两边共用，所以 V6-060 的卡片样式、V6-016 的标签数量、V6-018 的撤销在抽屉里同时生效。两边不同时出现在同一个页面上，所以不做推送：进入页面、切回标签页时重读，自己写入之后也重读。
- **后端补的东西**（§2、§3）：
  - 评分字段，以及按评分筛选、排序和批量评分。
  - 「最近添加」视图。
  - 分类计数、标签计数和分组计数。
  - 用量接口。
  - 清空回收站。
  - 删除分组的撤销。
  - 主色计算与回填，以及颜色、画幅筛选。
  
  「放入项目」直接用画布现有的 `batch` 命令，不新增接口。
- **导入不查重（owner 2026-10-11）**：同名照样导入。只有类型不支持、文件太大、空间不够时才跳过，并逐项说明原因。按内容查重等第 3 期 V6-073。
- **用量显示「已用 / 上限」加进度条（owner 2026-10-11）**。数值是整个创作空间的媒体占用（画布里上传和生成的也算），和配额扣减的口径一致。
- **画幅分三档（owner 2026-10-11）**：横幅、方形、竖幅。长边和短边之比不超过 1.1 算方形。
- **名称排序沿用第 1 期 D4**：规范化之后按 Unicode 码位排序，和项目名排序是同一条规则。V6-016 AC-02 要的「明确规则」就是这一条，§2.1 写明。
- **批量操作一次最多 100 项**，和现有批量接口的上限一致。选中超过 100 项时，批量条和检查器提示「一次最多处理 100 项」，操作按钮不可用。

本期不做：

- 生成记录视图（V6-070）、生成信息区块（V6-071）、智能分组（V6-072）、内容查重（V6-073）。树里不出现这些入口，筛选条件也不出现「存为智能分组」。
- 手机上的资料库树（V6-067 范围外）。
- 视频的主色（V6-069 AC-01 只要求图片）。视频可以按画幅筛选。

## 2. 契约变更（`api/openapi.yaml`）

### 2.1 `GET /creative/assets` 新增参数

| 参数 | 取值 | 说明 |
|---|---|---|
| `view` | 新增 `recent` | 最近 7 天内添加、未进回收站的素材。默认按添加时间倒序，也可以换排序 |
| `min_rating` | 0.5–5，步长 0.5 | 评分不低于此值。「5 星」就是 `min_rating=5` |
| `unrated` | `true` | 只要未评分的。不能和 `min_rating` 同时出现 |
| `shape` | `landscape` / `square` / `portrait` | 只匹配有宽高、并且内容可读的图片和视频（§3.6） |
| `color` | `#rrggbb` | 按主色匹配（§3.5）。只匹配主色计算成功、并且内容可读的图片 |
| `sort` | 新增 `rating` | 评分高的在前，未评分的排最后；同分时按添加时间倒序，最后按 id |
| `include_facets` | `true` | 只在首屏（没有 `cursor`）时允许，响应里带上 `facets`（§2.4） |

名称排序（`sort=name`）的规则：标题先做 NFKC 规范化、转小写、去掉首尾空白，再按 Unicode 码位排序，同名时按 id 排序，所以分页是稳定的。码位顺序是数字、拉丁字母、中文；中文之间按码位排，不按拼音（第 1 期 D4）。

游标里加上 `rating`，和现有的游标一样绑定查询条件，换了条件的游标会被拒绝。

### 2.2 `CreativeLibraryAsset` 新增字段

- `rating`：`number | null`，取值 0.5–5，步长 0.5。`null` 表示未评分，不使用 0。
- `palette`：主色数组，最多 5 项，每项是 `{hex, weight}`，按占比从高到低排列。还没算、算失败、不是图片，或者内容不可读（`unavailable`）时为空数组。

### 2.3 `POST /creative/assets/batch-rate`（新）

`Idempotency-Key` 和 `operation_id` 的规则同现有批量接口。

```yaml
payload:
  items:            # 1–100 项
    - asset_id: string
      expected_revision: CreativeRevision
      rating: number | null   # 0.5–5、步长 0.5，或 null 清除
response:
  items: [{ id, revision }]
  library_revision
```

- 每一项各写各的分数，所以 toast 里的「撤销」能把多选时各自的原分数原样写回，一次请求完成。
- 整批要么全部成功，要么全部失败：任何一项的 revision 对不上就返回 409，一项都不写。回收站里的素材不能评分，返回 409 `creative_asset_trashed`，和改标题等编辑一致。
- 写入会推进素材的 `revision`，和改标题一样。
- 单选评分也走这个接口，只是只有一项。`metadata` 接口不加评分字段，免得出现两条写入路径。

### 2.4 列表首屏带计数

不单独开计数接口。两个 HTTP 请求各开各的读事务（`WithReadSnapshot` 每次调用一个事务），中间夹着一次评分或归类，数量就会和结果对不上。

改成：`GET /creative/assets?include_facets=true` 时，`CreativeAssetPage` 多返回一个 `facets`。它和 `items`、`total_count` 在同一个读事务里查出来：

```yaml
facets:
  kinds: { image: int, video: int, audio: int, text: int, link: int }
  tags: [{ tag_id, count }]
```

- 只有首屏允许带 `include_facets`，带了 `cursor` 时返回 400 `validation_failed`，和其他参数错误一致。翻页不重新统计。

- 类型计数忽略 `kind` 参数，其余条件照常生效，所以切换类型分段时数量不跳。数量为 0 的类型分段不显示（V6-067 AC-03）。
- 标签计数（V6-016 AC-01）：
  - 「同时满足」：标签 t 的数量 = 满足当前条件、并且也带 t 的素材数。也就是勾上 t 之后会剩几项。
  - 「满足任一」：不看已选标签，在其余条件下带 t 的素材数。
  
  数量为 0 的标签照常列出，显示为 0。
- 前端每次换条件发一个首屏请求，用请求序号丢弃过期条件的响应（V6-016 AC-03）。

### 2.5 `GET /creative/library-usage`（新）

返回 `{ asset_count, stored_bytes, limit_bytes, pending_release_bytes }`。

- `asset_count`：不在回收站里的素材数。
- `stored_bytes`、`limit_bytes`：来自 `creative_media_quotas`。账号还没有配额记录时，返回 0 和配置里的上限。
- `pending_release_bytes`（V6-075 增补，2026-10-12）：`stored_bytes` 中已被媒体 GC 标记删除、对象删除后即释放的字节，见[媒体模块 §6.4](../../../docs/product/creative-canvas-system/modules/media.md)。

### 2.6 `POST /creative/library/empty-trash`（新）

请求体 `{ expected_library_revision }`，带 `Idempotency-Key`。

- 打开确认框时，前端重新读一次回收站首屏（`view=trash&limit=1`），拿到当前数量和 `library_revision`。确认框写「将永久删除 N 项」。
- 执行时先锁资料库根，再核对 `library_revision`：
  - 一致：永久删除回收站里的全部素材。
  - 不一致：返回 409，一项都不删。前端重新读取数量，再请摄影师确认一次（owner 2026-10-12 接受）。
- 为什么核对版本号就够了：移入回收站和恢复都会在资料库根锁下让 `library_revision` 加一（`assets.go`、`organization.go` 的 `libraryResult`）。所以只要版本号没变，回收站里的素材就正好是确认框统计的那一批。这个判断不依赖任何时钟。不用截止时间，是因为浏览器时钟会有偏差；而服务端时间也挡不住「取时间在前、提交在后」的那一笔移入回收站。
- 代价：确认框开着的时候，资料库里有任何写入（包括别的窗口改了评分）都会要求重新确认。这种情况很少见，所以不为此单独加回收站版本号。
- 清理走和 `batch-purge` 相同的路径（V6-020 AC-02、AC-03：还有节点或运行引用的媒体不会被误删）。
- 返回 `{ purged_count, library_revision }`。

### 2.7 删除分组的撤销（V6-018）

- `POST /creative/asset-groups/{id}/delete` 的返回值新增 `deletion_id`。
- 新增 `POST /creative/asset-groups/deletions/{deletion_id}/restore`，带 `Idempotency-Key`。
  - 恢复分组本身，id、名称、父级和位置都不变。
  - 恢复当时的成员关系。已经被永久删除的素材跳过，其余照常恢复。
  - 恢复当时被提升到上一级的子组。
  - 期间分组结构有过任何变化（`hierarchy_revision` 和删除后记下的值不一致）时，返回 409，什么都不改。前端提示「分组已经有新的调整，无法撤销」（V6-018 AC-03）。只改了素材归类不算结构变化，不影响撤销；撤销时成员关系取并集，不会覆盖期间的新归类。
  - 有素材在此期间已归入 100 个分组（每份素材的分组上限）时，返回 409 `creative_group_restore_limit`，什么都不改，快照保留，腾出位置后可以再撤销。不静默跳过这份素材的成员关系（2026-10-12 代码审计）。
  - 同一个 `deletion_id` 只能恢复一次。重复请求按幂等键回放原结果（AC-04）。

### 2.8 分组列表带计数

`CreativeGroupPage` 新增 `asset_counts: { [group_id]: int }`，统计不在回收站里的素材。

- 子组的数量是它自己的成员数。
- 顶层分组的数量包含子组，同一份素材同时在父组和子组里时只算一次（`count(DISTINCT asset_id)`，按 `coalesce(parent_id, id)` 分组）。

### 2.9 不变的部分

- 上传、创建文字或链接素材、`batch-organize`、`batch-trash` / `restore` / `purge`、`metadata` 的契约都不变。
- 画布 `commands` 的契约不变。「放入项目」复用 `batch` 和 `add_node`。

## 3. 后端

### 3.1 迁移 `0061_creative_asset_library`

```sql
-- 评分按半星存成整数 1–10，空值表示未评分。
ALTER TABLE creative_assets ADD COLUMN rating_halves SMALLINT CHECK (rating_halves BETWEEN 1 AND 10);
CREATE INDEX creative_asset_rating ON creative_assets(account_id, rating_halves DESC NULLS LAST, created_at DESC, id DESC)
  WHERE deleted_at IS NULL;

-- 主色是图片文件本身的事实，挂在 blob 上，和素材、画布都无关。
CREATE TABLE creative_blob_palettes (
  account_id TEXT NOT NULL, blob_id TEXT NOT NULL,
  algorithm TEXT NOT NULL,                 -- 例如 oklab-kmeans-v1，换算法时据此重算
  state TEXT NOT NULL CHECK (state IN ('ready','failed')),
  failure_reason TEXT NOT NULL DEFAULT '' CHECK (char_length(failure_reason) <= 100),
  colors JSONB NOT NULL DEFAULT '[]',      -- [{l,c,h,hex,weight}]，按 weight 降序
  computed_at TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp(),
  PRIMARY KEY (account_id, blob_id)
);

-- 删除分组时的快照，供撤销使用。
CREATE TABLE creative_asset_group_deletions (
  id TEXT PRIMARY KEY, account_id TEXT NOT NULL,
  group_snapshot JSONB NOT NULL,           -- {id, parent_id, name, position}
  promoted_child_ids TEXT[] NOT NULL,
  member_asset_ids TEXT[] NOT NULL,
  hierarchy_revision_after BIGINT NOT NULL,
  restored_at TIMESTAMPTZ,
  created_at TIMESTAMPTZ NOT NULL DEFAULT clock_timestamp(),
  UNIQUE (account_id, id)
);
```

新表都带 `account_id`，查询走账号作用域基座（ADR-001）。删除快照保留 30 天：超过 30 天的快照恢复时按不存在处理；记录本身由 067.3 新增的回收站到期清理任务一并删除（§3.7）。

### 3.2 评分

- `SearchAssets` 的条件和排序按 §2.1 补充，按评分排序时用上面的索引。
- `BatchRate` 和 `batch-organize` 走同一套命令框架（`libraryRun`）：先锁资料库根，再逐项锁素材、核对 revision，校验全部通过之后才写入。
- 账号隔离：素材 id 只在本账号作用域内查找，查不到返回 404，不会写到别的账号。

### 3.3 计数和用量

- 把 `SearchAssets` 拼条件的那段抽成 `searchCondition(q)`。列表、`total_count` 和 `facets` 都调用它，在同一个 `WithReadSnapshot` 里执行，保证三处条件和数据状态完全一致。
- 类型计数是一条 `GROUP BY kind`，标签计数是一条 `GROUP BY tag_id`，按 §2.4 的两种模式生成条件。几千项的账号，首屏多两条聚合查询，可以接受。
- 用量读 `creative_media_quotas`，素材数是一条 `count`。

### 3.4 内容可读条件

颜色、画幅筛选都要读内容的属性，必须和关键词搜索一样，先过内容授权。否则即使列表不显示这张图，命中结果和计数也会暴露已撤销内容的颜色和尺寸。

- 把 `list.go` 关键词搜索里那段授权条件抽成 `readableContent(alias)`：修订状态是 `ready`、来源声明允许展示、`display` 授权没有撤销，并且没有失效的依赖授权（`creative_content_required_grants`）。条件和 `creativecontent.ReadDisplayBatch` 的读取守卫一致。
- 关键词正文命中、颜色筛选、画幅筛选，以及它们参与的 `total_count` 和 `facets`，都带上这个条件。
- 列表返回时，`unavailable` 的素材 `palette` 为空，也没有宽高。
- 单测断言 `readableContent` 和 `ReadDisplayBatch` 对同一批样例给出相同结论，防止两处以后改得不一致。

### 3.5 主色（V6-069）

**计算**：在 `verifyImage` 里，图片已经解码并转正了方向。

1. 缩到长边 64 像素。
2. 转到 OKLab 色彩空间，做 k-means，k 等于 5，初始中心固定，所以同一张图每次结果相同。
3. 输出 5 个颜色，每个带 OKLCH 值（明度 L、色度 C、色相 h）、hex 和占比。

结果放进 `Verified.Palette`，和 blob 记录在同一个事务里写入。上传和生成导入都会经过 `Verify`，所以两条入口都覆盖到（AC-01）。这里图片已经解码成功，计算本身出错只可能是确定性的，所以写一条 `state='failed'` 并记下原因，不影响入库（AC-04）。

**回填**：新增后台任务 `media.palette_backfill`，挂在现有的 jobs（River）上。

1. 每批取 50 个 `state='ready'`、还没有当前算法版本主色记录的图片 blob。
2. 读每张图之前先加读取锁（`creative_blob_read_pins`，和媒体事实探测 `registerProbePin` 的做法相同），防止读到一半被删除。读完就释放。blob 已经不是 `ready` 的直接跳过，不记失败。
3. 读显示图（没有显示图就读原图），然后计算主色。
4. 本批的结果，以及「还有剩余就排下一批」这一步，在同一个事务里提交（`jobs.EnqueueInTx`）。写入按 `(account_id, blob_id)` 做 upsert，所以中断后重跑、重复执行都安全。

失败分两类处理：

- **临时故障**：对象存储读取超时、数据库错误。本批不写任何结果，直接返回错误，由 jobs 按退避有限次重试。重试用完后任务进入失败状态，这些 blob 仍然没有记录，下次排队时还会被扫到。
- **确定性失败**：图片解码不了、尺寸异常。写 `state='failed'` 和原因，之后不再自动重试。

服务启动时排一次，任务本身按幂等键去重。另外提供运维命令 `creative-palette rebuild --account <id> [--algorithm <版本>]`：删掉这个账号指定算法版本的记录（包括 `failed`）后重新排队。换算法版本时，扫描条件会自然把旧版本的 blob 当成「没有记录」。

**匹配**（AC-02）：查询色转成 OKLCH，记为 (Lq, Cq, hq)。素材只要有一个占比不低于 10% 的主色满足下面的条件就算命中：

| 查询色 | 条件 |
|---|---|
| 中性色（Cq < 0.04） | 主色也是中性色（C < 0.04），并且 \|L − Lq\| ≤ 0.12 |
| 有彩色 | 主色是有彩色（C ≥ 0.04），色相差 ≤ 25°，并且 \|L − Lq\| ≤ 0.2 |

黑白照片的主色全是中性色，所以用暖色查不出来。这个条件在 SQL 里用 `jsonb_array_elements` 写成 `EXISTS`，经过 `creative_content_objects`（`role='original'`）连到 blob，并带上 §3.4 的内容可读条件。单个账号的素材量在几千这个级别，不建专门的索引。阈值作为常量写在一处，并用一组固定样例图做单测。

**界面**：

- 颜色筛选弹层是 12 个预设色块：红、橙、黄、绿、青、蓝、紫、粉、棕、白、灰、黑。
- 检查器里点某个主色，等于用这个颜色筛选（V6-069 范围）。

### 3.6 画幅

- 不新增存储（AC-03）。条件经过 `creative_content_objects` 连到原图 blob 的宽高，并带上 §3.4 的内容可读条件：
  - `max(w,h)/min(w,h) ≤ 1.1` 为方形；
  - 其余宽大于高为横幅，高大于宽为竖幅。
- 文字、链接、音频没有宽高，选了画幅后它们不出现在结果里。

### 3.7 清空回收站与删除分组撤销

- 清空回收站：在 `libraryRun` 里先锁资料库根，再核对 `expected_library_revision`。核对通过后，对回收站里的所有素材调用现有的 purge 逻辑，一次命令、一个事务。几千项会不会让事务太长，先用真实规模的数据测一次，有问题再考虑拆分。
- 删除分组：在 `groupCommand` 的删除分支里，先把快照写进 `creative_asset_group_deletions`，再执行原来的删除逻辑。恢复按 §2.7 的规则执行，同样先锁资料库根，再核对 `hierarchy_revision`。
- 回收站到期清理（067.3，V6-020 AC-02）：现在没有这个任务，`purge_after` 到期后素材一直留在回收站里。新增维护任务 `library.trash_expiry`，挂在 jobs 的 `maintenance` 队列上，服务启动时排一次，之后每小时排一次，不依赖页面打开。
  - 每次取一个有到期素材的账号，在 `libraryRun` 同样的锁序下（先锁资料库根）删除 `purge_after <= now()` 的素材，每批最多 100 项，走和 `batch-purge` 相同的删除路径；同一事务推进 `library_revision`，并顺手删掉这个账号超过 30 天的分组删除快照。
  - 还有剩余就在同一事务里排下一批（`jobs.EnqueueInTx`），中断后重跑是安全的：已经删掉的不会再出现在条件里。
  - 移入回收站时的 `purge_after` 不随设置变化，所以缩短保留期不会提前删除已经显示了期限的素材（data-model 保留策略）。

### 4.3 选择与整理（067.2）

- **选择**（AC-04）：`selection.ts` 是纯函数，输入当前选择、点击项、修饰键和可见顺序，输出新的选择。
  - 单击选中，⌘ 加选，Shift 从锚点连选。
  - 在空白处拖动框选，框选时按住 ⌘ 是在原选择上叠加。
  - ⌘A 选中已加载的全部项，Esc 取消。
- **拖到分组**：卡片拖到树里的分组上，就调用 `batch-organize` 的 `add_group_ids`。拖动整批选中项时一起归入。进入某个分组后，右键菜单多一项「移出这个分组」。
- **检查器**（AC-05）：
  - 单选：大图、可编辑的标题和备注、星级、主色、分组和标签 chip（就地增删，可以新建标签）、属性（类型、尺寸、大小、添加时间）。下面是放入项目、最爱、下载、移到回收站。
  - 多选：叠放预览、批量星级。只属于部分素材的分组和标签显示为半透明，点一下补齐到全部。
- **批量条**：检查器可见时不出现，检查器收起或放不下时出现。批量条、检查器和右键菜单调用同一组操作函数：归入分组、打标签、评分、最爱、放入项目、回收站。
- **评分交互**（V6-068）：`StarRating` 组件。
  - 点星星左半边是半星，右半边是整星；点当前分数清零。
  - 悬停预览，方向键每次 ±0.5。
  - 选中素材后按数字键 1–5 打整星，0 清除。焦点在输入框里时不响应。
  - 多选评分之后 toast 提供「撤销」，用原分数调用 `batch-rate`。
  - 所有修改先在界面上生效，失败时回滚并 toast 说明原因。409 时重读这些素材，提示「已在别处修改，已刷新」。
- **放入项目**（AC-06）：`ProjectPicker` 列出当前项目，按最近编辑排序，超过 8 个时显示搜索框；最后一项是「新建项目并放入」。`placement.ts` 负责：
  1. 读目标画布（`GET /creative/canvases/{default_canvas_id}`），取所有节点的包围盒。
  2. 新节点从包围盒右边缘加 40 开始横排，顶端对齐包围盒顶部；空画布从原点开始。间距 40，和 V6-057 AC-05 一致。节点高度按素材比例计算，和抽屉相同。
  3. 组装 `add_node` 动作（从 `WorkspacePage` 抽出的共用函数），带上 `expected_topology_revision` 和 `change_group_id`，一次 `batch` 发出。整批要么全部成功，要么全部失败；进入画布后可以一步撤销。
  4. 结构版本冲突时重读画布、重新排布，再试一次。还失败就 toast 说明原因并提供「重试」，不会只放进一部分。
  5. 成功后 toast 提供「打开画布」。
  
  「新建项目并放入」先建项目，再执行上面的步骤。放入失败时项目保留，重试时继续用这个项目，不会再建一个。
  
  资产库不记录、也不显示素材被哪个项目用过。
- **删除分组撤销**（V6-018）：删除之后 toast 显示「已删除分组」和「撤销」，调用恢复接口。409 时提示无法撤销。抽屉里的删除走同一个函数。

### 4.4 查看浮窗（V6-066）

`MediaViewer` 是通用外框，宿主传入素材列表、当前序号和右侧面板。资产库传 `AssetInfoPanel`，以后的生成记录、画布节点和助手结果各自传自己的面板。

- **打开**（AC-01）：双击、空格或 Enter、悬停时的放大按钮。单击仍然只是选中。
- **画幅**（AC-02）：图片和视频按原比例完整显示（`object-fit: contain`）。铺不满的两侧用同一张图模糊放大作为背景（`filter: blur(48px)`）。只有内容本身的模糊，界面皮肤不用玻璃效果。
- **缩放**（AC-03，`zoom.ts`）：
  - 只对图片生效。
  - 带 `ctrlKey` 的 wheel（触控板捏合）和鼠标滚轮负责缩放，范围 1×–8×，以指针为中心。
  - 区分鼠标滚轮和触控板滑动的规则照搬原型 `viewer.mjs:184`：纵向步长为整数且不小于 40、没有横向量的，认为是鼠标滚轮。Safari 另外处理 `gesturechange`。
  - 放大后拖动或两指滑动平移，并限制范围，内容不会拖出视野。
  - 底部显示比例，点一下还原；翻到下一项自动复位；单击不缩放。
  
  视频只做完整显示，不缩放，免得和播放控制冲突。
- **其他类型**（AC-04）：
  - 视频和音频用原生控件，空格播放或暂停。
  - 文字按阅读排版显示全文（打开时读单个素材，拿到完整正文）。
  - 链接显示域名、标题、网址和「打开网址」按钮，不抓取远程预览。
  - 方向键翻看，Esc 关闭。
  - 浮窗里打开的菜单挂在浮窗的根节点上，所以显示在浮窗之上。
- **右侧面板**（AC-05）：从上到下是类型与尺寸、可编辑的标题、星级、添加时间与文件大小，然后是分组、标签和备注。
  - 「生成信息」区块留出位置，内容等 V6-071。
  - 修改即时保存，失败时回滚并提示。写入调用的是和检查器同一组函数。
- **底部操作**（AC-06）：
  - 放入项目（同一个 `ProjectPicker`）、下载（`media-access-tickets` 的 download 用途）、移到回收站。
  - 移到回收站之后，浮窗里直接显示「已移到回收站」和「恢复」。
- **焦点**（AC-07）：用 `useFocusTrap` 把焦点限制在浮窗内，关闭后回到打开它的那张卡片。

### 4.5 导入与回收站（067.3）

- **导入**（AC-07）：
  - 「导入」菜单有三项：上传文件、添加链接、新建文字。

  - 撤销某张图的展示授权后，它不再命中颜色、画幅筛选，相应的计数也减少；列表里它的 `palette` 为空。

  - `readableContent` 和 `ReadDisplayBatch` 对同一批样例给出相同的结论。
- 主色：
  - 纯色图、黑白照片、暖色照片的计算结果符合预期。
  - 同一张图两次计算结果相同。
  - 坏图写成 `failed` 并记下原因，入库不受影响。
  - 用暖色筛选时，黑白照片不出现（AC-02）。
  - 回填任务处理完所有存量图片。
  - 回填的故障恢复：
    - 读取对象存储时注入一次超时：本批不写任何记录，任务返回错误，重试后补齐，没有一张被记成 `failed`。
    - 在两批之间中断后重新运行，结果和一次跑完的相同，没有重复记录。
    - 同一批重复执行，记录不变。
    - 回填期间 blob 进入删除流程：这张图被跳过，不记失败，读取锁按时释放。
  - 运维命令 `rebuild` 只清理并重算指定账号、指定算法版本的记录。
- 清空回收站：
  - 版本号一致时，删除回收站里的全部素材，返回删除数量。
  - 读取版本号之后，另一连接又移入一项：返回 409，一项都不删。
  - 读取版本号之后，另一连接恢复一项：同样返回 409。

  - 还被节点引用的媒体不会被删（V6-020 AC-03）。
- 回收站到期清理（067.3）：
  - 只删 `purge_after` 已到的素材，未到期和设为不自动清除的保留。
  - 超过 100 项时分批完成；中途中断后重跑，结果和一次跑完相同。
  - 超过 30 天的分组删除快照一并删除，未到 30 天的保留。
- 删除分组撤销：
  - 恢复分组、成员关系和子组位置。
  - 期间有结构变化时返回 409。
  - 期间新加的归类保留。
  - 有素材已满 100 个分组时整体拒绝，分组和快照都不变；腾出位置后同一个快照可以撤销。

- 放入项目：成功一次；冲突后重排成功一次；失败后重试一次。
- 浮窗：打开方式、缩放、焦点。
- 导入跳过时的说明。
- 回收站的提示文案（7 天和不自动清除两种）。

抽屉现有的 e2e 也要跑一遍，确认卡片样式、标签计数和分组撤销没有破坏原有行为。

合回 `develop` 前跑 `make check`。

## 6. 上线、回滚与派生数据

**部署顺序**：

1. 先执行迁移 `0061`。它只新增可空列和新表，不改现有列，所以迁移完成后旧版本实例照常运行和写入。
2. 再部署新版本。新实例启动时排一次回填任务。

**旧实例继续写入时的补漏**：滚动部署期间，旧实例上传的图片不会计算主色。回填扫描的条件是「`ready` 状态、没有当前算法版本记录的图片」，所以这些图片会被下一次回填补上。最晚在下一次服务启动时排队；也可以用运维命令立即补。旧实例不认识评分字段，但它不会写这个字段，评分不受影响。

**回滚**：只回滚应用代码，不执行 down 迁移。评分、主色和删除分组的快照都保留在库里，重新上线后接着用。旧代码不读这些列和表，不受影响。down 迁移只用于开发环境。

**派生数据的生命周期**：

- 主色是从 blob 派生出来的数据，不是媒体保留根。媒体保留和清理的判断都不读 `creative_blob_palettes`。
- blob 被删除时，同时删除它的主色记录。目前代码只会把 blob 标成「删除中」，还没有最终删除对象的清理任务；那个任务落地时，同一个事务里删掉对应的主色记录。在那之前，主色记录跟着 blob 记录一起留着，不会单独悬空。
- 删除分组的快照保留 30 天，到期由回收站到期清理任务删除（067.3 新增，§3.7）。

**ADR-008 关联清单**：新增的两类关系要登记进数据模型的关联清单，并加进一致性扫描：

| 关系 | 类型 | 写入守卫 | 扫描规则 |
|---|---|---|---|
| `creative_blob_palettes.blob_id` → `creative_blobs` | 派生数据 | 只在同账号、`ready` 的 blob 上写入（入库事务里写，或者回填时在读取锁下写） | 指向的 blob 不存在时报异常，不自动删除；不参与媒体保留 |
| `creative_asset_group_deletions` 里的分组、子组和素材 id | 历史来源 key | 恢复时逐个核对是否存在、是否属于本账号；不存在的跳过 | 允许失效，不算悬空引用 |

两张新表都带 `account_id`，不建外键，所有读写都走账号作用域。

## 10. 评审记录

2026-10-12 设计评审（S1，按每个账号约 5,000 项、峰值 5 QPS 作假设）的结论，均已修订：

| # | 评审意见 | 处理 |
|---|---|---|
| 1 | 阻塞：清空回收站的截止时间取自浏览器时钟，可能误删确认之后才移入的素材 | §2.6、§3.7 改成核对 `library_revision`，变化时返回 409、重新确认（owner 2026-10-12 接受）。移入回收站和恢复都会在根锁下推进这个版本号，所以不再需要截止时间 |
| 2 | 高风险：列表和计数是两个请求，做不到同一个读快照 | §2.4 改成首屏 `include_facets=true`，在同一个读事务里返回；取消独立的计数接口 |
| 3 | 高风险：颜色、画幅筛选没有接上内容授权 | 新增 §3.4 内容可读条件：筛选和计数都带上它，不可读的素材 `palette` 为空 |
| 4 | 高风险：回填把临时失败记成永久失败 | §3.5 区分临时故障（交给 jobs 重试）和确定性失败，结果与下一批入队同事务提交，写入幂等，并提供运维重算命令。另外补了一点：回填读图时加读取锁 |
| 5 | 建议：补上线、回滚和派生数据生命周期 | 新增 §6，包括 ADR-008 关联清单 |

评审建议不要加的独立搜索服务、额外 MQ、跨请求快照和提前分段提交，本设计都没有加。

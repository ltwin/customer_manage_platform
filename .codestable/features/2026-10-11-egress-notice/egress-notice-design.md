# 助手首次外发说明

## 0. 结论

- **只补首次说明，不新增授权环节。** 发送时自动按本条消息的范围创建授权（V6-030.2 起）；后端在建运行、派发、重试、补充时都会核对授权（§1）。所以 AC-02、AC-04 已经满足，本条主要补 AC-01 的首次说明。
- **形式**：第一次发送时弹窗说明。点「知道了，发送」后才发出；点「取消」或按 Esc 关闭弹窗，草稿原样保留，其他功能照常可用（owner 2026-10-11）。
- **本机记住**：按「账号 + 说明版本」记在 localStorage。换设备或清缓存后会再弹一次（owner 2026-10-11）。这条记录只决定弹不弹窗，不参与授权：每次发送仍然创建本条消息的授权，由后端核对。
- **只管助手**：画布内助手面板和首页一句话开始共用同一个入口。图片生成保持不弹窗（owner 2026-10-09 / 2026-10-11）。
- **不做撤销入口**：后端的撤销能力保留，界面不提供入口（owner 2026-10-11）。AC-03 的撤销部分用已有的后端测试作为证据。
- **重新询问只有一个触发条件：说明版本变化。** 说明里列出的是助手当前会发送的全部数据类型。以后助手要发送新的类型（例如整库检索、音视频元信息）时，必须改写说明并升级版本，届时所有账号都会再看到一次。

本期不做：

- 服务端记录「已看过说明」。
- 图片生成的说明。

## 1. 现状

| 能力 | 位置 | 结论 |
|---|---|---|
| 每条消息建授权，范围是本条的图片和数据类型 | `frontend/src/creative-canvas/editor/agentState.ts` 的 `messageSteps` | 复用：同一会话里，后续每条消息各自授权，不再询问 |
| 建运行时核对授权：会话一致、未撤销、说明版本一致、有 `text`；引用的修订必须在授权清单里，图片还需要 `image_preview` | `backend/internal/creativeagent/runs.go` 的 `coversRun` | AC-04 已满足 |
| 派发前、重试、补充时在同一事务里再核一次；撤销后的运行不再外发 | `execute.go`、`waiting.go`、`retry.go` | AC-03 撤销部分已满足 |
| 读取画布内容由 `canvas_metadata` 控制 | `context.go`、`inputs.go` | 说明里如实写出 |
| 说明版本 `policyVersion = "egress-2026-10-1"` | `backend/internal/creativeagent/service.go` | 前端用同一个字符串 |
| 首次说明、撤销入口 | — | 都没有 |

「换模型或服务商路由变化不影响复用」（AC-02 后半句）由 model-routing 设计保证：授权按平台记录，不记具体服务商。

## 2. 交互

### 2.1 触发

助手的三个入口：

1. 画布面板发送新消息，包括第一条和后续的消息。
2. 首页「交给助手」，在建项目之前就检查。
3. 首页按 Enter 发送。

其中「交给助手」和 Enter 发送走同一个函数。

发送前检查本机记录。记录的版本不等于当前说明版本时，先弹窗，不发出任何请求。

以下情况不弹窗：

- **补充消息**：沿用原运行的授权，弹窗之前必然已经发过消息。
- **重试步骤、重放待确认链（「重新发送」「重试发送」）**：这些都是此前已经确认过的发送。
- **对话改名、归档**：不涉及外发。

### 2.2 弹窗

标题：**发送前说明**

正文：

> 这条消息会发送给平台签约的模型服务商，用来生成助手的回复。详见隐私说明。
>
> 发送的内容：
> - 你写的文字，以及选择的 Skill
> - 你附带或 `@` 引用的图片（压缩后的预览图）
> - 助手完成任务时读取的当前画布内容：节点标题、文字、生成提示词和参数
>
> 资产库里没有被引用的素材不会发送。每次发送只带这条消息涉及的内容。说明有变化时会再告诉你。

按钮：「取消」（次要，打开时默认获得焦点）、「知道了，发送」（主按钮）。默认焦点放在「取消」上，这是现有 `ConfirmDialog` 的行为：按 Enter 发出消息后，再按一次 Enter 只会关闭弹窗，不会意外发送。

- 点「知道了，发送」：写入本机记录，然后照常发送。
- 点「取消」、按 Esc 或点遮罩：关闭弹窗。不写记录，草稿和附件原样保留。下次发送还会弹窗。
- 弹窗打开时焦点限制在弹窗内，关闭后回到输入框。

「隐私说明」链接到公开页 `/privacy`，在新标签页打开，草稿和弹窗都还在（§5 D-1）。正文里有链接，所以用 `data-autofocus` 把初始焦点固定在「取消」上。

### 2.3 本机记录

- 键：`creative-egress-notice:{account}`，值为说明版本字符串。
- 读写都放在 try/catch 里。localStorage 不可用时视为没看过：每次发送都弹窗，宁可多弹也不漏弹。
- 版本常量 `egressNoticeVersion` 放在 `agentState.ts`，注释指向后端的 `policyVersion`。两者必须同时修改，见 §4 的测试。

## 3. 实现

前端改动：

- `editor/EgressNotice.tsx`（新）
  - `useEgressNotice(account)` 返回 `{ confirm(): Promise<boolean>, dialog }`。
  - `confirm()` 在已经看过时直接返回 `true`。没看过时打开弹窗，等摄影师选择后再 resolve。
  - 弹窗直接复用 `components/ConfirmDialog`（遮罩、Esc、焦点限制和归还都已具备），挂到 `.cc-workspace` 上，没有就挂到 body。
- `AgentPanel.sendDraft`：新消息分支在组装链之前先 `await confirm()`，返回 `false` 时直接退出。补充消息分支不变。
- `HomeComposer.send`：在 `save(current)` 和建项目之前先 `await confirm()`。取消时什么都不建，首页本机记录也不写。
- `agentState.ts`：新增 `egressNoticeVersion`、`noticeSeen(storage, account)` 和 `rememberNotice(storage, account)`。
- `pages/privacy/`（新）：`PrivacyPage.tsx` 和 `privacy.css`。`App.tsx` 加上公开路由 `/privacy`，打开时不恢复会话。
- `components/useFocusTrap.ts`：如果有标了 `data-autofocus` 的元素，初始焦点优先给它。`ConfirmDialog` 在没有输入框时给「取消」打上这个标记；`body` 允许传入节点。

后端代码和契约不改。补一条后端测试：说明版本较早的授权不能启动运行（`TestAConsentUnderAnEarlierNoticeDoesNotStartARun`），作为 AC-03 和 AC-04 的服务端证据。

## 4. 验证

单测 `creative-agent.test.ts`：

- 没有记录、版本不同、localStorage 抛错时，`noticeSeen` 都返回 `false`；写入后返回 `true`。
- 不同账号互不影响。
- 读取 `backend/internal/creativeagent/service.go`，确认里面的 `policyVersion` 等于 `egressNoticeVersion`。两边只改一边，测试就会失败。

e2e：

- `creative-home.e2e.mjs`：
  - 首次在首页发送时弹窗。
  - 点「取消」：没有任何 `/projects` 请求，文字保留。
  - 点「知道了，发送」后完成发送；再发一次不弹窗。
  - 版本记录不同时再次弹窗。
- 面板（`creative-agent.e2e.mjs`）：首次发送弹窗；补充消息和「重新发送」不弹窗。现有用例预先写入本机记录，以免被弹窗挡住。

AC 对应：

| AC | 证据 |
|---|---|
| AC-01 | 上面的 e2e：弹窗文案、取消后保留草稿、取消后人工功能照常 |
| AC-02 | 已有后端测试：同会话多次运行、换模型；本条不改 |
| AC-03 | 版本不同时重新弹窗（e2e）；撤销后阻止运行用已有的后端测试（列出测试名） |

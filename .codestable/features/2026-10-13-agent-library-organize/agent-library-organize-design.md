# 助手整理资产库

## 0. 结论

在 V6-035 已交付的查找工具之上，加四个资产库写工具和一个只读的整理结果分页工具。复用已有整理命令，同时补齐可恢复执行、完整结果分页、归类筛选分页、删除影响预览，以及全入口统一的描述长度限制。恢复记录需要新增数据库表；描述限制需要同步前端和 API 契约，不再限定为两处小的后端补充。

| 决定 | 内容 | 来源 |
|---|---|---|
| 何时整理 | 摄影师指派，或助手在创作中觉得需要时先问、同意后再做。服务端无法判定「是否同意」，靠基础提示词约束模型，用真实模型记录验证；以后由 V6-033 的确认交互兜底 | owner 2026-10-13 |
| 允许的操作 | 改标题和描述、加减标签和分组；新建、改名、移动、删除分组、分类和标签；移入回收站、从回收站恢复 | owner 2026-10-13 |
| 禁止的操作 | 彻底删除、清空回收站：没有对应工具，也没有可以拼出它们的参数 | owner 2026-10-13 |
| 不碰的字段 | 评分、收藏、标签颜色。这些是摄影师的判断或审美，助手不改 | V6-078 范围外 + owner 2026-10-13 同意 |
| 工具形状 | `organize_assets`（逐个素材改）、`manage_library`（改归类结构）、`trash_assets` / `restore_assets`（移入、移出回收站） | V6-078 建议 + owner 2026-10-13 |
| 单次上限 | 素材类 50 个，结构类 20 个动作；条数上限之外仍按实际序列化字节预算分页 | V6-078 + owner 评审 |
| 读取完整性 | 限制单次返回量，不限制可达数据；所有省略都有继续读取入口，不能把部分结果当作全集 | owner 2026-10-13 评审 |

| 写入结果 | 短摘要包含每项状态；完整原值和改动保存在持久化记录，通过 `read_library_result` 分页读取，读取不重做写入 | 本次审查修正 |
| 冲突 | 每个素材带助手看到的修订号；对不上就不写，原样报告冲突，不自动重试 | V6-078 AC-05 |
| 改写已有文字 | 允许。改写已有标题或描述前，先在对话里列出原值和新值，摄影师同意后再写；结果里也列出原值。由基础提示词约束，不加服务端开关 | owner 2026-10-13 |
| 新入库素材 | `save_to_library` 必须带标题和描述。存入前先在对话里列出标题、描述、分组、标签（含要新建的标签），摄影师同意后再存 | owner 2026-10-13 |
| 基础提示词 | 整理成分节的基础提示词，放进独立文件；跨工具的行为规则（何时整理、何时确认）写在这里，工具说明只讲单个工具怎么用。Skill 仍是在基础提示词后追加。顺带补上 V6-035/077 新工具的说明 | owner 2026-10-13 |
| 能力类别 | 沿用 `manual_write`，和 `edit_canvas`、`save_to_library` 一致；不新增类别 | 本设计 |
| 看图成本 | 复用 `read_asset` 一次读一张，不做拼图缩略图；整理范围由摄影师指定 | 本设计（有界简化，见 §7） |

本期不做：

- 撤销删除分组（见 §7）
- 评分、收藏、标签颜色
- 合并标签、多分类（资产库页本身没有）
- 确认交互（V6-033）
- 语义检索

## 1. 现状

2026-10-13 核对，`33361de` 之后的代码。

**助手侧（V6-035 已交付）**

- `search_assets`、`read_library` 只在授权为 `account_library` 且含 `media_metadata` 时可用（`requireLibrary`）。
- `search_assets` 返回 `asset_id`、`content_revision_id`、标题、描述摘录、标签和分组名称，**不返回素材的 `revision`**。
- `read_library` 返回分组、分类、标签的 ID、名称和数量，**不返回各自的 `revision`**。
- `read_asset` 能读授权内的资产库图片，一次一张。上下文里最多保留 8 张图（`ImagePreviewCount`），更早的只留引用。
- `save_to_library` 收到 `new_tags` 时拒绝，提示「新建标签属于整理资产库」。

**资产库后端（`creativelibrary`）**

| 命令 | 作用 | 并发保护 | 备注 |
|---|---|---|---|
| `Metadata` | 改单个素材的标题、描述、收藏 | 素材 `expected_revision` | 标题 1–200 字，描述 ≤2000 字；回收站内拒绝 |
| `Organize` | 给 1–100 个素材加减同一组标签和分组 | 每个素材的 `expected_revision`，整批原子 | 每个素材最多 50 个标签、100 个分组 |
| `Trash` / `BatchTrash` | 移入回收站 | 素材 `expected_revision` | 可在资产库页恢复 |
| `Restore` / `BatchRestore` | 从回收站恢复 | 素材 `expected_revision` | 不在回收站时拒绝 |
| `Purge` / `BatchPurge` / `EmptyTrash` | 彻底删除 | — | **助手不接** |
| `CreateGroup` / `RenameGroup` / `MoveGroup` / `DeleteGroup` | 分组结构 | 分组 `expected_revision` + 全库 `hierarchy_revision` | 名称 ≤80 字，最多两层；删除时子分组上提，成员关系删除 |
| `CreateTag` / `EditTag` / `DeleteTag` | 标签 | 标签 `expected_revision` + `hierarchy_revision` | 编辑必须同时给名称和颜色；同名新建返回已有标签；删除从所有素材上移除，含回收站 |
| `CreateCategory` / `EditCategory` / `DeleteCategory` | 分类 | 分类 `expected_revision` + `hierarchy_revision` | 删除后其下标签变成未分类 |

- 所有写命令走 `creativeops` 执行器、`manual_write` 能力，按 `operation_id` 幂等。重放要求请求体 hash 一致，hash 包含 `CreatedAt`。
- 删除标签和分组时，`removeRelations` 会把受影响素材的 `revision` 加一。但返回体 `LibraryResult` 里没有影响数量。
- 删除分组有 30 天内的恢复快照（`RestoreGroup`），条件是之后分组结构没再变过。删除标签和分类不能恢复。
- `SearchAssets` 有 `unclassified`（未分组）视图，**没有「未打标签」筛选**。
- 助手的 `search_assets` 拒绝 `view=trash`，所以助手现在看不到回收站。
- 素材标题必填（1–200 字），描述可以为空；`save_to_library` 现在只要求标题。
- 助手有一段基础提示词 `assistantInstruction`（`context.go`），是一行 Go 字符串常量。没有 Skill 时单独使用；有 Skill 时由 `joinInstruction` 拼成「基础提示词 + Skill 指令」。它没有文档和测试，也没有随 V6-035/077 更新：`search_assets`、`read_library`、`list_conversation_assets`、`save_to_library`、`compress_image` 都没提到，`read_history` 的说法也已过时。

## 2. 工具总则

四个写工具共用以下规则；只读的整理结果工具适用相同账号/会话许可与返回预算，不适用写前确认。

### 2.1 可用条件

- 和 `search_assets` 相同：授权为 `account_library` 且含 `media_metadata`，否则不出现在工具列表里。每次调用再检查一次（`requireLibrary(ctx, true)`），与查找工具一致。
- 没有搜索能力就拿不到素材和归类的 ID，所以写工具不单独放开。

### 2.2 何时可以写（模型约束）

基础提示词的「资产库」一节写明（§2.7）：

- 只在摄影师要求整理，或摄影师同意了助手的整理提议后调用。
- 创作过程中觉得需要整理，先在对话里问，不直接调用。
- **改写已有文字要先确认**（owner 2026-10-13）：要改写已有的标题或非空描述时，先在对话里按素材列出原值和新值，摄影师同意后再写。可以一批列出、一次确认，不必逐个问。补写空描述、加减归类不需要额外确认，已在整理指派范围内。
- **新入库要先确认**（owner 2026-10-13）：`save_to_library` 存入前，先列出标题、描述、分组、标签（标明哪些标签要新建），摄影师同意后再存。
- **删除要先告知影响**：删除前用 `read_library` 的 `delete_impact` 告知读取时的预计影响。标签、分组报素材数，分类报标签数；不可使用页面浏览数量或当前页条数替代，口径见 §3.2。执行后按回执报告实际数量。
- **禁止的操作**：没有彻底删除和清空回收站的能力，摄影师要求时如实说明并请其在资产库页操作。

服务端没有「摄影师是否同意」的可靠信号，这些都不在服务端强制。验证靠 AC-04 的真实模型记录。以后的手动模式（V6-033）在这些写工具（含 `save_to_library`）执行前插入确认，接入点与其他写工具相同：工具调度前，按工具的 `EffectClass` 判断。

### 2.3 冲突：不覆盖，不自动重试

- 素材类操作要求带上助手看到的素材 `revision`。为此 `search_assets` 的每项结果增加 `revision`，见 §3.4。
- 修订号不一致说明摄影师或别的操作改过这个素材。工具不写，结果里给出当前修订号，助手重新查找后再决定。
- 与 `edit_canvas` 不同，这里**不自动重试**。原因是重试会用助手的旧判断覆盖摄影师的新改动。
- 结构类操作带分组、分类或标签自己的 `revision`。全库 `hierarchy_revision` 由工具在执行前读取，见 §3.2。

### 2.4 幂等与重放

只查子操作回执还不够：已提交的 `Metadata` 会提升素材版本，现有 `LibraryResult` 又不保存原文。必须先持久化执行计划，再执行命令，并以回执作为提交事实。

**持久化归属**

- 在 `creativeagent` 增加专用的库整理执行记录，由 additive migration 建表。按 `(account_id, tool_step_id)` 唯一关联一个调用，包含 `run_id`、`conversation_id`、工具与协议版本、原始参数 hash、稳定 `created_at`、逐项计划、阶段状态、结果摘要及分页明细。数据库账号隔离约束、查询账号过滤、会话删除清理一并接入。
- 首次进入工具时解析、验证整批参数，在只读快照中按项读取版本、完整原值及所请求关系的差异，保存为不可变计划；原值不能等写完再补读。计划登记成功前不执行任何资产库写入。其他进程已创建同一调用时校验 hash 后复用，不能覆盖原计划。
- 每个子命令的 `operation_id = toolOperation(seed + "/" + 序号 + "/" + 阶段 + "/" + attempt)`。普通素材阶段 `attempt=0`；结构全库版本冲突的有限重试才递增 attempt。执行前持久化本次命令的完整 payload 和稳定 `CreatedAt`；中断重放相同 attempt 必须使用完全相同的请求体。
- 原计划中的前值、关系名称是读取时的快照；实际成功阶段由回执决定。返回不能把计划中未执行的变更报成已完成。

**逐项恢复顺序**

1. 先加载执行记录和已经持久化的终态。已完成调用直接返回原结果；已终结的失败项也不再尝试。
2. 对未终结阶段先通过 `creativeops.Executor.Lookup` 核对回执（检查账号、有效期和 operation 类型）。有回执则恢复提交结果，不先拿最初的 `expected_revision` 检查当前素材。
3. `Metadata` 未执行时使用原始 `expected_revision`；已执行时恢复它返回的修订号，作为尚未执行的 `Organize` 的期望修订号。没有文字改动时，归类步骤沿用原始修订号。两步都已提交时直接重建结果，不受后来的素材修改、删除影响。
4. 只有尚未提交的步骤执行版本比较。期间摄影师有新改动就报冲突；不得换成最新版本自动覆盖。文字已成功而归类冲突返回 `partial`，并同时报告已提交阶段的修订号和观察到的当前修订号。
5. 确定性的业务失败（冲突、对象不存在、校验失败等）写入本项终态；`manage_library` 同时冻结后续 `not_run`。若失败记录落库前中断，可重新核对未提交步骤，不能假设所有失败都会永远相同。数据库连接或提交结果不确定时停止后续写入，先查回执；无法查明则返回顶层 `success:false`、`effect:unknown`、`result_id` 和已知阶段，未确定阶段标为 `unknown`（非业务终态），不能当作 `none/refused`、不能盲目重试。
6. 单个命令与其回执由现有执行器在同一事务提交。执行记录可在随后事务更新；即使该更新失败，下次仍能由固定命令身份与回执补齐。并发恢复相同阶段使用相同 payload/CreatedAt，依靠执行器的操作锁和请求 hash 保证最多提交一次。

`Metadata` 的回执无需塞入完整原文：原文和拟修改关系已在写前计划中。删除的实际影响数、创建标签是否复用等只能在命令事务确定的信息，必须写进该命令的回执（§3.2、§3.4），不能用执行后查询猜测。

执行记录的详细正文保留 90 天，与操作回执窗口对齐；`retained_until` 随结果返回，过期明确返回 `result_expired`，不能伪装为空结果。它不是素材内容引用，不延长图片 GC 生命周期，也不是永久元数据版本历史。回执或计划缺失、过期、协议不兼容时禁止重做已无法证明状态的写步骤。

**已经返回 unknown 后的收口路径**

选择“停止剩余写入，查询只核对回执”的方案，不依赖运行器重新执行已登记为终态的工具步骤，也不把现有 Skill 只读重试入口扩展成隐式资产库重试。

- 专用调用状态为 `executing → settling → complete`。正常执行直接 complete；准备向运行器返回 unknown 之前，必须先把调用持久化为 settling、冻结所有尚未提交阶段的命令身份并禁止该调用再产生业务写入。如果 settling 状态无法可靠落库，则不登记普通 unknown 工具结果，按执行中断保留恢复入口；恢复时仍先查回执。
- 为阻止迟到的执行者在核对后又提交，每个 Agent 资产库写阶段（包括 save_to_library）必须有事务内的执行守卫：在现有操作锁之后、领域写入之前，锁定专用调用行，检查该调用仍为 executing、阶段身份和固定请求匹配，并持锁到命令事务结束。守卫是服务端注入的内部能力，模型/HTTP 参数不能提供或跳过；人工页面命令不受 Agent 调用状态限制。
- 全链路锁顺序为操作锁 → 整理调用行 → 既有领域锁。进入 settling 只短暂锁调用行并提交，不能持调用行等待操作锁；因此它会等已经通过守卫的事务结束，也能挡住尚未开始的旧执行者。发现已有回执时可以回放，不能重新进入领域 Apply。
- `read_library_result(result_id)` 遇到 settling 时是明确的核对入口：按已登记阶段的 operation_id，在对应操作锁内查回执；等待在途事务有界超时后仍返回 `in_progress`，允许以后再次查询，不将“暂时没查到”冒充未提交。取得锁且能确认无有效回执、调用已被禁止写入后，该阶段才记为 `not_run`。有回执则记录提交事实。
- 全部阶段核清后，查询路径把专用记录变为 complete：Metadata 已提交、Organize 未执行的素材是 partial；没有任何提交的项是 not_run；已全提交的项为 applied。所有批量工具摘要支持 not_run，并返回停止原因。原工具步骤仍保留当时 unknown 的历史输出，新查询返回核对后的确定结果，不能改写对话历史假装从未不确定。
- 核对只读业务回执并更新 Agent 的执行/结果记录，绝不执行 Metadata、Organize、Trash、Restore、结构命令或保存节点。需要补做的部分由摄影师明确要求或同意后，重新查询当前版本并发起新调用；结果读取仍归类为 read_only。
- 普通 executing 的结果查询只报告当前已知阶段，不接管活跃执行者。运行已经取消/终结且留下未完成记录时，查询先通过同一个关闭协议进入 settling 后核对，不能永久停在没有执行者的 in_progress。许可撤销时先拒绝外发结果；内部收口不得恢复资产库写权限。


### 2.5 结果大小与汇报

**通用规则**：限制一次返回量，不把剩余数据丢掉。页条数只是上限；序列化后的完整 JSON（含游标、计数、转义）也必须符合 `ToolResultBytes`。不得依赖运行器在写入后抛 `ErrLimit` 来兜底。

**只读列表**

- `search_assets`、`read_library` 按条数和字节预算取能装下的完整前缀；`total_count` 是完整筛选结果的数量，不是本页数量。
- `next_cursor` 指向实际返回的最后一条；`has_more` 来自未返回数据，不能复用被裁短前候选页的尾游标。
- 每个游标绑定账号、规范化筛选、排序、协议版本和读取时的 `library_revision`，采用服务端可验证的编码，拒绝篡改和跨账号使用。下一页在同一只读快照内核对库版本并读取；库有变化返回明确的 `cursor_stale`，指导重新查询，不能静默跳项或伪装成结束。
- 不使用深 OFFSET；按稳定键取下一页。分页耗时与页大小相关，不先加载整个库再截取。单条确实装不下时使用该工具定义的明细继续入口；若配置预算小到连必需核心字段也装不下，则返回可读的预算拒绝，不提供成功但缺字段的对象。

**批量写入**

- 写工具返回有界摘要：`result_id`、`retained_until`、全部项的 `index`、ID（新建失败时为 null）、状态、修订号/阶段状态、实际增减数量、短错误码，以及 `details_available`。完整前后文字和关系名称、ID 全部保存，摘要不假装含有全部明细。
- 增加只读工具 `read_library_result`，参数为 `result_id`、`limit`（1–50）、`cursor`。结果归属当前账号和当前会话，可在该会话后续运行读取；每次仍检查当前 `requireLibrary(ctx, true)`。不能只凭结果 ID 跨账号或跨会话读取，不复用仅允许本 run 的 `read_run_result` 去绕过范围。
- 明细按 `(item_index, detail_index)` 固定排序，记录类型为 `item_summary`、`metadata_change`、`relation_change`、`action_result`。完整文字前后值在 `metadata_change` 中，每个关系变化是一条记录；单个素材的上百项关系可以跨页。每页返回 `total_count`、`has_more`、`next_cursor`，不重新调用写命令，也不从变化后的素材重算历史。
- 完成的结果不可变；读取游标绑定结果 ID、摘要 hash 和分页位置，不因当前库变化而失效。未完成调用按 §2.4 的状态处理：executing 报当前进度，settling 触发只核对回执的收口，无法核清则明确 `in_progress`。未知阶段不得报成功或无改动；完成后从首个明细页读取。
- 首次写入前校验摘要最坏大小（含每项可能的失败状态）和计划、明细的总持久化预算。单次调用内部预算为 8 MiB，和 64 KiB 的模型返回预算分开；用本批实际前值、计划差异及合法返回字段的最坏长度预留空间。超出则在任何资产库写入前可读拒绝并建议缩小批次。每个摘要项的说明有界，完整原因放明细，不在写后通过删状态或删素材 ID 挤预算。
- 原有 `creative_agent_context_items.payload` 和 `creativeops` 单张回执也限制 64 KiB，因此完整批次不能塞进这些现有单行。完整计划及明细存专用记录，原有工具结果位置只登记短摘要；单个库命令回执保持小对象。

### 2.6 错误转译

`asRefusal` 补充以下映射：

## 3. 工具契约

### 3.1 `organize_assets`（整理素材）

逐个素材修改。每项可以同时改文字和归类，所以每个素材能打不同的标签。

**参数**

| 字段 | 说明 |
|---|---|
| `items` | 1–50 项，`asset_id` 不重复 |
| `items[].asset_id` | 必填 |
| `items[].expected_revision` | 必填，来自 `search_assets` |
| `items[].title` | 可选，1–200 字 |
| `items[].description` | 可选，0–1000 个 Unicode 码点，空串表示清空；未提供表示不改 |
| `items[].add_tag_ids` / `remove_tag_ids` | 可选，各 ≤50，已有标签 ID |
| `items[].add_group_ids` / `remove_group_ids` | 可选，各 ≤50，已有分组 ID |

改写已有文字没有参数开关，按 §2.2 先在对话里确认。

每项至少要有一个改动字段。同一项里同一个 ID 不能既加又减。

**执行**

1. 首次执行先按 §2.4 持久化整批逐项计划并通过 §2.5 的预算预检。每项记录完整原文和请求涉及的关系差异；修订号不匹配的项记为 `conflict`，不会计划写入。
2. 逐项、按请求顺序执行；业务失败互不影响。恢复时必须先恢复子命令回执，不能先比较最初修订号。
3. 文字确有变化时调 `Metadata`；它的回执修订号成为归类步骤的期望值。无变化的阶段记为 `unchanged`，不凭空增加版本。
4. 归类确有变化时调 `Organize`，`assets` 只放这一个素材；使用冻结计划的增减，不根据新的库状态擅自改变意图。
5. 用原计划及已核实的回执构建实际结果并持久化，再返回短摘要。库命令未提交的变化不能出现在实际改动里。

**结果**

`items[]` 每项包含：

- `asset_id`
- `status`：取值 `applied` / `unchanged` / `partial` / `conflict` / `trashed` / `not_found` / `refused` / `not_run`
- `revision`：本调用最后已提交步骤的修订号；无成功步骤的冲突项给观察到的当前修订号。`partial` 另给 `current_revision`，区分自身已提交结果和后续并发改动
- 摘要：文字、归类各阶段状态，实际标签/分组增减数量
- 分页明细：完整 `title_before/after`、`description_before/after`（文字发生改变时给，空原值也保留，不截断）
- 分页明细：实际 `tags_added`、`tags_removed`、`groups_added`、`groups_removed` 拆成关系变更记录（名称 + ID）
- `message`：失败原因

`partial` 的含义：文字已写入、归类没写入（第 4 步冲突或校验失败）。结果里写明哪部分生效了。两步不合成一个事务，取舍见 §7。

摘要与完整明细按 §2.5 分离；完整信息可继续读取，不能截断原描述或永久丢弃关系 ID。前述 50 素材 × 25 标签、原标题 200 字的合法请求必须成功返回有界摘要，并能取回所有明细。

### 3.2 `manage_library`（管理资产库结构）

按顺序执行 1–20 个动作。**遇到第一个失败就停止**，因为后面的动作常常依赖前面的结果；结果标出已执行、失败和未执行的动作。

**动作**

| `action` | 参数 | 对应命令 |
|---|---|---|
| `create_group` | `name`，可选 `parent_id`、`position` | `CreateGroup` |
| `rename_group` | `group_id`、`expected_revision`、`name` | `RenameGroup` |
| `move_group` | `group_id`、`expected_revision`、`parent_id`（`null` 表示移到顶层），可选 `position` | `MoveGroup` |
| `delete_group` | `group_id`、`expected_revision` | `DeleteGroup` |
| `create_category` | `name` | `CreateCategory` |
| `rename_category` | `category_id`、`expected_revision`、`name` | `EditCategory` |
| `delete_category` | `category_id`、`expected_revision` | `DeleteCategory` |
| `create_tag` | `name`，可选 `category_id` | `CreateTag`，颜色用默认灰 `#a1a1a7`（同资产库页 `NEW_TAG_COLOR`） |
| `edit_tag` | `tag_id`、`expected_revision`，可选 `name`、`category_id`（`null` 表示移出分类） | `EditTag`，没给的字段和颜色沿用当前值 |
| `delete_tag` | `tag_id`、`expected_revision` | `DeleteTag` |

- 同一调用里新建的对象不能被后面的动作引用。需要先建分类再往里建标签时分两次调用，第二次用第一次返回的 ID。这样不必引入调用内的临时键。
- `hierarchy_revision` 由工具在每个动作执行前读取当前值并填入。
  - 理由：对象自己的 `expected_revision` 已经保护了「改的是助手看到的那个对象」，同名、层级、数量这些不变量在命令事务里检查。全库修订号保护的是资产库页「整棵树的视图」，助手并不持有这个视图。
  - 仅在确认上一 attempt 未提交、对象自身修订号仍匹配、冲突确由全库版本引起时，允许重读全库版本并创建下一 attempt，最多 `conflictRetries` 次。每个 attempt 先持久化完整命令；提交状态未知先查回执。对象修订号冲突直接报告，不重试。
- `create_tag` 遇到同名标签时返回已有标签，结果标 `existing: true`。是否复用必须由创建事务写入回执，不能根据返回 revision 或事后同名查询推断；复用保持已有分类和颜色，返回实际归属。
- 同批多次修改同一已有对象不隐式刷新 `expected_revision`；若前一动作改变它，后续仍用旧版本则冲突并停止。需要连续操作时分次调用，使用上次结果的版本。

**删除的影响数**（AC-02）

`LibraryResult` 增加两个可选字段，在删除命令的事务内计数：

- `affected_asset_count`：删除标签时是带这个标签的素材数，删除分组时是这个分组的成员数，都含回收站。来自 `removeRelations` 更新素材的行数。
- `affected_tag_count`：删除分类时，变成未分类的标签数。分类删除不移除素材标签关系，不能把各标签素材数相加当作影响素材数。

`read_library` 每个结构对象增加 `delete_impact`：标签为全部关联素材数，分组为全部直接成员数（不含子组成员），两者均含回收站；分类为其下全部标签数。计数在该页的只读快照内对完整数据聚合，不受分页和搜索词影响。另保留现有浏览用 `asset_count` 时必须注明口径，禁止混用。

删除父分组还会将子组上提；预览提供 `promoted_group_count` 并说明这不会删除子组及其成员。预览明确是读取时数量，实际数量来自删除事务，发生变化时如实报告两者差异。无需冻结整库或把预览当作写入授权凭据。

页面以后也可以用实际影响字段；`LibraryResult` 同步 OpenAPI 的可选加法字段。0 是已统计为零，字段不存在是该操作不适用，不能用 `omitempty` 把这两种含义混为一谈。

**结果**

`actions[]` 每项包含：

- `index`、`action`
- `status`：取值 `applied` / `unchanged` / `conflict` / `not_found` / `refused` / `not_run`
- `id`、`revision`
- 新建时的 `existing`
- 删除时的 `affected_asset_count` 或 `affected_tag_count`
- `message`

**删除说明**

基础提示词要求删除前先用 `read_library.delete_impact` 告知对应对象的预计影响。工具说明只解释以下操作后果与字段含义：

- 删除标签和分类不能恢复。
- 删除分组后，资产库页的撤销提示看不到这次删除。

### 3.3 `trash_assets` / `restore_assets`（移入、移出回收站）

两个工具参数相同：

| 字段 | 说明 |
|---|---|
| `items` | 1–50 项，每项 `asset_id` + `expected_revision` |

- `trash_assets` 逐项调用 `Trash`，`restore_assets` 逐项调用 `Restore`，项与项相互独立。
- 结果每项包含 `index`、`asset_id`、`status` 和 `revision`，按 §2.4 恢复、§2.5 分页；两工具均拒绝重复 asset_id。
  - `trash_assets` 的状态：`applied` / `conflict` / `trashed`（已在回收站）/ `not_found` / `not_run`。结果另给出回收站保留天数，取自资产库设置，`null` 表示不自动清除。
  - `restore_assets` 的状态：`applied` / `conflict` / `not_trashed` / `not_found` / `not_run`。已被自动清除的素材是 `not_found`。
- 恢复的素材 ID 来自本对话里 `trash_assets` 的结果，或者 `search_assets(view: "trash")`，见 §3.4。
- 恢复不改变素材内容，也不扩大读取范围，摄影师指派的整理里可以直接做，不需要额外确认。

没有彻底删除、清空回收站。

### 3.4 对已交付工具的补充

#### 3.4.1 `search_assets`：完整描述与双预算分页

- 保留现有筛选，增加 `asset_id` 精确定位、`untagged: true`（与 `tag_ids` 互斥）；领域 `Search` 增加对应字段，本期不增加这两个 HTTP 查询参数。按 ID 读取也遵守账号、视图与读取许可，不绕过回收站规则。
- 每项返回 `asset_id`、`content_revision_id`、`revision`、完整标题和完整描述，取消描述 200 字截断。存量 1001–2000 字描述也完整返回，模型用这一版原值和 revision 生成覆盖确认方案。
- 每页 1–20 项，按 §2.5 用实际 JSON 字节预算选完整前缀。预算不足时先缩小本页素材数量，游标停在实际返回项之后。`total_count` 在同一快照统计全部匹配项。
- 单个素材最多 50 标签、100 分组；完整名称遇到 JSON 转义时仍可能超过一页。因此素材核心文字与归类关系分开：能装下时 `tags/groups` 完整内联并设 `relations_complete:true`；单条核心可装下而完整关系装不下时，不给残缺数组，返回 `relations_complete:false`、准确 `tag_count/group_count` 和 `relations_query`（`read_library` 的 `kind:asset_relations`、asset_id、expected_library_revision）。缺字段不等于无标签；工具说明要求需要完整关系时继续读取。
- `read_library(kind:asset_relations)` 可以读取该素材全部关系的 ID、名称、对象 revision，按 §3.4.2 分页。即使内联关系完整，也允许按此入口定向查询。
- 候选素材、关系名称与计数、返回 revision 必须来自同一只读快照；不能沿用当前“查完资产后分开查询名称”的做法声称结果一致。
- 放开 `view:trash`，每项带 `trashed:true`；其他视图为 false。仅凭回收站搜索结果不能取得新的内容读取或放上画布的权限。已有显式、画布、会话引用仍按 V6-035/077 的规则读取；指定 asset_id 放上画布仍拒绝回收站素材，已获许可的会话内容引用不因素材入回收站而被撤销。
- 整理会改变库版本，跨写入复用旧搜索游标会收到 `cursor_stale`。批处理先收集本批素材，再写；若继续查未打标签素材，可从新的首页取剩余集合，不把旧页位置套到新集合。

#### 3.4.2 `read_library`：结构筛选、稳定分页和素材关系明细

不再把整棵归类树限制为前 500 项。返回平铺对象，通过 `parent_id/category_id` 表达关系；子对象不会因为父对象没在当前页而被丢弃。

| 参数 | 契约 |
|---|---|
| `kind` | `all`（默认）、`group`、`category`、`tag`、`asset_relations` |
| `id` | 结构对象 ID 精确筛选，和 kind 共同限定；不存在返回正常空匹配 |
| `query` | 名称关键词，最多 200 字，沿用归一化规则；结果完整分页 |
| `parent_id` | 仅 group 可用，null 表示顶层；缺省表示所有层级，不递归混算 |
| `category_id` | 仅 tag 可用，null 表示未分类；缺省表示所有分类 |
| `asset_id` | 仅 asset_relations，必填，拒绝与结构筛选混用 |
| `expected_library_revision` | asset_relations 首次按搜索的 relations_query 读取时必填；其后由 cursor 绑定 |
| `limit` / `cursor` | limit 默认 50，范围 1–100；cursor 为上页返回值 |

- 结构查询按 `(kind顺序 group/category/tag, id)` 排序，关系查询按 `(关系类型 tag/group, id)` 排序。服务端按账号与筛选进行有界查询，不能先读取全部结构再丢弃尾部。
- 返回 `items`、`total_count`、`has_more`、`next_cursor`、`library_revision`。每项有 `kind/id/name/revision`、适用的 `parent_id/category_id` 和 §3.2 的删除预览。关系模式还带 asset_id 和 asset_revision，支持回收站素材的元数据关系查询，不返回内容字节。
- 数量和当前页数据在同一快照取得。总数不是当前页长度，分类下标签总数不是本页内的标签条数，浏览数量与删除影响分字段表达。
- 空参数仍可读取第一页，只是返回结构改为平铺分页；工具说明与版本一并升级。未知或不适用字段组合明确拒绝，不能静默忽略筛选。
- 若库版本改变，返回 `cursor_stale` / `revision_conflict` 并指导重新读取，不能把变化前后的页面拼成完整快照。没有变化时遍历各页必须每个匹配对象恰好出现一次，包括第 501 项和父对象不在当前页的标签。

#### 3.4.3 全入口描述上限与 `save_to_library`

- 资产库描述在新建、入库和提交更新时统一最多 1000 个 Unicode 码点（Go rune，与 UTF-8 字节数、浏览器 UTF-16 length 区分）。`Metadata` 仍允许空描述；Agent `save_to_library` 要求 1–1000 字，纯空白拒绝。
- 后端统一由资产库领域的长度常量与校验维护，涵盖直接创建、`Metadata`、`ImportTarget`、媒体导入及画布保存的资产库入口。前端输入提示和提交校验一致，不只修改 Agent schema；本规则不更改画布节点 intent、媒体内容 caption 等其他字段。
- 前端保留原始输入并报错，不静默截断；码点计数不能只依赖 HTML `maxLength`。已有 1001–2000 字描述不迁移、不截断，读取契约仍允许这些值。未修改描述时不提交该字段，修改标题、收藏、归类或从回收站恢复不受旧描述长度影响；明确提交 description 时按 1000 字写入规则验证。
- OpenAPI 的描述写入字段改为 1000，素材读取 DTO 保留旧数据兼容范围，不能把共享响应定义一起改成不接受长描述。生成 Go/TS 类型，补新旧字段路径的契约测试。
- `save_to_library` 接受 `new_tags`：≤10 个，每个 `{name, category_id?}`，新建颜色用默认灰，`client_tag_key` 按调用内序号稳定生成。同名标签复用原分类和颜色。
- 创建/复用结果必须在入库事务内保存到回执：`tags_created` 只包含真正新建的标签；另给 `tags_reused` 及实际分类。现有 `TagMapping` 只能说明 client key 对应哪个 ID，不能直接冒充“新建列表”，需要补充创建事实字段并同步 DTO。
- 相同内容修订已在库中时保留现有“复用、仅追加归类”语义，不偷偷覆盖已有标题描述。返回 `reused:true`、实际素材 revision 和实际标题描述，明确本次拟定文字没有覆盖；要改已有文字，使用独立确认后的 `organize_assets`。
- 该工具同样先保存稳定调用计划，再执行并核对回执；首次解析绑定节点的具体内容修订和 data revision，重放不得重新绑定节点后来的内容。必要的实际标题描述、标签创建事实随命令回执原子持久化，避免写完再读造成错误汇报。若入库结果明细超过摘要预算，也按 §2.5 读取。

`read_asset` 的内容读取和许可逻辑不改。基础提示词要求看图整理按不超过 8 张的小批推进；若需要覆盖确认，先展示方案等摄影师确认，不能用“每 8 张写一次”绕过确认。

## 4. 典型流程

**摄影师说「把未打标签的图整理一下，先做 20 张」**

1. `read_library` 按类型、名称筛选已有分类和标签，需要时继续分页，不能把第一页当作全部。
2. `search_assets(untagged: true, kind: image, limit: 20)`。
3. 逐张 `read_asset`，每看 8 张左右调一次 `organize_assets` 写入：补空描述、打标签、归入分组。
4. 缺合适的标签时，先 `manage_library(create_tag…)`，用返回的 ID 再整理。
5. 如果觉得某些已有标题或描述也该改（比如标题只是文件名），先列出「原值 → 新值」，等摄影师同意后再写。
6. 根据结果摘要列出完成、部分完成和冲突的项；需要完整前后值或标签明细时用 `read_library_result` 分页读取，不重复写工具。

**创作中**

助手在 `search_assets` 时发现素材缺标签、难以检索，就在回答里提议整理，不调用写工具。摄影师同意后，下一轮再按上面的流程做。

**把生成结果存入资产库**

助手先列出拟定的标题、描述、分组和标签（标明要新建的标签），摄影师同意或修改后，再调 `save_to_library`。

**撤回误删**

摄影师说「刚才那几张别删」，助手用本对话 `trash_assets` 结果里的 ID 调 `restore_assets`；找不到 ID 时用 `search_assets(view: "trash")` 查。

## 7. 取舍与风险

- **一次读一张图（有界简化）**
  - 不做拼图缩略图，直接复用 `read_asset`。
  - 上限：建议摄影师每次指派不超过 20–30 张。
  - 触发条件：如果 AC-06 的真实记录显示每 20 张超过 10 分钟，或单次运行接近 30 分钟时长上限，再加一次读多张缩略图的读取方式。
- **`organize_assets` 每项两步不合一个事务**
  - 复用现有 `Metadata` 和 `Organize`，不新增资产库命令。
  - 代价：可能出现 `partial`，例如文字写入了、标签没写入。结果会如实标出，重试时只需补归类。
  - 如果真实使用中 `partial` 频繁出现，再加一个合并命令。
- **助手的删除没有撤销入口**
  - 删除分组的恢复快照存在，但资产库页的撤销提示只认页面自己发起的删除。删除标签和分类本来就不能恢复。
  - 现在是自动模式，靠基础提示词要求先告知影响数。确认交互随 V6-033 补上。
- **改写已有文字没有版本历史**
  - 不建设永久元数据版本历史；确认对话展示完整原文，专用整理结果在 90 天窗口内保留完整前后值，可分页读取。过期后明确提示不可读，不宣称永久可恢复。
  - 改写前要确认（§2.2）就是为了这一点。如果以后发现模型不按说明确认，再考虑加服务端约束或元数据历史。
- **「先问再整理」「改写前确认」「存入前确认」都不在服务端强制**：见 §2.2。手动模式（V6-033）上线后由确认交互兜底。
- **描述与工具读取契约变化**：save_to_library 的必填描述影响模型调用；全入口 1000 字上限也影响前端和 HTTP 写入，响应仍兼容旧长描述。工具版本、API 和前端必须同步；旧运行按 checkpoint 兼容规则处理。
- **一致分页不保留无限期数据库快照**：游标绑定库版本，库改变就明确失效并重查；完整性保证适用于同版本遍历，不能把并发更新下的不同页假装成同一全集。
- **恢复记录是新增持久化成本**：单调用有预算，正文 90 天到期清理；用途仅限恢复与核对，不扩展为通用工作流引擎。

# 经 AiCodeWith 接入 GPT Image 生图：文生图、图生图与参数面板

## 0. 结论

- **接入三个模型**：`gpt-image-2`、`gpt-image-2.5-sunburst`、`gpt-image-2.5-flare`。三者参数相同，都支持文生图和图生图（带参考图就是图生图），所以每个模型只注册一个模式 `image`，参考图是可选输入。
- **生成底座已经齐了，不重造**：网关的生成契约、规则与计价引擎（`generation_policy`）、任务生命周期、结果取件、写入画布版本都已实现并有测试，只是生产环境没接线（`NewProduct(nil, nil)`）、也没有真实适配器。本次补三样东西：AiCodeWith 适配器、三份规则配置、生产接线；前端补专用参数面板。
- **参考图用 data URL 内联发送**，不给中转签名链接。实测 9 张、共 19 MB 的请求能正常受理。这样对象存储保持私有，发出去的字节就是做过摘要核验的那份。
- **计价按 token**：中转按文字输入、图像输入、图像输出三类 token 计费，每次任务都会回报实际用量和金额。预留按「数量 × 单张输出上界 + 参考图张数 × 单张输入上界」计算，结算按实际用量。参考图很贵：9 张 1536 px 参考图的输入费用是出图费用的 18 倍，所以必须进入报价。
- **生成任务不提供取消**（owner 2026-10-09）。中转的取消接口本来就不生效，任务一旦受理必然跑完扣费；给摄影师一个「停止」按钮只会制造「停了还收钱」的误会。
- **只有没出图才退**（owner 2026-10-09）：因出错或审核违规而一张都没生成时，摄影师不付费，供应商成本由平台承担；其余情况按实际落下的张数收费。网关账本照实记录供应商成本，两者分开。

本期不做：报价与点数展示（V6-022）、`gpt-image-2-beta`（参数固定、只能出 1 张，与正式出图定位不符）、局部重绘与蒙版（中转文档没有提供）、多供应商切换（生图链路沿用自己的部署注册，等第二家供应商出现再说）。

## 1. 实测结论（2026-10-09，花费约 1.8 元）

文档来源：控制台 `dashboard/text-to-image/api` 页面（需要登录，正文在页面的服务端渲染数据里），以及官方生图页的前端代码。文档只列了 `gpt-image-2-beta` 和 `gpt-image-2`；`/v1/models` 里还有两个 2.5 模型，下表全部以实测为准。

| 项目 | 结论 |
|---|---|
| 协议 | 异步任务。`POST /v1/images/generations` 返回 `{id, status:"processing", usage.credits_reserved}`；`GET /v1/tasks/{id}` 轮询，返回 `status`（processing / completed / failed）、`progress`（0–100）、`results`（图片 URL 数组）和 `usage` |
| 耗时 | 1K 低画质约 20 秒；4K 高画质约 67 秒；9 张参考图约 140 秒。创建时返回的 `estimated_time` 为 300–600 秒 |
| `size` | `auto`，或 15 种比例：1:1、1:2、2:1、1:3、3:1、2:3、3:2、3:4、4:3、4:5、5:4、9:16、16:9、21:9、9:21。也可以直接写像素 `WxH`（边长能被 16 整除，0.64–8.29 MP，最长边 3840，比例不超过 3:1）。非法值创建时直接返回 400，错误信息里列出全部合法值 |
| `resolution` | 1K / 2K / 4K，只在 `size` 是比例时生效。实测：1:1 1K 输出 1024×1024；2:3 2K 输出 1680×2512；16:9 4K 输出 3840×2160；2:3 4K 输出 2352×3520 |
| `quality` | low / medium / high |
| `n` | 1–10，生效（`n=2` 返回 2 张）。11 返回 400 |
| `background` | 文档没写，但会透传：传 `transparent` 输出 RGBA、背景 alpha 为 0；不传则输出 RGB |
| 参考图 `image_urls` | 最多 16 张，第 17 张同步返回 400。接受 data URL，参考图确实起作用（蓝色色块作参考，生成的杯子是同一种蓝）。官方页面只收 jpeg / png / webp、单张 10 MB |
| 输出 | PNG。地址形如 `https://api.aicodewith.com/files/<账号>/images/<日期>/file_<uuid>.png`，**无需鉴权**，直接 200、不重定向，缓存 3 天。4K 单张 10–13 MB |
| 计费 | `usage` 给出 `text_input_tokens`、`image_input_tokens`、`image_output_tokens`（含缓存部分）和 `cost{usd, cny}`。按实测反推：图像输出约 $27 / 百万 token，图像输入约 $7.3 / 百万 token；三个模型费率相同 |
| 单张参考价 | 1K 低画质 ¥0.037（输出 196 token）；4K 低画质 16:9 ¥0.069（371 token）；4K 高画质 2:3 ¥0.726（3948 token）；9 张 1536 px 参考图 + 1K 低画质 ¥0.707（参考图占 13689 token） |
| 同步错误 | 400 参数错误、401 key 无效、402 余额不足、503 无可用渠道，都在创建时返回，此时没有任务 ID。任务失败时，`error.code` 取值有 content_policy_violation、image_processing_error、generation_timeout、resource_exhausted 等 |
| 取消 | 没有可用的取消接口：`POST /v1/tasks/{id}/cancel` 返回 404；`DELETE /v1/tasks/{id}` 返回 200，但任务照常跑完并扣费 |
| 幂等 | 不支持客户端提交的请求 ID，也查不到「我提交过哪些任务」。创建请求超时，就无法得知任务是否已经受理 |

官方前端会把「Please generate N distinct images」「Please render this image at 4K resolution」拼进提示词。我们实测不拼也能得到正确的张数和分辨率，所以不照搬。

## 3. 方案

### 3.1 模型与模式

| model_key | 显示名 | 中转模型名 |
|---|---|---|
| `gpt-image-2` | GPT Image 2 | `gpt-image-2` |
| `gpt-image-2.5-sunburst` | GPT Image 2.5 Sunburst | `gpt-image-2.5-sunburst` |
| `gpt-image-2.5-flare` | GPT Image 2.5 Flare | `gpt-image-2.5-flare` |

每个模型一个模式 `image`：

- Prompt 必填。
- 参考图角色为 `reference`，0–9 张，只收 jpeg / png / webp。
- 输出：PNG，数量 1 到 `count`，单张字节上限 40 MB。
- 部署 ID 为 `aicodewith/images/<model>`，限流键 `aicodewith/images` 三个模型共享，并发 4。中转建议 3–5 秒轮询一次；我们沿用运行时的持久调度，间隔 15 秒。

**结果张数下限取 1，不取 `count`**。中转少给一张也照样收费；如果把它判成协议错误，摄影师就得不到已经付过钱的那几张。实际得到几张，就落几张，并在执行记录里标注「请求 4 张，得到 3 张」。

### 3.2 参数

| 参数 key | 取值 | 默认 | 发给中转 |
|---|---|---|---|
| `aspect_ratio` | `auto` + 15 种比例 | `1:1` | `size` |
| `resolution` | `1K` / `2K` / `4K` | `2K` | `resolution`；比例为 `auto` 时不发 |
| `quality` | `low` / `medium` / `high` | `medium` | `quality` |
| `count` | 1 / 2 / 4 | 1 | `n` |
| `background` | `auto` / `opaque` / `transparent` | `auto` | `background`；`auto` 时不发 |

- 参数由模式 schema 校验，适配器只做字段映射，不透传任意字段。
- `auto` 比例下清晰度不生效：界面把清晰度置灰，适配器不发 `resolution`。规则里不加约束，因为默认值总会补上清晰度，加约束反而会拒绝 `auto`。
- `opaque` 还没有实测，实现第一步补测。中转如果不认，就去掉这一档。

### 3.3 适配器

`Submit`：

1. 通过读取端口按 revision 和 digest 取出每张参考图的字节，再次核对摘要，然后编码成 data URL。
2. `POST /v1/images/generations`，带固定的 User-Agent（Cloudflare 会拦截部分默认 UA）。
3. 返回 200 且带 `id` → `accepted`，`TaskID` 就是中转的任务 ID。
4. 返回 400 / 401 / 402 / 503 → 中转明确没有受理，没有任务 ID → `rejected`，预留全额释放。其中 401 / 402 / 503 不是摄影师的错，界面显示「服务暂时不可用」。
5. 超时、5xx、断开 → 按运行时约定返回错误，即「受理未知」。预留保留，不重新提交。中转没有可查询的提交记录，所以不实现 `LookupSubmission`。这类请求停在待核实，由运维到中转后台对账。

`Observe`：

- `GET /v1/tasks/{id}`。processing → `running`，`progress` 除以 100。
- completed → `completed`。每个结果 URL 生成一个输出：输出 ID 取文件名里的 uuid，在同一请求内稳定，符合「不能用会轮换的签名 URL 作身份」的约束；取件 URL 只进入受保护数据。
- failed → `failed`，`error.code` 原样作为错误码（经过 token 校验）。
- 404 → `unknown`。
- `usage` 归一化成 `text_input_tokens`、`image_input_tokens`、`image_output_tokens` 三个维度；中转报的 `cost.usd` 和 `cost.cny` 作为对账证据记录，不参与结算。

`Cancel`：接口要求必须实现，但不调用远端，直接做一次 `Observe` 返回当前状态，不声称已经取消。画布层不再为生成类执行提供取消（§3.8），只有运行时在部署被停用等内部场景才会走到这里。

**参考图读取端口**：在网关层定义 `GenerationReferenceOpener`，按 `GenerationReference` 打开字节流，由组合根用 `creativemedia` 的现有读取实现注入。授权与摘要核验沿用 `creativemedia` 现有的读取路径，适配器不直连对象存储。

### 3.4 参考图外发

- 只发送摄影师在节点上明确选中的参考图，最多 9 张。中转允许 16 张，9 是产品上限（D4），写在规则里，以后可以调整。
- 单张不超过 10 MB，与中转官方页面一致。
- 本期不在服务端缩放参考图：缩放会产生新的内容修订，还要重新报价，复杂度不值得。代价是参考图越大，输入 token 越多，费用越高；报价会如实反映（§3.5）。
- 不做逐次外发授权（D10），也不设按素材的单独生成授权：素材可展示且权利矩阵允许其来源用于生成即可作参考（摄影师自有素材通过，授权素材拒绝）。原先的 `generation_reference` 单独授权在生产里没有任何授予入口，等于所有参考都被拒，已删除。守卫仍在最终派发事务里复核。
- **隐私说明要补一条**：中转生成的图片在其文件服务上公开可访问，至少保留 3 天（取件后我们无法删除）。这条写进隐私说明的服务商条目。

### 3.5 计价与预留

用量维度和单价（单位：USD 微单位 / token），三个模型共用：

| 维度 | 单价 | 单个任务的上界 |
|---|---|---|
| `text_input_tokens` | 5 / token（OpenAI 公开价，单独测不准） | 48000（提示词限 16000 字符，每字符按 3 token 计） |
| `image_input_tokens` | 7.3 / token | 18000（9 张 × 2000） |
| `image_output_tokens` | 27.2 / token | 64000（4 张 × 16000） |

- **上界是每个模式一个常量**，不随参数变化：引擎按「最高单价 × 部署声明的硬上限」算预留，单次预留约 $2.11，结算后退回差额。
- **输出 token 和像素数不成正比，没法按「画质 × 清晰度」查表**。4K 高画质实测：2:3 为 3948，1:1 为 5930，21:9 为 8196，3:1 只有 1328；自动比例的中转预留折合约 14300。所以单张上界统一取 16000。
- **参考图无论多大都约 1521 token**（1536 px 和 4096 px 实测相同），单张上界取 2000。
- 实际用量超过上界时，按引擎约定进入费用争议，并阻断该部署的新准入；不会按零记账。
- 引擎只能用单一事实作估算量，所以报价里的「估算」对本模式没有意义；摄影师看到的价格由 V6-022 的单张定价给出（§3.9）。
- 结算按实际用量乘单价。中转报的金额只作对账证据：实测几次结算与中转金额一致到 0.1 美分以内。
- 账本按 USD 记，与对话模型一致。单价来源见 D6。

### 3.6 生产接线

- **cmd/server**：用三份注册（模型投影 + `PrepareInTx`）替换 `NewProduct(nil, nil)`；`AICODEWITH_API_KEY` 缺失时目录给出 `disabled_reason`，与对话模型的做法一致。
- **cmd/creative-worker**：注册生成任务处理器，挂上恢复扫描 `SweepDue`。
- **规则发布**：规则配置像对话目录一样内置在 Go 代码里，带版本号，改价格或上界必须升级版本号。部署控制面（`llm_generation_deployments`）是按账号记录的，所以每次生成前，在受理事务之外用一个短事务为当前账号登记部署（`EnsureDeploymentInTx`）：没有记录就启用，规则变化或有效期将尽就续期，被人工停用的保持停用。受理事务里只读修订号，不反转网关的锁序。
- **新增环境变量** `CREATIVE_GENERATION_PROTECTION_KEY`（32 字节，base64）：用于加密保存任务 ID 和取件 URL；`.env.example` 补占位。缺失时生成能力整体不可用，不影响对话。
- **取件白名单**：只有 `api.aicodewith.com`。
- **结果字节数**：中转的结果文件既不返回 Content-Length，也不支持 Range，提前拿不到字节数。`GeneratedMedia` 增加 `size_is_limit`，表示 `byte_size` 只是取件上限（25 MB），导入时按实际字节记录。
- **取件器不检查解析地址**（owner 2026-10-09）：只允许写死的 `api.aicodewith.com`、只走 HTTPS 并校验证书、不跟随重定向，这三条已足够；原先对解析结果的公网地址检查已删除（它还会让开 fake-ip 代理的本机无法取件）。若将来要抓取任意链接（如 V6-009），需要另行加回。

### 3.7 前端参数面板

按截图做，替换节点输入框底栏里通用的「参数弹层」：

- **底栏 chip**：显示比例图标和「2:3 · 标准画质 · 2K · 1张」，点开弹出面板。
- **面板分节**：画质（低 / 标准 / 高）、清晰度（1K / 2K / 4K）、背景（自动 / 不透明 / 透明）、比例（带画幅示意的网格，`auto` 放在第一格）、生成数量（1 / 2 / 4 张）。模型不支持的分节不显示。
- **已知参数用专用控件**，按 key 识别；未知参数仍然回落到通用控件，以后接其他模型时不会丢参数。
- **空节点联动**：改比例时保持当前宽度、重算高度（V6-021 AC-03，复用 `fitMediaHeight`）；`auto` 不改尺寸。
- **契约改动**：`CreativeGenerationParameter` 增加 `default` 字段，这是唯一的契约改动。选项文案（如 `medium` 显示为「标准画质」）由前端按 key 映射，不进契约。改完运行 `make generate`。

### 3.8 状态与异常（V6-023 AC-03）

| 情况 | 摄影师看到 | 费用 |
|---|---|---|
| 生成中 | 进度百分比（来自中转） | 预留中 |
| 完成 | 结果落为新版本；主版本规则沿用现有实现 | 按实际用量结算；摄影师按张数付费 |
| 部分完成 | 落下已有的几张，提示少了几张 | 按实际用量结算；摄影师按实际落下的张数付费 |
| 中转判定失败（例如内容违规） | 按错误码给出中文原因 | 摄影师不付费；网关按中转回报的用量记供应商成本，没有用量时等待核实，不默认记为零 |
| 创建时被拒（400 / 401 / 402 / 503） | 立即失败 | 全额释放 |
| 受理未知（创建超时等） | 「结果待核实」 | 保留预留，人工核实；核实后没有出图，摄影师不付费 |
| 摄影师想中途停止 | 不提供。生成中只显示进度，`cancel_execution` 对生成类执行返回状态错误 | — |
| 重复提交 | 同一幂等键返回同一次执行 | 不重复派发 |

### 3.9 摄影师应付与供应商成本分开

仓库里还没有摄影师侧的点数账本（V6-022）。本期把计费依据落在执行记录上，V6-022 直接读取，不再推断：

- 计费张数就是这次执行写入的作品版本数（`creative_node_versions.execution_id_snapshot` 指向该执行的行数），不另加列。没有出图（失败、违规、核实为无产出）时为 0。
- 应付 = 单张点数 × 计费张数，单价由 V6-022 定。本期不扣点，也不显示价格。
- 网关的 `llm_usage_measurements` 继续记录供应商的真实成本。两者的差额就是平台承担的部分，可以直接对账。

### 3.10 创作助手：画布增删查改 + 单纯的生成

助手和摄影师用同一套动作：先编辑节点，再点生成。工具各做一件事（owner 2026-10-09 拍板，取代最初把建节点塞进生图工具的做法）：

| 工具 | 作用 |
|---|---|
| `read_canvas` | 按页读节点的类型、标题、位置尺寸、内容修订 ID、文字正文开头、生成设置（提示词、模型、参数、`draft_revision`）、版本数和生成状态，以及连线 |
| `read_asset` | 读节点内容、看图（已有） |
| `edit_canvas` | 一次提交多个动作，全部成功或全部不生效：新建、改标题、移动、缩放、改写文字正文、连接或断开参考、删除。新节点用调用内的临时名互相引用 |
| `set_node_prompt` | 写提示词、模型和参数，不生成；工具说明里列出每个模型的参数取值和默认值；返回 `draft_revision` |
| `generate_node` | 只生成：按节点上的设置提交，等待最长 150 秒（不超过运行剩余时间），返回新版本的内容修订 ID；`draft_revision` 与节点当前不一致时拒绝，避免花钱生成了别人改过的版本 |

- **生成不参考本节点**（owner 2026-10-09 确认保持）：生成只用连入的上游节点和草稿附件作参考，不用节点自己当前的内容；要基于已有图片修改，新建节点并把原节点连为参考。这条写进了 `set_node_prompt`、`generate_node` 的说明和系统提示，避免助手在上传的原图节点上直接生成。
- **人工放入的媒体也是版本**：上传（暂存放入、直接传到节点、采用候选）和从资产库放入的图片、视频、音频都登记为节点版本（来源分别为 upload、asset），之后在节点上生成不会让原图从版本列表消失。设计本就要求「人工来源登记版本」（migration-release.md），此前未实现。文字正文随手编辑、频繁保存，不按版本登记。
- 写操作走与手动编辑相同的画布命令，进入画布历史，摄影师可以撤销。这期不做确认（删除也不确认），后续做助手权限模式（手动批准 / 自动执行）时统一接入。
- 幂等：每次调用的操作 ID、新节点 ID、执行 ID 都由运行步骤 ID 派生。已提交的调用重放时按回执跳过；读写之间画布被别人改动时，按最新画布重建命令重试。
- 业务拒绝以文字返回给模型转述，不让整次运行失败。
- 生成未启用（缺凭证）时只提供读和 `edit_canvas`。
- 运行限制（creative-agent-6）：去掉工具调用总数和模型轮数限制，调用多少次由模型决定；单轮并发 64 只是存储分页；运行时长 30 分钟；花费由账号月度预算约束。

### 3.11 已知缺陷（后续优化）

- **参数只靠说明文字约束**（owner 2026-10-09 记录）：`set_node_prompt` 的 `parameters` 在工具定义里只是一个对象，模型和参数取值写在说明文字里，靠服务端 `DraftParameters` 校验兜底。模型多了、参数各不相同（如接入视频）时说明会变长、易混淆。届时改为按模型生成严格的参数定义，或拆出只读的 `list_generation_models` 按需查询。

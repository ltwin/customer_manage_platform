# V6-007 节点工具条、右键菜单与派生 · design

需求：[V6-007](../../requirements/creative-workspace-v6/items/V6-007.md)，PRD CV-70/71/72/74、CV-80–83。本条只改前端，工具条和菜单的文案与顺序以 PRD 为准，PRD 没写的部分参照原型 `composer.mjs barHTML` 和 `canvas.mjs nodeMenu`。

## 1. 工具条差异（CV-70，基线 19d782c）

| 选区 | PRD | 现状 | 改动 |
|---|---|---|---|
| 多选 | 「已选 N 项」/ 打组 / 解组（含组时）/ 合并为参考生成（≥2 个非组）/ 复制 / 删除 | 「N 个节点」/ 合并为参考生成 / 打组 / 复制 / 删除；含组时没有解组 | 文案改为「已选 N 项」；按 PRD 顺序排列；选区含组时加「解组」，解开所有被选中的组 |
| 单个组 | 重命名 / 解组 / 复制整组 / 更多 | 解组 / 复制 / 删除 | 加「重命名」；复制按钮的名称改为「复制整组」；删除按钮换成「更多」，删除改到更多菜单里 |
| 文本 | 编辑 / 生成图片 / 更多 | 编辑 / 生成图片（只在有正文时）/ 复制 / 删除 | 加「更多」，复制和删除放进更多菜单；「生成图片」仍要求正文不为空，空文本当参考没有意义 |
| 空媒体 | 上传 / 更多 | 上传图标 / 复制 / 删除 | 「上传」改为带文字的按钮；加「更多」 |
| 有内容的图片 | 派生入口 / 全屏 / 存入资产库 / 下载 / 更多 | 生成视频 / 放大预览 / 下载 / 替换 / 存入资产库 / 复制 / 删除 | 顺序改为生成视频 / 全屏 / 存入资产库 / 下载 / 更多；替换、复制、删除放进更多菜单。重绘、扩图、高清按 CV-73 不加 |
| 有内容的视频 | 全屏 / 存入资产库 / 下载 / 更多 | 同上，没有派生 | 与图片相同，但没有派生入口 |
| 音频、链接 | §3.13，由 V6-009/010 负责 | — | 本条只给它们加「更多」，其他按钮维持现状，由 V6-009/010 补齐 |
| 文档 | PRD 没写 | 最大化 / 复制 / 删除 | 加「更多」，其他不变 |

「更多」（CV-74）在按钮下方打开该选区的右键菜单，菜单内容与在节点上右键完全相同，用同一个 `contextItems`。

## 2. 右键菜单差异

| 场景 | PRD | 现状 | 改动 |
|---|---|---|---|
| 单个节点（CV-80） | 重命名 / 编辑文字（仅文本）/ 全屏查看、下载（仅有内容时）/ 复制 / 存入资产库… / 删除 | 编辑节点 / 重命名 / 替换或上传 / 放大预览 / 下载媒体 / 从资产库添加参考 / 存入个人资产库 / 复制节点 / 移除节点 / 撤销 / 重做 | 按 PRD 排顺序和改文案：「编辑节点」改为「编辑文字」，只对文本显示；「放大预览」改为「全屏查看」；「下载媒体」改为「下载」；「存入个人资产库」改为「存入资产库…」；「复制节点」改为「复制」；「移除节点」改为「删除」。上传/替换、从资产库添加参考保留在复制之前，因为工具条已经去掉了替换，菜单是唯一入口。节点菜单里去掉撤销/重做，它们只属于空白处的菜单（CV-83） |
| 多选（CV-81） | 打组 / 解组（含组时）/ 复制 / 存入资产库… / 删除 | 打组 / 复制选中节点 / 移除选中节点 / 撤销 / 重做 | 加「解组」（含组时）和「存入资产库…」（批量入库，复用 `saveNodes`，弹出分组选择）；文案改为「复制」「删除」；去掉撤销/重做 |
| 组标题（CV-82） | 重命名分组 / 解组 / 复制整组 / 适应到分组 / 删除分组及内容 | 重命名分组 / 解组 / 复制节点 / 移除分组及其中节点 / 撤销 / 重做 | 加「适应到分组」（复用 `fitCanvas` 的避让规则，只包住这个组）；文案改为「复制整组」「删除分组及内容」；去掉撤销/重做 |
| 空白（CV-83） | 添加节点 / 上传文件 / 撤销、重做 / 全选 / 适应画布 | 添加菜单项 / 适应全部节点 / 撤销 / 重做 | 加「全选」；「适应全部节点」改为「适应画布」；顺序改为添加 / 上传 / 资产库 / 撤销 / 重做 / 全选 / 适应画布。撤销和重做在不可用时已经置灰，本条补验收 |
| 连线 | 不在 CV-83 中 | 删除连线 | 不变 |

未选中的节点在右键时先变成单选，这一点现在已经做到（`onNodeContextMenu`），本条补验收。

工具条上「复制节点」和「移除节点」按钮的 aria-label 会随新文案改为「复制」「删除」。依赖旧名称的 e2e 同步修改。

## 3. 派生（CV-71/72）

现在的 `derive` 已经做到：新建 1:1 节点，放在所有来源右侧 120 处，垂直方向取来源中心的平均值，每个来源都连线，并选中新节点。本条补三点：

1. **预填提示词**：派生时同时在本机草稿 `prompt:${canvasID}:${newID}` 里写入 `text`：
   - 文本「生成图片」：`@[src] `
   - 图片「生成视频」：`@[src] 镜头缓慢推进，`
   - 多选「合并为参考生成」：依次 `@[a] @[b] …`

   草稿结构与 `NodeGenerationPanel.edit` 写入的结构相同，`model_key` 为空，进入面板后由模型选择逻辑补上默认模型。连线和节点在同一个 intent 里，面板打开时引用就已经是「已连接」状态，`@` 显示为 chip。
2. **聚焦**：派生后调用 V6-006 的 `onCreated(id, kind)`，焦点交给生成输入框。
3. **一步撤销**：节点和连线本来就在同一个 `act` 里。预填草稿只是本机输入，不进撤销栈。撤销后节点消失，残留的草稿没有对应节点，不会显示。本条补验收。

派生不会自动开始生成。

## 4. 撤销/重做与范围（AC-04）

- 工具条和菜单在 `canUndo` / `canRedo` 为 false 时置灰，现在已经如此，补验收。
- 删除和复制都用 `selectionRoots` 加 `group_mode: 'subtree'`，选中组的同时又选中组内节点时不重复计算，现在已经如此，补验收。

## 5. 验证计划

- mock e2e `creative-node-toolbar.e2e.mjs`：
  - AC-01、AC-02、AC-05：三种派生都检查位置、连线、预填文本、焦点、不自动生成，以及一步撤销。
  - AC-03：五种选区的工具条按钮名称和顺序；多选含组时可以解组和批量入库；组可以适应到分组；「更多」打开的菜单与右键菜单一致。
  - AC-04：撤销/重做置灰；同时选中组和组内节点时，复制和删除按子树规则处理。
- 跑全部纯 mock e2e，更新依赖旧文案的断言。

# 积分计费：运维成本账与用户积分账分层

> 创意空间 | 2026-10-14 创建 | 状态：方向已拍板，落地走计费独立分支（承接 `.codestable/issues/2026-10-10-creative-billing-budget/`）

## 出发点

现在只有一套账：`llmgateway` 的预算账。它同时承担两件事：

- **运维成本账**：每次调用花了供应商多少美元。证据分等级，允许长期 `unknown`，后到的账单能覆盖估算。
- **用户额度**：每个账号一个月度美元上限（`llm_budgets.limit_micros`），准入时按供应商价格的最坏上界预扣，不够就拒绝。

两件事共用一个数字，成本侧的不确定性直接漏到了摄影师面前：

- 2026-10-10：钱包有余额却生不了图（每次生图固定按最坏上界预留约 $2.1，两次对话各冻结约 $9），见计费 issue。
- 2026-10-14：调用失联后每笔永久冻结约 $7.2，运行一直显示「已发生的费用仍在核实」。网关侧已用估算结清止血（`1d8542b`），但「核实中」本就不该是摄影师要关心的事。

摄影师不该看到供应商美元价格、价格上界和核实状态。他们需要的是：一个积分余额，每次操作花多少积分事先知道，失败了积分退回。

## Owner 已拍板（2026-10-14）

1. **积分与人民币的比例、毛利目标**暂不定，先参考 TapNow 的定价。
2. **订阅和充值都要**：
   - 订阅可选月付、季付、年付，积分**每月刷新**；
   - 充值是直接购买积分。
3. **Agent 对话怎么计费**：参考 buzzy、TapNow、LibTV 的做法后再定（调研见下文，建议见「设计方向」）。
4. **只要生成成功就不算失败**。不能因为摄影师没采用结果就退积分。

第二轮拍板（同日，回应下文「待拍板」）：

5. **定价**：以约 ¥0.07/积分为起点，档位、积分数和年付折扣按 TapNow 的结构走（具体数字见「设计方向 3」）。
6. **充值**：没有订阅也能充值。以后可以把部分高级功能设为订阅专享。
7. **免费额度**：只有注册赠送。admin 系统完成后，管理员可以手动发放积分。
8. **Agent 对话**：采用「按实际用量后扣」。
9. **订阅变更与退款**：
   - **升级**：立即生效，正常增加积分。
   - **降级**：下个周期才生效。否则本月如果已经用掉超过新档位包含的积分，账就没法算。
   - **退款**：只在同时满足以下三点时受理：一个积分都没消耗；在订阅付费后 24 小时内；摄影师通过邮箱联系客服，由人工操作。

- **积分价值**：1 积分 ≈ $0.01 ≈ ¥0.07。档位越高，每美元换到的积分越多（95 → 116），订阅和充值用同一个汇率。

- **退订**：可随时取消，取消后当期仍可使用。
- **用量上限**：FAQ 说达到上限后基础功能仍可用，高级功能限制到下个账期。
- **积分有效期、失败退款**：页面上没有写明。

### LibTV（liblib.tv 首页源码中的界面文案，2026-10-14）

**积分分池，可设置消耗顺序**

| 积分池 | 来源 | 有效期 |
|---|---|---|
| 会员积分 | 订阅发放 | 每 31 天重置 |
| 每日免费积分 | 每日登录赠送 | 当日有效 |
| 通用积分 | 充值购买 | 2 年（「积分一经使用，退款可能受限」） |
| LibTV 专属积分、模型卡积分 | 活动、模型卡 | 只能在特定范围使用 |

另外，**充值需要先是会员**（「升级会员可购买」）。

**生成：先预估，再扣费**

- 提交前提示「预计消耗 N 积分，是否继续？」，并注明「积分为预估消耗，最终会按实际执行消耗扣除」。
- 批量生成会先汇总预估。
- 如果实际消耗超出预估，会再次提醒。

**退还规则**

- 有专门的「已退还」明细页签。
- 失败时提示「本次消耗积分将稍后自动返还」。
- 少数操作明说不退：「智能补全任务不会取消，积分不返还」「停止将不退还已消耗算力」。

**Agent 对话：推理实时扣，生成另计**

- 「推理将实时消耗积分，素材生成积分另计」。
- 每轮显示预估区间：「{min}–{max} 积分／轮」。
- 非会员每天可免费对话 3 轮。
- 可以开启「Agent 直接消耗积分、无需逐次确认」。

**余额不足**

- 弹出升级或充值的提示。
- Agent 任务会暂停，充值后发「继续进行」即可接着做。

**其他机制**

- 项目级「积分预算阈值提醒」。
- 会员专属模型。
- 会员可用「Unlimited」模式：免积分但要排队，也可以花积分插队。
- 团队版：团队积分池，管理员给成员分配每月个人上限。

**价格参考（第三方）**：699 元买 1 万积分，即约 ¥0.07/积分；一张 2K 图约 60 积分。

### buzzy（同类产品源码，`/Users/samson/workspace/zmo_ai/buzzy`）

**两层账分开**

- 模型真实成本记在网关 bifrost 的请求日志里（`bifrost/framework/logstore`）。
- 用户积分记在 `buzzy-user` 的积分账本里（`pkg/pb/entitlement/credit_ledger.proto`）。

**积分账本**

- 每笔扣费带调用方的业务单号 `out_biz_no`，作为幂等键：同一单号重试会返回原结果，不会重复扣。
- 退款用原扣费的 `out_biz_no`，金额从原扣费推出。一笔扣费只能退一次，所以不会多退。
- 积分分订阅池和充值池。退款按原扣费各池的比例退回，防止把会过期的订阅积分「洗」成不过期的充值积分。
- 账本里另有一个「发放」接口，用于注册赠送、运营奖励和人工调账。它和退款分开：退款必须指向原扣费，发放不指向任何扣费。

**生成：询价 → 扣费 → 失败退款**

- 积分价格来自规则表（GrowthBook 的 `credits_rule`），按模型、分辨率、时长、张数询价。
- 命中的规则作为快照（`calc_rule`）写进扣费流水，供事后对账。
- 业务单号由工作流运行 ID、节点、功能类型和序号拼成，重放时保持稳定。
- 积分价格和供应商成本完全脱钩。

**对话：余额门槛 + 成功后按 token 扣**

- 余额至少 5 积分才能开始一轮（`buzzy-workflow/internal/temporal/activity/agentic_chat_model.go`）。
- 调用成功后，按「实际 token × 每个模型的积分单价」扣费；调用失败不扣。
- 不足 1 积分的零头先在 Redis 里累计，攒够整数再扣。

### 共性

- **两层账分开**：积分价格由平台定，和供应商成本脱钩，毛利在两账之间算。
- **生成**：提交时按报价扣（或先冻结），失败退回，成功不退。
- **对话**：要么按实际用量后扣，要么按次计价；都设余额门槛；失败不收。
- **账本形态**：分池；每笔流水带业务单号、只追加；退款指向原扣费并回到原池。

### 值得学 / 不照搬

**值得学**

- 业务单号幂等，扣费和退款成对。
- 计价规则快照写进流水。
- 分池管理，退款按原池比例退回。
- 生成前展示预估，超出预估再提醒（LibTV）。
- 余额不足时 Agent 暂停，充值后可以继续（LibTV）。
- 项目级消耗提醒（LibTV）。

**不照搬**

- **Redis 累计零头**：不在数据库事务里，有丢账风险。我们用 PostgreSQL 账本，直接以 0.001 积分为最小单位记账。
- **询价失败按 0 计**：这是 buzzy 的历史语义。我们询价失败就拒绝，不放行免费。
- **V1 / V2 双轨接口**：buzzy 的迁移历史包袱，我们从一开始只有一套。

## 设计方向

### 1. 两层账

| | 运维成本账（现有 `llmgateway`） | 用户积分账（新建） |
|---|---|---|
| 记什么 | 供应商真实成本（美元），证据等级，`unknown` 与估算 | 摄影师积分余额与流水 |
| 给谁看 | 运营与对账 | 摄影师 |
| 不确定时 | 保留 `unknown`，必要时估算结清 | 一律按「失败不收」，差额由平台承担 |
| 预算 | 改为平台级防跑飞：按部署或全平台的上限 | 积分余额就是摄影师的额度 |

- 两账都记下同一个运行 ID、执行 ID 或操作 ID，可以按次比较积分收入和模型成本，得出毛利。
- 现有的账号月度美元预算（`llm_budgets`），不再作为摄影师的额度。
- 「已发生的费用仍在核实」这类提示从摄影师界面撤掉；运维侧的结算状态只在运营视图里显示。

### 2. 积分池与有效期

| 积分池 | 来源 | 有效期 |
|---|---|---|
| 订阅积分 | 订阅每月发放（季付、年付也是按月发） | 当月结束清零，不累积 |
| 充值积分 | 购买积分包，不需要先订阅（拍板 6） | 长期有效，具体年限待定（LibTV 是 2 年） |
| 赠送积分 | 注册赠送；admin 系统完成后由管理员发放（拍板 7） | 按每次发放时设定的期限 |

- **管理员发放**：走单独的「发放」操作，必须写明原因（运营奖励、补偿、人工调账），和退款分开。这一点参考 buzzy：退款必须指向原扣费，发放不指向任何扣费。

- **消耗顺序**：默认先用最早过期的（赠送 → 订阅 → 充值）。
- **退款回原池**：退款按原扣费各池的比例退回。如果退回时原池已过期，退回的部分随之失效，与原池一致。

### 3. 定价

- **积分价格表**：按模型、规格、数量（张数、时长）定价，存放在可审计的价格表里。每笔扣费把命中的规则作为快照写进流水。
- **锚定价**：约 ¥0.07/积分（拍板 5）。
- **档位**：按 TapNow 的结构换算成人民币，高档位每元换到更多积分。下表是建议值，月价按 TapNow 美元价 × 7 取整：

  | 档位 | 每月积分 | 建议月价 | 每元换积分 | 充值单价 |
  |---|---:|---:|---:|---|
  | 免费 | 注册赠送（数量待定，TapNow 是 200） | — | — | 约 ¥0.074/积分（按 TapNow 的 95 积分/$1 换算） |
  | 标准 | 1,500 | ¥105 | 约 14.3 | ¥0.07/积分 |
  | 专业 | 6,000 | ¥392 | 约 15.3 | 约 ¥0.065/积分 |
  | 旗舰 | 30,000 | ¥1,806 | 约 16.6 | 约 ¥0.061/积分 |

  充值单价按摄影师当前档位计算；没订阅的按「免费」档。
- **季付、年付折扣**：TapNow 页面的年付折扣比例没有取到。建议年付相当于送 2 个月（约 8.3 折），季付 9.5 折。积分照样按月发放。
- **毛利**：从运维成本账按模型统计实际成本，反推每种操作的积分价格。上线前需要用真实成本数据核一遍。

### 4. 扣费时机

**生成（生图、生视频）**

- **提交时**：按报价扣积分；余额不足就拒绝提交，并提示升级或充值。
- **退回**：以下情况全额退回：
  - 供应商拒绝；
  - 生成失败；
  - 超时没有结果；
  - 结果不确定（运维侧 `unknown`）。
- **不退**：只要生成成功、作品入库就不退，不管结果有没有被采用（owner 拍板 4）。
- **部分成功**：比如要 4 张只出了 2 张，按成功的数量结算，退回其余部分。
- **摄影师取消**：供应商受理后不能取消（owner 2026-10-09 的既有规则），所以不存在「取消后退款」。供应商受理前取消则全额退回。

**Agent 对话（拍板 8 采纳）**

- **余额门槛**：开始一轮前，余额要不低于该模型一轮的预估上限。
- **扣费**：每轮结束后，按「实际 token × 模型积分单价」扣，以 0.001 积分为最小单位记账；调用失败或结果不确定都不扣。
- **展示**：界面显示每轮预估区间。
- **生成另计**：对话里触发的生成按生成规则另外扣费。
- **余额不足**：Agent 停在当前步骤，充值后可以继续。

**为什么不按轮次固定价**：一轮的成本随上下文长度变化很大，固定价要么亏本，要么对短对话不公平。按用量扣是 buzzy 和 LibTV 的共同做法。

### 5. 订阅变更与退款（拍板 9）

**升级**：立即生效，按新档位正常增加积分。具体做法建议如下：
- 摄影师补付本周期剩余天数的差价；
- 当即补发「新档位月积分 − 原档位月积分」。

已经用掉的积分不受影响，新档位的积分照样在当月结束时清零。补差价和补积分的具体算法待实现时确认。

**降级**：记成待生效的变更，下个周期开始时切换。本周期内的档位和积分保持不变。

**取消订阅**：当期结束前可以继续使用，到期后不再续费。订阅积分照常在当月结束时清零。

**退款**：不做自助退款。受理需要同时满足以下三点：
- 本次订阅发放的积分一个都没有消耗；
- 在订阅付费后 24 小时内提出；
- 摄影师通过邮箱联系客服，由人工操作。

系统要支撑两件事：
- 客服能一眼看出这次订阅积分有没有被用过、付费时间是什么时候；
- 退款操作留有审计流水：作废该笔订阅积分，标记订单已退款。

### 6. 账本不变量

- **只追加**：每笔流水只追加，不修改、不删除；更正用新流水表达。
- **幂等**：每笔扣费带业务单号，同一单号重放返回原结果。
- **退款**：每笔扣费最多退一次，退回金额不超过扣费金额。
- **余额**：余额等于各池流水之和；按池分别检查是否过期。
- **账号隔离**：账本表带 `account_id`，查询限定在当前账号（ADR-001）。

### 7. 与现有代码的关系

- **`llmgateway`**：保留，定位为运维成本账。
  - 账号级 `llm_budgets` 改为平台级保护。
  - 「对话扣积分」放在 Agent 服务里，在网关结算后折算，不改网关的记账语义。
- **新建积分领域包**，包含：
  - 积分池；
  - 流水；
  - 价格表；
  - 订阅（档位、周期、每月发放）；
  - 订单（充值、订阅支付）。
- **支付渠道**：微信支付、支付宝、Stripe 的接入单独定，不在本设计范围内。产品定位是云端 SaaS，见记忆中的产品定位。

## 待拍板

第一轮待拍板的 5 项已在 2026-10-14 定下（见「Owner 已拍板」5–9）。剩下的细项可以在实现时再定：

1. **注册赠送的积分数**：TapNow 是 200。
2. **充值积分的有效期**：LibTV 是 2 年。
3. **季付、年付折扣**：「设计方向 3」里的建议值（年付约 8.3 折、季付 9.5 折）请确认。
4. **升级补差价和补积分的具体算法**：见「设计方向 5」。
5. **高级功能哪些设为订阅专享**：后续再定（拍板 6）。
6. **网关冻结额过宽**（2026-10-15 记录，随计费分支一起修）：
   - **现状**：
     - 网关每次模型调用前按上界冻结。
     - 输出部分按模型最大输出冻结：DeepSeek 为 384k token，同样作为 `max_tokens` 发给厂商（`creativeagent/execution.go`）。
     - 首轮输入在创建运行时按字节上限冻结，即 `min(InputTextBytes, 窗口 × 4)`（`creativeagent/runs.go`）。后续轮次已按真实请求大小冻结。
   - **影响**：
     - V4 Pro 高峰价下，单次调用冻结约 $2.2，其中输出约 $1.52、首轮输入约 $0.69。
     - 在 $20 的账号月度上限下，同时只能跑约 9 个调用，并发会话很快被卡住。

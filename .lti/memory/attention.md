## 测试

- 本机日常开发验证只运行改动影响的模块、包或浏览器场景。先确认测试命令的覆盖范围，重型测试默认串行，避免同时运行多个测试、构建或容器任务；运行时留意 CPU 和内存压力，持续高负载或出现明显卡顿时，停止任务并缩小范围或降低并发。合并与发布门禁见 AGENTS.md。来源：2026-11-15 上下文小窗交互修复中 owner 明确要求。

## 实施

- LTI 规格文档编写完成、进入实施阶段时，如果要在新 Git worktree 中开发，必须先在主工作区提交本次变更的规格文档，再从包含该提交的分支或提交创建 worktree。未提交的文件（包括已暂存和未跟踪的文件）不会随新 worktree 带过去。提交须经用户明确授权；未获授权时，先不要创建实施 worktree。来源：2026-11-17 owner 明确要求。

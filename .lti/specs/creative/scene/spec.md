## 新建并打开 3D 场景

摄影师可以在画布上新建 3D 场景节点。新建时同一事务产生场景文档，第 1 版只含一块内置地面。打开节点进入全屏编辑视图，画布的助手面板保持可用。

### Scenario: 新建场景
- GIVEN 摄影师打开一张画布
- WHEN 在创建菜单中选择「3D 场景」
- THEN 画布出现场景节点，标题为「未命名场景」，卡片显示物件数；读取该文档得到 `type_key = "scene"`、修订号 1，快照只有一个 `ground@1` 物件

### Scenario: 打开编辑视图
- GIVEN 画布上有一个场景节点
- WHEN 摄影师双击节点或点击最大化
- THEN 进入全屏编辑视图，显示场景中的物件；画布的助手面板仍可打开，会话不切换；首次打开时才加载 3D 相关代码

## 手动编辑与静默保存

摄影师放置内置基础体，移动、旋转、缩放，改参数、名称、显隐和锁定，复制和删除。改动立即显示，并自动保存为新修订。一次确认的操作只产生一个修订，无论涉及多少个物件。

### Scenario: 一次操作只保存一次
- GIVEN 场景中选中了 3 个物件
- WHEN 摄影师按 G 移动它们并确认，或用 gizmo 拖动后松手
- THEN 视口立即显示新位置；只提交一次命令，产生一个修订，Cmd+Z 一次撤销全部；状态栏最终显示「已保存」

### Scenario: 重开一致
- GIVEN 摄影师做了若干修改，状态栏显示「已保存」
- WHEN 关闭编辑视图后重新打开，或刷新页面
- THEN 物件、变换、参数、名称、显隐和锁定与关闭前一致

### Scenario: 视窗回到离开时的样子
- GIVEN 摄影师转到某个视角、切成正交、选中一个物件并换成移动工具
- WHEN 关闭编辑视图后重新打开，或刷新页面
- THEN 视角、正交或透视、选中的物件、工具和面板开合都和离开时一样；这些只存在本机浏览器，不产生修订

### Scenario: 非法内容被拒绝
- GIVEN 一批操作里有未知内置体、父子成环、数值越界或重复的物件 ID
- WHEN 提交
- THEN 返回 400 `validation_failed`，整批不生效，不产生修订

## Blender 式编辑交互

编辑器采用 Blender 2.80 之后的默认键位（左键选择）。鼠标中键与 Alt + 左键两种导航方式并存，触控板按 Blender 的手势。状态栏、菜单和速查随时提示可用按键。

### Scenario: 键盘添加并精确移动
- GIVEN 编辑视图已打开，鼠标在视口里
- WHEN 摄影师按 Shift + A 选「方块」，再按 G、Z、输入 2、回车
- THEN 方块出现在鼠标所指的地面位置，然后沿 Z 轴移动 2 m；移动过程中状态栏显示当前轴向和数值；确认后只产生一个修订

### Scenario: 取消变换
- GIVEN 选中了一个物件
- WHEN 按 R 旋转一段后按右键或 Esc
- THEN 物件回到旋转前的样子，不产生修订，编辑视图也不会关闭

### Scenario: 吸附
- GIVEN 选中了一个物件
- WHEN 按 R 后按住 Ctrl（macOS 为 Cmd）转动
- THEN 旋转按 5° 吸附

### Scenario: 多选
- GIVEN 场景中有若干物件，地面已锁定
- WHEN 摄影师在视口里拖出选框，或按 A
- THEN 框内或全部未锁定的可见物件被选中，地面不会被选中；Shift + 单击可以加选或取消

### Scenario: 复制并移动
- GIVEN 选中了 2 个物件
- WHEN 按 Shift + D，移动鼠标后单击确认
- THEN 出现 2 个副本并跟随鼠标移动；确认后复制与移动合计只产生一个修订

### Scenario: 没有中键也能导航
- GIVEN 摄影师用的是没有中键的鼠标
- WHEN 按住 Alt 用左键拖动，或再加按 Shift
- THEN 视角分别环绕和平移；有中键的用户照常用中键

### Scenario: 触控板导航
- GIVEN 编辑器处于触控板模式（自动推测或在「视图」菜单中手动选择）
- WHEN 双指滑动、Shift + 双指滑动、捏合
- THEN 视角分别环绕、平移、推拉，浏览器页面本身不滚动也不缩放；环绕和平移都是画面跟着手指走；手动选择在刷新后保持

### Scenario: 输入框里打字不触发快捷键
- GIVEN 焦点在属性栏的名称输入框里
- WHEN 输入包含 g、r、s、x 的文字
- THEN 文字正常输入，不触发移动、旋转、缩放或删除

### Scenario: 按住快捷键只执行一次
- GIVEN 编辑视图里选中了物件
- WHEN 按住 Alt+G、N 等快捷键不放
- THEN 只执行一次，不随系统的按键重复反复执行，按键也不会漏给画布或浏览器；按住 Cmd+Z / Cmd+Shift+Z 例外，和 Blender 一样连续撤销 / 重做

## 摆放与内容分开做并发控制

每个物件有两个单元：摆放（名称、变换、显隐、锁定）和内容（基础体参数、材质槽、灯光、摄像机）。层级和兄弟顺序归集合单元 `objects` 管。

### Scenario: 改同一物件的不同单元
- GIVEN 两方基于同一版本
- WHEN 一方改物件 A 的位置，另一方改 A 的基础体参数
- THEN 两者都成功

### Scenario: 改同一单元
- GIVEN 两方基于同一版本
- WHEN 两方都改物件 A 的位置
- THEN 后到者收到 409 `creative_document_conflict`，冲突明细指向 `object:<A>`；编辑器提示冲突，摄影师可以选择用最新版本重新应用自己的修改

### Scenario: 同时新增不同物件
- GIVEN 两方基于同一版本，各自新增一个物件
- WHEN 两者先后提交
- THEN 后到者只在 `objects` 上冲突，编辑器自动用最新版本重新提交，两个物件都在场景中

### Scenario: 删除遇到层级变化需要确认
- GIVEN 甲准备删除物件 A，乙先把 A 移进另一个分组
- WHEN 甲的删除提交，只在 `objects` 上冲突
- THEN 编辑器不自动重发删除，而是提示 A 刚被修改，由甲选择「仍然删除」或放弃

### Scenario: 前一步被拒绝，后一步暂停
- GIVEN 摄影师连续改了物件 A 两次，第一次发出后收到冲突
- WHEN 第一次被拒绝
- THEN 第二次不发出，和第一次一起出现在冲突提示里，可以按最新版本重新应用或放弃；与 A 无关的修改照常保存

## 只撤销自己的操作

Cmd+Z 只撤销本次打开期间摄影师自己的操作，撤销本身是一个新修订。某一步之后同一物件被别人改过，这一步就跳过并提示，绝不覆盖别人的改动。

### Scenario: 逐步撤销与重做
- GIVEN 摄影师先移动物件 A，再移动物件 B
- WHEN 按两次 Cmd+Z，再按 Cmd+Shift+Z
- THEN B、A 依次回到原位，然后 A 重新移动到新位置；每一步都产生一个新修订

### Scenario: 每个操作是一步，保存慢也一样
- GIVEN 摄影师新建方块后按 S 缩放并确认，新建可能还没保存完
- WHEN 按 Cmd+Z
- THEN 只撤销缩放，方块还在；再按一次才撤销新建

### Scenario: 没有改变任何值的操作不保存
- GIVEN 物件已经在原点
- WHEN 按 Alt+G 清除位置，或把某个值设成和现在一样
- THEN 不产生修订，也不占撤销步骤；一次修改里只有部分值变了时，只提交变了的部分

### Scenario: 保存中撤销
- GIVEN 摄影师上一个修改还在保存中
- WHEN 按 Cmd+Z
- THEN 状态栏提示「正在保存，保存后撤销」，保存完成后撤销这个修改；如果在此之前又做了新的修改，或者这个修改没有保存成功，则不再撤销

### Scenario: 别人改过就跳过
- GIVEN 摄影师移动物件 A 之后，另一个写入者又改了 A
- WHEN 摄影师按 Cmd+Z 想撤销对 A 的移动
- THEN 这一步被跳过并提示「这一步之后物件已被修改，无法撤销」，A 保持另一方的改动；之后即使摄影师再改 A，这一步也不会重新变得可撤销

### Scenario: 撤销删除
- GIVEN 摄影师删除了一个物件
- WHEN 按 Cmd+Z
- THEN 物件以原 ID、原位置和原参数回到场景

### Scenario: 撤销删除大分组
- GIVEN 摄影师删除了一个含 150 个物件、内部有嵌套分组的分组
- WHEN 按 Cmd+Z
- THEN 一次请求恢复全部物件，层级和顺序与删除前完全一致；若其中任一物件已被别人改过，整次撤销不生效并提示

## 历史版本列表

历史版本列表按写入者、助手运行和时间窗分组显示修订。可以只读预览某一版，确认后整份恢复，产生一个新版本。

### Scenario: 分组显示
- GIVEN 摄影师在 2 分钟内连续做了几次修改，之后助手的一次运行又写了几个修订
- WHEN 打开历史版本列表
- THEN 摄影师的修改合并为一组，助手这次运行的修订合并为一组，每组显示写入者、时间段和改动物件数

### Scenario: 预览并恢复
- GIVEN 场景当前修订为 N
- WHEN 摄影师点开第 k 版并确认恢复
- THEN 预览期间视口只读；恢复后产生修订 N+1，场景与第 k 版一致，撤销栈清空；列表中可以再恢复回第 N 版

## 多个标签页之间同步

同一场景在多个标签页打开时，一处保存后，其他标签页自动显示新状态，不打断正在进行的拖动。

### Scenario: 另一标签页的修改出现
- GIVEN 同一场景在两个标签页打开
- WHEN 标签页一保存了修改
- THEN 标签页二在几秒内显示新状态；若标签页二正在拖动，等松手后再更新

### Scenario: 另一标签页进出回收站
- GIVEN 同一场景在两个标签页打开
- WHEN 标签页一把场景移入回收站，之后又移出
- THEN 标签页二的编辑视图先切换为只读并提示先恢复，移出后恢复可编辑

## 未保存时离开会被提示

未发出的修改不保存在本机。只要还有未保存的修改，离开页面就会被拦截提示；关闭编辑视图后，保存在后台继续。

### Scenario: 未保存时关闭标签页
- GIVEN 场景还有待发、发送中、结果未知或因冲突暂停的修改
- WHEN 摄影师刷新或关闭标签页
- THEN 浏览器拦截并提示「场景还有未保存的修改，离开会丢失」；全部保存后不再拦截

### Scenario: 有冲突待处理时关闭编辑视图
- GIVEN 有修改因冲突暂停，等待摄影师处理
- WHEN 摄影师关闭编辑视图
- THEN 先确认「有 n 处修改因冲突没有保存，关闭后会丢失」，可以返回处理或仍然关闭

## 用代码生成模型

摄影师可以在代码面板里粘贴或编写一段几何模块代码，生成一个模型放进场景，也可以修改已有模型实例的代码后重新生成。代码在浏览器的隔离环境里编译成 GLB，GLB 是几何的事实源；服务端不执行代码，只校验 GLB 和提交的信息。

### Scenario: 新建代码模型
- GIVEN 摄影师打开场景编辑视图
- WHEN 在添加菜单选「代码模型」，用默认模板点「生成」
- THEN 物件出现在打开菜单时指针所指的地面位置并被选中；只提交一次命令，其中包含 `commit_model` 和 `add_objects`，产生一个场景修订和一个模型内容修订；关闭再打开后物件和几何不变

### Scenario: 修改代码
- GIVEN 场景中选中了一个模型实例
- WHEN 摄影师在代码面板修改代码并重新生成
- THEN 这个实例换成新几何；原参数中新代码仍然支持的值保留，其余取新代码的默认值

### Scenario: 编译失败不改场景
- GIVEN 代码有语法错误、运行时报错、`build` 返回的不是 three.js 对象，或运行超过 5 秒
- WHEN 摄影师点「生成」或「重新生成」
- THEN 代码面板显示错误（语法和运行错误标出行号）；场景不变，不上传，不产生修订

### Scenario: 超出上限不提交
- GIVEN 代码超过 64 KiB，或生成的几何超过 30 万个三角形，或 GLB 超过 16 MiB
- WHEN 摄影师生成
- THEN 编辑器提示超出了哪个上限，不上传，不产生修订

### Scenario: 修改参数定义后重新生成
- GIVEN 选中了一个模型实例
- WHEN 摄影师在代码里新增一个参数、删除一个参数并改了另一个参数的范围，然后重新生成
- THEN 参数面板显示新的参数定义；保留的参数沿用原值（超出新范围的被限制到范围内）；保存的生成信息带新的参数定义

### Scenario: 不接受静态子集以外的 GLB
- GIVEN 生成的 GLB 声明的包围盒与顶点数据不符，或索引越界、节点成环，或含形变、骨骼、动画、纹理、未知扩展
- WHEN 编辑器准备保存，或服务端校验上传
- THEN 编辑器提示原因、不上传；直接上传的这类文件被服务端判为校验失败，无法提交

### Scenario: 服务端拒绝与 GLB 不符的提交
- GIVEN 一个 `commit_model` 的 manifest 与服务端从 GLB 算出的不一致，或代码哈希不符，或参数不符合定义
- WHEN 提交
- THEN 返回 400 `validation_failed`，整批不生效，不产生修订

## 调参数重新生成

模型实例的参数面板按模型的参数定义生成。改参数会用同一份代码重新烘焙，一次修改是一个修订，也是一个撤销步骤。

### Scenario: 改参数
- GIVEN 选中了一个模型实例，它的模型不与其他实例共用
- WHEN 摄影师在属性栏把高度从 6 改成 8
- THEN 几何随之变化，状态栏最终显示「已保存」；同一模型内容追加一个修订，产生一个场景修订

### Scenario: 撤销调参
- GIVEN 摄影师刚改过一个模型实例的参数
- WHEN 按 Cmd+Z，再按 Cmd+Shift+Z
- THEN 实例先回到原来的几何，再回到新几何；各产生一个修订

### Scenario: 参数限定在定义的范围内
- GIVEN 参数定义为 `min: 2, max: 20`
- WHEN 摄影师输入 50
- THEN 输入框把值限制在 20 以内，不提交越界值

## 共用模型先分叉

一个模型修订可以被多个实例共用（例如复制出来的实例）。修改其中一个时，默认只改它自己，先分叉出新模型；摄影师明确选择时，才让所有共用的实例一起变。

### Scenario: 默认只改当前实例
- GIVEN 场景中两个实例共用同一个模型修订
- WHEN 摄影师修改其中一个的参数
- THEN 只有它变化，另一个保持原样；新几何写入一个新的模型内容

### Scenario: 应用到全部实例
- GIVEN 场景中两个实例共用同一个模型修订
- WHEN 摄影师打开「应用到全部 2 个实例」后修改参数
- THEN 两个实例一起变化，只产生一个场景修订

### Scenario: 保存模型期间别人改了同一实例
- GIVEN 摄影师改了一个模型实例的参数，编辑器正在生成和上传
- WHEN 这期间另一个标签页或助手改了同一实例的参数并保存
- THEN 摄影师这次保存收到冲突提示，可以选择重新应用或放弃；对方的修改不会被悄悄覆盖

### Scenario: 移动与换模型并发都成功
- GIVEN 两个标签页打开同一场景
- WHEN 一个标签页移动某个模型实例，另一个同时修改它的参数
- THEN 两边都成功；两边都修改它的参数时，后到者收到冲突提示

## 模型代码在隔离环境中执行

模型代码可能来自不可信的来源，只能在隔离的沙箱里执行：拿不到登录凭证，不能访问网络和站点存储，不能操作编辑器页面，超时会被终止。

### Scenario: 恶意代码被阻断
- GIVEN 一段模型代码尝试 `fetch`、XHR、WebSocket、EventSource、动态 `import`、`importScripts`，读取 cookie、`localStorage`、IndexedDB 或父页面 DOM，修改顶层页面地址，或使用 `eval`
- WHEN 摄影师生成它
- THEN 这些访问全部失败，外部地址收不到任何请求；编辑器保持可用

### Scenario: 死循环被终止
- GIVEN 一段模型代码进入死循环，或不断申请内存
- WHEN 摄影师生成它
- THEN 编辑器在 5 秒内终止它并提示超时或失败；编辑器一直可以操作，之后的生成照常进行

## 模型不可用时显示占位

### Scenario: 模型不可用
- GIVEN 场景引用的某个模型修订不可用
- WHEN 摄影师打开场景
- THEN 这个实例显示「模型不可用」的占位，可以移动、删除；场景其余部分照常显示和编辑

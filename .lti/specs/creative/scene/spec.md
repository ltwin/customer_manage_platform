## 新建并打开 3D 场景

摄影师可以在画布上新建 3D 场景节点。新建时同一事务产生场景文档，第 1 版只含一块内置地面。打开节点进入全屏编辑视图，画布的助手面板保持可用。

### Scenario: 新建场景
- GIVEN 摄影师打开一张画布
- WHEN 在创建菜单中选择「3D 场景」
- THEN 画布出现场景节点，标题为「未命名场景」，卡片显示物件数；读取该文档得到 `type_key = "scene"`、修订号 1，快照只有一个 `ground@1` 物件

### Scenario: 打开编辑视图
- GIVEN 画布上有一个场景节点
- WHEN 摄影师双击节点或点击最大化
- THEN 进入全屏编辑视图，显示场景中的物件；画布的助手面板仍可打开，会话不切换；首次打开时才加载 3D 相关代码

## 手动编辑与静默保存

摄影师放置内置基础体，移动、旋转、缩放，改参数、名称、显隐和锁定，复制和删除。改动立即显示，并自动保存为新修订。一次确认的操作只产生一个修订，无论涉及多少个物件。

### Scenario: 一次操作只保存一次
- GIVEN 场景中选中了 3 个物件
- WHEN 摄影师按 G 移动它们并确认，或用 gizmo 拖动后松手
- THEN 视口立即显示新位置；只提交一次命令，产生一个修订，Cmd+Z 一次撤销全部；状态栏最终显示「已保存」

### Scenario: 重开一致
- GIVEN 摄影师做了若干修改，状态栏显示「已保存」
- WHEN 关闭编辑视图后重新打开，或刷新页面
- THEN 物件、变换、参数、名称、显隐和锁定与关闭前一致

### Scenario: 视窗回到离开时的样子
- GIVEN 摄影师转到某个视角、切成正交、选中一个物件并换成移动工具
- WHEN 关闭编辑视图后重新打开，或刷新页面
- THEN 视角、正交或透视、选中的物件、工具和面板开合都和离开时一样；这些只存在本机浏览器，不产生修订

### Scenario: 非法内容被拒绝
- GIVEN 一批操作里有未知内置体、父子成环、数值越界或重复的物件 ID
- WHEN 提交
- THEN 返回 400 `validation_failed`，整批不生效，不产生修订

## Blender 式编辑交互

编辑器采用 Blender 2.80 之后的默认键位（左键选择）。鼠标中键与 Alt + 左键两种导航方式并存，触控板按 Blender 的手势。状态栏、菜单和速查随时提示可用按键。

### Scenario: 键盘添加并精确移动
- GIVEN 编辑视图已打开，鼠标在视口里
- WHEN 摄影师按 Shift + A 选「方块」，再按 G、Z、输入 2、回车
- THEN 方块出现在鼠标所指的地面位置，然后沿 Z 轴移动 2 m；移动过程中状态栏显示当前轴向和数值；确认后只产生一个修订

### Scenario: 取消变换
- GIVEN 选中了一个物件
- WHEN 按 R 旋转一段后按右键或 Esc
- THEN 物件回到旋转前的样子，不产生修订，编辑视图也不会关闭

### Scenario: 吸附
- GIVEN 选中了一个物件
- WHEN 按 R 后按住 Ctrl（macOS 为 Cmd）转动
- THEN 旋转按 5° 吸附

### Scenario: 多选
- GIVEN 场景中有若干物件，地面已锁定
- WHEN 摄影师在视口里拖出选框，或按 A
- THEN 框内或全部未锁定的可见物件被选中，地面不会被选中；Shift + 单击可以加选或取消

### Scenario: 复制并移动
- GIVEN 选中了 2 个物件
- WHEN 按 Shift + D，移动鼠标后单击确认
- THEN 出现 2 个副本并跟随鼠标移动；确认后复制与移动合计只产生一个修订

### Scenario: 没有中键也能导航
- GIVEN 摄影师用的是没有中键的鼠标
- WHEN 按住 Alt 用左键拖动，或再加按 Shift
- THEN 视角分别环绕和平移；有中键的用户照常用中键

### Scenario: 触控板导航
- GIVEN 编辑器处于触控板模式（自动推测或在「视图」菜单中手动选择）
- WHEN 双指滑动、Shift + 双指滑动、捏合
- THEN 视角分别环绕、平移、推拉，浏览器页面本身不滚动也不缩放；环绕和平移都是画面跟着手指走；手动选择在刷新后保持

### Scenario: 输入框里打字不触发快捷键
- GIVEN 焦点在属性栏的名称输入框里
- WHEN 输入包含 g、r、s、x 的文字
- THEN 文字正常输入，不触发移动、旋转、缩放或删除

### Scenario: 按住快捷键只执行一次
- GIVEN 编辑视图里选中了物件
- WHEN 按住 Alt+G、N 等快捷键不放
- THEN 只执行一次，不随系统的按键重复反复执行，按键也不会漏给画布或浏览器；按住 Cmd+Z / Cmd+Shift+Z 例外，和 Blender 一样连续撤销 / 重做

## 摆放与内容分开做并发控制

每个物件有两个单元：摆放（名称、变换、显隐、锁定）和内容（基础体参数、材质槽、灯光、摄像机）。层级和兄弟顺序归集合单元 `objects` 管。

### Scenario: 改同一物件的不同单元
- GIVEN 两方基于同一版本
- WHEN 一方改物件 A 的位置，另一方改 A 的基础体参数
- THEN 两者都成功

### Scenario: 改同一单元
- GIVEN 两方基于同一版本
- WHEN 两方都改物件 A 的位置
- THEN 后到者收到 409 `creative_document_conflict`，冲突明细指向 `object:<A>`；编辑器提示冲突，摄影师可以选择用最新版本重新应用自己的修改

### Scenario: 同时新增不同物件
- GIVEN 两方基于同一版本，各自新增一个物件
- WHEN 两者先后提交
- THEN 后到者只在 `objects` 上冲突，编辑器自动用最新版本重新提交，两个物件都在场景中

### Scenario: 删除遇到层级变化需要确认
- GIVEN 甲准备删除物件 A，乙先把 A 移进另一个分组
- WHEN 甲的删除提交，只在 `objects` 上冲突
- THEN 编辑器不自动重发删除，而是提示 A 刚被修改，由甲选择「仍然删除」或放弃

### Scenario: 前一步被拒绝，后一步暂停
- GIVEN 摄影师连续改了物件 A 两次，第一次发出后收到冲突
- WHEN 第一次被拒绝
- THEN 第二次不发出，和第一次一起出现在冲突提示里，可以按最新版本重新应用或放弃；与 A 无关的修改照常保存

## 只撤销自己的操作

Cmd+Z 只撤销本次打开期间摄影师自己的操作，撤销本身是一个新修订。某一步之后同一物件被别人改过，这一步就跳过并提示，绝不覆盖别人的改动。

### Scenario: 逐步撤销与重做
- GIVEN 摄影师先移动物件 A，再移动物件 B
- WHEN 按两次 Cmd+Z，再按 Cmd+Shift+Z
- THEN B、A 依次回到原位，然后 A 重新移动到新位置；每一步都产生一个新修订

### Scenario: 每个操作是一步，保存慢也一样
- GIVEN 摄影师新建方块后按 S 缩放并确认，新建可能还没保存完
- WHEN 按 Cmd+Z
- THEN 只撤销缩放，方块还在；再按一次才撤销新建

### Scenario: 没有改变任何值的操作不保存
- GIVEN 物件已经在原点
- WHEN 按 Alt+G 清除位置，或把某个值设成和现在一样
- THEN 不产生修订，也不占撤销步骤；一次修改里只有部分值变了时，只提交变了的部分

### Scenario: 保存中撤销
- GIVEN 摄影师上一个修改还在保存中
- WHEN 按 Cmd+Z
- THEN 状态栏提示「正在保存，保存后撤销」，保存完成后撤销这个修改；如果在此之前又做了新的修改，或者这个修改没有保存成功，则不再撤销

### Scenario: 别人改过就跳过
- GIVEN 摄影师移动物件 A 之后，另一个写入者又改了 A
- WHEN 摄影师按 Cmd+Z 想撤销对 A 的移动
- THEN 这一步被跳过并提示「这一步之后物件已被修改，无法撤销」，A 保持另一方的改动；之后即使摄影师再改 A，这一步也不会重新变得可撤销

### Scenario: 撤销删除
- GIVEN 摄影师删除了一个物件
- WHEN 按 Cmd+Z
- THEN 物件以原 ID、原位置和原参数回到场景

### Scenario: 撤销删除大分组
- GIVEN 摄影师删除了一个含 150 个物件、内部有嵌套分组的分组
- WHEN 按 Cmd+Z
- THEN 一次请求恢复全部物件，层级和顺序与删除前完全一致；若其中任一物件已被别人改过，整次撤销不生效并提示

## 历史版本列表

历史版本列表按写入者、助手运行和时间窗分组显示修订。可以只读预览某一版，确认后整份恢复，产生一个新版本。

### Scenario: 分组显示
- GIVEN 摄影师在 2 分钟内连续做了几次修改，之后助手的一次运行又写了几个修订
- WHEN 打开历史版本列表
- THEN 摄影师的修改合并为一组，助手这次运行的修订合并为一组，每组显示写入者、时间段和改动物件数

### Scenario: 预览并恢复
- GIVEN 场景当前修订为 N
- WHEN 摄影师点开第 k 版并确认恢复
- THEN 预览期间视口只读；恢复后产生修订 N+1，场景与第 k 版一致，撤销栈清空；列表中可以再恢复回第 N 版

## 多个标签页之间同步

同一场景在多个标签页打开时，一处保存后，其他标签页自动显示新状态，不打断正在进行的拖动。

### Scenario: 另一标签页的修改出现
- GIVEN 同一场景在两个标签页打开
- WHEN 标签页一保存了修改
- THEN 标签页二在几秒内显示新状态；若标签页二正在拖动，等松手后再更新

### Scenario: 另一标签页进出回收站
- GIVEN 同一场景在两个标签页打开
- WHEN 标签页一把场景移入回收站，之后又移出
- THEN 标签页二的编辑视图先切换为只读并提示先恢复，移出后恢复可编辑

## 未保存时离开会被提示

未发出的修改不保存在本机。只要还有未保存的修改，离开页面就会被拦截提示；关闭编辑视图后，保存在后台继续。

### Scenario: 未保存时关闭标签页
- GIVEN 场景还有待发、发送中、结果未知或因冲突暂停的修改
- WHEN 摄影师刷新或关闭标签页
- THEN 浏览器拦截并提示「场景还有未保存的修改，离开会丢失」；全部保存后不再拦截

### Scenario: 有冲突待处理时关闭编辑视图
- GIVEN 有修改因冲突暂停，等待摄影师处理
- WHEN 摄影师关闭编辑视图
- THEN 先确认「有 n 处修改因冲突没有保存，关闭后会丢失」，可以返回处理或仍然关闭

## 用代码生成模型

摄影师可以在代码面板里粘贴或编写一段几何模块代码，生成一个模型放进场景，也可以修改已有模型实例的代码后重新生成。代码在浏览器的隔离环境里编译成 GLB，GLB 是几何的事实源；服务端不执行代码，只校验 GLB 和提交的信息。

### Scenario: 新建代码模型
- GIVEN 摄影师打开场景编辑视图
- WHEN 在添加菜单选「代码模型」，用默认模板点「生成」
- THEN 物件出现在打开菜单时指针所指的地面位置并被选中；只提交一次命令，其中包含 `commit_model` 和 `add_objects`，产生一个场景修订和一个模型内容修订；关闭再打开后物件和几何不变

### Scenario: 修改代码
- GIVEN 场景中选中了一个模型实例
- WHEN 摄影师在代码面板修改代码并重新生成
- THEN 这个实例换成新几何；原参数中新代码仍然支持的值保留，其余取新代码的默认值

### Scenario: 编译失败不改场景
- GIVEN 代码有语法错误、运行时报错、`build` 返回的不是 three.js 对象，或运行超过 5 秒
- WHEN 摄影师点「生成」或「重新生成」
- THEN 代码面板显示错误（语法和运行错误标出行号）；场景不变，不上传，不产生修订

### Scenario: 超出上限不提交
- GIVEN 代码超过 64 KiB，或生成的几何超过 30 万个三角形，或 GLB 超过 16 MiB
- WHEN 摄影师生成
- THEN 编辑器提示超出了哪个上限，不上传，不产生修订

### Scenario: 修改参数定义后重新生成
- GIVEN 选中了一个模型实例
- WHEN 摄影师在代码里新增一个参数、删除一个参数并改了另一个参数的范围，然后重新生成
- THEN 参数面板显示新的参数定义；保留的参数沿用原值（超出新范围的被限制到范围内）；保存的生成信息带新的参数定义

### Scenario: 不接受静态子集以外的 GLB
- GIVEN 生成的 GLB 声明的包围盒与顶点数据不符，或索引越界、节点成环，或含形变、骨骼、动画、纹理、未知扩展
- WHEN 编辑器准备保存，或服务端校验上传
- THEN 编辑器提示原因、不上传；直接上传的这类文件被服务端判为校验失败，无法提交

### Scenario: 服务端拒绝与 GLB 不符的提交
- GIVEN 一个 `commit_model` 的 manifest 与服务端从 GLB 算出的不一致，或代码哈希不符，或参数不符合定义
- WHEN 提交
- THEN 返回 400 `validation_failed`，整批不生效，不产生修订

## 调参数重新生成

模型实例的参数面板按模型的参数定义生成。改参数会用同一份代码重新烘焙，一次修改是一个修订，也是一个撤销步骤。

### Scenario: 改参数
- GIVEN 选中了一个模型实例，它的模型不与其他实例共用
- WHEN 摄影师在属性栏把高度从 6 改成 8
- THEN 几何随之变化，状态栏最终显示「已保存」；同一模型内容追加一个修订，产生一个场景修订

### Scenario: 撤销调参
- GIVEN 摄影师刚改过一个模型实例的参数
- WHEN 按 Cmd+Z，再按 Cmd+Shift+Z
- THEN 实例先回到原来的几何，再回到新几何；各产生一个修订

### Scenario: 参数限定在定义的范围内
- GIVEN 参数定义为 `min: 2, max: 20`
- WHEN 摄影师输入 50
- THEN 输入框把值限制在 20 以内，不提交越界值

## 共用模型先分叉

一个模型修订可以被多个实例共用（例如复制出来的实例）。修改其中一个时，默认只改它自己，先分叉出新模型；摄影师明确选择时，才让所有共用的实例一起变。

### Scenario: 默认只改当前实例
- GIVEN 场景中两个实例共用同一个模型修订
- WHEN 摄影师修改其中一个的参数
- THEN 只有它变化，另一个保持原样；新几何写入一个新的模型内容

### Scenario: 应用到全部实例
- GIVEN 场景中两个实例共用同一个模型修订
- WHEN 摄影师打开「应用到全部 2 个实例」后修改参数
- THEN 两个实例一起变化，只产生一个场景修订

### Scenario: 保存模型期间别人改了同一实例
- GIVEN 摄影师改了一个模型实例的参数，编辑器正在生成和上传
- WHEN 这期间另一个标签页或助手改了同一实例的参数并保存
- THEN 摄影师这次保存收到冲突提示，可以选择重新应用或放弃；对方的修改不会被悄悄覆盖

### Scenario: 移动与换模型并发都成功
- GIVEN 两个标签页打开同一场景
- WHEN 一个标签页移动某个模型实例，另一个同时修改它的参数
- THEN 两边都成功；两边都修改它的参数时，后到者收到冲突提示

## 模型代码在隔离环境中执行

模型代码可能来自不可信的来源，只能在隔离的沙箱里执行：拿不到登录凭证，不能访问网络和站点存储，不能操作编辑器页面，超时会被终止。

### Scenario: 恶意代码被阻断
- GIVEN 一段模型代码尝试 `fetch`、XHR、WebSocket、EventSource、动态 `import`、`importScripts`，读取 cookie、`localStorage`、IndexedDB 或父页面 DOM，修改顶层页面地址，或使用 `eval`
- WHEN 摄影师生成它
- THEN 这些访问全部失败，外部地址收不到任何请求；编辑器保持可用

### Scenario: 死循环被终止
- GIVEN 一段模型代码进入死循环，或不断申请内存
- WHEN 摄影师生成它
- THEN 编辑器在 5 秒内终止它并提示超时或失败；编辑器一直可以操作，之后的生成照常进行

## 模型不可用时显示占位

### Scenario: 模型不可用
- GIVEN 场景引用的某个模型修订不可用
- WHEN 摄影师打开场景
- THEN 这个实例显示「模型不可用」的占位，可以移动、删除；场景其余部分照常显示和编辑

## 助手搭建和修改场景

助手可以读场景、改场景、用几何代码生成模型、截图回看。它可以在画布上新建场景节点，摄影师不打开场景也能让它搭建。需要页面完成的工作（烘焙模型、截图）由服务端派成任务，交给打开着的创意空间页面执行。

### Scenario: 在编辑视图里请助手搭景
- GIVEN 摄影师打开场景编辑视图
- WHEN 用一段描述请助手搭景
- THEN 助手写出若干程序化物件并摆放，过程中至少回看一次截图；物件陆续出现在编辑器里

### Scenario: 不打开场景也能搭建
- GIVEN 摄影师停在画布视图，没有打开任何场景
- WHEN 请助手搭一个场景
- THEN 助手在画布上新建场景节点并完成搭建，任务由画布页在后台执行；助手面板里能看到回看的截图；之后打开场景，看到搭好的结果

### Scenario: 编译失败由助手自己修
- GIVEN 助手写的几何代码有错误、超时或超出上限
- WHEN 页面执行烘焙任务
- THEN 助手收到错误信息和行号，运行不失败，场景不变；助手可以修改代码重试

### Scenario: 雾和摄像机用 near、far

## 摆放摄像机

摄影师可以在场景里放多台摄像机，设置焦距、画幅和高度，从摄像机的视角取景，也可以让摄像机对齐当前视图。这些都是普通的场景修改：静默保存，Cmd+Z 可以撤销。视场角按画面长边对应传感器长边计算，与全画幅相机的经验一致。

### Scenario: 按当前视角添加摄像机
- GIVEN 摄影师在编辑视图里转到一个满意的视角
- WHEN 在「添加」菜单选「摄像机」
- THEN 新摄像机出现在当前视角的位置、朝当前视角的方向，焦距 35 mm、画幅 3:2；属性栏可以改标签、焦距、画幅和高度

### Scenario: 从摄像机取景
- GIVEN 场景里选中了一台画幅 16:9 的摄像机
- WHEN 按 `0`
- THEN 视口切到这台摄像机的视角，显示 16:9 的取景框，框外压暗；框内画面与这台摄像机的导出图一致

- THEN 退出相机视图

### Scenario: 摄像机对齐当前视图
- GIVEN 场景里选中了一台摄像机，视口在另一个视角
- WHEN 按 `Ctrl + Alt + 0`（macOS 为 `Cmd + Alt + 0`）
- THEN 摄像机移到当前视图的位置和朝向，产生一个修订；Cmd+Z 撤销回原位

### Scenario: 竖拍与横拍同一焦距取景一致
- GIVEN 一台焦距 35 mm、画幅 3:2 的摄像机
- WHEN 把画幅改成 2:3
- THEN 画面长边方向的取景范围不变，与全画幅相机竖拍 35 mm 一致；改回 3:2 时画面与原来相同

### Scenario: 换传感器预设
- GIVEN 一台焦距 35 mm 的全画幅摄像机
- WHEN 在「更多」里把传感器预设改成 APS-C
- THEN 传感器变为 23.5 × 15.6 mm，属性栏显示等效焦距约 53.6 mm，取景随之变窄

### Scenario: 构图辅助线
- GIVEN 摄影师在相机视图里
- WHEN 打开三分线
- THEN 取景框内显示三分线；导出图里没有辅助线；重开编辑器后保持上次的选择

## 摄像机景深与对焦

摄像机可以打开景深，设置光圈和对焦。对焦可以填距离，也可以选场景里的物件或空物体。打开景深后，白模导出按光圈和对焦虚化，相机视图打开「景深预览」时视口实时虚化；线稿始终清晰。景深默认关闭。助手和摄影师调的是同一组相机参数；助手回看的截图默认清晰，助手可以要求按景深回看。

### Scenario: 按光圈看清晰范围
- GIVEN 一台 50 mm 的全画幅摄像机
- WHEN 打开景深，光圈设为 f/2.8，对焦距离 3 m
- THEN 属性栏显示清晰范围约 2.74–3.32 m，线框在 3 m 处标出焦点

### Scenario: 对焦到物件
- GIVEN 场景里有一尊雕像
- WHEN 摄影师把对焦设为「物件」，在视口里拾取雕像
- THEN 焦点落在雕像上；之后移动雕像，焦点跟着它走

### Scenario: 对焦到空物体
- GIVEN 摄影师想把焦点放在两根柱子之间的空处
- WHEN 在「添加」菜单选「空物体」，把它移到那里，再让摄像机对焦到它
- THEN 视口里显示空物体的十字标记，焦点落在它的位置

### Scenario: 白模导出按光圈虚化
- GIVEN 一台打开了景深的摄像机，光圈 f/1.8，对焦到近处的物件
- WHEN 导出白模和线稿
- THEN 白模图里对焦物件清晰、远处背景虚化；线稿全清晰

### Scenario: 相机视图实时预览景深
- GIVEN 一台打开了景深的摄像机，摄影师在它的相机视图里
- WHEN 打开「景深预览」开关
- THEN 视口按这台摄像机的光圈和对焦实时虚化，与导出图一致；改动场景、对焦物件或光圈时虚化跟着更新，开关保持打开
- WHEN 再点一下关闭开关
- THEN 视口不再虚化，AO 与打开前相同

### Scenario: 视口与导出同一套白模画面
- GIVEN 任意场景
- WHEN 摄影师在编辑器里查看，或助手不带景深调用 `render_view`
- THEN 画面带与白模导出相同的 AO（接触阴影），不需要打开景深预览；网格和变换手柄不受 AO 影响

### Scenario: 对焦物件被删除
- GIVEN 一台摄像机对焦在一尊雕像上
- WHEN 摄影师删除了雕像
- THEN 摄像机改按对焦距离对焦，属性栏提示对焦物件已删除；删除、撤销都照常进行，撤销后焦点回到雕像

### Scenario: 助手设置相机参数
- GIVEN 助手在搭场景
- WHEN 助手给摄像机写焦距、画幅、传感器、景深开关、光圈和对焦物件
- THEN 写入成功，属性栏显示相同的设置；对焦物件不存在、是摄像机自己、灯光或另一台摄像机，或光圈超出 0.5–64 时，写入被拒绝并说明原因

### Scenario: 助手回看默认不带景深
- GIVEN 一台打开了景深的摄像机
- WHEN 助手按这台摄像机回看，不要求景深
- THEN 截图全清晰，助手看到的是场景结构

### Scenario: 助手按景深回看
- GIVEN 一台打开了景深的摄像机，光圈 f/1.8，对焦在近处的物件上
- WHEN 助手按这台摄像机回看，并要求带景深
- THEN 截图里对焦物件清晰、远处背景虚化，与这台摄像机的白模导出一致

### Scenario: 不能按景深回看时说明原因
- GIVEN 助手要求带景深回看
- WHEN 用的是临时视点或预设视角，或这台摄像机没有打开景深
- THEN 工具直接返回错误并说明原因，不发起回看

## 导出分镜到画布

摄影师或助手可以把场景按摄像机导出成图，落成画布上的图片节点。导出方式有白模（`clay`）、线稿和材质光照（`lit`）；每张图按摄像机画幅出图，长边按场景的输出分辨率（1K、2K、4K、8K 分别为 1024、2048、4096、8192 px，缺省 2K）。白模与编辑器的白模一致，按工作台出图；材质光照与编辑器的最终渲染一致，按场景所选的渲染器出图。图片节点记录来源场景、修订、摄像机和导出方式。

### Scenario: 导出 3 台摄像机
- GIVEN 场景里有 3 台摄像机
- WHEN 摄影师在编辑视图里点「导出」，选全部摄像机和白模、线稿两种方式
- THEN 画布上场景节点右侧出现 6 个图片节点，每台摄像机一行、白模和线稿各一列；在画布上撤销一次，6 个节点一起移除

### Scenario: 导出材质光照
- GIVEN 场景里有 3 台摄像机，摄影师在最终渲染模式下
- WHEN 打开「导出」
- THEN 白模、线稿、材质光照默认都勾选；导出后得到 3 行 3 列 9 个节点，材质光照图与相机视图里最终渲染的画面一致，摄像机打开景深时同样虚化

### Scenario: 白模模式下默认不带材质光照
- GIVEN 摄影师在白模模式下
- WHEN 打开「导出」
- THEN 默认只勾选白模和线稿，可以手动勾选材质光照

### Scenario: 先保存再导出
- GIVEN 摄影师刚移动了一个物件，修改还没保存完
- WHEN 点「导出」
- THEN 先完成保存，再按保存后的场景出图；导出图记录的修订包含这次移动

### Scenario: 再次导出不叠在旧图上
- GIVEN 场景节点右侧已经有一组导出图
- WHEN 再导出一次
- THEN 新的一组排在旧图下方，不重叠，旧图保留

### Scenario: 不能导出时说明原因
- GIVEN 场景里没有摄像机，或选择的组合超过 48 张图
- WHEN 打开导出
- THEN 「导出」不可用，分别提示先添加摄像机、分次导出

### Scenario: 提交时断网不重复
- GIVEN 摄影师点了导出，图片已经上传，提交时网络中断，而服务端其实已经建好节点
- WHEN 页面重试提交
- THEN 拿到的是同一组节点，画布上不会出现第二组

### Scenario: 助手导出
- GIVEN 摄影师请助手导出分镜，只开着画布页
- WHEN 助手调用导出
- THEN 画布页在后台完成导出，任务完成时图片出现在这次对话所在画布的场景节点旁；助手得到每张图的节点、摄像机和方式；助手可以要求材质光照图，不指定时导出白模和线稿

### Scenario: 助手知道导出图怎么拍的
- GIVEN 一台对焦在人物上、光圈 f/1.8、打开景深的摄像机已导出白模和线稿
- WHEN 助手读取画布，准备拿这两张图做参考重绘
- THEN 两个导出图节点都给出来源：哪台摄像机、哪种导出方式、导出时的焦距、景深开关、光圈、对焦距离和对焦物件「人物」，以及场景之后是否改过；助手按此在白模的重绘提示词里写明对焦在人物上、焦外虚化，线稿的提示词要求全清晰

### Scenario: 导出中途换页面不重复
- GIVEN 执行助手导出的页面已经出完图，但在完成任务前被关闭
- WHEN 另一个页面接手这个任务
- THEN 画布上只出现接手页面导出的一组节点；助手照常得到结果

### Scenario: 助手导出时场景节点已被移走
- GIVEN 助手的导出任务正在执行
- WHEN 摄影师在任务完成前把场景节点从画布上删掉
- THEN 一个节点也不建，助手得到失败原因

## 导出图提示场景已更新

导出之后场景被修改，并且修改会改变这张图时，画布上的导出图显示「场景已更新」；改回原样后不再显示。只是提示，不改图片。哪些修改算数按导出方式区分：线稿只看几何和这台摄像机，白模另看景深，材质光照再看环境、灯光、材质、曝光和渲染器。物理天空下，材质光照的曝光是这台摄像机自己的曝光：自动时是模式和补偿，手动时是 ISO、快门和光圈；「渲染」选项卡里默认摄像机的曝光不算；其他天空下是曝光补偿。输出分辨率不算。

### Scenario: 几何变化让导出图过时
- GIVEN 画布上有某台摄像机的白模图和线稿
- WHEN 摄影师移动了场景里的一根柱子
- THEN 两张图都显示「场景已更新」

### Scenario: 改挂分组也算几何变化
- GIVEN 画布上有某台摄像机的白模图和线稿
- WHEN 助手在同一次修改里把两根柱子移进一个旋转过的分组，并新增了一台摄像机
- THEN 两张图都显示「场景已更新」，即使柱子在画面中的位置没变

### Scenario: 改回原样不再提示
- GIVEN 导出后摄影师移动了一根柱子，导出图显示「场景已更新」
- WHEN 把柱子移回原位
- THEN 导出图不再显示「场景已更新」

### Scenario: 摄像机被删除
- GIVEN 画布上有某台摄像机的导出图
- WHEN 摄影师删除了这台摄像机
- THEN 导出图显示「场景已更新」

### Scenario: 环境只影响材质光照图
- GIVEN 画布上有某台摄像机的白模图、线稿和材质光照图
- WHEN 摄影师改了太阳高度，打开了雾，或在物理天空下改了地点、时刻、大气参数或太阳的亮度和色温
- THEN 只有材质光照图显示「场景已更新」

### Scenario: 灯光和材质只影响材质光照图
- GIVEN 画布上有某台摄像机的白模图、线稿和材质光照图
- WHEN 摄影师改了一盏灯的颜色，或换了一个槽位的材质
- THEN 只有材质光照图显示「场景已更新」

### Scenario: 曝光只影响材质光照图
- GIVEN 画布上有某台摄像机的白模图、线稿和材质光照图，天空是程序化天空
- WHEN 摄影师调了曝光补偿
- THEN 只有材质光照图显示「场景已更新」；调回原值后不再显示

### Scenario: 物理天空下改摄像机曝光
- GIVEN 物理天空，画布上有摄像机 A 和摄像机 B 的材质光照图
- WHEN 摄影师改了摄像机 A 的快门，或把 A 切成环境测光、改了 A 的补偿
- THEN 只有 A 的材质光照图显示「场景已更新」；改「渲染」选项卡里默认摄像机的曝光（模式、补偿、默认曝光值）时，两张图都不显示

### Scenario: 景深参数不影响线稿
- GIVEN 一台打开了景深的摄像机，画布上有它的白模图、线稿和材质光照图
- WHEN 摄影师改了光圈，或移动了对焦物件
- THEN 白模图和材质光照图显示「场景已更新」，线稿不显示；景深关闭时改光圈，天空不是物理天空则三张图都不显示，是物理天空则只有材质光照图显示

### Scenario: 渲染器只影响材质光照图
- GIVEN 画布上有某台摄像机的白模图、线稿和材质光照图，场景一直用工作台
- WHEN 摄影师把渲染器换成实时 GI
- THEN 只有材质光照图显示「场景已更新」；换回工作台后不再显示

### Scenario: 改输出分辨率不提示
- GIVEN 画布上有某台摄像机的白模图、线稿和材质光照图
- WHEN 摄影师把输出分辨率从 2K 改成 4K
- THEN 三张图都不显示「场景已更新」

### Scenario: 不影响画面的修改不提示
- GIVEN 画布上有某台摄像机的白模图和线稿
- WHEN 只新加、删除或调了另一台摄像机，加了或删除一盏灯光，改了场景标题、显示模式、曝光补偿、默认摄像机的曝光，或者某个槽位的材质
- THEN 导出图不显示「场景已更新」

### Scenario: 换了图或场景没了就不再提示
- GIVEN 一张导出图之后场景有过几何修改
- WHEN 摄影师换掉了这个节点的图片内容，或场景已被删除
- THEN 不显示「场景已更新」

## 助手用目标点摆朝向

助手修改场景时可以给物件写一个目标点，服务端按 three.js `Object3D.lookAt` 的规则算出朝向：摄像机和灯光的 −Z、其余物件的 +Z 对准目标点，上方向为 +Y。

### Scenario: 摄像机对准物件
- GIVEN 场景里有一个石台，中心在 (0, 0.4, −3)
- WHEN 助手加一台摄像机，位置 (4, 1.6, 2)，目标点写石台中心，再按这台摄像机回看
- THEN 石台在截图的画面中心

### Scenario: 在分组里也对得准
- GIVEN 摄像机放在一个旋转过的分组里
- WHEN 助手给它写目标点
- THEN 摄像机在世界坐标里对准目标点，与 three.js 的结果一致

### Scenario: 写法冲突被拒绝
- GIVEN 助手在同一处修改里既写了目标点又写了旋转，目标点与物件位置重合，或者同一次修改里还移动或改挂了物件的父级
- WHEN 提交修改
- THEN 修改被拒绝并说明原因，场景不变

## 四种显示模式

编辑视图参照 Blender 的视口着色，提供线框、白模、材质预览、最终渲染四种显示模式。白模与白模导出一致，最终渲染与材质光照导出一致。白模用固定的工作室光，只用来看结构，不受场景的天空、太阳、环境光、雾和灯光影响。白模、材质预览和最终渲染按 AgX 色调映射：明亮的饱和色（落日、彩色灯光）越亮越接近白色，但不偏成别的颜色。显示模式是本机的查看状态，按场景记住，不写进场景，也不算一步编辑。

### Scenario: 切换显示模式
- GIVEN 场景里有分配了材质的物件和一盏投射阴影的点光
- WHEN 摄影师按 `Z`，在弹出的菜单里依次选线框、白模、材质预览、最终渲染
- THEN 线框只显示物件的轮廓边，能看到被挡住的物件，框选时被挡住的物件也会选中，点击仍选中最前面的表面；白模是统一的浅灰材质，背景是中性灰，看不到天空，灯光不影响画面；材质预览显示材质，光照是固定的中性室内光；最终渲染显示材质，点光照亮周围并投下阴影

### Scenario: 材质预览不受打光影响
- GIVEN 摄影师在材质预览模式下
- WHEN 删除场景里全部灯光，或改变太阳方向
- THEN 画面不变

### Scenario: 白模不受环境影响
- GIVEN 摄影师在白模模式下，天空是程序化天空，太阳高度 35°
- WHEN 把太阳调到 5°，把天空换成纯色，打开雾，改环境光，或加一盏投射阴影的点光
- THEN 画面不变；转到另一个角度看，光仍从视角的左上方照来，物体不投影，接触处有 AO 的暗部

### Scenario: 线框切换
- GIVEN 摄影师在最终渲染模式下
- WHEN 按 `Shift + Z`
- THEN 切到线框；再按一次回到最终渲染

### Scenario: 显示模式记在本机
- GIVEN 摄影师把场景切到最终渲染后离开
- WHEN 重开这个场景
- THEN 仍是最终渲染；Cmd+Z 不会撤销显示模式的切换；同一场景在另一个标签页里的显示模式不受影响

### Scenario: 第一次打开按场景的建议方式
- GIVEN 本机从没打开过这个场景，助手把场景的显示方式设成了 `lit`
- WHEN 摄影师打开场景
- THEN 以最终渲染显示

## 按槽位分配材质

物件的每个材质槽位可以分配一种材质：原理化 BSDF，或带图案的程序化预设（石砖、木纹、大理石等）。基础体只有一个槽位，模型的槽位由几何代码划分。程序化预设按真实尺寸铺在物件表面，不依赖模型 UV，物件缩放时不拉伸。材质在材质预览、最终渲染和材质光照导出里显示。改动静默保存，Cmd+Z 可以撤销。

### Scenario: 给方块铺石砖
- GIVEN 场景里有一个 1 m 见方的方块
- WHEN 摄影师给它的槽位选「石砖」，再把方块沿 X 放大到 4 倍
- THEN 砖块大小不变，铺满更长的面，没有拉伸

### Scenario: 原理化 BSDF
- GIVEN 摄影师给一个球体的槽位选了原理化 BSDF
- WHEN 把金属度设为 1、糙度设为 0.2
- THEN 最终渲染里表面像抛光金属，映出天空

### Scenario: 半透明
- GIVEN 一块原理化 BSDF 的玻璃板立在一根柱子前
- WHEN 把 Alpha 设为 0.3
- THEN 能透过玻璃板看到柱子，玻璃板表面没有环境光遮蔽的阴影

### Scenario: 多选一起换材质
- GIVEN 选中了 5 根共用同一模型的柱子
- WHEN 给 `stone` 槽位选一种材质
- THEN 5 根柱子的 `stone` 槽位都换成它，只产生一个修订，一次 Cmd+Z 全部撤回

### Scenario: 预设转为原理化
- GIVEN 一个槽位用的是「漆面」预设
- WHEN 点「转为原理化」
- THEN 槽位改用原理化 BSDF，颜色、糙度、金属度沿用原来的值，画面看起来基本不变，可以继续调其他参数

### Scenario: 没有指定材质时按提示
- GIVEN 一个模型的槽位带提示 `wood`，没有分配材质
- WHEN 切到材质预览
- THEN 这个槽位显示为木纹；带不认识的提示的槽位显示模型代码里写的颜色，基础体显示中性浅灰

### Scenario: 不认识的材质
- GIVEN 场景里有一个槽位的材质是本版本不认识的预设
- WHEN 打开场景
- THEN 这个槽位显示中性灰，属性栏提示「未知材质」；其他编辑照常

## 复制材质

材质可以从一个物件复制到其他物件，参照 Blender 的「关联材质」；单个槽位的材质也可以复制、粘贴，包括跨场景。

### Scenario: 复制到选中物件
- GIVEN 选中了两个模型和一个方块，活动物件是一根槽位为 `stone`、`trim` 的柱子
- WHEN 执行「复制材质到选中物件」
- THEN 有同名槽位的模型得到相同的材质，没有同名槽位的不变；只产生一个修订，一次 Cmd+Z 撤回

### Scenario: 单槽位的物件复制给全部槽位
- GIVEN 活动物件是只有一个槽位的方块，另一个选中的模型有 3 个槽位
- WHEN 执行「复制材质到选中物件」
- THEN 模型的 3 个槽位都换成方块的材质

### Scenario: 跨场景粘贴
- GIVEN 摄影师在一个场景里对某个槽位「复制材质」
- WHEN 到另一个场景的物件槽位上「粘贴材质」
- THEN 材质和参数相同，可以撤销

## 编辑灯光与环境

摄影师可以添加平行光、点光、聚光，编辑它们的颜色、强度、阴影和光锥；天空、环境光和雾在属性区的「环境」选项卡里编辑，曝光在「渲染」选项卡和摄像机属性里。灯光、太阳、天空、环境光、雾和曝光只在最终渲染和材质光照导出里生效，白模用固定的工作室光；不在最终渲染模式时，「环境」选项卡提示环境在「最终渲染」里生效。天空是物理天空时，灯光按物理单位解释，环境光不生效，曝光由摄像机决定（见「物理天空」「摄像机曝光」）。改动静默保存，可以撤销。

### Scenario: 加一盏聚光
- GIVEN 摄影师在最终渲染模式下
- WHEN 用 Shift + A 加一盏聚光，把光锥角调到 30°，打开「投射阴影」
- THEN 光照范围和图标的光锥一致，物件在地面投下阴影；存储的光锥角为 π/12 弧度

### Scenario: 换灯光类型
- GIVEN 一盏聚光
- WHEN 把类型改成点光
- THEN 光锥角和柔化消失，颜色、强度、阴影设置保留

### Scenario: 白模里灯光不生效
- GIVEN 摄影师在白模模式下选中一盏灯
- WHEN 查看属性栏
- THEN 提示灯光在最终渲染模式下生效

### Scenario: 白模里打开环境选项卡
- GIVEN 摄影师在白模模式下
- WHEN 打开「环境」选项卡
- THEN 看到提示：环境在「最终渲染」里生效；仍可以编辑，改动静默保存

### Scenario: 调太阳高度
- GIVEN 天空是程序化天空
- WHEN 在「环境」选项卡里把太阳高度从 35° 调到 5°
- THEN 最终渲染里影子变长，天空变成黄昏色调；白模不变；Cmd+Z 回到 35°

### Scenario: 调曝光补偿
- GIVEN 一个只有两盏壁灯的室内场景，天空是程序化天空，最终渲染偏暗
- WHEN 在「渲染」选项卡里把「曝光补偿」调到 +2
- THEN 最终渲染变亮；白模不变；Cmd+Z 回到 0

### Scenario: 纯色天空和雾
- GIVEN 摄影师在最终渲染模式下打开「环境」选项卡
- WHEN 把天空改成纯色，打开雾并设置起止距离
- THEN 背景和雾按设置显示，与材质光照导出一致

## 手动编组

摄影师可以编组、取消编组、设置和清除父级，也可以在物件列表里拖动调整层级和顺序。这些操作都保持物件在画面中的位置，每个操作是一次修改、一步撤销，撤销后回到原来的父级、顺序和变换。

### Scenario: 编组
- GIVEN 选中了 3 个分属不同父级的物件
- WHEN 按 Ctrl + G
- THEN 出现一个新分组，3 个物件挂在它下面，画面中的位置不变；只产生一个修订
- WHEN 按 Cmd+Z
- THEN 分组消失，3 个物件回到原来的父级、顺序和变换

### Scenario: 取消编组
- GIVEN 选中一个旋转过、缩放过的分组
- WHEN 按 Ctrl + Alt + G
- THEN 分组被删除，子物件挂回它原来的父级，画面中的位置不变

### Scenario: 设置父级
- GIVEN 选中了两个物件，活动物件是一个空物体
- WHEN 按 Ctrl + P
- THEN 另一个物件挂到空物体下，位置不变；之后移动空物体，它跟着移动

### Scenario: 父级只能是分组
- GIVEN 选中了两个物件，活动物件是一个方块
- WHEN 按 Ctrl + P
- THEN 提示只能挂到分组或空物体下，场景不变

### Scenario: 清除父级
- GIVEN 选中一个挂在旋转过的分组里的物件
- WHEN 按 Alt + P
- THEN 物件挂回根，位置不变

### Scenario: 在物件列表里拖动
- GIVEN 物件列表里有一个分组和一个根下的物件
- WHEN 把物件拖到分组上
- THEN 物件挂进分组，画面中不动；拖到两行之间时，物件挂到那一行的父级下并排在该位置

### Scenario: 编组时助手改了其中一个物件
- GIVEN 摄影师选中 3 个物件准备编组，助手在此期间改了其中一个物件的位置
- WHEN 摄影师按 Ctrl + G
- THEN 编组按现有的冲突规则处理，不会出现物件跳位或丢失

## 助手配材质和打光

助手可以给物件分配材质、加灯光、调天空和雾，用材质光照回看画面，也可以编组和改挂物件。材质的可选项来自与编辑器同一份目录；写错时工具直接说明原因并列出可用项，不改场景。

### Scenario: 请助手布置黄昏
- GIVEN 摄影师请助手「把这个场景改成黄昏、墙用石砖、窗户用彩色玻璃、加两盏暖色壁灯」
- WHEN 助手完成这一轮
- THEN 场景里写入了黄昏的程序化天空、墙的石砖材质、窗户的原理化 BSDF 透射材质和两盏暖色点光；助手至少用一次材质光照回看

### Scenario: 写了不存在的材质
- GIVEN 助手给一个槽位写了目录里没有的预设，或参数超出范围
- WHEN 提交修改
- THEN 修改被拒绝，场景不变，助手得到原因和可用的预设或参数范围

### Scenario: 没有内置 HDRI
- GIVEN 助手把天空写成 HDRI
- WHEN 提交修改
- THEN 修改被拒绝，助手得到「暂无内置 HDRI，请用程序化天空或纯色」

### Scenario: 助手编组
- GIVEN 场景里有 4 根散放的柱子
- WHEN 助手把它们编进一个分组，再整体移动分组
- THEN 编组时柱子在画面中不动，之后随分组一起移动

### Scenario: 助手用材质光照回看
- GIVEN 助手打完光
- WHEN 用材质光照方式回看某台摄像机
- THEN 截图与编辑器最终渲染模式下这台摄像机的画面一致

## 模型存入资产库

摄影师可以把场景里的代码模型存进资产库。存进去的是摄影师当时看到的那一版模型、参数和材质；位置、旋转和缩放属于场景，不随资产保存。同一版模型配同样的材质，在库里只有一份，再存只追加分组。

### Scenario: 存入资产库
- GIVEN 场景里有一个已生成好的代码模型实例
- WHEN 摄影师选中它，在物件菜单里点「存入资产库」，确认标题并选一个分组
- THEN 资产库的该分组里出现这个模型，类型为「模型」，卡片缩略图显示它在场景里配的材质；标题默认是模型名；弹框里说明位置、旋转和缩放不随资产保存

### Scenario: 同一版模型再存一次
- GIVEN 某个模型已经存入资产库
- WHEN 摄影师对引用同一版模型、配同样材质的实例再点「存入资产库」，选另一个分组
- THEN 提示「已在资产库中」，不新建资产，只把它归入这个分组

### Scenario: 换了材质再存
- GIVEN 某个模型已经存入资产库
- WHEN 摄影师给场景里的这个实例换了一个槽位的材质，再点「存入资产库」
- THEN 资产库里多出一份资产，缩略图显示新的材质；原来那份不变

### Scenario: 不能存入的物件
- GIVEN 摄影师选中的是内置基础体、灯光、「模型不可用」的占位、还在生成中的模型，或改动还没保存完的模型实例
- WHEN 打开物件菜单
- THEN「存入资产库」不可点，并说明原因

### Scenario: 存入前模型被别人改了
- GIVEN 摄影师打开了存入弹框
- WHEN 助手在此期间改了这个实例的模型或材质，摄影师再点存入
- THEN 不存入，提示模型刚被修改；编辑器显示出新版后，弹框提示「模型已更新为最新版本」

### Scenario: 确认新版后再存
- GIVEN 弹框已提示「模型已更新为最新版本」
- WHEN 摄影师再点存入
- THEN 存进资产库的是新版模型和材质

## 从资产库放入模型

摄影师可以把资产库里的模型放进任意场景，模型带着资产的材质进来。放进来的模型与库里的那份互不影响：之后调参数、换材质只改这个场景。

### Scenario: 编辑器侧栏的资产面板

## 渲染器与输出分辨率

属性区参照 Blender 分成「渲染」「环境」「物件」三个选项卡。「渲染」里可以选渲染器和输出分辨率，调曝光，并看到当前的渲染后端。曝光在程序化天空和纯色天空下是曝光补偿，在物理天空下是默认摄像机的曝光（只用于视口的自由视角和助手的临时视点）：自动或手动，自动时调补偿，手动时调默认曝光值（EV100）。渲染器有工作台、实时 GI，以及还不能选的「路径追踪 · 规划中」：工作台是标准的光栅化渲染；实时 GI 在它之上加入物体之间的间接光反弹、反射和接触阴影，只计算画面里可见的表面。渲染器决定编辑器的最终渲染、助手的材质光照回看和材质光照导出的画面；白模、线框、材质预览和线稿总按工作台画，正交视图也按工作台显示。灯光图标、摄像机视锥、空物体等辅助对象在视口里照常显示，但不参与光照：不遮挡、不压暗周围。输出分辨率只决定导出图的长边。这些都是场景的设置，静默保存，可以撤销，其他标签页和助手看到的一样。

## 物理天空

「环境」选项卡的天空类型可以选「物理天空」，与程序化天空、纯色并列。物理天空按地点（城市或经纬度）、日期、当地时刻和场景的正北方向推算太阳的真实位置，也可以切到手动调太阳角度。天空颜色、太阳光和天空光照由同一套物理大气算出，覆盖晨昏蒙影；海拔、空气密度、尘埃密度和臭氧可调，有「晴朗」「雾霾」「高原」「沙尘」四个预设；太阳的亮度和色温可调。物理天空下场景按真实照度渲染：太阳和平行光按照度（lux），点光和聚光按坎德拉，自发光按亮度（cd/m²），环境光不生效。黄昏和夜里场景按真实照度变暗；默认的环境测光让入夜平滑变暗，只比正午暗 2–4 档，夜里画面略偏蓝（见「摄像机曝光」「夜空」）；手动曝光按真实照度成像。太阳落下后天空经晨昏蒙影变暗，地点模式下夜空随之显现（见「夜空」）。白模不受物理天空影响。改动静默保存，可以撤销。

城市表离线可用，数据来自 GeoNames（CC BY 4.0），城市下拉的底部注明来源。已知局限：太阳在地平线以下 6°–9° 时，天空比实际亮 2–3 档。

## 摄像机曝光

物理天空下，曝光是观看者的设置，可选自动或手动。每台摄像机的属性里有「曝光」：
- 环境测光（新建的摄像机缺省）：按场景的环境光测光，不看画面。从下午起画面匀速变暗，满月之夜比正午暗约 2.5 档、新月之夜约 3.5 档；太阳低时朝向太阳的面不会比当天正午更亮；不用调曝光也看得清；可以加减补偿（±5 档）。转动视角、切换摄像机不改变曝光。测光看的是场景原点的天光，室内或浓荫下的取景会偏暗，用补偿调整。光圈只决定景深。
- 手动：ISO、快门和光圈，光圈与景深共用，同时决定亮度和景深，旁边显示 EV100，按真实照度成像。

视口的自由视角和助手的临时视点、预设视角是「默认摄像机」，在「渲染」选项卡里设置：缺省环境测光，补偿可调；切成手动时用默认曝光值（EV100，缺省 15，约为晴天）。从摄像机取景、导出和按摄像机回看时用这台摄像机的曝光。夜色（见「夜空」）对两种曝光都生效。其他天空下这些设置保存但不生效，界面置灰并说明原因。

- GIVEN 物理天空，晴朗预设，太阳高度 60°，摄像机设为手动曝光，ISO 100、1/125 s、f/16
- WHEN 导出材质光照图
- THEN 画面曝光正常，不偏暗也不过曝
- WHEN 把时刻改到日落后 20 分钟，曝光不变，再导出
- THEN 画面明显变暗

### Scenario: 光圈同时改亮度和景深
- GIVEN 物理天空，一台手动曝光、打开了景深的摄像机，光圈 f/8
- WHEN 把光圈开到 f/4
- THEN 画面亮两档，景深变浅；环境测光的摄像机改光圈时只有景深变化

### Scenario: 视口的默认曝光
- GIVEN 物理天空，视口在自由视角下，「渲染」选项卡的曝光是手动
- WHEN 把默认曝光从 15 调到 12
- THEN 视口亮三档；切到某台摄像机的相机视图时，按这台摄像机的曝光显示，不受默认曝光影响

### Scenario: 添加摄像机时沿用默认摄像机的曝光
- GIVEN 物理天空，「渲染」选项卡是环境测光、补偿 +1
- WHEN 按当前视角添加摄像机
- THEN 新摄像机是环境测光、补偿 +1，相机视图与视口一样亮

### Scenario: 添加摄像机时亮度一致
- GIVEN 物理天空，「渲染」选项卡是手动曝光，默认曝光是 12
- WHEN 按当前视角添加摄像机，再按 `0` 进入相机视图
- THEN 相机视图与添加之前的视口一样亮；新摄像机的 ISO 是 100，快门是与默认曝光最接近的标准档

### Scenario: 添加摄像机时快门不够长
- GIVEN 物理天空，「渲染」选项卡是手动曝光，默认曝光是 −5
- WHEN 按当前视角添加摄像机
- THEN 新摄像机的快门是 30 s，ISO 调高到与默认曝光最接近的档位，相机视图与视口一样亮

已知局限：默认曝光高于 EV100 约 17.9 时，缺省光圈 f/2.8 加上 1/8000 s 和 ISO 25 也不够暗，新添加的摄像机比视口暗，最多约 2 档，需要手动收光圈。

### Scenario: 其他天空下曝光置灰
- GIVEN 天空是程序化天空
- WHEN 查看摄像机属性的曝光一组
- THEN 整组（模式、补偿、ISO、快门）置灰，提示只在物理天空下生效；「渲染」选项卡照旧显示曝光补偿

## 夜空

物理天空的地点模式下，太阳落下后天上出现月亮、星星、银河和夜天光，位置都按地点、日期和当地时刻算出，随时刻转动，正北方向同样作用于它们。月亮按真实的位置、月相和视直径绘制，带月面纹理，亮面朝向太阳；月光是第二个平行光源，经大气衰减，满月约 0.3 lux，月亮在地平线以上、太阳低于 −6° 时投射阴影；月亮也照亮天空。星星取自 BSC5 星表中视星等不超过 6.5 的 8404 颗亮星，颜色按星表的色指数，地平线附近变暗变红。银河由渲染端程序化生成，银心、银道和暗隙的位置真实，细部结构是近似的。无月的晴夜天空有一层很暗的夜天光。夜空的光计入天空光照、全局雾的亮度和环境测光的测光。默认设置下无月的夜空是深蓝而不是黑色，银河和亮星可见。

入夜后画面渐进偏蓝、降饱和（夜色），模拟人眼的夜视和电影「日拍夜」的调色；「夜空」一组的「夜色」滑杆调强度，调到 0 为纯物理颜色。夜色属于场景，对所有摄像机和两种曝光模式都一样，地点和手动两种太阳模式下都生效，黄金时刻之前不起作用。

「环境」选项卡的「夜空」一组有月亮、星星（含夜天光）、银河三个开关，月亮、星空各自的亮度倍率和色温（6500 K 为物理计算的颜色），以及夜色强度；手动模式下除夜色外这一组置灰，月亮和星空不画。时间一组显示当天的月相与照亮比例、月出月落，以及前后最近的满月和新月日期，点日期即改成那一天。白天的天空盖过星星，月亮照样看得见。星表来自 Yale 亮星星表（Hoffleit & Warren 1991，经 CDS/VizieR），月面纹理来自 NASA SVS，「夜空」一组底部注明星表出处。白模不受夜空影响。改动静默保存，可以撤销。

已知局限：不画行星、日食和月食、地照、光污染；月面纹理不计天平动；星星不闪烁，不计自行。

### Scenario: 北京的满月之夜
- GIVEN 物理天空的地点模式，城市选「北京」，日期是一个满月日，当地时刻 22:00
- WHEN 打开最终渲染，不调曝光（默认环境测光）
- THEN 月亮的位置与天文数据相差不超过 1°，是满月；月光照亮院子，看得清，画面比正午暗 2–3 档、略偏蓝；影子朝向背离月亮的一侧；天空是暗蓝色，能看到较亮的星星
- WHEN 把视口改成手动曝光，默认曝光调到 EV100 约 −3
- THEN 同样看得清院子

### Scenario: 月相
- GIVEN 物理天空的地点模式，日期是上弦月当天，时刻在日落后
- WHEN 查看天上的月亮
- THEN 月亮只亮一半，亮面朝向太阳落下的一侧；时间一组显示「上弦月」和照亮比例

### Scenario: 北极星与星空旋转
- GIVEN 城市选「北京」，太阳在地平线以下
- WHEN 朝正北看，再把时刻往后拖
- THEN 北极星在正北，高度约等于北京的纬度；星空绕北极星转动

### Scenario: 南半球的星空
- GIVEN 城市选「悉尼」，太阳在地平线以下
- WHEN 朝南看
- THEN 能看到南十字座和麦哲伦云，北极星在地平线以下

### Scenario: 新月之夜看银河
- GIVEN 北京的新月之夜，银河在天上
- WHEN 打开最终渲染，不调曝光（默认环境测光）
- THEN 没有月光；天空是深蓝而不是黑色，能看到银河的亮带和暗隙；场景只由星光、银河、夜天光和灯光照亮，比正午暗 3–4 档，仍能分辨

### Scenario: 夜色
- GIVEN 满月之夜，默认设置
- WHEN 把「夜色」调到 0
- THEN 画面的蓝调和降饱和消失，颜色为物理计算，亮度不变；调回 1 恢复
- WHEN 把时刻拖回下午
- THEN 夜色逐渐消失，黄金时刻之前画面与没有夜色时相同

### Scenario: 调月亮和星空
- GIVEN 满月之夜
- WHEN 把月亮亮度调到 2，或把月亮色温调高
- THEN 月盘、月光和月光照亮的天空一起变亮一档，或一起变冷；调回 1 和 6500 K 后与调之前相同
- WHEN 调星空的亮度或色温
- THEN 星星、银河和夜天光一起变化

### Scenario: 开关夜空
- GIVEN 满月之夜
- WHEN 分别关闭月亮、星星、银河
- THEN 对应的部分从天空和光照里消失，其余不变；关闭月亮时月光和月光照亮的天空一起消失

### Scenario: 手动模式没有夜空
- GIVEN 物理天空的地点模式，满月之夜
- WHEN 把太阳位置改为「手动角度」
- THEN 月亮和星空不画，「夜空」一组置灰并说明夜空只在地点模式下生效

### Scenario: 跳到满月
- GIVEN 物理天空的地点模式
- WHEN 在时间一组点「下一个满月」的日期
- THEN 日期改成那一天，月亮按那天的位置和月相显示；Cmd+Z 回到原来的日期

### Scenario: 夜空上线后的旧导出
- GIVEN 夜空上线之前存的物理天空场景，画布上有它的材质光照导出图
- WHEN 夜空上线后打开画布
- THEN 这些导出图各显示一次「场景已更新」；程序化天空和纯色天空的导出不受影响
- WHEN 之后改夜空的任一字段
- THEN 材质光照导出显示「场景已更新」，白模和线稿导出不显示

### Scenario: 请助手安排满月之夜
- GIVEN 摄影师请助手「改成北京下一个满月的晚上十点，拍月光下的院子」
- WHEN 助手完成这一轮
- THEN 场景里写入了物理天空（北京、月亮参考给出的满月日期、22:00），摄像机用环境测光或设了夜景的手动曝光；助手至少用一次材质光照回看。助手读场景和写入环境时能看到月亮参考：当前月亮的高度和方位、月相与照亮比例、月出月落、前后最近的满月和新月
- WHEN 助手在程序化天空里写 `night`，或写超出范围的亮度、色温
- THEN 修改被拒绝，场景不变，助手得到原因

## architecture: ADD 图像文档模块

### 职责与边界
- 依赖通用文档底座：图像文档以文档类型端口注册为 `layered_image` 类型，节点类型为 `core.layered_image`。读取、命令、回收站和历史都走通用入口。
- `backend/internal/creativeimagedoc`：
  - 图像文档快照的 schema 校验、单元版本与命令应用、恢复。
  - 像素分块清单的校验：引用的分块存在、属于本账号、已通过校验，清单不越出文档上限。
  - 导出编排（新图片节点，或写回来源图片节点作为新版本）；预览图的写入。
- 不职责：
  - 合成、渲染；
  - 执行助手代码、解析 ABR；
  - 画布节点的布局规则（调画布命令层完成）；
  - 分块字节的存储、配额和回收（归 `creativemedia`）。
- 依赖方向：
  - `creativeimagedoc` → 通用文档层 / `creativecontent` / `creativemedia` / `creativestaging` / `creativecanvas`（命令层）/ `platform/store` / `platform/realtime`。
  - `creativeimagedoc` 不 import gin，`gin.Context` 不下穿（ADR-003）。
  - 画布读取导出图节点时，`creativecanvas` 经自己定义的端口询问来源文档是否已更新（进程启动时注册实现），`creativecanvas` 不 import `creativeimagedoc`。
  - `creativeimagedoc` 与 `creativeimageedit`（图片节点的裁切、压缩）互不依赖。
- 前端 `frontend/src/creative-image/`：
  - 组成：编辑器外壳（React）、文档状态（快照 + outbox + 本人撤销栈）、光栅引擎（分块存储、GPU 合成器、工具）、Worker（分块编解码、导出编码、CPU 重计算）。
  - 光栅引擎不依赖编辑器外壳，界面只经命令和视图状态访问它。
  - 编辑视图嵌入画布的同一个助手面板。
  - 画布页不加载光栅引擎；打开编辑器时才加载。
- 合成、预览和导出只在浏览器完成；服务端不渲染。视口、预览和导出经同一条合成管线出图，同一快照、同一参数的导出结果逐像素相同。

### 关键数据流
- 像素编辑：
  1. 光栅引擎记录脏分块，Worker 编码并计算内容哈希。
  2. 上传服务端还没有的分块。
  3. outbox 提交带新分块清单的命令 → 新文档修订 → 账号失效通知 → 其他标签页按单元重读，并按哈希拉取缺少的分块。
- 参数编辑（图层属性、调整、文字、路径）：outbox 直接提交命令。
- 预览图：编辑器在保存后空闲时渲染并暂存上传，写入文档，不推进单元修订号；画布节点显示它。
- 导出：
  1. 编辑器按分块渲染整图、编码、暂存上传。
  2. 导出接口经画布命令层新建图片节点，或给来源图片节点加版本，并写入来源记录。
  3. 读画布时经上述端口计算过时状态。
- 从图片节点打开：
  1. 画布命令新建文档节点，记录来源节点与内容修订。
  2. 编辑器解码原图（方向校正、转 sRGB），切块上传后提交命令，建立底层图层。

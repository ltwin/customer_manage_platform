# 创意空间图像编辑器（类 Photoshop）探索共识

## 目标

打通拍摄后期全流程：摄影师和专业创作者在创意空间里完成**人像精修**和 **CG 合成**的像素级后期，不必为此离开平台去 Photoshop。

owner 原始诉求（2026-10-22）：在创意空间引入类 Photoshop 的图像编辑器，首版可以简化，但要有核心功能：
- 图层系统：蒙版、混合模式、剪贴蒙版、图层样式、透明度锁定等，接近 PS 核心图层功能
- 选区：常规选区工具；技术允许时加智能选区（一键选择主体）
- 画笔：柔边圆、硬边圆等；支持导入 `.abr` 画笔作为资产（资产库新增画笔类型）
- 调色：曲线、色相/饱和度、亮度/对比度、色调分离、色彩平衡等
- 变形：自由变换、透视、扭曲、操控变形
- 滤镜：液化、高反差保留等修图常用滤镜
- 这是重型组件，先调研有没有可用的前沿开源项目；AI 选区等重计算如有第三方 API 可优先用

## 已定取舍（owner 决定）

1. **首版同时服务人像精修和 CG 合成，并补上修复类工具**（2026-10-22）：污点修复、修复画笔、仿制图章进入首版。范围最大、工期最长，owner 知情。
2. **产物形态：分层文档节点 + 导出**（2026-10-22）：
   - 画布上新增「图像文档」节点，双击进入全屏编辑器，分层工程可以反复打开。
   - 导出平面图落成画布图片节点，记录来源（`based_on`），文档改了提示过时。
   - 从图片节点打开编辑器时，可以选择把导出写回原图片节点、作为它的新版本。
   - 理由：完全复用 3D 场景已经走通的「文档类型 + 全屏编辑视图 + 导出回画布」链路；图片节点的版本语义不变。
3. **8 位工作精度，PSD 读写放到后续**（2026-10-22）：
   - 首版导出 PNG / JPEG / WebP。
   - 图层模型（混合模式、蒙版、剪贴、样式、调整图层）按 PSD 的概念和取值对齐，以后加 PSD 导入导出不用改模型。做法参照场景格式对齐 three.js 的先例。
4. **选型：自研外壳 + 自研分块 GPU 合成核心 + 构件库**（2026-10-22，owner 大体同意调研推荐）：
   - 不整体嵌入现成编辑器。
   - 算法以 PhotoCraft（Apache-2.0）和论文为参考移植；ABR 解析用 ag-psd（MIT）。
   - Epic 第一个子项做穿刺，同时实测对照组「PhotoCraft 引擎编译成 WASM + 我们自己的 React 界面」。对照组明显更好时再回来改选型。
5. **AI 选区**（2026-10-22，owner 大体同意）：
   - 点选/框选交互分割在浏览器端跑（SAM 2.1 / SlimSAM）。
   - 选择主体先接一家服务端 API，接口按可换供应商设计。
   - 智能选区成本可忽略，不扣积分。
   - 不引入非商用或 AGPL 许可的模型。
6. **助手能力**（2026-10-22）：
   - 能看合成图和图层结构。
   - 能做参数化操作：调整图层、图层属性、用智能选区建蒙版、生成式填充、导出。
   - **能用画笔：以代码的形式作画**（owner 补充）。
7. **首版范围补充**（2026-10-22）：生成式填充、钢笔、渐变、文字列为首版基本功能。橡皮擦、吸管、抓手/缩放、裁切、油漆桶默认包含。
8. **画笔资产粒度**（2026-10-22，owner 大体同意）：一个 `.abr` 文件导入后是一份「画笔包」资产，包里的画笔可以单独选用。
9. **钢笔首版只做路径**（2026-10-22）：画和编辑路径、路径转选区、填充或描边路径。矢量形状图层（矩形、椭圆形状工具）放后续。
10. **走 Epic**（2026-10-22）：在同一 ID `creative-image-editor` 上建 Epic，预估 13–14 个子项，第一个子项是穿刺。
11. **首版补上中性灰修图与溶图能力**（2026-10-22，owner 审阅 Epic 草稿时补充）：
    - 加深 / 减淡工具（中性灰修图），排在 I3。
    - 混合颜色带（合成溶图），排在 I13。
    - 新建图层对话框（Photoshop 的 `Ctrl+Shift+N`），选柔光、强光、线性光等有中性色的模式时可以勾选「填充中性色」，排在 I1。
12. **浏览器保留的组合键**（2026-10-22）：`Ctrl/Cmd+Shift+N` 在 Chrome 和 Safari 里是开无痕窗口，普通标签页拿不到。
    - 采用：键位按 Photoshop 原样定义。安装成应用的窗口里，或浏览器全屏 + Keyboard Lock 时，直接生效；普通标签页提供替代操作（如 Alt 点新建图层按钮）。
    - I0 实测各环境；是否把创意空间做成可安装应用，由 owner 决定（Epic design 未决事项 13）。

## 事实依据（代码与契约现状）

- **已有图片编辑一期**（V6-076，`.codestable/requirements/creative-workspace-v6/items/V6-076.md`）：图片节点工具条「图片编辑」菜单只有「裁切」「压缩」，由服务端 libvips 子进程处理（`backend/internal/creativeimageedit/codec.go`），结果作为节点新版本采用。新编辑器的入口可以挂在这个菜单下。
- **通用文档底座可复用**（`.lti/contracts/architecture.md`「通用文档底座」、`patterns: 文档类型端口`）：修订、单元并发、恢复、回收站、画布接入都由 `creativedocument` 统一提供；新类型实现 `creativedocument.Type` 并声明唯一的节点类型（如 `scene` ↔ `core.scene`）。
- **场景的导出链路可复用**（`architecture: 场景模块`「关键数据流」）：前端渲染 → 暂存上传 → 画布命令层建图片节点写 `based_on` → 读画布时经端口算过时状态（`backend/internal/creativecanvas/scene_exports.go`）。
- **媒体上限**（`backend/internal/creativemedia/config.go:28-39`）：单张图片 ≤ 25 MB、长边 ≤ 12000、像素 ≤ 8192×8192（约 67MP）。60MP 原片在像素上限内，但未压缩的分层像素远超 25 MB，图层像素的存储方式需要专门设计（见未决项）。
- **资产库加类型有先例**（迁移 `0079_creative_asset_model.up.sql`、`data: 模型资产`）：`creative_assets.kind` 的 CHECK 加值，分组、标签、评分、回收站一视同仁；`model` 只能放进场景、不能放上画布。画笔类型可以照这个模式加。
- **前端渲染约定**（`patterns: 场景着色写法`）：场景和模型渲染统一走 three.js `WebGPURenderer` + TSL，静态检查禁止 GLSL 字符串和 `ShaderMaterial`。约定的适用范围是 `frontend/src/creative-scene/` 和渲染场景/模型的代码，2D 画布不受约束；图像编辑器的 GPU 合成是否沿用这套约定待定（见未决项）。
- **协同撤销原则**（owner 2026-10-16）：Cmd+Z 只撤销自己的操作，历史列表可以回退任何人；任何可编辑对象都不做共享时间线。图像文档同样适用。
- **受众含专业创作者**：交互按专业工具惯例（这里是 Photoshop 的键位和行为），不为新手加特殊兜底。

## 调研结论（详见 `research/editor-and-ai-options.md`）

- **没有可以直接嵌进来的现成编辑器**：
  - Photopea 闭源，要授权费，只能 iframe 嵌入，界面和存储都不是我们的。
  - PhotoCraft（storytold/photocraft，Apache-2.0 / MIT，Rust + wgpu，可编译为 WASM）能力最全，液化、操控变形、ABR 导入、修复工具都有。但它 2026-09-30 才建库，自评 alpha，25 项性能预算 22 项未达标；界面是 egui，不是 React；自带文档模型；「选择主体」不是 AI。
  - photobaer 是 AGPL；Graphite 的栅格能力不足；Canvas2D 类编辑器撑不住专业修图。
- **PhotoCraft 适合当算法参考**：它的液化、ARAP 操控变形、修复、ABR 解析、混合模式和图层样式都是 Apache-2.0 的 clean-room 实现，可以移植。
- **AI 选区的可用组合**：
  - 交互分割（点选/框选）：SAM 2.1 / SlimSAM（Apache-2.0）可以在浏览器端用 WebGPU 跑，没有调用费用。
  - 选择主体：BiRefNet / BEN2（MIT），可以在浏览器端跑（lite 版 fp16 约 115 MB），也可以调用阿里云「通用高清分割」API（输出全尺寸四通道 PNG，边长 < 10000，通用分割约 ¥0.002/次；平台文档已停止维护，长期可用性存疑）。
  - 发丝细化：先做 GPU 上的导向滤波边缘细化，matting 模型放到后续。
  - 排除：RMBG-2.0（CC BY-NC）、@imgly/background-removal（AGPL）。SAM 3 是 Meta 自定义许可，要用的话先过法务。
- **大图是核心技术难点**：60MP 一层 RGBA8 约 241 MB；WebGPU 默认纹理边长上限是 8192。合成核心必须做分块存储、按视口和缩放级别加载，不能一层一张纹理。

## 工作假设（待 design 核实，owner 可随时推翻）

- 编辑器在浏览器里完成交互渲染和合成，服务端不渲染（沿用场景的决定）。
- **助手代码作画**的形态（细节在对应子项 design 定）：
  - 助手写绘画代码，在已有的客户端代码沙箱里执行（`patterns: 客户端代码沙箱`：隔离 iframe、禁网、硬超时）。
  - 代码输出的是**结构化的绘制指令**，不是像素：笔触路径（点、压力、倾斜）、所用画笔（含导入的 ABR 画笔）、颜色、大小，以及填充、渐变、钢笔路径。宿主校验后交给编辑器的画笔引擎渲染。
  - 推荐理由：
    - 助手的笔触和摄影师手绘的效果一致，能用画笔资产。
    - 回传的数据小，好校验。
    - 结果可以重放；保留代码和参数，可以「调参数重画」，与场景模型「代码 + 参数」的做法对称。
  - 程序化纹理一类需要逐像素生成的内容，以后再加像素输出通道。
- **生成式填充**走已有生成链路（gpt-image-2.5 带蒙版局部重绘），按现有积分规则提交即扣、失败退回，结果落成新图层。

## 成功标准（草案，Epic proposal 时由 owner 确认）

- **端到端样张**：两张样张全程在平台内完成并导出。
  - 人像精修：修复、液化、高反差保留 / 频率分离、调色。
  - CG 合成：3D 场景导出图 + 抠出的人物 + 变形 + 混合模式 + 调色 + 生成式填充。
- **大图性能**：在基准设备上，60MP、10 层以上，笔触跟手，图层属性调整实时预览。具体数值由穿刺子项测定后写进 Epic design。
- **显示与导出一致**：混合模式、调整图层的结果与 Photoshop 参考图的误差在阈值内（参考图集和阈值在 design 定）。
- **文档可靠**：反复打开图层完整；历史版本可恢复；多标签页同步；摄影师的 Cmd+Z 只撤销自己的操作。
- **助手**：能读文档、做参数化操作、用代码作画并落成图层；摄影师能从历史回退助手的改动。

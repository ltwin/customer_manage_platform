# 角色卡

## Why

生图模型多半不认识摄影师要画的角色（二游角色、原创角色、只有一张设定图的角色），每次生成都要重新找参考图、重新描述外貌，同一个角色在九张分镜里长得不一样。角色卡把一个角色的参考图和外貌描述存成资产库里一份可复用、有版本的资产，连到生成节点就能用。

## What Changes

- 资产库新增资产类型 `character`（角色卡）：参考图（带视角）、外貌描述、原始素材，加身份字段所属 IP、作品、版本说明、别名，以及可选的来源备注。不做版权或授权限制。沿用资产库的分组、标签、评分、回收站、筛选和查看浮窗。
- 新建角色卡与存新版本两个接口；改角色卡产生新版本，已经放在画布上的角色卡停在原版本并提示有新版本。入口：资产库「新建角色卡」、资产库多选图片和画布图片节点的「创建角色卡」、查看浮窗的「编辑角色卡」。
- 内置角色 IP 目录（首批 50–100 个常见 IP，作品带简称别名）、写入时的 IP 与作品归一、联想接口；资产库按 IP、作品筛选，列表在标题下显示 IP · 作品 · 版本说明。
- 画布节点 `core.character`：放进画布，连到生成节点做参考，在提示词里 `@` 它。
- 生成受理时把角色卡展开成参考图和「角色设定」段，超出模型参考上限时整体拒绝；生成记录写明角色卡版本。
- 助手：`search_assets` / `read_asset` 支持角色卡和 IP、作品过滤，`edit_canvas` 能放置角色卡节点并连线，对话输入框能引用角色卡；外部助手的只读工具随之支持。
- 后端开工前先做一次参考图一致性调查，按事先定好的基线和判据确定参考图上限、视角枚举和展开写法（见 design「未决事项」）。

## Acceptance Criteria

建卡与资产库：

- WHEN 摄影师在资产库多选三张某角色的图片，选「创建角色卡」，填上名字和外貌描述并指定每张图的视角
  THEN 资产库出现这张角色卡，封面是第一张参考图；查看浮窗里能看到参考图（带视角）、外貌描述，以及填了的 IP、作品和来源备注。整个过程没有版权确认或授权步骤，来源字段都可以不填。
- WHEN 建卡请求的参考图里有一张不属于当前账号、不是图片、还没处理完，或不能用作生成参考
  THEN 返回 400 并指出是哪一张，资产库里不出现角色卡，也不留下内容或修订；同一张可展示的图放进「原始素材」可以正常保存。
- WHEN 摄影师建卡时在「所属 IP」里输入「Genshin」
  THEN 候选里出现「原神」；即使直接保存「Genshin」，角色卡也归到内置的原神下，按「原神」筛选能找到它。
- WHEN 摄影师在「所属 IP」里输入一个候选里没有的名字（自己的原创系列）并保存
  THEN 下次建卡时这个名字出现在候选里，并显示已有几张角色卡。
- WHEN 资产库里有两张「阿尔托莉雅」，作品分别是 Fate/stay night 和 Fate/Grand Order，都没有填版本说明
  THEN 两张卡的标题都是「阿尔托莉雅」，但资产列表、选参考的候选和助手给出的候选里，标题下都显示「Fate · Fate/stay night」「Fate · Fate/Grand Order」，能区分它们。
- WHEN 摄影师按作品筛选，分别输入「Fate/Grand Order」和「FGO」
  THEN 两次都只出现 FGO 那张；输入一个在多个 IP 下都是作品简称的词时，提示有歧义并列出候选，而不是随便选一个。
- WHEN 摄影师先用自建 IP「某系列」建了卡，之后版本更新时内置目录收录了「某系列」
  THEN 用「某系列」筛选，更新前后都能找到这张旧卡。

版本：

- WHEN 摄影师改了角色卡的外貌描述并保存
  THEN 角色卡变成新版本；画布上已有的这张角色卡仍是原来的版本，节点上提示有新版本，点「更新」后换成新版本，可撤销。
- WHEN 两个标签页基于同一版本先后保存角色卡
  THEN 后保存的返回 409 冲突，提示重新读取，不覆盖前一次保存。
- WHEN 摄影师没改任何内容又点了保存
  THEN 不产生新版本。

生成：

- WHEN 摄影师把角色卡放进画布，连到一个生成节点，在提示词里 `@` 它并生成
  THEN 生成请求带上了角色卡的全部参考图和外貌描述；生成结果的信息里能看到用的是哪张角色卡的哪个版本。
- WHEN 一个生成节点连了三张角色卡，展开后的参考图超过当前模型的上限
  THEN 生成不受理，提示上限、展开后的总数和每张角色卡各占几张，不会悄悄丢掉一部分参考图，也不计费。
- WHEN 摄影师把角色卡节点连到非生成节点，或作为数据输入
  THEN 连线被拒绝。
- WHEN 摄影师把一张角色卡移进回收站，或彻底删除
  THEN 资产库里看不到它；画布上已经放置的角色卡节点照常能用来生成，只是不再提示新版本。
- WHEN 用角色卡生成之后，摄影师删掉画布上的角色卡节点、彻底删除角色卡资产，后台随后清理了无人引用的内容
  THEN 打开那次生成的结果，仍能看到用的是哪张角色卡的哪个版本，并能读出它的参考图和外貌描述。

助手：

- WHEN 摄影师在对话里说「用芙宁娜的角色卡出一张正面半身」
  THEN 助手能找到这张角色卡，放到画布上、连到生成节点并生成，不需要摄影师手动连线，也不逐张连它的参考图。
- WHEN 摄影师说「用 FGO 里第三灵基的 Saber」
  THEN 助手按 IP、作品、别名和版本说明定位到唯一一张角色卡；有多张符合时列出来让摄影师选，而不是随便挑一张。
- WHEN 外部助手经 MCP 搜索和读取角色卡
  THEN 得到与内置助手相同的要点和载荷，并按参考图顺序拿到全部参考图（沿用现有的整账号连接授权）；某张图无法压缩到可发送的大小时只省略这一张，并说明原因。
- WHEN 内置助手当前用的模型不能看图，或本次对话没有授权图片预览
  THEN 读取角色卡时只给文字，并说明参考图因此没有附上。

导出预留：

- WHEN 检查任意一个角色卡版本的载荷
  THEN 里面只有文字、本账号的不可变图片修订 ID 和全局的 IP 目录 key，不含画布、节点、项目、资产的引用。

## 范围与非目标

- 非目标：
  - **版权与授权限制**。来源字段全部可选、只做备注；不加版权确认、按用途授权或选图提示（owner 2026-11-10）。
  - **外部助手的连接级图片授权**。沿用现有整账号连接授权（owner 2026-11-10）。
  - **助手建草稿角色卡**（`create_character`、对话里的草稿卡片、「存为新角色卡 / 更新原角色卡」）和**角色设定图模板**（内置 Skill、画布图片节点的「生成角色设定图」）。拆到后续 Feature，依赖本次的角色卡、建卡和存新版本接口（owner 2026-11-10）。
  - **真人角色**。只支持虚构角色（原创或作品衍生），不支持基于真人照片（coser、客户）建卡（owner 2026-11-10）。
  - 角色卡市场、分享链接、导入导出、跨账号收藏。只保证版本载荷可导出，不建任何表和接口（owner 2026-11-10）。
  - 「角色 → 造型」两层。换装就复制成一张新角色卡（owner 2026-11-10）。
  - 角色以外的主体（宠物、道具、服装）（owner 2026-11-10）。
  - IP 管理页（改名、合并、删除自建 IP）、内置角色卡（带官方图的角色）。
  - LoRA 等模型训练。一致性只靠参考图和外貌描述。
  - 3D 角色模型作为角色卡的一种表示（随 `cosplay-pipeline` CP-17 和姿态 Epic 再做）。
  - 策划人设章节改为引用角色卡、角色卡改了以后提示分镜过时（由 `cosplay-pipeline` 承接）。

角色卡是通用基础设施，不限于 cosplay；cosplay 策划以后引用角色卡版本。

## 决策记录

- 2026-11-10 owner：先做私有角色卡，架构预留以后接入角色卡市场。市场的难点是热门角色多为 IP 衍生（平台会变成分发者）、真人肖像、审核合规、跨账号数据，以及供给冷启动。
- 2026-11-10 owner：只支持虚构角色；不分「角色 → 造型」两层；只做角色；角色卡是通用基础设施，独立于 `cosplay-pipeline`。
- 2026-11-10 owner：角色身份用「所属 IP + 作品 + 版本说明 + 别名」。IP 要能选而不是手填：内置常见 IP 目录，加账号自建（输入新名字即新建）；首版不做 IP 管理页，角色卡里存 IP 名字快照和可选的目录 `key`。
- 2026-11-10 owner：做成一个 Feature，不做 Epic。原先起草的 Epic 按「存储 → 生成 → 助手建草稿」拆了三个子项，但只存不用对摄影师没有价值；建卡加用卡生成是一个完整的闭环，一次交付。助手建草稿和设定图模板是建立在它之上的扩展，拆成后续 Feature。
- 2026-11-10 owner：不搞版权和授权限制。二创是常见需求，主流模型一般也不拒绝 IP 类创作，限制只会打击创作热情。来源字段改为可选备注；建卡时只把生成受理本来就有的检查提前，避免「建卡成功、生成失败」。
- 2026-11-10 owner：外部助手沿用现有整账号连接授权，读取角色卡时附全部参考图；按图片预览授权降级只用于内置助手。
- 2026-11-10 方案评审修订：展开改到路由预检之前，由预检、锁内受理、提示词编译共用；角色卡版本由执行和结果版本的输入关系持有；作品带别名并定义歧义；搜索投影改用非空部分索引并兼容目录扩充；同名卡靠列表显示 IP · 作品 · 版本说明区分；一致性调查补基线和采用判据。
- 2026-11-10 起草：角色卡是资产类型，不是文档类型，也不是资产之外的独立实体，理由见 design.md「设计上下文与关键决策」。

## Impact

- 代码：
  - 后端 `creativecontent`、`creativelibrary`、`creativecanvas`、`creativeagent`、`creativereference`、`platform/httpapi`，迁移一个。`creativegeneration` 不改代码，但预检拿到的参考变成展开后的图片。
  - 前端 `creative-canvas/assets`、`creative-canvas/viewer`、`creative-canvas/editor`。
- 契约：
  - OpenAPI 新增三个接口；资产 `kind` 枚举加 `character`，资产列表加两个过滤。
  - 助手工具参数扩展；画布节点类型加一个。
  - 全部见本 Feature `contracts.md`。
- 外部：
  - 生图路由（aicodewith、RunningHub）只是参考图变多，接口不变。
  - 外部助手（MCP）的工具说明随之更新。

## Risk Notes

- **trust-boundary**：新增两个写接口，载荷里有图片修订 ID，服务端要逐张复核属于本账号、是 `image`、已就绪，`views` 内的还要能用作生成参考，防止引用别人的或未处理完的图；生成预检、受理和派发时展开出的图片照常复核。`read_asset` 附多图时逐张校验属于该版本的 `views`，不接受调用方另指图片。真人照片冒充虚构角色，服务端无法判断，首版只靠界面说明。
- **data-migration**：`creative_contents.kind`、`creative_assets.kind`、`creative_content_revision_refs.role` 三处 CHECK 加值，不改已有数据。已经有角色卡数据后不能回滚，只能前向修复（同材质资产）。
- **broad-impact**：展开接在生成的路由预检、锁内受理和提示词编译三处，被画布生成、助手生成共用；执行输入关系多了 `role = character` 行，派发复核、衍生权利和结果发布都会读到。改错会影响所有生成，用两类回归测试兜底：不带角色卡时编译结果和输入关系与改动前完全相同；带角色卡时三处结果一致。

# 本次交付：场景文档与编辑器外壳（C1 `scene-document-shell`）

## Why

Epic `scene-editor-3d`（批准基线 v1）的第一个子项。roadmap 对 C1 的要求是做出**最小贯通**：摄影师能在画布上新建 3D 场景、进入全屏编辑视图、手动摆放内置基础体，改动静默保存，Cmd+Z 只撤销自己的操作，重开后一致，并能从历史版本列表回退。

本批要消除两个不确定性：

1. 场景文档存储、单元版本和撤销，能否承受 3D 编辑的写入频率。
2. R3F 编辑器外壳能否和现有画布、助手面板共存。

前置的通用文档底座（`creative-document-foundation`）已于 2026-10-16 集成到 develop（`bcf139a`）。场景只需注册为底座的一种文档类型。

## What Changes

**交付的 epic 目标契约**（`epic bind --deliver`，正文在 epic `contracts.md`，以批准的修订版为准）：
- `architecture: 场景模块`
- `data: 场景文档`
- `api: 读取场景`
- `api: 提交场景命令`

**后端**：
- 新包 `creativescene`：把 `scene` 注册为底座的文档类型（节点类型 `core.scene`，可新建），实现快照 schema 校验、单元划分、场景操作、按单元恢复、读取分支和卡片摘要。
- 对象 schema 一次定全：服务端完整校验基础体、灯光、摄像机、分组、材质槽字段。`model_instance` 留给 C2。
- 内置基础体清单（7 种）成为服务端校验依据。前端从同一份清单生成参数面板。
- `creativecontent` 加内容类型 `scene`，并新增一条迁移。
- OpenAPI 加场景读取分支和操作 schema；画布 `add_node` 的节点类型加 `core.scene`。
- 底座小幅扩展：`restore_units` 一次可恢复的单元数从 200 提高到 4096，与底座单元容量一致。这样删除大分组后，撤销能在一个请求里原子完成。

**前端**（新目录 `frontend/src/creative-scene/`，按需加载）：
- 画布创建菜单出现「3D 场景」。场景节点卡片显示物件数等摘要，双击或最大化进入全屏编辑视图。
- 编辑视图的布局：
  - 顶栏：标题（可改名）、「添加 / 物件 / 视图」菜单、保存状态、历史、快捷键速查、关闭；
  - 左侧：工具栏，以及物件列表和属性栏；
  - 中间：3D 视口，带网格、视图方向小部件和底部状态栏；
  - 右侧：助手面板保持画布原样。面板打开时，视口自动让出右侧空间。
- 交互按 Blender 2.80+ 默认键位实现（epic 设计「编辑器交互约定」，owner 2026-10-16 拍板）：
  - **导航**：中键与 Alt + 左键两种方式并存；触控板按 Blender 式；「鼠标 / 触控板」自动推测并可手动切换；数字行切视图。
  - **选择**：默认框选工具，Shift 加选，A 全选，Alt + A 取消全选，**多选在本批完成**。
  - **变换**：G / R / S 模态变换，支持锁轴、吸附、精细调整和数字输入，作用于全部选中物件；工具栏可切到调整、移动、旋转、缩放，后三者显示 gizmo。
  - **编辑**：Shift + A 添加、Shift + D 复制并移动、X / Delete 删除、H / Shift + H / Alt + H 显隐、F2 重命名、右键上下文菜单、Alt + G / R / S 清除变换。
  - **上手辅助**：状态栏提示、菜单标注快捷键、`?` 速查、首次打开提示。
  - **偏离 Blender 的地方**：Esc 不关闭视图；Ctrl/Cmd + S 提示已自动保存；不做 3D 游标，新物件落在鼠标所指的地面。
- 属性栏可以改活动物件的名称、变换、基础体参数、显隐和锁定；场景标题可改名。
- 场景状态：权威快照加本机待发操作的投影。
  - 一次拖动只在松手时提交一次，滑块合并 300ms 再提交；同一次连续编辑（属性栏同一字段）未发出的提交合并。不同的操作不合并，每个操作就是一步撤销，保存再慢也一样（owner 2026-10-17）。
  - 冲突时提示，并可「重新应用我的修改」。只有能证明不影响原意图的新增才自动重发；删除遇到冲突必须确认。
  - 每个已发出的修改都有明确终态：确认、拒绝或结果未知。前一个被拒绝时，依赖它的修改暂停并等摄影师处理；结果未知时用原请求重发；不相关的修改照常保存。
- 本人撤销和重做：撤销栈只包含本次打开期间摄影师自己的操作。撤销以 `restore_units` 新命令提交；某一步之后同一物件被别人改过就跳过并提示。
- 历史版本列表：
  - 按写入者、助手运行和 2 分钟时间窗分组；
  - 点开某个版本，在视口里只读预览；
  - 确认后整份恢复，产生新版本。
- 其他标签页同步：复用画布已有的账号级失效通知，节流后直接重读文档，同时覆盖内容变化和进出回收站，不新增 SSE 端点。
- 离开提示：未发出的修改不存本机（owner 已确认），但只要还有未保存的修改，刷新、关闭标签页或离开站点都会被拦截，并提示「场景还有未保存的修改，离开会丢失」。关闭编辑视图后，保存在后台继续。

**本批不做**：
- 摄像机和灯光的新建 UI（C4、C5）。已有的灯光、摄像机只显示并可以变换。
- 材质与光照渲染（C5）。视口固定 clay 显示。
- 环境编辑 UI（C5）。
- 模型实例和代码面板（C2），助手工具（C3），导出（C4）。
- 场景卡片缩略图（建议随 C4 导出一起做）。
- 编组的手动 UI（多选、Cmd+G、取消编组、列表拖动改层级）：owner 2026-10-16 决定并入 C5。C1 服务端支持分组和改层级，编辑器能显示分组，也能选中整组移动。
- 本机草稿持久化：未发出的修改不写 IndexedDB（owner 2026-10-16 确认，以离开提示兜底）。

## Acceptance Criteria

- **AC-1 新建与打开**：**WHEN** 摄影师在画布空白处的创建菜单选「3D 场景」，**THEN** 画布出现场景节点，卡片显示「未命名场景」和物件数；同一事务里产生场景文档，第 1 版快照只含一块内置地面。**WHEN** 双击节点或点最大化，**THEN** 进入全屏编辑视图，视口显示地面和网格，画布的助手面板仍可打开，会话不切换。
- **AC-2 放置与变换**：
  - **WHEN** 摄影师在视口里按 Shift + A 选「方块」，**THEN** 方块出现在鼠标所指的地面位置并被选中。
  - **WHEN** 接着按 G、Z、输入 2、回车，**THEN** 方块沿 Z 轴移动 2 m；移动过程中状态栏显示「移动 · Z 轴」和当前数值；确认后只产生 1 个修订，状态栏最终显示「已保存」。
  - **WHEN** 按 R 后右键，**THEN** 方块回到旋转前的样子，不产生修订。
  - **WHEN** 按住 Ctrl 做 R，**THEN** 旋转按 5° 吸附。
  - **WHEN** 切到移动工具拖动 gizmo 后松手，或在属性栏把宽度改成 3 m，**THEN** 分别只产生 1 个修订（数值输入停下 300ms 后提交）。
- **AC-2a 导航**：
  - **WHEN** 用鼠标，**THEN** 中键拖动环绕，Shift + 中键平移，滚轮缩放；Alt + 左键拖动同样能环绕，加 Shift 平移。
  - **WHEN** 切到触控板模式，**THEN** 双指滑动环绕，Shift + 双指平移，捏合缩放，页面本身不会被缩放；环绕和平移都是画面跟着手指走（与 Blender 跟随系统自然滚动时一致，owner 2026-10-17）。
  - **WHEN** 按 1 / 3 / 7 / 5，**THEN** 分别切到前 / 右 / 顶视和正交透视切换；按 `.` 框住选中物件，按 Home 框住全部。
  - **WHEN** 首次在 macOS 上用触控板双指滑动，**THEN** 编辑器自动推测为触控板模式；推测错了可以在「视图」菜单切换，刷新后保持。
- **AC-2b 多选**：
  - **WHEN** 摄影师框选 3 个物件（或 Shift + 单击逐个加选）后按 G 移动并确认，**THEN** 3 个物件一起移动，只产生 1 个修订，Cmd+Z 一次撤销全部。
  - **WHEN** 按 A，**THEN** 选中全部未锁定物件；按 Alt + A 取消选择。
  - **WHEN** 按 Shift + D，**THEN** 选中物件被复制，并立即进入移动；确认后复制和移动合计只产生 1 个修订。
  - **WHEN** 按 X 并确认，**THEN** 全部选中物件被删除，只产生 1 个修订。
  - 锁定的地面点不中、框不进来。
- **AC-2c 上手辅助与按键边界**：
  - **WHEN** 打开编辑器，**THEN** 状态栏显示当前可用的主要按键，顶部菜单项都标注快捷键，`?` 打开快捷键速查。
  - **WHEN** 焦点在属性栏的输入框里打字，**THEN** G / R / S / X 等字母不触发快捷键。
  - **WHEN** 按 Esc，**THEN** 只取消正在进行的操作或当前选择，不关闭编辑视图。
  - **WHEN** 按 Ctrl/Cmd + S，**THEN** 浏览器不弹出保存网页，编辑器提示场景会自动保存。
  - 编辑视图里的快捷键不会同时触发画布的快捷键（例如画布的撤销、删除）。
- **AC-3 重开一致**：**WHEN** 关闭编辑视图后重新打开，或刷新页面，**THEN** 场景与关闭前一致，包括物件、变换、参数、名称、显隐和锁定；视窗也回到离开时的样子：视角、正交或透视、选中的物件、当前工具和面板开合（owner 2026-10-17；存在本机浏览器，不进文档、不产生修订，换设备不带过去）。
- **AC-4 只撤销自己**：
  - **WHEN** 摄影师先后移动物件 A 和 B，按两次 Cmd+Z，**THEN** B、A 依次回到原位，各产生一个新修订；Cmd+Shift+Z 可以重做。
  - **WHEN** 摄影师新建方块后按 S 缩放，再按 Cmd+Z，**THEN** 只撤销缩放，方块还在；即使新建还没保存完也一样（owner 2026-10-17 发现）。**WHEN** 上一个修改还在保存中按 Cmd+Z，**THEN** 提示「正在保存，保存后撤销」，保存完成后撤销它。
  - **WHEN** 另一个标签页（代表助手或其他写入者）在摄影师移动 A 之后又改了 A，摄影师再按 Cmd+Z 撤销对 A 的移动，**THEN** 这一步被跳过并提示「这一步之后物件已被修改，无法撤销」，A 保持另一方的改动。
  - **WHEN** 摄影师删除一个物件后按 Cmd+Z，**THEN** 物件按原位置和原 ID 回来。
  - **WHEN** 删除一个含 150 个物件的嵌套分组后按 Cmd+Z，**THEN** 一次请求恢复全部物件，层级和顺序完全复原；其中任一单元冲突时整体不生效，并提示冲突。
- **AC-5 单元并发**：**WHEN** 两方基于同一版本，一方改物件 A 的摆放（位置），另一方改 A 的内容（基础体参数），**THEN** 两者都成功。**WHEN** 两方都改 A 的位置，**THEN** 后到者收到 409 `creative_document_conflict`，冲突明细指向 `object:<A>`；编辑器提示冲突并提供「重新应用我的修改」，选择后以最新版本重新提交成功。
  - **WHEN** 甲删除 A 的同时，乙把 A 移进另一个分组（只推进 `objects`），**THEN** 甲的删除不会自动重发，而是提示确认「仍然删除」。
  - **WHEN** 两方同时各新增一个物件，**THEN** 后到者只在 `objects` 上冲突，编辑器自动用最新版本重发，两个物件都在场景中。
  - **WHEN** 摄影师连续改了 A 两次，第一次被拒绝，**THEN** 第二次不会发出，而是和第一次一起出现在冲突提示里；与 A 无关的修改照常保存。
- **AC-6 历史版本**：
  - **WHEN** 摄影师打开历史版本列表，**THEN** 修订按写入者、助手运行和 2 分钟时间窗分组，每组显示写入者、时间段和改动物件数；整份恢复和按单元恢复单独标注。
  - **WHEN** 点开某一版，**THEN** 视口只读预览这一版，编辑操作禁用。
  - **WHEN** 确认恢复，**THEN** 产生一个新修订，场景回到那一版，撤销栈清空；之后还能从列表恢复回去。
- **AC-7 多标签页同步**：**WHEN** 同一场景在两个标签页打开，一个标签页保存修改，**THEN** 另一个标签页在几秒内显示新状态，不打断正在进行的拖动。**WHEN** 一个标签页把场景移入或移出回收站，**THEN** 另一个标签页的编辑视图随之切换为只读或可编辑。
- **AC-7a 离开提示**：**WHEN** 还有未保存的修改（待发、发送中、结果未知或因冲突暂停）时刷新或关闭标签页，**THEN** 浏览器拦截并提示会丢失；全部保存后不再拦截。**WHEN** 有因冲突暂停的修改时关闭编辑视图，**THEN** 先确认是否丢弃这些修改。
- **AC-8 校验与上限**：
  - **WHEN** 请求里有未知内置体、父子成环、四元数非单位、数值越界、同一单元出现两次、ID 与现有物件重复，**THEN** 返回 400 `validation_failed`，整批不生效。
  - **WHEN** 应用后快照超过 512 KiB、物件超过 2000 个或摄像机超过 32 台，**THEN** 返回 413 `creative_size_limit`。
  - 灯光、摄像机、分组、材质槽字段按 `data: 场景文档` 完整校验，即使本批 UI 不产生它们。
- **AC-9 账号隔离与回收站**：**WHEN** 用其他账号的场景 ID 读取或提交命令，**THEN** 返回 404。**WHEN** 场景在回收站，**THEN** 可读，提交命令返回 409 `creative_state_conflict`；编辑视图只读并提示先恢复。
- **AC-10 按需加载**：**WHEN** 打开一张没有场景节点的画布，**THEN** 不下载 three 相关代码块；首次打开场景编辑视图时才加载。浏览器不支持 WebGL2 时，编辑视图显示说明而不是空白。
- **AC-11 写入频率实测**：记录以下基线，结论写进 verification：
  - 300 个物件的场景上，连续 100 次 `update_objects` 的服务端耗时（p50 / p95）和每修订新增存储；
  - 一张有 10 个这样的场景节点的画布，读快照的耗时。

- 前端：新目录 `frontend/src/creative-scene/`。
  - `creative-canvas/editor` 的改动：创建菜单、节点卡片、最大化入口、乐观投影的默认动作和尺寸。

## Risk Notes

风险面：
- **数据迁移**：内容类型 CHECK 加 `scene`。新迁移接在 0072 之后，回滚链头和各迁移测试的标签列表都要更新。
- **并发**：场景写入走底座的按单元乐观并发。前端撤销栈要判断「这一步之后有没有别人改过」，判断错了会覆盖助手的改动。
- **性能**：每次保存存一份全文快照（几十 KB）；画布快照还要为每个场景节点读当前快照来算摘要。写入频率和存储增长正是本批要实测的不确定性。
- **广影响**：前端新增 three、R3F、drei 依赖，必须按需加载，不能拖慢画布首屏；画布节点、创建菜单、最大化入口都要认识 `core.scene`。
- **浏览器输入差异**：触控板和鼠标滚轮的区分、Safari 的捏合事件、各浏览器能否拦下 Cmd + D 等组合，都只能真机实测。导航任务开始前先做一次穿刺，结论记入 design。

契约方面是扩展，不破坏已有接口，但落地前需要先批准一次 epic 修订，见下面第 1 条。

1. **需要先修订 epic，并小幅扩展底座**。按底座实际交付核对后，epic 契约有以下几处必须改，才能实现和交付：
   - **一批新增多个物件**：底座规定同一批里每个单元最多被一个操作涉及，而 `add_object` 每次都涉及 `objects`，所以一批只能加一个物件，粘贴、复制分组、助手一次放多个都做不了。建议改为 `add_objects`，层级调整同理改为 `reparent_objects`。
   - **批量更新与条目上限**：多选放进 C1 后，「全选再按 G」会一次更新上千个物件，而底座一批最多 200 个操作。建议把 `update_object` 改为批量的 `update_objects`，并把几个批量操作的条目上限统一提高到 2000，与物件上限一致。这样一次多选操作始终是一个请求、一个修订、一个撤销步骤。
   - **层级字段归属**：`data: 场景文档` 把 `parent_id`、`order` 列进摆放单元，`api: 提交场景命令` 又说改层级只涉及 `objects`，两处矛盾。建议层级和顺序只归 `objects` 管，摆放单元只含名称、变换、显隐、锁定。
   - **按单元恢复的规则**：`objects` 不能单独恢复；物件的存在性会变化时，两个单元必须一起列出。加回时先算出恢复后的完整物件集合，再统一解析父对象和顺序：父对象也在本次加回的集合里时，层级保持不变；只有在最终集合里找不到时，才挂到最近的祖先或根。结果与 `units` 的排列顺序无关。
   - **恢复单元上限**：底座 `restore_units` 一次最多 200 个单元，删除含 101 个物件的分组就有 202 个单元，撤销必然失败。上限提高到 4096，与底座单元容量一致；撤销始终是一个请求，不拆分。
   - **初始快照前后不一致**：数据契约写「一个内置地面」，接口补充说明写「一块地面加一台摄像机」。建议只放地面，摄像机随 C4 的放置 UI 一起出现。
   - 另有一处文案：读取失败示例的「场景不存在」改为底座统一的「文档不存在」。

# 3D 场景编辑器（CG 合成白模）探索共识

## 目标

为 cosplay 后期 CG 合成提供**稳定、可控、多机位一致**的场景底图：

- Agent 根据搜集的信息和需求搭建 3D 场景。
- 摄影师有三种修改方式：点物件让 AI 改、用描述让 AI 整体改、自己上手改。
- 多台摄像机各自导出分镜底图，交给生图模型重绘。

这一阶段不追求精细建模，质感由重绘负责。另外可以选择加上程序化纹理和光照，给生图提供更多信息。

要解决的问题（owner 原始诉求）：AI 直出的场景 CG 质感差、场景不可控也无法微调、多图分镜不稳定。

## 范围

- **本期**：编辑器基础设施，包括：
  - 场景数据模型、程序化几何、手动编辑、多机位
  - 程序化材质与光照渲染（可选的渲染模式）
  - 渲染与导出、Agent 工具、建模资产可选入库
- **非目标**：
  - Skill 接入（cosplay 策划 Skill 等以后再接，owner 2026-10-15）
  - ComfyUI / ControlNet 管线、服务端渲染、路径追踪
  - 物理和动画、AI 3D 生成物件、外部模型导入
  - 拍摄指导卡（反推实拍参数，随 Skill 接入阶段再做）

## 已定取舍（owner 决定）

1. **先做基础设施，后接 Skill**：基础设施较重，先做完善。
2. **不引入 ComfyUI**（部署成本高）；重绘走 gpt-image-2.5 加良好提示词。导出通道按参考图类模型设计，不按 depth ControlNet 设计。
3. **编排用 JSON，几何用代码**：
   - 场景 JSON 是编排的事实源，记录实例、transform、参数、材质分配、灯光、摄像机。
   - 物件几何由 Agent 写生成代码，带参数 schema，烘焙出的 GLB 是唯一的几何事实源。
   - 代码在禁网的沙箱里执行。
4. **首版不做服务端渲染**：交互渲染、几何烘焙、Agent 截图（`render_view`）和分镜导出都在前端完成，通过渲染桥交给 Agent（SSE 推送请求，暂存上传回传结果）。编辑器页面关闭时 Agent 无法渲染。服务端 headless 渲染等出现后台运行或批量导出的需求再加，届时只需加载 GLB 渲染。
5. **页面关闭提醒**：
   - Agent 使用页面期间常驻提示「关闭会中断」。
   - 只在当前页是唯一渲染端时注册 `beforeunload`。
   - 页面关闭后运行停在当前步骤，重开时可以继续。
6. **选型：自研外壳 + 构件库**：编辑器外壳、数据模型和 Agent 工具自研；渲染和几何用 three.js / R3F 9 / drei 10 / three-mesh-bvh / CSG 库。几何模块契约参考 Pascal 的 authored objects，不依赖 `@pascal-app/*`，不 fork。
7. **建模资产入库保留代码和参数**：
   - 新增素材类型 `model`，主体是 GLB；程序化资产附带生成代码、参数 schema 和材质槽的分配，入库后再放进场景仍可调参数。
   - 入库和取用都是复制，遵守内容归属约定。
   - 缩略图在前端渲染后上传，服务端只做结构校验。
8. **首版不支持外部模型导入**：首版只有 Agent 生成的程序化模型；导入外部 GLB（Sketchfab / Poly Haven 等）下一版再讨论。
9. **可选的程序化纹理与光照渲染**（owner 2026-10-15）：除纯白模外，可以切换到「材质 + 光照」模式，给生图提供更多信息。
10. **产品位置**（owner 基本同意）：
    - 画布上是场景节点，双击进入全屏编辑视图，助手和画布共用一个，和策划编辑视图同一个结构。
    - 分镜导出后每个机位落成画布图片节点，记录 `based_on` 场景版本；场景改了，提示分镜已过时。

以上第 6–10 条均为 owner 2026-10-15 的决定。

## 程序化材质与光照的方案（工作假设，进 design 细化）

- **材质按槽位分配，不烘进 GLB**：
  - 生成代码只声明材质槽（命名约定 `slot_<id>`，参考 Pascal），并把语义默认值写进 GLB。
  - 编辑器在渲染时按「槽位 → 材质库预设 + 参数」挂上程序化材质。
  - 材质库是平台内置的一组参数化预设，例如石砖、木、金属、布、泥土、草地、水面。Agent 和摄影师选预设、调参数，不写 shader。
  - 理由：GLB 保持轻量；换材质不用重新烘焙；同一套材质在不同场景里观感一致。
- **用三平面投影（triplanar）代替 UV**：Agent 生成的几何 UV 质量没有保证，三平面投影按物体或世界空间取样，不依赖 UV。
- **光照**：实时光栅渲染。阳光和天空可调时间与方向，另有点光、聚光、环境贴图（HDRI 或程序化天空）、阴影贴图和屏幕空间 AO。路径追踪（如 three-gpu-pathtracer）延后：它只支持标准材质，和程序化 shader 材质不兼容，需要先烘焙贴图。
- **渲染模式**：编辑和导出都可以在 clay（纯白模）和「材质 + 光照」之间切换。每个机位导出一组图：clay、线稿、材质 + 光照。
- **已知风险**：渲染越像 CG，gpt-image 越可能照抄廉价质感。所以两种模式都保留，由摄影师按镜头选择喂给生图的组合；重绘提示词要明确「按此构图和光向重绘为写实质感」。用哪种组合效果最好，在 change 实测中确定。
- 这会推翻原 A5（「生成代码只能用能导出到 GLB 的材质」）：几何代码仍然只产出标准材质和槽位声明，程序化外观由编辑器的材质库负责，烘焙不受影响。

## 首版成功标准

1. **Agent 搭景**：给一段场景描述，Agent 搭出一个包含远景和若干程序化物件的场景，过程中会用 `render_view` 回看自检，不清楚的地方会提问（包括材质和光影氛围）。
2. **三种修改都可用**：点选物件让 AI 改，只影响这一个物件；描述整体修改；手动移动、旋转、缩放、调参数、换材质、调光。所有改动都能撤销。
3. **多机位导出**：至少 3 台摄像机，可设焦距和高度。每台导出 clay、线稿、材质 + 光照三种图，落到画布上。用 gpt-image-2.5 重绘后，三张图的空间布局一致，由 owner 肉眼判断。
4. **资产入库与复用**：物件存入资产库后，放进另一个场景仍可调参数、换材质。
5. **安全**：生成代码在禁网沙箱中执行，恶意代码样例访问不到网络、cookie 或 DOM。
6. **页面关闭提醒**按约定生效，重开后可以继续运行。

## 事实依据

- 选型调研见 `research/editor-and-geometry-options.md`。核心先例是 Pascal Editor（MIT）的 authored objects：三个导出（`params` / `mount` / `build`），在禁网的 worker 里编译成 GLB + manifest，产物是事实源，`slot_<id>` 声明涂装槽。
- 前端是 React 19 + zustand 5 + Vite 8，还没有引入 three.js（`frontend/package.json`）。
- 资产库现有素材类型 `text` / `link` / `image` / `video` / `audio`，由 CHECK 约束（`backend/internal/platform/store/migrations/0041_creative_media.up.sql:4-6`）和内容校验白名单（`backend/internal/creativemedia/verify.go:34-48`）共同限定；0041 就是扩展类型的先例。
- 内容归属约定（owner 2026-10-07）：节点只持有独立内容（不可变 revision），不记录来源资产。

## 工作假设

- **A4 共享实例改代码**：多个实例共用一个程序化资产时，「点一根让 AI 改」默认写时复制成新资产，只改这一根；要改全部时明确说「全部」。
- **A5（修订）**：几何代码只产出标准材质和槽位声明，不写自定义 shader；程序化外观由编辑器的材质库在渲染时提供。

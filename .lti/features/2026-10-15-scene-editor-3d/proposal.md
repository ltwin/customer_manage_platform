# Epic: scene-editor-3d — CG 合成用 3D 场景编辑器

永久需求文档：本 Epic 的目标、边界和交付计划。整体方案见 design.md，目标契约见 contracts.md。项目 `.lti/contracts/` 记录当前已交付事实。探索共识见 `discovery/brainstorm.md`，选型调研见 `discovery/research/editor-and-geometry-options.md`。

## 目标

cosplay 后期 CG 合成需要一张稳定的场景底图。AI 直接生成的场景有三个问题：质感差，场景不可控也无法微调，多张分镜之间不一致。

本 Epic 完成后，摄影师在创意空间里可以：

1. 在画布上新建 3D 场景，进入全屏编辑视图，由助手根据需求搭建白模场景。物件几何由助手写代码生成，渲染结果回看自检。
2. 用三种方式修改场景：点选物件让助手改；用描述让助手整体改；自己动手移动、旋转、缩放、调参数、换材质、调光。自己的每一步都能用 Cmd+Z 撤销；任何人的改动都能通过历史版本列表或本轮改动清单明确地回退。
3. 放置多台摄像机，每台导出 clay、线稿、材质 + 光照三种图，落到画布上。之后交给 gpt-image-2.5 重绘，多张分镜的空间布局保持一致。
4. 把满意的建模物件存进资产库，放进别的场景时仍能调参数、换材质。

细节建模交给几何代码，最终质感交给重绘。这一阶段的目标是**几何一致、可控**，不追求精细渲染。

## 范围与非目标

- **范围**：
  - 场景文档（编排 JSON）、画布场景节点和全屏编辑视图；手动编辑、本人撤销、历史版本列表。
  - 程序化几何：几何模块契约，禁网沙箱，浏览器内烘焙出 GLB，新增 `model` 内容。
  - 助手工具和客户端任务（渲染桥），页面关闭提醒与恢复。
  - 摄像机、三种导出图、落到画布、分镜过时提示。
  - 程序化材质库（槽位 + 三平面投影）和实时光照，clay 与「材质 + 光照」两种渲染模式。
  - 建模资产存入资产库和从资产库放入场景（复制语义，保留代码和参数）。
- **非目标**（显式排除）：
  - Skill 接入，包括 cosplay 策划 Skill 和拍摄指导卡（基础设施完善后再说，owner 2026-10-15）。
  - ComfyUI / ControlNet 管线、服务端渲染、路径追踪。
  - 外部 GLB 导入（下一版再讨论）、AI 3D 生成物件、物理和动画、精细 PBR 贴图。
  - 多人同时编辑同一场景的实时协同。并发写入只按版本冲突处理。
  - 手机端编辑：只保证桌面 Chrome / Edge / Safari 最新版。

## 接口约定

目标契约在本 Epic 的 `contracts.md` 中定义，子项按 `epic bind` 引用：

- 数据：`data: ADD 场景文档`、`data: ADD 模型内容`、`data: ADD 场景客户端任务`、`data: ADD 导出图来源`、`data: ADD 模型资产`
- 接口：`api: ADD 读取场景`、`api: ADD 提交场景命令`、`api: ADD 场景模型命令`、`api: ADD 认领场景客户端任务`、`api: ADD 续租场景客户端任务`、`api: ADD 完成场景客户端任务`、`api: ADD 导出分镜`、`api: ADD 模型存入资产库`
- 架构与模式：`architecture: ADD 场景模块`、`patterns: ADD 几何模块契约`、`patterns: ADD 客户端代码沙箱`

前置依赖：独立 change `creative-document-foundation`（通用文档底座）定义文档读取与命令外壳、冲突错误、回收站、修订历史和工作会话。本 Epic 的场景接口是它在 `type_key = "scene"` 上的分支，路径为 `/api/v1/creative/documents/{id}`。

既有约定沿用：
- `creativeops` 的 operation id 幂等与回执（`Idempotency-Key` 头）、`ErrorEnvelope` 错误封套。
- 暂存上传（`creativestaging`）、内容不可变修订、`/api/v1/creative/...` 路径前缀。

## 验收标准

全部子项完成后做整体验收：

- **AC-1**：**WHEN** 摄影师在画布上新建场景并双击打开，**THEN** 进入全屏 3D 编辑视图，助手面板就是画布的那一个，会话不切换。
- **AC-2**：**WHEN** 摄影师用一段描述请助手搭景（例如「黄昏的废弃哥特教堂中殿」），**THEN** 助手写出若干程序化物件和远景，过程中至少调用一次 `render_view` 回看；不清楚的地方（尺度、材质、光影氛围）会提问；完成后对话里列出本轮改动。
- **AC-3**：**WHEN** 摄影师点选一根柱子说「改成断裂的」，**THEN** 只有这根柱子改变。它和其他柱子共用同一个模型时，先分叉出新模型再改。
- **AC-4**：**WHEN** 摄影师手动移动、旋转、缩放、调参数、换材质或调光，**THEN** 改动即时显示并静默保存；Ctrl/Cmd+Z 逐步撤销**摄影师自己**的操作，重新打开后状态一致。**WHEN** 助手改了物件 A、摄影师随后改了物件 B 并按 Cmd+Z，**THEN** 撤销的是 B，A 保持助手的改动；再按 Cmd+Z 也不会撤销 A。**WHEN** 要撤销的那一步之后，同一物件又被助手改过，**THEN** 跳过这一步并提示，不覆盖助手的改动。
- **AC-4a**：**WHEN** 摄影师打开历史版本列表，**THEN** 修订按写入者、助手运行和时间分组显示；点开某个版本可以在 3D 视图里只读预览，确认后恢复为一个新版本。**WHEN** 摄影师在本轮改动清单里点「恢复这一处」，**THEN** 只有这一处回到本轮之前的样子。
- **AC-4c**：**WHEN** 助手正在为某个物件烘焙新模型，或本次运行刚改过某个物件，**THEN** 编辑器高亮这个物件并标注「助手正在修改」；**WHEN** 摄影师编辑它，**THEN** 显示不打断操作的提示，修改照常生效。**WHEN** 助手换某个物件模型的同时摄影师在移动它，**THEN** 两边都成功（摆放和内容是不同单元）；**WHEN** 两边改的是同一类属性，**THEN** 助手的写入冲突，助手据冲突信息重做或询问摄影师，摄影师的修改保留。
- **AC-4b**：**WHEN** 摄影师手动改过、从历史恢复过，或用清单恢复过助手改动的对象之后再和助手对话，**THEN** 助手在这一轮得到「自你上次写入后的变化」摘要，不会按旧状态继续操作。**WHEN** 摄影师在对话里要求助手撤回它本轮的改动，**THEN** 助手把自己改过的单元恢复到运行开始前的版本。
- **AC-5**：**WHEN** 助手正在使用创意空间页面渲染（场景编辑视图，或没有打开场景时的画布页），**THEN** 页面常驻「关闭会中断」提示；如果这是唯一的渲染端，关闭页面前浏览器会拦截。**WHEN** 页面在任务进行中被关闭又重开，**THEN** 等待中的任务被重新认领，运行从原步骤继续。**WHEN** 摄影师没有打开场景，只在画布上请助手搭景，**THEN** 助手照样能新建场景并搭建。
- **AC-6**：**WHEN** 场景里有 3 台摄像机并执行导出，**THEN** 每台得到 clay、线稿、材质 + 光照三张图，作为画布图片节点出现，并记录来源场景的修订。**WHEN** 场景之后被修改，**THEN** 这些节点提示「场景已更新」。
- **AC-7**：**WHEN** 用这 3 个机位的导出图，用 gpt-image-2.5 分别重绘，**THEN** 三张图里主要物件的相对位置和空间结构一致（owner 肉眼判断，保留样例记录）。
- **AC-8**：**WHEN** 摄影师把一个物件存入资产库，再放进另一个场景，**THEN** 仍可调它的参数、换材质；改动不影响原场景，也不影响资产库里的那一份。
- **AC-9**：**WHEN** 几何代码试图访问网络、cookie、存储、父页面 DOM 或死循环，**THEN** 访问失败或在时限内被终止，编辑器和账号数据不受影响（安全测试样例全部通过）。
- **AC-10**：**WHEN** 场景、模型、任务相关的数据库读写发生，**THEN** 全部限定在当前账号内（ADR-001），跨账号访问返回不存在。

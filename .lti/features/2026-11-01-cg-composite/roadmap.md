# Roadmap

> 草案（2026-11-01）：需求细化完成后，随 design 一起定稿再批准。

## 子项

串行推进（policy: serial）。顺序原则：

- 先用穿刺消除外部能力的不确定性（抠图质量、蒙版重绘、浏览器写 PSD、透明人片的阴影）。
- 再按「人片 → 进 3D → 导出与溶图 → PSD」做出全合成的最小贯通，然后用复用件补上半合成。
- 增强项（只重绘背景、机位匹配、深度图）放在两条通路都贯通之后。

- **Skill 随子项一起写**〔决定 2026-11-01〕：
  - 合成工作流 Skill 的草稿从 K1 开始，每个子项交付时补上本段流程的写法。
  - 每个子项（K1–K5、K7、K8）的验收都包括一次 Skill 走查：用当时的 Skill 草稿，让真实模型走一遍本段流程，每例至少跑两次，确认工具的粒度和返回信息够助手用。
  - 走查发现工具不够用，在本子项内修，不留到 K6。
  - K6 只负责整合全流程、补全提示词模板和合成策划写法，再做端到端走查。调研和构思两步可以更早用现有工具验证，和 V6-081 的做法一致。
- CG-29 遮挡体是 P2，暂不排入。

### 验收责任

- 每个子项按自己的 proposal 验收，由 owner 接受后归档。
- 只能由 owner 判断的质量验收：K0 / K1 的抠图边缘质量、K3 的溶图样例、K6 的全流程走查。
- 每个子项的 Skill 走查记录（模型、输入、两次运行的结果、发现的工具缺口）放在该子项目录里，作为验收证据。
- Epic 整体验收按 proposal 的 A1–A6，在 K6 归档后进行；K7、K8 不阻塞整体验收，是否纳入由 owner 届时决定。

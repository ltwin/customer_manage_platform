# 物理大气 LUT 穿刺（Epic 未决事项 1）

- 日期：2026-10-22
- 问题：Hillaire 2020 的 LUT 用 TSL 片元 pass 生成，在 WebGL2 下 RGBA16F 的精度够不够；两个后端是否一致；生成要多久。另外顺带确定大气参数的基准和预设。
- 原型：`prototype/`（`src/atmoGpu.ts`、`src/atmoCpu.ts`），数据与图在 `spike/`。

## 结论

1. **可行。** 透射率、多次散射、天空视图三张 LUT 都写成全屏片元 pass，渲染到 `RenderTarget`。同一份 TSL 在三种环境下编译运行，没有报错：
   - WebGPU（Metal）；
   - WebGL2（ANGLE Metal，`forceWebGL`）；
   - WebGL2（SwiftShader，日常 e2e 的环境）。
2. **三张 LUT 都用 RGBA16F。**
   - 透射率和多次散射：fp16 比 fp32 只多约 0.03% 和 0.1% 的平均误差。
   - 天空视图：fp16 和 fp32 的误差相同（约 1.2%），来源是 GPU 的双线性采样和 fp32 运算，与存储精度无关。
   - 前提：天空视图按「环境相对单位」存储（Epic design「物理单位与曝光」）。按每单位太阳照度存储时，晨昏蒙影下数值只有 10⁻⁴…10⁻⁶，fp16 的最大误差升到 6–8%。
3. **两个后端一致。**
   - WebGPU 对 ANGLE：平均差不超过 0.003，差 > 8 的像素不超过 0.002%。
   - WebGPU 对 SwiftShader：平均差不超过 0.47，差 > 8 的像素不超过 0.01%。
4. **生成很快**（参考设备 M4 Pro，WebGPU）：
   - 换大气参数时重算透射率和多次散射：1.2 ms。
   - 换时刻时重算天空视图：0.3 ms。
   - 天空视图加天空光照（PMREM）一起重建：4.3 ms，远低于 200 ms 的节流。
5. **对 Epic 设计的修订建议**：
   - 天空视图也画星球地面，原因见第 4 节。
   - 米氏散射的基准系数取 Blender Nishita 的量级。
   - 米氏吸收随波长变化。
   - `dust_density` 的上限放宽到 50。

   后三条决定了四个预设能否做出来（第 5 节）。

## 1. 做法

- 大气参数取 Hillaire 示例的地球大气（sebh/UnrealEngineSkyAtmosphere 的 `SetupEarthAtmosphere`），长度单位 km：
  - 地球半径 6360 km，大气顶 6460 km；
  - 瑞利散射 (5.802, 13.558, 33.1) × 10⁻³ /km，标高 8 km；
  - 米氏标高 1.2 km，g = 0.8；
  - 臭氧吸收 (0.650, 1.881, 0.085) × 10⁻³ /km，在 25 km 处为三角形分布，半宽 15 km。
- LUT 的参数化与示例相同：

  | LUT | 尺寸 | 参数化 | 每像素工作量 |
  |---|---|---|---|
  | 透射率 | 256 × 64 | Bruneton 2017（高度、天顶角） | 40 步 |
  | 多次散射 | 32 × 32 | 太阳天顶角、高度 | 8 × 8 个方向 × 20 步，在像素里循环，代替示例的 compute 共享内存归约 |
  | 天空视图 | 192 × 108 | 天顶角（地平线附近加密）、相对太阳的方位 | 30 步 |

- 采样都用 `texture(...).sample(uv).level(0)`，避开循环和分支里隐式导数的限制。
- 参照：同一模型的 CPU 双精度实现（`atmoCpu.ts`），离散方式与 GPU 相同，在各纹素中心逐个比较。比较时按两种行序各算一次，取误差小的一种（WebGL2 读回的行序与 WebGPU 相反）。

## 2. 精度

太阳高度 30°，相对误差只统计参照值大于下限的通道（透射率 10⁻⁴，其余 10⁻⁶）：

| 后端 | 格式 | 透射率 平均 / 最大 | 多次散射 平均 / 最大 | 天空视图 平均 / 最大 | Inf/NaN |
|---|---|---|---|---|---|
| WebGPU | RGBA16F | 0.032% / 0.13% | 0.095% / 5.15% | 1.26% / 4.94% | 0 |
| WebGPU | RGBA32F | 0.002% / 0.09% | 0.006% / 0.08% | 1.14% / 4.67% | 0 |
| ANGLE | RGBA16F | 0.032% / 0.13% | 0.096% / 5.15% | 1.31% / 4.94% | 0 |
| ANGLE | RGBA32F | 0.002% / 0.09% | 0.005% / 0.07% | 1.19% / 4.67% | 0 |
| SwiftShader | RGBA16F | 0.016% / 0.10% | 0.081% / 2.34% | 1.22% / 8.84% | 0 |
| SwiftShader | RGBA32F | 0.002% / 0.07% | 0.068% / 2.66% | 1.21% / 8.79% | 0 |

- 多次散射的最大误差出在接近 0 的纹素上，绝对误差不超过 8 × 10⁻⁵。
- 天空视图换成 fp32 也降不下来，误差来自采样和运算本身。

天空视图按每单位太阳照度存储时，低太阳的误差（WebGPU）：

| 太阳高度 | RGBA16F 平均 / 最大 | RGBA32F 平均 / 最大 | 最大值 |
|---|---|---|---|
| 2° | 1.65% / 8.49% | 1.20% / 4.90% | 0.39 |
| −4° | 0.62% / 7.96% | 0.38% / 2.53% | 4.6 × 10⁻³ |
| −8° | 0.95% / 6.14% | 0.21% / 1.78% | 4.2 × 10⁻⁴ |

- 晨昏蒙影的数值落进了 fp16 的次正规数范围（< 6.1 × 10⁻⁵），精度明显下降。
- 乘以 E_sun · s_env 存成环境相对单位后，场景用例的天空在各时刻都落在 O(0.1–1)（`exposure.md` 第 2 节）。所以设计里的环境相对单位是必需的，不只是为了防溢出。

## 3. 两个后端与耗时

### 出图一致性

院子场景 900 × 600，物理天空，自动曝光；PNG 逐像素比较（`spike/backends-compare.json`）：

| 画面 | WebGPU 对 ANGLE 平均 / > 8 | WebGPU 对 SwiftShader 平均 / > 8 / > 2 |
|---|---|---|
| 正午 | 0.000 / 0% | 0.060 / 0.008% / 0.011% |
| 黄金时刻（6°） | 0.001 / 0.001% | 0.104 / 0.009% / 0.021% |
| 日落后（−4°） | 0.003 / 0.002% | 0.182 / 0.010% / 0.095% |
| 晨昏蒙影（−9°） | 0.002 / 0.001% | 0.466 / 0.009% / 0.155% |
| 镜头对着太阳 | 0.001 / 0% | 0.030 / 0% / 0% |
| 夜里一盏台灯 | 0.000 / 0.001% | 0.017 / 0.004% / 0.012% |
| 沙尘 | 0.002 / 0.001% | 0.182 / 0.007% / 0.018% |
| 高原 | 0.001 / 0.001% | 0.048 / 0.008% / 0.013% |

- 差 > 8 的像素在阴影边缘。原型没有开 MSAA，产品管线的抗锯齿会让它们更少。
- **建议阈值**（AC-W2-9）：物理天空的 `lit` 沿用 R1 的 `lit` 阈值；只含天空的画面另设平均差 ≤ 0.5、差 > 8 的像素 ≤ 0.05%。实测都在这两档的十分之一以内。

### 耗时

每项 30 次的中位数。WebGL2 没有 GPU 完成的回调，靠读回一个纹理同步，同步本身约 8 ms，所以「空」一行是要扣掉的底数。

| 后端 | 空 | 透射率 + 多次散射 | 天空视图 | 天空视图 + PMREM |
|---|---|---|---|---|
| WebGPU | 0.0 ms | 1.2 ms | 0.3 ms | 4.3 ms |
| ANGLE | 8.4 ms | 8.8 ms | 8.6 ms | 16.8 ms |
| SwiftShader | 8.3 ms | 16.0 ms | 8.6 ms | 283 ms |

- 拖动时刻滑杆时每次提交要做「天空视图 + PMREM」：参考设备上不到 5 ms，满足 AC-11 的 200 ms。
- SwiftShader 的 PMREM 要 283 ms，天空光照会比滑杆慢一拍。SwiftShader 只用于正确性检查，不是性能参照。

## 4. 地平线以下：画出星球地面

示例的天空视图只画大气，打到地面的视线没有地面反射的光。原型照此实现后有两个问题（`spike/horizon-before.jpg`，右列是物理天空）：

- 场景地面之外露出一道黑带：地平线以下只剩地面前方那段大气的散射。
- 天空光照（PMREM）的下半球是黑的，没有地面反射光。物理天空下环境光又不生效（E4），所以背光面发黑，比程序化天空暗很多。

改法：天空视图里打到地面的视线，加上被太阳照亮的地面（反照率 0.3，透射率衰减），与多次散射里的地面用同一个公式。改完后背光面和金属球的下半部有了地面反光，正午与程序化天空的观感接近（`spike/calibration.jpg`）。

剩下的瑕疵：晨昏蒙影时，场景地面的边缘和地平线之间仍有一道暗线（`spike/shanghai-0621.jpg` 的 19:15 之后）。原因是星球地面只计入了太阳直射，没有计入天空光。两个处理办法：
- 在星球地面上再加上天空光，用多次散射 LUT 近似；
- 交给 W4，空气透视会把场景地面的远处和地平线融在一起。

这条作为 W2 的设计细节，不影响验收。

## 5. 大气参数的基准与预设

### 米氏基准太小

示例的米氏散射在海平面是 0.004 /km，整层气溶胶光学厚度只有约 0.005，相当于极其通透的天。契约里 `dust_density` 的范围是 0…10，调到 10 也几乎看不出雾霾（`spike/mie-base.jpg` 前两列）。

- Blender Nishita 的米氏系数是 2 × 10⁻⁵ /m（0.02 /km），约为示例的 5 倍。
- 按 Blender 的量级取基准：
  - 散射 0.02 /km；
  - 消光 0.0222 /km，保持示例的单次散射反照率 0.908。

  这样 `dust_density = 1` 与 Blender 的 Dust 1 同义，晴天仍然通透，与示例的画面几乎相同（`spike/mie-base.jpg` 第一、三列）。

### 沙尘偏黄需要两处改动

米氏散射与波长无关。只加尘埃，天空只会变白，做不出 Epic AC-4 要的「沙尘偏黄」（`spike/preset-candidates.jpg`）。试过三种办法：

| 办法 | 结果 |
|---|---|
| 降低空气密度（0.4） | 天空变灰白，不偏黄 |
| 米氏吸收随波长变化（蓝光吸收更强），尘埃 10 | 略偏米色 |
| 米氏吸收随波长变化，尘埃 40 | 明显偏黄褐，太阳光也变暖 |

建议：
- 米氏吸收按 (0.6, 1.2, 3.0) 逐通道乘到基准吸收上，没有归一：三个通道的平均吸收是基准的 1.6 倍（原稿写的「平均值与示例相同」有误，2026-10-22 方案评审指出）。本节的预设样张都用这组值。矿物尘埃在蓝光处吸收更强，这个方向符合实测。
- 这是模型常量，对所有尘埃生效。晴天（尘埃 1）几乎不受影响：平均差 0.45，最大 4（`spike/presets.jpg` 前两列）。
- `dust_density` 的上限从 10 放宽到 50。这会改动 `data: 物理天空` 的取值范围，需要 Epic 修订；外形不变，旧数据不受影响（W2 之前没有物理天空）。

### 预设取值

`spike/presets.jpg`，每个预设在固定曝光和自动曝光下各一张：

| 预设 | `altitude_m` | `air_density` | `dust_density` | `ozone_density` | 观感 |
|---|---|---|---|---|---|
| 晴朗 | 0 | 1 | 1 | 1 | 蓝天，地平线发白 |
| 雾霾 | 0 | 1 | 12 | 1 | 天空灰白；照度比晴朗低 0.2 档（太阳 40°）到 0.7 档（太阳 8°） |
| 高原 | 4000 | 1 | 0.2 | 1 | 天顶深蓝，阳光略亮更白 |
| 沙尘 | 0 | 1 | 40 | 1 | 天空和光线偏黄褐；照度比晴朗低约 0.6 档 |

- 自动曝光会把整体亮度拉平，所以「更暗」只在固定曝光下看得出。
- 观感是否可信由 owner 判断（Epic AC-4）。

## 6. 已知局限

- **晨昏蒙影偏亮**：太阳在 −6° 到 −9° 时，水平照度比实测高 4–10 倍；到 −12° 又降得太快（`exposure.md` 第 1 节）。
  - 原因是 Hillaire 的多次散射近似：每个点只按它自己高度的太阳角查表，在地影里不准。
  - 自动曝光下看不出；手动曝光下，蓝调时刻比实拍亮 2–3 档。
  - 改进办法（更高阶的散射，或 Bruneton 的预计算）留作后续增强。
- **米氏相函数**沿用示例的 g = 0.8（Blender 是 0.76），差别看不出。
- **天空视图的分辨率**沿用示例：太阳盘附近的米氏光晕由解析的太阳盘补上，LUT 本身只到约 1.9° 一个纹素。

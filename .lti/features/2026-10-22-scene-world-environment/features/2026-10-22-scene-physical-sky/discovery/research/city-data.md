# 调研：物理天空的城市数据（2026-10-22）

> 状态：Epic design 未决事项 4 的调研结论，供 W2 design 引用。新疆时区的处理需要 owner 选。
> 辅助材料：处理脚本在 `city-data/scripts/`，覆盖率、体积、时区核对的结果摘要在 `city-data/results/`。原始数据集没有入库。

## 结论先行

1. **Natural Earth 单独用不够。**
   - 中文名够用：`NAME_ZH` 100% 有值，以简体为主。
   - 时区不够用：16% 的条目没有 `TIMEZONE`，悉尼、丽江、敦煌都缺；已有的值里有成批的大错，如澳门是 `America/Fortaleza`，布拉格是 `America/Chicago`。
   - 覆盖不够：清单里 7 个国内拍摄地查不到（香格里拉、稻城、漠河、阳朔、张家界、黄山、婺源）。
2. **推荐方案**：
   - GeoNames `cities15000` 提供地点、坐标、IANA 时区和人口；
   - 中文名取 Wikidata 标签（CC0），按 GeoNames ID 反查；
   - 另加一张自维护的补丁表。
3. **打包档位**：中国大陆和港澳台全收，海外按人口取前 5,000，共 7,337 条。紧凑格式原始 349,839 字节，gzip 160,023 字节（brotli 125,418）。去掉繁体名一列后 gzip 140,998 字节。
4. **覆盖率**：清单 49 项找到 48 项。45 项能用中文搜到，并且都排第一。林芝、稻城、漠河只能用英文或拼音搜到。婺源没有。这 4 项由补丁表补上。
5. **时区**：GeoNames 的时区 100% 有值，全部是现行 IANA 名。浏览器 `Intl` 和 Go `time.LoadLocation`（嵌入 `time/tzdata`）都能加载。
6. **授权**：GeoNames 是 CC BY 4.0，要署名，但没有相同方式共享（share-alike）要求。Wikidata 是 CC0，Natural Earth 是公有领域，都不需要署名。
7. **需要 owner 决定**：新疆的 115 个条目在 GeoNames 里是 `Asia/Urumqi`（UTC+6，新疆时间）。官方和多数游客用的是北京时间。建议构建时改成 `Asia/Shanghai`，见第六节。

## 二、Natural Earth 核实（问题 1）

### 字段与填充率

| 项 | 结果 |
|---|---|
| 条目数 | 7,342 |
| 属性数 | 137 |
| `NAME_ZH` | 7,342 / 7,342（100%）。以简体为主。约 645 条（8.8%）含繁体字或台湾译名，例如「三蘭港」「長灘」「瓜地馬拉」「聖地牙哥」 |
| `NAME_ZHT` | 100%。繁体，常带「市」，例如「臺北市」「廣州市」 |
| `TIMEZONE` | 6,159 / 7,342（83.9%），320 个不同值 |
| `WIKIDATAID` | 7,192（98.0%） |
| `GEONAMESID` | 6,797（92.6%） |
| `POP_MAX`、`LATITUDE`、`LONGITUDE`、`ISO_A2` | 100% |

`NAME_ZH` 是 Natural Earth 从 Wikidata 取来的（官网授权页有说明），有几处配错：

- 「婺源」配给了内蒙古的 Wuyuan（41.09°N，108.27°E），那其实是五原。
- 奥克兰（新西兰）是「奥克兰都会区」，搜「奥克兰」时排在美国 Oakland（「奥克兰」）后面。
- 智利的 Los Angeles 是「洛桑赫莱斯」。

### 时区质量

- **全部能加载**：320 个值在 Node `Intl.DateTimeFormat` 和 Go `time.LoadLocation` 下都有效。
- **用了已废弃的名字**：22 个值是旧别名。中国的占多数：
  - `Asia/Harbin` 89 条，北京也在内；
  - `Asia/Chongqing` 99 条，包括广州、深圳、成都、西安、拉萨；
  - `Asia/Kashgar` 4 条。
  - 这些名字在 2026 年的规则和 `Asia/Shanghai`、`Asia/Urumqi` 相同，所以不会算错，但不是规范名。
- **有错**：每个条目找 25 km 内最近的 GeoNames（cities5000）条目，比较两者 2026 年 1 月和 7 月的 UTC 偏移。
  - 共比较 5,955 条，有 79 条（1.3%）不一致。人口最多的 40 条不一致里，逐条看都是 Natural Earth 错。
  - 错到别的国家或大洲的（偏移差 3 小时以上的 13 条，加上两条错国家的）：

    | 城市 | Natural Earth 的值 | 应为 |
    |---|---|---|
    | 澳门 | `America/Fortaleza` | `Asia/Macau` |
    | 布拉格 | `America/Chicago` | `Europe/Prague` |
    | 卡迪夫 | `Australia/Sydney` | `Europe/London` |
    | 科伦坡 | `America/Sao_Paulo` | `Asia/Colombo` |
    | 亚松森 | `Asia/Manila` | `America/Asuncion` |
    | 蒙得维的亚 | `America/Chicago` | `America/Montevideo` |
    | 圣萨尔瓦多 | `Asia/Manila` | `America/El_Salvador` |
    | 马累 | `Europe/Rome` | `Indian/Maldives` |
    | 拉各斯 | `Europe/Athens` | `Africa/Lagos` |
    | 的黎波里（黎巴嫩） | `Africa/Tripoli` | `Asia/Beirut` |

    另有布里奇顿、圣多美、阿皮亚、卡斯特里、乔治敦（开曼）。
  - 其余是时区规则变了而数据没更新：俄罗斯 2016 年的调整（萨拉托夫、乌里扬诺夫斯克、阿斯特拉罕、巴尔瑙尔）、墨西哥 2022 年取消夏令时（马塔莫罗斯、华雷斯城），还有嘉峪关被标成 `Asia/Urumqi`。
- **有缺**：1,183 条没有时区，按国家排前几位的是加拿大 118、俄罗斯 99、中国 88、美国 77、阿根廷 74、澳大利亚 63。悉尼（W2 的参考地点之一）、丽江、敦煌、林芝都缺。
  - 用 25 km 内最近的 GeoNames 条目只能补上 637 条，而且一旦用 GeoNames 补，就要承担 CC BY 署名，公有领域的好处就没有了。

**结论**：中文名字段足够，时区字段不能直接用，国内拍摄地覆盖也不够。不满足设计假设，所以另选方案。

## 三、备选数据源（问题 2）

### GeoNames

| 项 | cities15000 | cities5000 |
|---|---|---|
| 条目数 | 34,179 | 69,936 |
| 其中中国大陆 + 港澳台 | 2,337 | 3,248 |
| `timezone` 填充 | 100%，356 个不同值 | 100%，371 个不同值 |
| 时区有效性 | 全部在 `Intl` 和 Go `time/tzdata` 下有效 | 同左 |
| 自带中文名（alternateNames 里有 `zh*` 标签的） | 11,220（32.8%）；其中只有繁体的 2,342 条 | 18,112（25.9%）；其中只有繁体的 3,756 条 |

- **时区**：用的是现行规范名。中国大陆一律 `Asia/Shanghai`，新疆为 `Asia/Urumqi`。乌克兰已用 `Europe/Kyiv`（384 条），墨西哥华雷斯城已用 `America/Ciudad_Juarez`。上面和 Natural Earth 不一致的 79 条里，抽查的都是 GeoNames 对。
- **中文名**：cities 文件本身只有一个不带语言标记的 `alternatenames` 列，汉字写法里混着日文和繁体，没法直接用。例如「霞浦」既是福建霞浦，也是日本的 Kasumigaura。有语言标记的中文名要从 `alternateNamesV2` 取，代价如下：
  - 要下载 205 MB 压缩包，解压后 786 MB；
  - 流式过滤 1,923 万行，本机约 9 秒；
  - 取到的名字质量一般。标签 `zh` 有 12,104 个，`zh-CN` 833、`zh-Hans` 356、`zh-TW` 259、`zh-Hant` 662、`zh-HK` 376。很多 `zh` 其实是繁体。
  - 错例：稻城写成「道成」；纽约只有繁体「紐約市」；雷克雅未克只有台湾译名「雷克亞維克」；开普敦只有「開普敦」。

### Wikidata

- **授权**：CC0，最宽松。
- **中文名**：质量好，`zh-hans` / `zh-cn` 的简体标签齐全。
- **时区：不现实**。
  - 「大城市」（`Q1549591`）共 2,973 个条目，只有 3 个有「所在时区」（`P421`），0 个能连到 IANA 时区名（`P6687`）。纽约（`Q60`）、北京（`Q956`）都没有 `P421`。
  - 要由坐标推时区，就得用时区边界数据。常用的 timezone-boundary-builder 来自 OpenStreetMap，用 ODbL 授权，有 share-alike 要求，按本项约束排除。
- **结论**：只用它的中文名。
  - 按 GeoNames ID（`P1566`）反查，cities15000 有 27,335 条（80%）能连上，其中 788 个 ID 连到不止一个条目（取第一个）。cities5000 能连上 53,666 条（77%）。
  - 取数代价：cities15000 要 86 次 SPARQL 请求（每次 400 个 ID），用时 3 分 40 秒，结果 12 MB；cities5000 要 175 次，约 10 分钟，20 MB。只在构建时跑，产物入库，运行时不联网。

### 组合：GeoNames + Wikidata 中文名

中文简体名按下面的顺序取，取到即止：

1. Wikidata `zh-hans`；
2. Wikidata `zh-cn`；
3. GeoNames 有语言标记的中文名（不含繁体字的）；
4. Wikidata `zh`（不含繁体字的）；
5. GeoNames 其他中文别名（不含繁体字的）；
6. 只对中国大陆和港澳台：cities 文件里不带语言标记的汉字别名（不含繁体字的）。

繁体名取 Wikidata `zh-hant` > `zh-tw` > `zh-hk` > GeoNames `zh-TW` / `zh-Hant`。和简体相同的不存。显示名去掉结尾的「市」「特别市」和消歧括注。

cities15000 的结果：

| 中文名来源 | 条数 |
|---|---|
| Wikidata `zh-hans` | 11,470 |
| Wikidata `zh-cn` | 342 |
| GeoNames 带标记的中文名 | 4,032 |
| Wikidata `zh` | 2,321 |
| GeoNames 其他别名 | 1 |
| 不带标记的汉字别名（仅中国） | 86 |

- **填充率**：全部 34,179 条里 53.4% 有中文名。按人口前 2,000 条为 84%，推荐档位为 74%。
- **繁体残留**：按启发式检测，简体列里还含繁体字的有 41 条（推荐档位里 8 条）。
- **再叠加 Natural Earth 的 `NAME_ZH`**（经 `GEONAMESID` 关联）：多出 1,005 个名字，繁体残留却从 41 条涨到 353 条，清单覆盖不变。不采用。

## 五、体积（问题 4）

### 字段与形状

前端需要的字段：中文名、英文名、纬度、经度、IANA 时区、国家代码（用于消歧显示），繁体名可选。

推荐的紧凑形状（下文称 C），示意如下，取自推荐档位的真实行，`…` 表示省略：

```text
{"tz":["Asia/Shanghai","Asia/Kolkata","Asia/Tokyo", …],
 "c":[["北京","Beijing",3991,11640,0,"CN"], …, ["台北","Taipei",2505,12153,26,"TW","臺北"], …]}
```

- **时区**：时区表按出现频率排序，每行存下标。推荐档位有 259 个时区，`Asia/Taipei` 排第 27 位（下标 26）。
- **坐标**：存成 0.01° 的整数，约 1.1 km。0.01° 的经度误差只让太阳时差 2.4 秒，太阳角误差小于 0.01°，远小于 AC-W2-2 的 0.5°。
- **人口**：不入包。行按人口降序排，顺序就是同类结果的排序依据。
- **国家名**：用 `Intl.DisplayNames('zh-CN', {type: 'region'})` 现取，例如 `GB` → 「英国」，不用另带数据。

同一档位（推荐档位，含繁体名）下几种形状的对比：

| 形状 | 原始 | gzip | brotli |
|---|---|---|---|
| A：对象数组（字段名每行重复，坐标 3 位小数，带人口） | 819,624 | 226,254 | 167,379 |
| B：行数组，坐标 3 位小数 | 386,369 | 173,170 | 136,800 |
| **C：行数组，坐标 0.01° 整数** | **349,839** | **160,023** | **125,418** |
| D：按列存 | 393,594 | 145,460 | 124,294 |

D 的 gzip 比 C 小 9%，brotli 几乎一样，但解析更绕。选 C。

## 六、推荐方案（问题 5）

### 数据管线

构建时离线跑一次，产物 JSON 入库，运行时不联网：

1. 取 GeoNames `cities15000`，按档位选出「中国大陆和港澳台全部 + 海外按人口前 5,000」。
2. 用 `alternateNamesV2` 和 Wikidata 标签补中文名，按第三节的顺序取。
3. 应用补丁表 `cities.patch.json`（自维护）：
   - `include`：按 GeoNames ID 从 cities5000 或 cities500 收入热门小地方，例如皇后镇、班夫、采尔马特。
   - `override`：按 GeoNames ID 改名或改坐标，例如：
     - 林芝：「Nyingchi」条目补中文名「林芝」；
     - 稻城：「道成」改为「稻城」；
     - 漠河：「Xilinji」改名「漠河」并核对坐标。
   - `add`：GeoNames 没有的地方，自填中英文名、坐标和时区，例如婺源（cities5000 里没有，allCountries 里有没有未核实）。补丁表是我们自己写的事实数据，不涉及授权。
4. 输出形状 C 的 JSON，加一段署名声明（见下）。构建时打印三份清单供人工检查：
   - 简体列里还含繁体字的条目；
   - 中国条目里人口 10 万以上却没有中文名的条目，cities15000 里有 57 条，例如常熟、长治（PPL 条目）、凤凰；
   - 时区不在当前 Node `Intl` 里的条目。

档位的取舍：

- 推荐档位已覆盖清单。
- 想要更广，可以换成「cities5000 + 中国全收 + 海外全部有中文名的」：30,950 条，gzip 约 776 KB，补充清单 12 项能找到 9 项。代价是包大约 5 倍。
- 想要更小，可以用「中国全收 + 海外前 2,000」：gzip 89 KB，清单 47/49。

### 搜索与显示

- **匹配**：
  - 简体名子串；
  - 繁体名子串；
  - 英文名去重音、不分大小写的前缀。中国条目的英文名就是拼音，所以没有中文名的条目也能用拼音搜到，例如「changshu」。
- **排序**：前缀命中在前，中间命中在后，同类按人口。否则搜「京都」会先出「东京都」，搜「喀什」会先出「马拉喀什」。
- **显示**：「伦敦 · 英国」「伦敦 · 加拿大」。国家名用 `Intl.DisplayNames` 现取。
- **场景只存数值**：选中后，经纬度、时区和显示名写进场景（`sky.latitude_deg`、`sky.longitude_deg`、`sky.timezone`、`sky.place`），场景不引用城市表。以后更新城市表，不会改变已有场景的渲染结果和渲染指纹。

### 时区

- **原样写入**：直接写城市表里的时区名。不要用 `Intl.DateTimeFormat().resolvedOptions().timeZone` 回写。Node 24（ICU 77.1）会把 GeoNames 时区里的 16 个名字规范成旧别名，例如 `Asia/Kolkata` → `Asia/Calcutta`、`Europe/Kyiv` → `Europe/Kiev`；用 ICU 的浏览器可能也这样，没有逐个验证。两种名字 Go 都能加载，但回写会让同一地点在场景里出现两种写法。
- **较新的名字**：`Europe/Kyiv`（2022b 起）、`America/Ciudad_Juarez`（2022g 起）在很旧的浏览器里可能不认识。这种情况由 design 的 E7 兜底：按经度推平太阳时，并给出提示。
- **新疆（需要 owner 选）**：GeoNames 给乌鲁木齐、喀什等新疆条目的是 `Asia/Urumqi`（UTC+6），推荐档位里有 115 条。官方作息、航班火车和多数游客用北京时间（UTC+8）。
  - 选项 A（建议）：构建时把中国条目的 `Asia/Urumqi` 改成 `Asia/Shanghai`。摄影师按北京时间填时刻，界面上时区仍可改。
  - 选项 B：保留 `Asia/Urumqi`。摄影师要知道滑杆上是新疆时间，否则太阳会差 2 小时。
  - 两种做法算出的太阳位置都对，差别只在滑杆上的「当地时刻」按哪种时间。

### 繁简

- **显示**：一律用简体列。没有中文名的显示英文（中国条目即拼音）。
- **搜索**：繁体列作为第二匹配列，覆盖港澳台的写法和繁体输入，例如「臺北」「雪梨」。推荐档位里 2,545 条有繁体名，多占 gzip 约 19 KB。不需要的话可以整列去掉。
- **不引入繁简转换库**。数据里残留的繁体字由构建脚本列出来，人工修正（推荐档位里 8 条）。
- **不收无标记的汉字别名**：海外条目不收 GeoNames 不带语言标记的汉字别名，避免把日文汉字当中文，例如日本的霞ヶ浦会变成「霞浦」。

### 缺失城市

- **经纬度手填始终可用**。搜不到时，在下拉底部提示「没找到？直接填经纬度」。
- **时区**：手填时保留当前时区，旁边给时区下拉（`Intl.supportedValuesOf('timeZone')`），并显示按经度估算的 UTC 偏移作参考。
- **常见拍摄地**：进补丁表，随版本更新。

### 署名义务

- **GeoNames（CC BY 4.0）**，按第 3(a) 条，分享时要做到四件事：
  - 注明来源 GeoNames 并给出链接 <https://www.geonames.org/>；
  - 注明许可证 CC BY 4.0 并给出链接 <https://creativecommons.org/licenses/by/4.0/>；
  - 说明我们做了修改；
  - 保留 GeoNames 的免责声明，原文是「The Data is provided "as is" without warranty or any representation of accuracy, timeliness or completeness.」。

  许可证允许按媒介采用合理的方式。建议做三处：
  1. 城市搜索下拉底部放一行小字：「城市数据：GeoNames（CC BY 4.0），已修改」，链接到上面两个地址。
  2. 产物 JSON 带 `attribution` 字段，或旁边放一个 `NOTICE` 文件，写全来源、许可、修改说明（字段裁剪、中文名来自 Wikidata、人工补丁）和免责声明。
  3. 项目的第三方声明文档记一条。仓库目前没有这类文档，可在 W2 新建。

  CC BY 4.0 没有 share-alike 要求。我们改过的数据可以随前端包分发，只要不附加阻止他人遵守原许可的限制。
- **Wikidata（CC0）**：没有署名义务，可以顺带致谢。
- **Natural Earth（公有领域）**：没有署名义务，推荐方案也没有用它。

## 七、局限

- 清单只有 49 项。清单以外的地方，只能用中文名填充率（推荐档位 74%，中国条目 79%）和补充清单（12 项）估计。
- 繁体检测用的是常用繁体字表（`scripts/zh-util.mjs`），不是完整的繁简转换。表里没有的繁体字会漏判。
- Wikidata 标签有它的粒度问题：
  - 东京是「东京都」，奥克兰是「奥克兰都会区」；
  - 珠海的井岸镇被标成「斗门区」，林芝的驻地是「八一镇」。
  - 构建时应人工过一遍中国条目和海外前 500 条的显示名。
- 同一个 GeoNames ID 连到多个 Wikidata 条目时，脚本取第一个。cities15000 里有 788 个这样的 ID，没有逐个核对。
- 判断「是同一个地方」用的是 60 km 容差，期望坐标取的是城区中心的近似值。这只能说明找到的是这一带的条目，不说明坐标精确到城区中心。漠河就差了 47 km。
- GeoNames 人口的口径不一（市区、全市、都会区），会影响同类结果的排序和档位截断。
- Wikidata 是实时数据，再跑一次结果会有出入。产物应记下取数日期。
- 时区有效性只在 Node 24.12（ICU 77.1，时区库 2025b）和 Go 1.25.5 上验证过，没有逐个浏览器验证。

## 八、复现

脚本在 `city-data/scripts/`，都用 `node <脚本> <数据路径>` 运行。每份下载放在单独的空目录里，脚本不在数据目录里执行。一键复现：

```sh
DATA=/path/to/city-data WORK=/path/to/city-work bash city-data/scripts/run-all.sh
```

| 脚本 | 作用 |
|---|---|
| `ne-inspect.mjs` | Natural Earth 字段、填充率、时区有效性、中文名样例 |
| `build-ne.mjs`、`build-gn.mjs` | 把 Natural Earth 和 GeoNames 转成统一记录格式；`build-gn.mjs` 同时从 `alternateNamesV2` 取中文名 |
| `wd-fetch-labels.mjs` | 按 GeoNames ID 分批查 Wikidata 中文标签 |
| `merge.mjs` | 按第三节的顺序合并中文名、清理显示名 |
| `select.mjs` | 档位选择（`5000`、`cn+5000`、`cn+5000z`、`all`） |
| `coverage.mjs` | 清单覆盖、排序名次、中文名填充、繁体残留、时区有效性 |
| `checklist.mjs`、`checklist-extra.mjs` | 任务清单（49 项）和补充清单（12 项），带期望坐标 |
| `tz-crosscheck.mjs` | Natural Earth 与 GeoNames 的时区偏移对照 |
| `tzcheck/main.go` | 用 Go `time/tzdata` 校验时区名 |
| `size.mjs` | 四种形状、各档位的原始 / gzip / brotli 体积 |
| `table.mjs`、`peek.mjs`、`near.mjs` | 生成覆盖率表、查看指定条目、查看坐标附近的条目 |

结果摘要在 `city-data/results/`：

- `cov-*.json`：各来源、各档位的覆盖率，含逐项命中；
- `extra-*.json`：补充清单；
- `size-*.json`：体积；
- `tz-crosscheck-ne-vs-gn5000.json`：79 条时区不一致的明细；
- `tzcheck-go.txt`：Go 校验输出；
- `*-stats.json`：中文名来源统计；
- `ne-inspect.txt`：Natural Earth 检查输出；
- `env-node.json`：Node 环境。

# 本次交付

## Why

本子项是 Epic `scene-world-environment` 的 W2，按修订 v2 的基线实施。它交付 Epic 的目标 2「物理天空」和目标 3「真实亮度，手动曝光」，承担 Epic 的 AC-2、AC-3、AC-4，以及 AC-8、AC-9、AC-10、AC-11 中与天空和曝光有关的部分。

- **为什么是主干**（roadmap「排序原则」）：W3 夜空、W4 空气透视、W5 体积物件都要读本项建立的大气 LUT、天文计算、物理单位和曝光。
- **穿刺已在设计阶段完成**。Epic 未决事项 1、3、4 的结论见本子项 `discovery/research/`：
  - `atmosphere-luts.md`：三张 LUT 用 TSL 片元 pass 生成，都是 RGBA16F；两个后端一致；耗时在毫秒级。
  - `exposure.md`：预曝光在 fp16 里成立；材质输出必须钳制；两种测光方式各有缺陷。owner 据此决定首版只做手动曝光。
  - `city-data.md`：Natural Earth 的时区不可用，改用 GeoNames 加 Wikidata 中文名。
  - `astronomy.md`：锁定 `astronomy-engine` 2.1.19，精度远好于验收线；当地时间换算 UTC 的函数和用例。
- **Epic 修订 v2**（owner 2026-10-22 的决定，先于本子项批准）：
  - 首版只做手动曝光；视口和临时视点用默认曝光值；
  - 太阳的亮度和色温可调；
  - 尘埃基准取 Blender 的量级，吸收偏蓝，`dust_density` 上限放宽到 50；
  - 不存在的本地时刻往后推；
  - 城市数据改用 GeoNames。

## What Changes

1. **物理天空**（`data: ADD 物理天空`）：
   - 「环境」选项卡的天空类型新增「物理天空」，与程序化天空、纯色并列。
   - **地点模式**：选城市（离线城市表，中英文或拼音搜索）或填经纬度；设日期、当地时刻（滑杆，精确到分钟）和场景的正北方向。时区随城市带出，也可以改。太阳按天文计算落在真实位置。
   - **手动模式**：直接调太阳高度和方位，用法与程序化天空相同。从地点模式切到手动时，把当前算出的角度写成手动值，画面不跳变；入夜后太阳低于 −10° 时例外，高度夹到 −10°，天空会变亮。
   - **大气**：海拔、空气密度、尘埃密度、臭氧；预设「晴朗」「雾霾」「高原」「沙尘」，取值见 design。
   - **太阳**：亮度倍率、色温、太阳盘的开关与大小。亮度和色温同时作用于太阳光、太阳盘、天空和天空光照。
   - **光照**：天空背景、太阳光的颜色与照度、天空光照（PMREM）都来自同一套 Hillaire 大气，覆盖晨昏蒙影，地平线以下画出被照亮的星球地面。
   - 物理天空下 `environment.ambient` 不生效，界面置灰并说明原因；全局雾按 Epic design 的物理着色。
   - 太阳落到地平线以下后，天空经晨昏蒙影变暗直至全黑。月亮和星空属于 W3，本子项的夜晚只有大气和灯光。
2. **物理单位与手动曝光**（`data: ADD 摄像机曝光`）：
   - 物理天空下按真实照度渲染：太阳与平行光为 lux，点光、聚光为 cd，天空为 cd/m²。光源在送进 GPU 前乘以曝光（预曝光），天空和天空光照按环境相对单位存储（Epic design「物理单位与曝光」）。
   - **摄像机**：属性栏新增「曝光」，ISO 和快门加上已有的光圈，旁边显示 EV100。光圈同时决定景深和亮度。
   - **默认摄像机**：视口的自由视角和 `render_view` 的临时视点按「渲染」选项卡的默认曝光值（EV100，缺省 15）显示。物理天空下，这个滑杆替换掉曝光补偿。
   - 在物理天空下添加摄像机时，按默认曝光值先换算快门，快门越界再调 ISO，新摄像机与视口一样亮。缺省光圈 f/2.8 下可达 EV100 约 −11.9…17.9，超出时新摄像机偏暗。
   - 材质的输出在渲染器创建入口统一钳到 60 000，防止 fp16 溢出（SwiftShader 上溢出会成为 NaN）。
   - 其他天空模式下，摄像机的曝光字段和默认曝光值保存但不生效，界面置灰并说明「只在物理天空下生效」；画面与 W2 之前相同。
3. **渲染指纹**（Epic design「渲染指纹」中 W2 的几条）：
   - `clay`、`line` 清除摄像机的曝光字段。
   - `lit`：天空不是物理天空时，清除摄像机的曝光字段；是物理天空时，清除 `render.exposure_ev`，并且景深关闭也计入 `f_stop`。
   - 任何导出方式都不计入 `render.exposure_ev100`。
   - 旧场景的指纹不变：旧快照读取时补齐的曝光缺省值，在非物理天空下被清除。
4. **城市数据**：
   - 构建脚本从 GeoNames `cities15000`、Wikidata 中文标签和补丁表离线生成 JSON，产物入库，运行时不联网。
   - 新疆的条目时区改为 `Asia/Shanghai`（北京时间）。
   - 署名：城市下拉的底部、产物 JSON 的 `attribution` 字段、新建的第三方声明文档。
5. **后端**：
   - **太阳参考**（Epic 修订 v2）：物理天空的地点模式下，助手读场景和写入环境时，结果里带上当前太阳的高度和方位（含换成场景坐标的方位）、日出日落、正午、早晚的黄金时刻和蓝调时刻。按 NOAA 公式在服务端计算，不存储，不参与渲染。环境选项卡也显示同样几项。
   - 按数据契约校验和补齐新字段，双向校验：物理天空不得带其他天空的字段，其他天空也不得带物理天空的字段。时区名用 `time.LoadLocation` 校验，并要求大小写与规范名相同；二进制嵌入 `time/tzdata`。
   - `api/openapi.yaml` 的 `CreativeSceneSky`、`CreativeSceneCamera`、`CreativeSceneRender` 加字段，运行 `make generate`，提交两份生成物。
6. **助手**：`edit_scene` / `read_scene` 的说明写入：
   - 物理天空和曝光的字段与单位；
   - 预设参数表；
   - 常见场景的 EV100 参考值（晴天、阴天、日落、蓝调时刻、夜景）；
   - 「物理天空下要给摄像机设曝光，视口和临时视点用默认曝光值」；
   - 按太阳参考选时刻（例如「傍晚黄金时刻」），按场景坐标的太阳方位摆逆光、侧光的机位，写入后用 `render_view` 的 `lit` 确认观感。

   `docs/dev/agent-skills-tools.md` 记录变更。
7. **静态检查**（`patterns: 场景着色写法`「检查」）：`frontend/src/creative-scene/world/` 和 `render/` 里出现 `Date.now()` 或无参的 `new Date()` 时，`make check-frontend` 失败。
8. **参考数据**（Epic design「验证与交付」交给 W2 确定）：
   - 参考场景：晴天正午、黄金时刻、日落后 20 分钟，作为 e2e 固定数据提交，内容沿用 R0 参考场景的「院子」。
   - 参考地点：上海、北京、成都，加上悉尼（南半球，检查方位约定）。
   - 参考设备沿用 R0：Mac16,8（Apple M4 Pro）。
9. **规格**：修订 `creative/scene` 的「编辑灯光与环境」「渲染器与输出分辨率」「导出图提示场景已更新」「摄像机景深与对焦」「助手配材质和打光」，新增「物理天空」「摄像机曝光」两条要求（specs.md）。

不在本子项：
- 夜空（W3）、空气透视（W4）、体积物件（W5）。`sky.night`、`sky.aerial_perspective`、`sky.clouds` 和 `environment.weather` 写入时返回 400（`data: 物理天空`）。
- 自动曝光（Epic 修订 v2 的非目标）。

## Acceptance Criteria

整体验收留在 Epic。参考设备、参考地点和参考场景见 What Changes 第 8 项。

- **AC-W2-1 地点与时间**（Epic AC-2）：
  - **WHEN** 物理天空设为上海、2026-06-21，时刻从 05:00 拖到 20:00，**THEN**：
    - 太阳的方向与 NOAA 太阳计算器相差不超过 0.5°（按角距比较，只比视高度 ≥ 0 的点）；
    - 日出、日落时刻（太阳上缘过地平线）相差不超过 2 分钟；
    - 画面依次经过晨昏蒙影、日出、蓝天、黄昏和入夜，太阳光的颜色和强度连续变化；
    - 改正北方向后，太阳和影子随之绕场景转动。
  - **WHEN** 换成悉尼的同一天正午，**THEN** 太阳在正北方向的天空里。
  - **WHEN** 时刻落在夏令时跳过的那一小时里，**THEN** 按往后推一个跳变量计算；重复的那一小时取较早的一次。
  - 天文精度和时间换算由 `world/astro.ts` 的单元测试对照 NOAA 的数据点验证，覆盖四个参考地点。
- **AC-W2-2 手动模式**：
  - **WHEN** 切到手动模式，**THEN** 可以直接调太阳高度和方位，用法与程序化天空相同。
  - **WHEN** 从地点模式切到手动，**THEN** 太阳位置不变，Cmd+Z 回到地点模式。例外：太阳低于 −10° 时，高度夹到 −10°。
- **AC-W2-3 物理亮度与曝光**（Epic AC-3）：
  - **WHEN** 选晴朗预设，太阳高度不低于 60°，**THEN** 场景原点处的水平照度在 100–130 klux 之间。
  - **WHEN** 摄像机设为 ISO 100、1/125 s、f/16（EV100 ≈ 15），分别拍晴天正午和日落后 20 分钟，**THEN** 正午的画面曝光正常，EV100 与正午的入射式测光值（测试里按 C = 250 算出）相差不超过 1 档；日落后的画面明显变暗，测光值比正午低 5 档以上。
  - **WHEN** 改光圈，**THEN** 画面亮度和景深一起变化。
  - **WHEN** 视口在自由视角下改默认曝光值，**THEN** 视口亮度随之变化，相机视图和导出不变；切到相机视图时按这台摄像机的曝光显示。
  - **WHEN** 在物理天空下添加摄像机，且默认曝光在缺省光圈 f/2.8 可达的范围内（EV100 约 −11.9…17.9），**THEN** 相机视图与添加前的视口亮度相差不超过 1/3 档。
- **AC-W2-4 太阳的亮度与色温**：
  - **WHEN** 把太阳亮度调到 2，**THEN** 太阳光、天空和天空光照一起变亮一档。
  - **WHEN** 把色温调低，**THEN** 光线和天空一起变暖；调回 6500 K 时与物理计算逐像素相同。
- **AC-W2-5 灯光与真实照度**（Epic AC-3）：**WHEN** 场景里有一盏 40 cd 的台灯，**THEN** 正午时几乎看不出它的光；入夜后它成为主要光源，手动曝光调到夜景（例如 ISO 1600、1/30 s、f/2.8）时能看清它照亮的区域。
- **AC-W2-6 其他天空模式不变**（Epic AC-3）：
  - **WHEN** 打开程序化天空或纯色天空的参考场景，**THEN** 最终渲染、`lit` 导出和 `render_view` 的 `lit` 与 W2 之前逐像素相同（差 > 2 的像素为 0）；已有导出图不显示「场景已更新」。
  - **WHEN** 在这些天空下查看摄像机属性和渲染选项卡，**THEN** 曝光一栏和默认曝光值置灰，说明只在物理天空下生效。
  - **WHEN** 物理天空下打开「环境」选项卡，**THEN** 环境光置灰并说明原因。
- **AC-W2-7 大气参数与预设**（Epic AC-4）：**WHEN** 依次选「晴朗」「雾霾」「高原」「沙尘」，或单独调尘埃密度和海拔，**THEN** 天空、太阳光和天空光一起变化：雾霾更白更暗，高原天顶更深蓝，沙尘偏黄。高原上地平线不下沉，场景地面与天空之间不露出海平面的地面。样例存进 evidence，由 owner 判断是否可信。
- **AC-W2-8 两个后端**（Epic AC-8）：**WHEN** 在 WebGL2 后端（SwiftShader）下打开物理天空的参考场景，**THEN** 视口和 `lit` 导出与 WebGPU 后端的差异在阈值内：含场景的画面沿用 R1 的 `lit` 阈值，只含天空的画面平均差 ≤ 0.5、差 > 8 的像素 ≤ 0.05%。
- **AC-W2-9 确定性与过时**（Epic AC-9）：
  - **WHEN** 在隐藏的标签页里连续两次导出物理天空的参考场景，**THEN** 两次结果逐像素相同。
  - **WHEN** 改地点、日期、时刻、时区、正北、大气参数、太阳的亮度、色温或太阳盘，**THEN** `lit` 导出显示「场景已更新」，`clay`、`line` 不显示。
  - **WHEN** 只改一台摄像机的曝光，**THEN** 只有这台摄像机在物理天空下的 `lit` 导出过时；改默认曝光值，或在非物理天空下改曝光，三种导出都不过时。
  - 由 `fingerprint_internal_test.go` 为 What Changes 第 3 项的每条规则各加一个用例。
- **AC-W2-10 助手**（Epic AC-10 中天空与曝光的部分）：
  - **WHEN** 摄影师请助手「改成成都 10 月 1 日傍晚的黄金时刻，加一点雾霾，用相机手动曝光」，**THEN** 助手写入物理天空（地点、日期、时刻、时区、预设参数），给摄像机设合适的 ISO 和快门，并用 `render_view` 的 `lit` 回看。写入的时刻落在太阳参考给出的傍晚黄金时刻里。
  - **WHEN** 助手读物理天空地点模式的场景，或写入这样的环境，**THEN** 结果里带太阳参考：当前太阳的高度和方位、日出日落、正午、早晚的黄金时刻（−4°…6°）和蓝调时刻（−6°…−4°），与 NOAA 的日出日落相差不超过 1 分钟。手动模式和其他天空下不带。
  - **WHEN** 助手写错字段，例如地点三项只写一部分、时区名无效或大小写不对、物理天空下写 `turbidity`、程序化天空下写 `date`、提前写 `night`，**THEN** 工具说明原因，场景不变。
- **AC-W2-11 性能**（Epic AC-11）：
  - **WHEN** 在参考设备上拖动时刻滑杆，**THEN** 视口不低于 30 fps，天空光照在 200 ms 内跟上。
  - **WHEN** 物理天空静止，**THEN** 视口帧时间比程序化天空多不超过 2 ms。
- **AC-W2-12 城市数据**：
  - **WHEN** 在城市搜索里输入「成都」「Chengdu」或「稻城」，**THEN** 第一项就是要找的地点，选中后经纬度和时区随之写入。
  - **WHEN** 打开城市下拉，**THEN** 底部显示 GeoNames 的署名。

## Risk Notes

- **影响面广（broad-impact）**：
  - 渲染管线的曝光改为可以在写入缓冲前生效，材质输出统一钳制。视口、`render_view` 和导出都经过它，非物理天空必须逐像素不变，用 AC-W2-6 的对照把关。
  - 回滚到不认识新字段的后端时，含物理天空或曝光字段的场景会读取失败，只做前向修复（Epic design「接口设计」）。
- **性能（perf-sensitive）**：拖动时刻滑杆时，每次提交都要重算天空视图 LUT、天空光照和 CPU 上的天空照度。穿刺里前两项在参考设备上 4.3 ms，CPU 照度积分的原型代码约 6 ms、换大气参数时约 175 ms，实现时要优化（typed array、去掉逐步分配），验收按 AC-W2-11。
- **手动曝光的门槛**：拖动时刻时画面会真实变暗变亮，需要摄影师自己调曝光。助手说明里给出 EV100 参考值；渲染选项卡在默认曝光值旁边列出同样的参考值。
- **晨昏蒙影偏亮**：太阳在 −6° 到 −9° 时，水平照度比实测高 4–10 倍（`atmosphere-luts.md` 第 6 节），手动曝光下蓝调时刻会比实拍亮 2–3 档。这是 Hillaire 多次散射近似的局限，记进规格，改进留作后续增强。
- **地平线接缝**：晨昏蒙影时，场景地面的边缘和地平线之间有一道暗线（`atmosphere-luts.md` 第 4 节）。本子项在星球地面上补上天空光，W4 的空气透视会进一步融合。
- **W2 的夜晚是黑的**：月亮和星空在 W3。
- **新摄像机的曝光范围**：默认曝光高于 EV100 约 17.9 时，缺省光圈 f/2.8 加上最快快门和最低 ISO 也不够暗，新摄像机比视口暗，最多约 2 档。不为此改光圈，因为光圈还决定景深。

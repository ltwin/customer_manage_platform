# 体积光照穿刺（Epic 未决事项 2、7）

- 日期：2026-10-23
- 问题：
  - 体积物件的光照用逐像素光线步进还是 froxel，在参考设备上各要多少帧时间；
  - WebGL2 下能不能实现；
  - 与实时 GI、空气透视怎么合成；
  - 每个场景最多几个体积物件。
- 原型：`prototype/`（`src/vol.ts`）。图在 `spike/`。
- 参考设备：M4 Pro，Chromium 无头模式；WebGPU 走 Metal，WebGL2 走 ANGLE Metal，另用 SwiftShader（日常 e2e 的环境）核对画面。

## 结论

1. **采用逐像素光线步进（做法 A）**。froxel（做法 B）更省，但光束边缘成阶梯，物体正面会漏光，不满足 AC-7 的窗框光束（第 3 节）。
2. **两个后端都能实现，结果一致。**
   - 同一份 TSL 只用片元 pass，在 WebGPU、WebGL2（ANGLE）和 SwiftShader 下都能编译运行。
   - 与 WebGPU 相比：
     - WebGL2 的平均差 ≤ 0.03，差值 > 8 的像素 ≤ 0.016%；
     - SwiftShader 与不加体积时一样，平均差约 0.19，差值 > 8 的像素约 0.4%。
   - 两个后端的帧时间相差在 15% 以内。
   - 所以不必启用「只支持 WebGPU 的统一规则」，`data: 场景客户端任务` 和 `api: 认领场景客户端任务` 不用改。
3. **帧时间。** 视口的条件：1440p、DPR 2、步进分辨率为画面的 1/4、太阳加聚光加点光、自身遮挡和环境光都算。
   - 1 个体积 2.0 ms，8 个体积 3.0 ms；
   - 每多一盏投影的灯约多 0.4 ms；
   - 4K 导出按半分辨率步进约 15 ms 一帧。
4. **体积上限仍为 8 个。** 开销大致随数量线性增长，8 个时视口约 3 ms。
5. **合成位置**：
   - 在不透明表面（含 GI 合成和全局雾）之后、空气透视之前；GI 路径里在 TRAA 之前。
   - 不与 W4 的 froxel 合并，因为没有采用 froxel。
6. **自遮挡：每个体积只算自身。** 光线在体积内到光源方向的出口距离用解析式求出，不另行步进；体积之间互相遮挡不计。
   - owner 定（第 6 节）：在表面上投影做成可选项 `volume.cast_shadow`，8 个都打开时 +2.5 ms；体积受天空光照照亮。
7. **导出确定。** 抖动用固定的交错梯度噪声：同一画面在 WebGPU 和 SwiftShader 下连拍两次，逐像素相同。

## 1. 做法

两种做法共用一份光照求值（`vol.ts` 的 `inscatter`）。在世界坐标 p 处：

- **体积**：
  - 每个体积是单位立方体或单位球，经物件的变换矩阵放进场景，最多 8 个，存在 uniform 数组里。
  - 密度从边界向内按 `edge_falloff` 由 0 升到满值（smoothstep）。
  - 系数取 `data: 体积物件`：σs = `scatter_density` × `scatter_color`，σa = `absorption_density` × (1 − `absorption_color`)，都按线性颜色计。
- **光**：
  - 太阳：按视深选级联，与产品的 `CSMShadowNode` 同一套 `_cascades` 区间和各级联的阴影矩阵；
  - 聚光：锥形衰减、距离平方衰减和 2D 阴影贴图；
  - 点光：距离平方衰减和立方体阴影贴图。
  - 光强取灯本身的颜色 × `intensity`。产品里这已经乘过预曝光（`world/exposure.ts`），与材质一致。
  - 阴影贴图直接取 three 设在 `light.shadow.map.depthTexture` 上的那张，做法与 `ShadowNode` 相同：`shadow.matrix` 变换、y 翻转、比较采样。
  - three 生成的是 `textureSampleCompare`。它在循环和分支里也能编译，因为 three 关掉了 WGSL 的 `derivative_uniformity` 诊断（`WGSLNodeBuilder.js:283`）。
- **相函数**：Henyey–Greenstein，g = `anisotropy`。
- **积分**：Hillaire 2015 的能量守恒步进，`L += T · (S − S · e^(−σt·dt)) / σt`，`T *= e^(−σt·dt)`。σt 是 RGB，所以透射率带颜色。
- **合成**：`颜色 · T + L`，在色调映射之前，与空气透视写法相同。

**做法 A（逐像素步进）**

- 按画面的一定比例，从摄像机向不透明表面发射线。
- 先与每个体积求交，只在穿过体积的区间里走固定步数，并记下这条线穿过了哪些体积，步进时只看这些。
- 起点按交错梯度噪声抖动。
- 两个输出：散射光和透射率，用 `outputStruct` 一次写两个目标。
- 之后在低分辨率上做一次按深度加权的可分离模糊（每个方向 7 个采样），再按深度相近度加权 4 点上采样到全分辨率。

**做法 B（froxel）**

- 视锥按 FX × FY × FZ 切成小格：深度方向按指数分布，范围贴合体积的视深范围。
- 小格存在 2D 图集里（按深度分片平铺），所以只用片元 pass，WebGL2 也能写。
- 第一个 pass 给每格算光照，第二个 pass 按列从前往后积分，合成时按像素的深度在两片之间插值。

## 2. 帧时间

计时方法：

- 连续提交 30 帧、只等一次，取 5 轮的中位数，记有体积减无体积的差。
- WebGL2 下逐帧读像素会对齐到合成器的节拍（约 8.3 ms 一档），测不准，所以统一用吞吐。
- 表中数字的波动约 ±0.2 ms。

**两种做法**（1920 × 1080，一个盖住整间屋子的体积，三盏灯，不算自遮挡和环境光，没有按穿过的体积跳过；单位 ms）：

| 用例 | WebGPU | WebGL2 |
|---|---|---|
| A，半分辨率，48 步，加模糊 | 2.33 | 2.49 |
| A，半分辨率，32 步，加模糊 | 1.63 | 1.89 |
| A，半分辨率，64 步，加模糊 | 3.00 | 3.09 |
| A，半分辨率，48 步，不模糊 | 2.25 | 2.27 |
| A，全分辨率，48 步 | 8.48 | 8.90 |
| A，半分辨率，48 步，只有太阳 | 1.53 | 1.67 |
| A，半分辨率，48 步，8 个体积 | 5.13 | 5.01 |
| B，160 × 90 × 64 | 0.90 | 0.86 |
| B，160 × 90 × 128 | 3.04 | 4.16 |
| B，240 × 135 × 64 | 1.84 | 3.33 |
| B，160 × 90 × 64，8 个体积 | 0.97 | 1.11 |

- B 的第二个 pass 每格从头积分到自己，开销随片数的平方增长。

**自遮挡**（WebGPU，1080p，A，半分辨率，48 步，加模糊，屋子加一个浓的球）：

| 用例 | ms |
|---|---|
| 不算自遮挡 | 2.73 |
| 只算自身：每个体积用自己的弦长 | 3.90 |
| 算所有体积的弦长 | 6.55 |
| 8 个体积，只算自身 | 6.17 |
| 8 个体积，算所有体积 | 18.65 |

**数量与分辨率**（WebGPU，A，48 步，加模糊，只算自身，按穿过的体积跳过）：

| 用例 | ms |
|---|---|
| 1080p，半分辨率，1 / 2 / 4 / 8 个体积 | 3.67 / 3.99 / 4.58 / 5.51 |
| 1080p，8 个体积，不按穿过的体积跳过 | 6.19 |
| 1440p，半分辨率 / 3/8 / 1/4 | 6.28 / 3.66 / 1.91 |
| 4K，半分辨率 | 14.84 |

**视口条件**（1440p，1/4 分辨率步进，48 步，加模糊，只算自身，加环境光；单位 ms）：

| 用例 | WebGPU | WebGL2 |
|---|---|---|
| 1 个体积，太阳、聚光、点光 | 2.05 | 1.98 |
| 8 个体积，太阳、聚光、点光 | 3.01 | 2.78 |
| 1 个体积，只有太阳 | 1.23 | 1.12 |
| 1 个体积，太阳和聚光 | 1.63 | 1.39 |
| 4K 导出，半分辨率 | 15.36 | 15.59 |

- 视口按 DPR 2 绘制（`Viewport.tsx:260`）。步进分辨率按 CSS 像素的一半定，相当于 DPR 2 时画面的 1/4。1440p 下与半分辨率的差别只在窗棂阴影的边缘略软（`spike/scale-1440p.jpg`）。
- 首次构建体积 pass 的编译：热缓存下 150–450 ms。灯光组合改变时与材质一样要重新编译。

## 4. 与实时 GI 和空气透视的合成

现行的两条路径（`render/sceneRenderer.ts`、`render/realtimeGI.ts`）：

- **工作台路径**：画面 × AO → 空气透视 → 景深 → 夜色 → 色调映射。
- **实时 GI 路径**：GI 合成 → 全局雾 → 空气透视 → 辅助对象 → TRAA → 景深 → 累积 → 夜色 → 色调映射。

体积插在两条路径的「空气透视」之前：

- 读同一张不透明深度：工作台路径读 prepass 的深度，GI 路径读 GI prepass 的深度。
- 与 Epic design「合成顺序」第 3 步一致，空气透视仍在体积之后，作用于整个画面。
- 世界空间 GI（`scene-world-space-gi`）改的是 GI 合成内部，不影响这个位置。

GI 路径里体积在 TRAA 之前：

- 步进的抖动可以每帧换一组，由 TRAA 和导出的帧累积做平均，深度加权模糊可以减弱或去掉。
- 帧序号是确定的，所以导出仍然确定。
- 工作台路径没有时域累积，用固定噪声加模糊。

透明物件：

- 与空气透视相同，体积按不透明表面的深度合成。
- 玻璃后面那段体积叠在玻璃之上，而不是被玻璃滤过，记为局限。

## 5. 体积上限

- 视口条件下 8 个体积 3.0 ms，比 1 个多 1 ms。开销主要来自每一步对所有体积求密度。按穿过的体积跳过之后，不在视线上的体积几乎不花时间。
- 上限维持 8 个（`data: 体积物件`）。放宽到 16 个技术上可行，但 uniform 数组和每步的循环都要加倍。目前没有用例需要，不预支。

## 6. 两处观感（owner 2026-10-23 已定）

1. **体积在表面上的投影：做成可选项**（`volume.cast_shadow`，缺省关）。
   - owner：「在体积雾中增加一个可选项」。
   - 薄雾（σ ≈ 0.1–0.3 /m）几乎没有影响。浓的体积（例如 σ = 4 /m 的烟团）在 Blender 里会在地上投下明显的影子，打开后这里也有。
   - 做法：太阳、聚光、点光的阴影节点乘上表面点到灯之间穿过各体积的透射率，用同样的解析弦长。原型里太阳包在产品的 `SunCascades` 外面，聚光、点光各包一个 `ShadowNode` / `PointShadowNode`（`vol.ts` 的 `volumeShadows`）。
   - **`spike/cast-shadow.jpg`**：左为关、右为开。上排是院子里的浓烟球，打开后在地上投下柔和的影子；下排是聚光下的烟柱，打开后下面的球和光斑变暗。
   - 开销（1440p，表面全分辨率着色，三盏投影灯，场景本身的帧时间增加）：

     | 打开投影的体积 | WebGPU | WebGL2 |
     |---|---|---|
     | 2 个 | +0.7 ms | +1.4 ms |
     | 8 个 | +2.5 ms | +3.6 ms |

   - 产品里只对打开了 `cast_shadow` 的体积求交，按 uniform 控制，开关不重新编译材质。
2. **环境光（天空光照）照亮体积：加**（`spike/ambient.jpg`）。
   - 体积按各向同性的平均天空亮度得到散射光，与材质得到的环境光一样不计遮挡。
   - 户外阴影里的雾不会发黑；室内的雾整体偏灰，光束的对比变弱。
   - 世界空间 GI 的辐照度探针落地后，体积可以改采样探针，室内就能暗下来（`scene-world-space-gi` 的质量层）。

## 7. 局限

- 体积之间互相遮挡不计（每个体积只算自身的弦长）。
- 自遮挡按均匀介质算，忽略边缘柔化，对柔化很宽的体积略偏暗。
- 透明物件后面的体积按不透明表面合成，见第 4 节。
- 原型里体积没有旋转。产品里按完整的变换矩阵求交，单位体上的解析式不变。
- 帧时间只在参考设备上测过，没有测更弱的集显。

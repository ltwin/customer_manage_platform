# Epic: creative-mcp-server — 外部助手经 MCP 使用创意空间

永久需求文档：本 Epic 的目标、边界和交付计划。整体方案见 design.md，目标契约见 contracts.md。项目 `.lti/contracts/` 记录当前已交付事实。探索共识见 `discovery/brainstorm.md`（Owner 决定 D1–D13）。调研见 `discovery/research/`：`libtv-plugin.md` 是竞品，`host-ui-surfaces.md` 是宿主交互面。原型见 `docs/prototypes/creative-mcp/`。

## 目标

不少创作者已经在用 ChatGPT、Claude 或编码助手（Codex、Claude Code）。本 Epic 完成后，他们可以：

1. 打开创意空间的「外部助手」接入页，选好自己用的宿主，复制一段话发给它，按提示授权一次，外部助手就连上自己的创意空间账号：
   - Codex CLI：安装插件。
   - Claude 桌面端、网页和 Claude Code：新建一个连接器。
   - ChatGPT：在 Developer Mode 里添加应用。
   - 没有权限新建连接器或应用时（例如 Team 成员），接入页给出回退方法。
2. 在宿主里让外部助手读画布、改画布、写提示词、生成图片、整理资产库、搭 3D 场景并回看、导出分镜，用平台 Skill 做策划。外部助手给出画布链接，创作者在浏览器里实时看到变化。
3. 在 ChatGPT 和 Claude 桌面端、网页里，生成和场景结果以内嵌卡片出现：
   - 生成前的预检可以直接点「生成」确认；
   - 提交后卡片自己显示进度和结果图；
   - 回看排队等页面时，卡片给出「打开创意空间」。

   Codex CLI 和 Claude Code 只有文字和链接，流程不受影响。
4. 在历史里看到「Claude」「Codex」「ChatGPT」的署名，回退它的改动；自己的 Cmd+Z 不会撤掉外部助手的改动。
5. 在接入页看到已连接的外部助手，随时断开。

外部助手拿到的能力与内置助手一致：同样的领域规则、同样的工具语义、同样的生成计费。只是对话和计划由外部助手自己负责。

## 范围与非目标

- **范围**：
  - OAuth 授权服务器（只服务外部助手接入）：元数据、客户端注册、授权页、令牌签发与轮换、撤销。
  - 远程 MCP 端点 `https://<域名>/mcp`：
    - 提供 22 个内置工具，以及 3 个外部专用工具：`get_capabilities`、`list_canvases`、`wait_tasks`。
    - 服务端 `instructions` 写明工具用法和运行规则，是所有宿主共用的使用说明。
  - 「外部助手连接」作为与「运行」并列的助手主体，接入文档署名、生成记录、资产库日志、场景客户端任务和 consent。
  - 画布交接：写工具的结果带画布链接（可聚焦到节点）；`generate_node` 支持 `dry_run` 预检，由外部助手自己决定是否使用。
  - 工具结果文字：
    - 第一行是结论，随后是链接和下一步，再附结构化结果；
    - 终端宿主只显示前几行时也能看懂；
    - 工具有中文显示名和只读、删除标注。
  - 内嵌卡片（MCP Apps，D10–D11），ChatGPT 与 Claude 共用：
    - 生成与任务卡：`generate_node`、`wait_tasks`；
    - 镜头卡：`render_view`、`export_shots`；
    - 只对声明支持卡片的宿主下发，其他宿主只收文字结果。
  - 前端：
    - 「外部助手」接入页：选宿主，复制接入文字，查看回退方法；连接列表与断开也在这里。
    - 授权确认页。
    - 创意空间的「外部助手已连接」指示。
    - 场景历史显示外部助手署名。
  - 接入物料：Codex 插件（manifest、MCP 配置，只发生产包）；Claude 连接器与 ChatGPT 应用的接入文字；Team 成员无权限时的回退文字。
  - 首批宿主（D7）：ChatGPT、Codex CLI、Claude Code、Claude 桌面端（含网页）。
- **非目标**（显式排除）：
  - 网页搜索和读取，以及运行内部工具 `update_plan`、`read_history`、`read_run_result`、`list_conversation_assets`（D6）。
  - 服务端无头渲染（D2）。建模、回看、导出仍需要一个打开的创意空间页面。
  - 把外部助手的对话镜像到内置助手面板（D4）。
  - 无人值守的批量自动化作为首要场景（D1），不为它做专门的调度和配额。
  - 平台 Skill 打包进公开插件（D3）。
  - 按工具或按画布的细粒度授权：一次授权就是账号级全部创意能力（D5）。
  - Claude 插件（D8）；Claude 桌面扩展（`.mcpb`）形式的本地代理。
  - 国内宿主（OpenClaw、Hermes、CodeBuddy 等），以及 Codex 桌面 app、IDE 扩展的首批验收。
  - 上架官方目录（Claude 连接器目录、ChatGPT 应用目录、OpenAI 插件目录）。
  - 其他卡片：画布卡、资产库卡片、Skill 卡片、画中画；在卡片里编辑画布（深度编辑回到创意空间页面）（D11）。
  - CRM 业务数据（客户、订单、日程）。
  - 本地 stdio MCP 进程。

## 接口约定

目标契约在本 Epic 的 `contracts.md` 中定义，子项按 `epic bind` 引用：

- 架构：`architecture: ADD 外部助手接入`
- 术语：`glossary: ADD 外部助手`、`glossary: ADD 外部助手连接`
- 数据：
  - `data: ADD 外部助手连接与 OAuth`
  - `data: MODIFY 通用文档`：写入者增加外部助手。
  - `data: MODIFY 场景客户端任务`：任务可以归属外部连接。
- 接口：
  - `api: ADD OAuth 授权服务器`、`api: ADD MCP 端点`
  - `api: ADD 外部助手连接列表与断开`、`api: MODIFY 列出文档修订`
  - `api: ADD MCP 只读工具`、`api: ADD MCP 写入与生成工具`、`api: ADD MCP 场景与 Skill 工具`
  - `api: ADD MCP 生成与任务卡`、`api: ADD MCP 镜头卡`

既有约定沿用：账号隔离（ADR-001）、`ErrorEnvelope`、`creativeops` 的 operation id 幂等与回执、暂存上传、`/api/v1/creative/...` 路径前缀、账号级失效通道。

## 验收标准

全部子项完成后做整体验收：

- **AC-1 接入**：**WHEN** 创作者在接入页选择 ChatGPT、Codex CLI、Claude Code 或 Claude 桌面端，把给出的文字发给外部助手（或按文字自己操作），**THEN** 宿主打开浏览器授权页，创作者用已有账号登录并确认后，外部助手就能调用工具。令牌过期后自动续期，不需要再次授权。
- **AC-1a 回退**：**WHEN** 创作者是 Claude Team 成员、没有权限新建连接器，**THEN** 接入页给出两条路：Claude Code 用本机命令添加；桌面端把一段说明发给管理员，由管理员在组织里添加。按任一条路都能完成 AC-1。
- **AC-2 隔离**：**WHEN** 外部助手调用任何工具，**THEN** 只能读写授权账号的数据。网页端令牌不能调用 MCP，MCP 令牌也不能调用网页端接口。
- **AC-3 读**：**WHEN** 创作者说「看看我最近的画布」，**THEN** 外部助手能列出画布、读取画布内容和引用素材的图片、查找资产库。**WHEN** 外部助手调用 `get_capabilities`，**THEN** 得到连接的账号、可用的生成模型、剩余额度，以及当前有没有打开的创意空间页面。
- **AC-4 写与生成**：**WHEN** 外部助手修改画布、写提示词并生成，**THEN** 浏览器里的画布实时出现变化，生成按与摄影师相同的规则扣额度，结果图片回到外部助手的上下文里，供它判断是否满意。工具结果带画布链接，可以聚焦到改动的节点。**WHEN** 外部助手用 `dry_run` 调用 `generate_node`，**THEN** 只返回将用的模型、参考和预计扣费，不生成、不扣费。是否预检由外部助手决定，创作者要求全自动执行时可以不做。
- **AC-5 长任务**：**WHEN** 生成或场景任务超过单次工具调用的等待上限，**THEN** 工具返回任务句柄，外部助手用 `wait_tasks` 继续等待。四个宿主在各自的默认超时下都不出错。
- **AC-6 场景**：**WHEN** 创作者开着创意空间页面，让外部助手搭一个场景，**THEN** 外部助手能写模型、改场景、用 `render_view` 回看、导出分镜到画布。**WHEN** 没有打开的页面，**THEN** 任务保持排队，`wait_tasks` 返回「等待页面」状态和要打开的链接；打开页面后任务继续完成。
- **AC-7 署名与撤销**：**WHEN** 外部助手改了场景里的物件 A，创作者随后改了物件 B 并按 Cmd+Z，**THEN** 撤销的是 B，A 保持外部助手的改动。历史列表里外部助手的修订署名为宿主名，可以预览和恢复。
- **AC-8 Skill**：**WHEN** 外部助手调用 `search_skills` 和 `load_skill`，**THEN** 能拿到平台 Skill 和账号自己的 Skill 的正文与资源，并按 Skill 的指引使用工具完成策划。
- **AC-9 感知与断开**：
  - **WHEN** 外部助手在最近 5 分钟内调用过工具，**THEN** 创意空间显示「外部助手已连接」及其名称。
  - **WHEN** 创作者在接入页断开连接，**THEN** 该连接的下一次调用立即被拒绝，排队中的场景任务被取消，宿主需要重新授权。
- **AC-10 四个宿主**：ChatGPT、Codex CLI、Claude Code、Claude 桌面端都完成 AC-1、AC-3、AC-4 的流程；C2b 归档前在 ChatGPT、Claude 桌面端补测 AC-11 的生成与任务卡；C3 归档前补测 AC-6、AC-8 与镜头卡。
- **AC-11 内嵌卡片**：
  - **WHEN** 外部助手在 ChatGPT 或 Claude 桌面端里用 `dry_run` 调用 `generate_node`，**THEN** 对话里出现预检卡，显示模型、参考、预计扣费；创作者点「生成」即提交，不需要再对外部助手说一句话。
  - **WHEN** 生成已提交，**THEN** 卡片自己显示进度和结果图，可以全屏查看、存入资产库；外部助手在下一轮得知创作者在卡片里做的决定，不重复提交。
  - **WHEN** 回看或导出分镜，**THEN** 出现镜头卡；任务排队等页面时，卡片给出「打开创意空间」，打开后自动继续。
  - **WHEN** 宿主不支持卡片（Codex CLI、Claude Code），**THEN** 同一工具只返回文字，AC-4、AC-6 照常完成。
  - 卡片跟随宿主的明暗主题。

## 交付路线

见 roadmap.md。四批串行：连接与只读（C1）→ 写入与生成（C2）→ 内嵌卡片（C2b）→ 场景与 Skill（C3，含镜头卡）。C1 设计前先做活原型，在真实宿主里核实宿主行为（D13）。

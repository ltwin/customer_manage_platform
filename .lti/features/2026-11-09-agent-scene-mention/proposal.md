# 助手引用画布节点与 3D 场景物件

## Why

助手的 @ 只能引用画布上的文本和图片，3D 场景节点不在候选里；选中的物件也只有在打开 3D 编辑器时才会带给助手。画布上有多个场景时，助手只能按标题猜是哪个场景；节点多了以后，@ 菜单里也很难找到想要的那一个。

## 现状（2026-11-09 核对）

- @ 候选只包含 `text` / `image` 内容（`frontend/src/creative-canvas/editor/agentReferences.ts` 的 `agentReferences`）。指令片段只有 `text`、`skill_ref`、`content_ref`、`command` 四种（`backend/internal/creativeagent/instruction.go` 的 `validSegments`）。
- @ 菜单只能靠 `@` 后面输入的文字过滤，只匹配标题和类型名；用按钮打开菜单时没有地方输入搜索词，列表也不分组（`PromptEditor.tsx`）。
- 选中物件通过 `scene_context` 传给助手：一次只有一个场景，而且只在场景编辑视图里发起时才带（`api/openapi.yaml` 的 `CreativeAgentRunPayload.scene_context`）。服务端把它冻结为运行输入，并在摄影师的消息后追加 `scene_selection` 块（`backend/internal/creativeagent/inputs.go`）。
- 画布节点的选中只在 `WorkspacePage` 里记录为单个 `selected`，助手面板拿不到。
- 场景工具都要求 `document_id`（`backend/internal/creativeagent/scene_tools.go`）。在画布视图下，助手需要先读画布，再按标题对应到场景。

## 已拍板（owner 2026-11-09）

1. 二级菜单是物件列表（类似 Blender 的大纲视图）。「拖选」指在列表里按住鼠标拖过连续多行；在 3D 缩略视口里框选不做，列为后续项。
2. 一个 feature 覆盖前端、后端和 OpenAPI 契约。
3. 顺带两项交互优化：在画布上点选节点后，节点进入输入框成为「待选 @」，交互参照 LibTV；@ 菜单增加搜索。
4. 待选 @ 的规则：
   - 在画布上点选单个节点时，输入框的光标位置出现一个置灰的待选引用。
   - 摄影师点进助手输入框后，待选引用转为正式的 @ 引用。
   - 正式引用之后输入了文字，再点选节点，会在光标后面再出现一个新的待选项。
   - 待选状态下点选其他节点，替换掉这个待选项。
5. 3D 编辑器里的物件选中也改用这套方案：选中的物件作为待选引用进入正文，不再显示浮在输入框上方的「选中物件」标签。这样摄影师可以自己安排语序，比如让一批物件改成一种样子、另一批改成另一种样子。

## What Changes

- **@ 场景**：@ 菜单列出画布上的 3D 场景节点，回车只引用场景本身。
- **@ 物件**：场景这一项可以展开二级菜单，按 `parent_id` 的层级列出物件。支持单击、Cmd/Ctrl + 单击、Shift + 单击、在列表里拖动连续多选；第一行是「整个场景」。正文里显示为「场景A · 台灯、主光 +2」这样的标签，点击标签可以重新编辑。
- **新指令片段 `scene_ref {document_id, object_ids?}`**：嵌在正文里，按出现位置排列，和 `content_ref` 一样。服务端校验后，把场景标题和物件名冻结成消息块的快照（做法同 `scene_selection`），助手的运行输入里写明每个引用指向哪个场景、哪些物件。引用之后被删掉的物件，会以「物件 ID + 已不在场景里」的形式告诉助手，不会静默丢掉。服务端只能读到当前场景，拿不到已删物件的名称，所以本期不承诺显示原名。
- **选中进入待选 @**：选中的内容会在输入框光标处变成一个置灰的待选引用。点进输入框后，它转为正式引用；选中发生变化时，待选引用随之替换；取消选中时，它消失。待选引用只是前端的占位，不存进草稿，也不会被发送；转为正式引用后，就是普通的 `content_ref` / `scene_ref`。待选引用有两个来源：
  - 画布视图：当前恰好选中一个可引用的节点（文本、图片或场景）时产生，对应这一个节点。
  - 3D 编辑器：当前选中的全部物件合成一个待选引用，例如「客厅 · 台灯、主光」。在编辑器里多选，就是在框定「一批」物件。
- **@ 菜单搜索**：菜单顶部加一个搜索框，按标题、节点类型、文本内容的开头匹配。在 `@` 后面打的字会同步到搜索框；用按钮打开菜单时，焦点直接落在搜索框里。列表按「场景 / 图片 / 文本」分组，画布上当前选中的节点排在前面。二级菜单也有搜索框，按物件名过滤，命中的物件会连同它的上级一起显示。
- **去掉编辑器的浮层选中标签**：删除输入框上方的「选中物件」标签（`SceneSelectionTag`）。`scene_context` 只保留「正在编辑哪个场景」这一层意思，前端发送时 `selected_object_ids` 固定为 `[]`，这个字段在 OpenAPI 中标记为 deprecated，但仍然接受，这样发布后还在跑旧页面的客户端不会被拒绝。服务端读取旧消息里的 `scene_selection` 块时照常显示，新消息不再产生这种块。

## Acceptance Criteria

### @ 场景与二级菜单

- WHEN 画布上有两个 3D 场景节点「客厅」「卧室」，摄影师在助手输入框里输入 `@` THEN 菜单的「场景」分组里出现这两项，显示节点标题。
- WHEN 在「客厅」这一项上回车，或单击这一项 THEN 正文插入「客厅」场景标签，菜单关闭。
- WHEN 在「客厅」上按 →，或单击右侧的展开箭头 THEN 打开二级菜单，按场景当前的快照列出物件，子物件缩进显示在父物件下面，第一行是「整个场景」。读取中显示加载状态；读取失败时显示原因和重试按钮，不插入任何引用。
- WHEN 单击「台灯」，再按住 Cmd（Windows 上为 Ctrl）单击「主光」 THEN 两个都被选中；再按住 Cmd/Ctrl 单击「主光」，只剩「台灯」。
- WHEN 选中第 2 行后按住 Shift 单击第 6 行 THEN 第 2 到 6 行（按显示顺序）全部选中。
- WHEN 在第 3 行按下鼠标、拖到第 7 行松开 THEN 第 3 到 7 行被选中；拖到列表边缘时列表自动滚动，选区继续扩大。
- WHEN 选好物件后回车，或点「插入」 THEN 正文插入「客厅 · 台灯、主光」标签；选中超过 2 个时显示前两个名称加「+N」，悬停可以看到完整列表。
- WHEN 选中「整个场景」，或者什么都没选就回车 THEN 插入只引用场景的标签。
- WHEN 选中的物件超过 50 个 THEN 「插入」按钮不可用，提示「一次最多引用 50 个物件」。
- WHEN 同一个场景插入两个引用，每个引用各有 40 个不同的物件 THEN 允许发送：50 个的上限按单个引用计算；这两个引用只算一个场景。
- WHEN 一条消息里已经引用了 5 个不同的场景（同一个场景只算一次） THEN 菜单里其他场景项不可选，提示「一条消息最多引用 5 个场景」；这时在画布上点选第 6 个场景，不会产生待选项。
- WHEN 单击正文里已经插入的场景标签 THEN 重新打开这个场景的二级菜单，原来的选择已经勾上；确认后标签原地更新。
- WHEN 场景节点没有标题 THEN 显示「未命名场景」；物件没有名称时显示物件类型，如「基础体」「模型」「灯光」「摄像机」。

### 画布点选进入待选 @

- WHEN 助手面板开着、输入框为空，摄影师在画布上点选图片节点「参考图1」 THEN 输入框里出现置灰的「参考图1」待选标签，焦点仍留在画布上。
- WHEN 接着点进助手输入框（鼠标点击或用 Tab 聚焦） THEN 「参考图1」转为正式引用（正常颜色），光标停在它后面。
- WHEN 待选的「参考图1」还没转正，摄影师又点选了场景「客厅」 THEN 待选项被替换成「客厅」，输入框里没有「参考图1」。
- WHEN 待选状态下，摄影师点击画布空白处取消选中，或者 Shift/Cmd/Ctrl 加选、框选，使选中的节点变成 0 个或多个 THEN 待选项消失，输入框里的其他内容不变。
- WHEN 正文已经是「把 @参考图1 的色调用在」，光标停在末尾，然后摄影师去画布点选「客厅」 THEN 光标位置（「用在」后面）出现置灰的「客厅」待选项；点回输入框后它转为正式引用，接着输入「上」，正文成为「把 @参考图1 的色调用在 @客厅 上」。
- WHEN 光标停在正文中间时离开输入框，然后去画布点选节点 THEN 待选项插在离开时的光标位置，而不是正文末尾。
- WHEN 待选项存在时，直接点击助手输入区域里的发送按钮 THEN 待选项先转正，再随消息发出。
- WHEN 正文为空，输入框里只有一个待选项 THEN 发送按钮可用；点击后待选项转正并发送。转正后按正文重新检查引用数量和图片能力等限制，不满足时按现有提示拦截，草稿保留。
- WHEN 待选项存在时，摄影师离开当前画布或刷新页面 THEN 待选项不会保存进草稿；恢复的草稿里只有正式引用。
- WHEN 点选的是视频、音频、链接或分组节点 THEN 不产生待选项；如果已有待选项，它被移除。
- WHEN 助手面板是收起的 THEN 点选节点不产生待选项；展开面板时也不补上。
- WHEN 助手正在等待补充，输入框处于「补充内容」状态 THEN 点选节点不产生待选项（补充内容是纯文本输入框，补充接口只接受文本）。
- WHEN 选中的节点发生变化——从未选中任何节点变为选中某个节点，或者从选中节点 A 变为选中节点 B THEN 产生（或替换）待选项。之前引用过的节点再次被选中时同样会产生，可以重复引用。
- WHEN 选中「参考图1」后点进输入框，待选项转为正式引用；之后摄影师离开输入框，「参考图1」仍处于选中状态，或者再次单击它、平移画布 THEN 不会新增待选项。
- WHEN 画布上有待选项「客厅」，摄影师双击进入 3D 编辑器，或从编辑器返回画布 THEN 待选项被移除；切换视图本身不产生待选项，正式引用不受影响。

### 3D 编辑器选中进入待选 @

- WHEN 在 3D 编辑器打开「客厅」，摄影师在视口或大纲里选中「台灯」，再 Shift 加选「主光」 THEN 输入框光标处出现置灰的待选引用，内容从「客厅 · 台灯」变为「客厅 · 台灯、主光」；输入框上方不再出现浮层的「选中物件」标签。
- WHEN 点进输入框 THEN 待选引用转为正式引用，光标停在它后面。
- WHEN 正文为「把 @客厅·台灯、主光 改成金属，」，摄影师回到视口选中「沙发」「茶几」，再点回输入框，接着输入「改成胡桃木」 THEN 正文成为「把 @客厅·台灯、主光 改成金属，@客厅·沙发、茶几 改成胡桃木」；发送后，`instruction_segments` 依次为 `text`、`scene_ref[台灯,主光]`、`text`、`scene_ref[沙发,茶几]`、`text`，两批物件分别得到各自的修改。
- WHEN 待选引用还没转正，摄影师在视口里改为选中别的物件，或者按 Esc、点空白处清空选中 THEN 待选引用分别被替换，或者消失。
- WHEN 摄影师在编辑器里拖动、旋转选中的物件，或者在待选引用转正后转动视角，但选中集合没有变化 THEN 待选引用不重新生成，输入框不闪动。
- WHEN 选中集合发生变化（从空变为非空，或者变成另一组物件） THEN 产生或替换待选引用；只是点进输入框又切出去、选中集合没有变化时，不会新增待选引用。
- WHEN 编辑器里一次选中超过 50 个物件 THEN 不产生待选引用，输入框附近提示「一次最多引用 50 个物件」。
- WHEN 在编辑器里不选中任何物件就发消息 THEN 运行请求仍带 `scene_context{document_id=客厅, selected_object_ids=[]}`，助手知道当前正在编辑「客厅」，但没有被指定的物件。
- WHEN 发布后仍在运行的旧页面提交了非空的 `selected_object_ids` THEN 服务端照常接受，并按原来的规则处理。
- WHEN 打开历史里含有 `scene_selection` 块的旧会话 THEN 这些消息下方仍显示当时选中的物件。

### 引用的编辑与撤销

- WHEN 剪切正文里的场景引用，再粘贴到同一个输入框的另一个位置 THEN 引用照常显示，并保留原来的场景和物件。
- WHEN 删除一个场景引用后按撤销 THEN 引用恢复，指向的场景和物件不变；再按重做，引用再次被删除。
- WHEN 插入引用后按撤销，再按重做 THEN 引用先消失，然后以原来的内容恢复。
- WHEN 点击场景引用、改选物件并确认后按撤销 THEN 引用回到修改前的物件。
- WHEN 发送或保存草稿 THEN 只发送或保存正文里实际出现的引用。

### @ 菜单搜索

- WHEN 用输入框旁的 @ 按钮打开菜单 THEN 焦点在菜单顶部的搜索框里；输入「台」后，列表只剩标题或文本开头含「台」的节点，按类型分组，每组显示命中数。
- WHEN 在正文里输入 `@客` THEN 搜索框同步显示「客」，列表按它过滤；回车插入后，正文里的 `@客` 被替换成引用标签。
- WHEN 焦点在搜索框里时按 ↑、↓、回车、Esc THEN ↑↓ 移动高亮，回车插入高亮的那一项，Esc 关闭菜单并让焦点回到正文原来的光标位置。
- WHEN 画布上有 200 个可引用的节点时打开菜单 THEN 列表在固定的最大高度内滚动；输入一个字后，100 ms 内出现过滤结果。
- WHEN 画布上选中了「卧室」后打开菜单 THEN 「卧室」排在所在分组的第一位，并标注「已选中」。
- WHEN 在二级菜单的搜索框里输入「灯」 THEN 只显示名称含「灯」的物件和它们的各级上级（上级置灰、不能选）；清空搜索后，之前的选择保持不变。
- WHEN 没有任何匹配 THEN 显示「没有匹配的节点」，并保留「从资产库添加参考」的入口。

### 发送与助手理解

- WHEN 在画布视图里发送「把 @客厅·台灯 换成落地灯」 THEN 运行请求的 `instruction_segments` 依次为 `text`、`scene_ref{document_id=客厅, object_ids=[台灯]}`、`text`；助手不按标题查找，直接修改这个场景里的台灯，「卧室」不变。
- WHEN 发送「@客厅 和 @卧室 的灯光统一成暖色」 THEN 助手的运行输入里分别列出两个场景的标题和 `document_id`，两个场景都被修改。
- WHEN 3D 编辑器打开着「客厅」，消息里引用了「客厅 · 台灯」 THEN 运行输入写明「正在编辑『客厅』」，并在消息中按位置写明引用的是「台灯」；「客厅」的标题和 `document_id` 在运行输入里只出现一次，不重复展开。
- WHEN 消息发出后，「台灯」被改名为「桌灯」 THEN 对话历史里仍显示「客厅 · 台灯」。
- WHEN 引用「台灯」之后、发送之前，它在另一个标签页里被删除了 THEN 运行照常创建；助手的运行输入写明这个物件 ID 发送时已不在场景里，并要求先向创作者确认、不猜测替代对象；对话历史里这个物件显示为「已删除的物件」（不显示原名）。

### 模型行为验收（真实模型，手动执行）

以上协议测试只能证明引用「传对了」。下面三条用真实模型检查「改对了」：观察助手实际调用的工具参数和场景前后的差异。这三条属于模型行为验收，不进 CI 门禁。

- WHEN 「客厅」和「卧室」各有一个名为「台灯」的物件，发送「把 @卧室·台灯 改成红色」 THEN 只有卧室的台灯变成红色，客厅的台灯不变。
- WHEN 发送「把 @客厅·台灯、主光 改成金属，@客厅·沙发、茶几 改成胡桃木」 THEN 台灯和主光改成金属材质，沙发和茶几改成木材质，两批物件之间没有交叉。
- WHEN 引用的物件在发送前已被删除 THEN 助手不调用修改工具，而是在回复里向创作者确认。

### 边界与失败

- WHEN 引用的场景在发送前已进入回收站或被彻底删除 THEN 不创建运行，返回 404；输入框保留草稿，提示「引用的场景已不可用，请重新选择」。
- WHEN 提交的 `scene_ref.document_id` 属于其他账号，或指向的不是场景类型的文档 THEN 返回 404，不透露这个文档是否存在。
- WHEN `scene_ref` 缺少 `document_id`，`object_ids` 为空数组、含空串、有重复、超过 50 个，或带了其他片段才有的字段 THEN 返回 400 `validation_failed`（与项目现有的片段格式错误相同），不调用模型。
- WHEN 本会话的外发授权不包含 `canvas_metadata`，但消息里有 `scene_ref` THEN 返回 403，走现有的外发授权提示，不创建运行。
- WHEN 一次提交里不同场景的 `scene_ref` 超过 5 个 THEN 返回 413，不调用模型。
- WHEN 补齐场景标题、物件名和说明后，整条消息超过消息长度上限（32 KiB） THEN 返回 413，提示消息过长；不创建运行。
- WHEN 引用较多、名称较长，本轮请求接近模型上下文上限 THEN 本轮成本按补齐后的引用说明计算（含名称、ID、已删除提示和消息开销），据此规划历史和决定是否先压缩，不会因为低估而发出超限的请求。
- WHEN 打开历史里没有 `scene_ref` 块的旧会话 THEN 照常展示和继续，不需要迁移。

## 范围与非目标

- 不做：在二级菜单里渲染 3D 缩略视口来框选（owner 已列为后续项）。
- 不做：在第一级菜单搜索里直接搜到物件；物件只能在二级菜单里搜。
- 不做：画布上多选或框选的节点一次性进入待选项。按 owner 给的规则，只有点选单个节点才会产生待选项。
- 不做：引用视频、音频、链接、分组节点。助手目前读不了它们的内容，分组也不会展开成里面的节点。
- 不做：悬停正文中的引用标签时，在视口里高亮对应物件。留作后续增强。
- 不涉及外部助手（MCP）。

## Risk Notes

- **trust-boundary**：`document_id` 和物件 ID 由客户端提交。服务端要在账号范围内读取，核对文档是 `scene` 类型且不在回收站；跨账号或非场景文档一律返回 404（ADR-001）。新片段接入 `validSegments` 现有的「未知字段一律拒绝」规则。
- **perf-sensitive**：
  - 二级菜单要读场景快照。现有的 `GET /creative/documents/{id}` 会附带模型和图片摘要，大场景的响应可能有几百 KB、物件有几百个。是复用这个接口加缓存还是只取物件列表、要不要虚拟滚动，由 design 决定。
  - 待选项随画布点选和编辑器选中变化，替换时只改动那一个标签，不重绘整个输入框，也不能打断摄影师在画布或视口里的操作。编辑器拖动物件时，帧级更新不能波及输入框，沿用 `setSceneContext` 现有的「选中集合和名称不变就不通知」去重。
  - 服务端每个引用的场景读一次当前快照，最多 5 次，都在创建运行的同一个事务里。
- **交互细节**：`contentEditable` 里的光标位置在失焦后要靠记录下来的 Range 还原（现有的 `rememberCaret`）。待选项插入、替换、转正都不能破坏输入法组合输入（`composing`），也不能弄乱撤销栈。design 要给出待选项在 DOM 里的表示方式，以及它和 `persist` / 草稿保存的边界。
- **不算 contract-break**：枚举只新增取值。`selected_object_ids` 标记为 deprecated，但仍然接受，服务端行为不变。前后端在同一版本上线；旧前端遇到不认识的块类型如何显示，留到 design 阶段核对。
- **行为变化**：既有规格「点选物件让助手改」的前提变了。以前选中物件后可以直接说「改成断裂的」；现在选中物件会变成正文里的引用，点进输入框后自动转正，所以说法依然成立，只是「这个」指的是正文里的引用。规格 delta 用 MODIFY 改写这条场景。
- **不算 data-migration**：新的块存在现有消息体的 JSON 里，不增加表或列。

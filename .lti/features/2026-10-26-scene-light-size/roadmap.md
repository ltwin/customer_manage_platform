# Roadmap

## 子项

串行推进（policy: serial）：前一项归档并合回之后，下一项才能进入实施；后面的子项可以提前准备设计。本文的 S0–S2 是本 Epic 的子项；`scene-world-space-gi` 的子项写作 GI-S1、GI-S2。

排序原则：
- **S0 先做**：软阴影有好几种做法，近似误差和噪声各不相同。owner 要先看图再定，S1 和 S2 的滤波做法、样本数、后端可行性和 AC 阈值都取决于它的结论。
- **S1 是最小贯通场景**：点光、聚光、平行光和天空的太阳都加上尺寸，就能修好 owner 反馈的场景。这一批同时打通一整条链路：数据字段、光照模型扩展、软阴影的四个接入点、命中点着色和编辑器。
- **S2 在 S1 的链路上加面光源**：新增一种类型，加上 LTC 和面光源阴影，共用的部分在 S1 已经验证过。

**S0 穿刺清单**：

1. **参考解**：用 GI-S1 光追底座的 `traceWithin`，在光源表面上均匀采样，每个像素追阴影光线，累积到收敛（例如 1024 帧），作为软阴影和直接光的真值。覆盖球、圆盘、矩形和椭圆四种形状。
2. **软阴影的候选做法**：
   - 候选：
     - PCSS：先搜索遮挡物，再按半影宽度做可变半径的 PCF；
     - 仿 EEVEE 的阴影图追踪；
     - 可预滤波的 PCSS：基于 VSM 或 MSM，或在阴影图的 mip 上做；
     - 对照组：现状的 PCF 只调大 `radius`；导出时的 Jitter 累积。
   - 每种都要测：
     - 与参考解的误差，包括多层遮挡和大半影，例如 r = 0.1、d_b = 1、d_r = 3 时核直径约 65 texel；
     - 每盏灯每帧的耗时；
     - `workbench`（没有时域累积）和 `realtime_gi`（有 TRAA）下的颗粒。核的旋转要随帧序号变化，不能用只取决于屏幕坐标的 IGN；
     - 级联边界和立方体面接缝处是否连续；
     - 接收面深度偏置在大核和斜受光面上的条纹与漏光。
3. **两个后端读取原始深度**（U7）：阴影深度纹理设了 `compareFunction`。要实测 WebGL2 和 WebGPU 上，同一张深度图能否在一个着色器里既做比较采样又读原始值。不行时，验证备选方案：阴影 pass 额外输出一张线性深度。
4. **接法**：
   - **光照模型**：在 `PhysicalLightingModel` 上加 `directSphere`、`directDisk`、`directEllipse`，包装方式同 `giSplit.ts`；光源节点经 `renderer.library.addLight` 把形状参数交给新入口；clearcoat 和 sheen 的处理。
   - **四个滤波接入点**：
     - 2D 用 `shadow.filterNode`；
     - 立方体用另一套签名 `{ depthTexture, bd3D, dp, shadow }`，`dp` 先线性化；
     - `SunCascades` 逐级设置；
     - standIn 的 `clone(false)` 加 `shadowLike` 能编出同一个着色器，灯光子类无参构造并覆写 `copy()`。
   - **尺寸为 0**：按 uniform 分支选择 PCF，与基线图的差异不超过 1/255（AC-2）。不能把比较采样放进按像素分叉的分支（`render/volumes/lights.ts` 的 NaN 教训）。
5. **面光源阴影**（U3）：
   - 用中心处的立方体贴图，还是正面半球的透视贴图；
   - 测单视点的误差：只有边缘看得到的遮挡关系；
   - 阴影相机的轴和面光源的局部轴不对齐时，滤波范围怎么算；
   - 半影上限随尺寸怎样增长（U5）。
6. **实时 GI 接触阴影**（U4）：按半影宽度缩短追踪长度，还是超过阈值就关掉。
7. **球形光源的地平线裁剪和 sheen 的误差**（U6）。
8. **Blender Cycles 对照**：
   - 同一参考场景用 Blender Cycles 渲染，灯光按 W 和 cd 换算对齐；
   - 逐项核对点光改半径时的四种变化（design I1）：远处照度不变、高光变大变暗、交界线外移、近处封顶；
   - 确认参考解与 Cycles 一致；
   - 同时核对 U8：点光和聚光的半径是否随物件缩放。
9. **缺省值的观感**：半径 0.1 m、面光源 10000 cd/m² 时，参考场景看起来怎么样。
10. **阈值**：为 AC-1、AC-4、AC-5、AC-8 提出阈值，由 owner 确认后经 Epic 修订回填。

### 验收责任

- 每个子项按自己的 proposal 验收，owner 接受后归档。
- 以下几项只能由 owner 判断：
  - S0 的对比图：选定软阴影的做法；
  - S1 的 AC-11：owner 反馈场景的改前改后对比；
  - S2 的面光源棚拍场景观感。
- 全部子项归档后，按 proposal 的 AC 做 Epic 整体验收。

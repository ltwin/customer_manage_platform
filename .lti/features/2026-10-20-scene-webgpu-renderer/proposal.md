# Epic: scene-webgpu-renderer — 3D 场景的 WebGPU 渲染器与实时全局光照

永久需求文档：本 Epic 的目标、边界和交付计划。整体方案见 design.md，目标契约见 contracts.md。项目 `.lti/contracts/` 记录当前已交付事实。前序 Epic `scene-editor-3d`（`.lti/features/2026-10-15-scene-editor-3d/`）交付了编辑器、导出和 C5 的材质与光照，本 Epic 在它之上替换渲染底座。

## 目标

渲染质量会直接影响 gpt-image 重绘的质量，也有高阶创作者希望从编辑器直接出接近影视级的画面（owner 2026-10-20）。现在的渲染是 WebGL2 光栅化，全局光照只靠天空环境贴图和 AO 近似：算不出物体之间的间接光反弹（渗色），光滑表面只能反射天空、看不到场景里的其他物体。导出也固定为长边 2048。

本 Epic 完成后：

1. 3D 编辑器的全部渲染都跑在 three.js 的 WebGPU 渲染器上，包括视口、助手回看（`render_view`）、导出、模型缩略图和资产 3D 预览。浏览器拿不到 WebGPU 时，自动改用同一渲染器的 WebGL2 后端，编辑和导出照常可用。
2. 编辑器参照 Blender 的属性编辑器新增「渲染」选项卡（owner 2026-10-21），可以选择渲染器，共三种：
   - **工作台**：现在的光栅化渲染，最快，质量最低；
   - **实时 GI**：屏幕空间的间接光反弹、物体之间的反射和接触阴影，经时域累积降噪，效果对标 UE5 Lumen 的屏幕空间层；
   - **路径追踪**：对标 Cycles 的无偏渲染器，由后续 Epic 交付，本 Epic 里显示为「规划中」。
3. 渲染选项卡里可以选输出分辨率：1K、2K、4K、8K（导出图的长边）。曝光补偿也挪到这里。
4. 渲染器和分辨率是场景的设置，摄影师和助手都能修改；编辑器、`render_view` 和导出看到的画面一致。实时 GI 的视口在停止操作后逐步收敛，导出多累积若干帧，噪点比视口更少（同 Blender 视口采样与渲染采样的区别）。
5. 为后续的路径追踪渲染器打底：着色统一用 TSL 编写，程序化材质的定义将来可以直接被 WebGPU compute 路径追踪器复用。

## 范围与非目标

- **范围**：
  - **渲染管线整体迁到 `WebGPURenderer` + TSL**：
    - 原理化 BSDF 与 14 种程序化预设；
    - 天空、阴影、AO、景深、线稿；
    - 线框、白模、材质预览、最终渲染四种显示模式，包括正交视图；
    - 编辑器的辅助显示：网格、选中描边、助手高亮、变换 gizmo。

    迁移完成后删除 WebGL 管线，不长期并存。
  - **渲染选项卡**：渲染器（工作台、实时 GI，路径追踪显示为「规划中」）、输出分辨率（1K / 2K / 4K / 8K）、曝光补偿、当前渲染后端提示。
  - **实时 GI 渲染器**：屏幕空间全局光照（SSGI）、屏幕空间反射（SSR）、接触阴影、时域重投影、降噪与 TRAA；视口收敛，导出多帧累积。
  - **导出与截图的确定性**：同一场景重复导出结果相同，隐藏标签页里也一样。
  - **渲染能力**：探测、WebGL2 后端退回、渲染设备丢失后的恢复。
  - **助手工具说明**：助手知道渲染器和分辨率这两项设置，能修改并回看。
- **非目标**（显式排除）：
  - **路径追踪**（无偏渲染器）：后续另立 Epic，基于 WebGPU compute 和 `three-mesh-bvh` 的 WebGPU 模块自研，不采用只支持 WebGL2 的 `three-gpu-pathtracer`（owner 2026-10-20）。本 Epic 只在界面上列出它（禁用），并保证着色写法与材质定义能被它复用。
  - **Nanite 式虚拟几何**：它解决的是海量三角形的绘制。场景模型由几何代码生成，单模型不超过 30 万面，没有这个瓶颈；它依赖的 64 位原子操作 WebGPU 目前也没有。
  - Lumen 的距离场与 surface cache 追踪层，也就是屏幕外的反弹光和反射；硬件光追（浏览器没有接口）。
  - PBR 贴图与 HDRI：仍是 `scene-editor-3d` 的子项 C5c，排在本 Epic 的 R1 之后，直接在节点材质上实现（owner 2026-10-21）。
  - 服务端渲染（沿用 `scene-editor-3d` 的决定）；手机端（浏览器范围沿用桌面 Chrome / Edge / Safari 最新版）。
  - 其他细项设置，例如采样数、视口分辨率比例、输出格式、透明背景：首期只做渲染器、分辨率和曝光，质量档位由渲染器内部按视口或导出选择。

## 接口约定

目标契约在本 Epic 的 `contracts.md` 中定义：

- 数据：`data: MODIFY 场景文档`（`render` 新增 `engine`、`resolution`）
- 架构与模式：`architecture: MODIFY 场景模块`（渲染端的技术基线）、`patterns: ADD 场景着色写法`

接口契约不变：`set_render` 已按键合并，字段以数据契约为准；`render_view`、导出和客户端任务的请求与结果外形都不变。OpenAPI 的 `CreativeSceneRender` / `CreativeSceneRenderPatch` 随数据契约加字段，运行 `make generate` 后提交两份生成物。8K 需要的总像素上限放宽只改媒体配置（`creativemedia`），不改契约（design「输出分辨率」）。

## 验收标准

全部子项完成后做整体验收。参考场景集与参考设备由 R0 确定并记录（design「验证与交付」）：

- **AC-1 迁移等价**：**WHEN** 参考场景集（室外正午、黄昏、只有灯光的室内、含 14 种预设和透射材质的材质板、带景深的机位）在迁移前后各导出 `clay`、`line`、`lit`，**THEN** 每组都有并排对照图和差异图，owner 判断是「同一张图」。迁移后渲染器为工作台；已发布的材质预设不因迁移升版本；正交视图的白模仍有正确的 AO。
- **AC-2 全部走新渲染器且结果确定**：
  - **WHEN** 在编辑器视口、`render_view`、手动导出、助手导出、模型缩略图、资产卡片缩略图和资产 3D 预览中渲染，**THEN** 用的都是 WebGPU 渲染器；前端代码里不再有 `WebGLRenderer`、`ShaderMaterial`、`onBeforeCompile` 和 GLSL 着色器字符串（由 `check-frontend` 里的静态检查保证）。
  - **WHEN** 在隐藏的标签页里连续两次导出同一场景的多台摄像机、多种导出方式，**THEN** 两次结果逐像素相同，每张图都是各自摄像机和导出方式的正确画面。
- **AC-3 退回与恢复**：
  - **WHEN** 浏览器没有可用的 WebGPU 适配器（用启动参数禁用 WebGPU 模拟），**THEN** 编辑器照常打开、编辑和导出，工作台的画面与 WebGPU 后端一致；实时 GI 同样可用（R0：WebGL2 后端运行完整的实时 GI 组合，画面一致）；不暴露原始错误。
  - **WHEN** 渲染设备丢失，**THEN** 视口自动恢复，进行中的离屏任务回队后由渲染端重新认领。
- **AC-4 实时 GI 效果**：**WHEN** 参考场景（红墙、白地面、金属球和光滑地板的盒子间）的渲染器选为实时 GI，**THEN** 最终渲染里白地面靠近红墙处被染红，金属球和地板反射出场景里的其他物体，物体与地面的接触处有接触阴影；切回工作台后回到标准渲染。
- **AC-5 渲染选项卡、一致与过时**：
  - **WHEN** 摄影师打开渲染选项卡，**THEN** 看到渲染器（工作台、实时 GI，以及禁用的「路径追踪 · 规划中」）、输出分辨率、曝光补偿和当前渲染后端。
  - **WHEN** 摄影师切换渲染器，**THEN** 编辑器的白模和最终渲染、`render_view`、`clay` 与 `lit` 导出看到同样的效果；设置写进场景，可以 Cmd+Z 撤销，其他标签页同步；已有的 `clay`、`lit` 导出图提示「场景已更新」，`line` 不提示。
  - **WHEN** 只改了输出分辨率，**THEN** 已有导出图不提示过时。
  - **WHEN** 场景从未改过渲染器，**THEN** 迁移前的导出图不会因为本 Epic 变成过时。
- **AC-6 助手**：**WHEN** 摄影师请助手「换成实时 GI，按 4K 导出」，**THEN** 助手用 `edit_scene` 的 `set_render` 修改两项设置，用 `render_view` 回看，再导出 4K 的图。
- **AC-7 性能**：
  - **WHEN** 参考场景在参考设备上使用实时 GI，**THEN** 视口交互帧率不低于 30 fps（1× 像素比；R0 实测参考场景约 21–23 ms 一帧）；停止操作后在目标时间内收敛并停止重绘，不空转；2K 导出在目标时间内完成（R0：K = 64 约 3 秒，目标随 R2 标定的 K 确定）。
  - **WHEN** 使用工作台，**THEN** 视口帧率不低于迁移前。
- **AC-8 重绘价值**：**WHEN** 同一机位分别用工作台和实时 GI 导出，交给 gpt-image-2.5 重绘，**THEN** owner 判断实时 GI 是否改善了重绘，保留样例记录。结论决定新场景的默认渲染器（design 未决事项 2）。
- **AC-9 输出分辨率**：
  - **WHEN** 输出分辨率选 1K、2K、4K、8K 并导出，**THEN** 导出图的长边分别是 1024、2048、4096、8192 px，短边符合摄像机的画幅比例，作为画布图片节点正常显示。
  - **WHEN** 当前设备或媒体上限不支持所选的档位与画幅组合，**THEN** 导出明确失败并说明原因，不悄悄降分辨率。两种渲染器都提供全部四个档位；4K、8K 出图时丢失设备，视为当前设备画不了这个档位，导出明确失败（design「输出分辨率」）。8K 实时 GI 如果在 R2 中实在难以实现，可以先只支持到 4K（owner 已同意，R2 验收时确认）。

## 交付路线

见 roadmap.md：3 个串行子项。

1. **R0 技术验证**：有界穿刺，只提交测试数据和证据，不提交产品代码。
2. **R1 迁移到 WebGPU 渲染管线**：功能等价，渲染器即工作台。
3. **R2 渲染选项卡**：渲染器选择、实时 GI、输出分辨率。

路径追踪不在本 Epic 内。

## 决策记录

| 日期 | 决定 | 理由 |
|---|---|---|
| 2026-10-20 | 渲染底座从 WebGL2 换成 `WebGPURenderer`，列为重点功能 | 渲染质量影响重绘质量，也有高阶用户希望直出影视级画面（owner） |
| 2026-10-20 | 仿照 Blender 提供多个渲染器，实时的用于交互，路径追踪用于高质量导出 | owner：类似 EEVEE 与 Cycles 的分工 |
| 2026-10-20 | 首期只做 WebGPU 渲染器和接近 Lumen 的实时 GI；路径追踪作为后续大型规划，基于 WebGPU compute 自研 | WebGPU 有 compute shader 和 storage buffer，路径追踪能做 wavefront 架构和高效降噪，上限高于 WebGL2；只支持 WebGL2 的 `three-gpu-pathtracer` 会带来第二个 GPU 上下文和第二套着色语言。自研周期长，先交付实时部分（owner） |
| 2026-10-20 | 不做 Nanite | 问题不匹配（场景面数不高），WebGPU 也缺 64 位原子操作 |
| 2026-10-20 | 整体迁移，不长期维护 WebGL 与 WebGPU 两条管线 | `WebGPURenderer` 自带 WebGL2 后端，同一份 TSL 在两个后端都能运行；两条管线意味着两套着色代码，而路径追踪也要走 WebGPU |
| 2026-10-21 | 参照 Blender 新增「渲染」选项卡；渲染器分工作台、实时 GI、路径追踪三种；可选输出分辨率 1K / 2K / 4K / 8K | owner：交互参照 Blender。路径追踪未交付前在界面上禁用并标注「规划中」，场景格式不接受这个值 |
| 2026-10-21 | 渲染器和输出分辨率都是场景设置，渲染器同时作用于白模和最终渲染 | 沿用「视口看到的就是导出的」（修订 v9 的原则）；白模按所选渲染器出图，与 Blender 用材质覆盖渲染白模相同；助手也能修改 |
| 2026-10-21 | 设计评审（一轮）结论并入设计：离屏出图由渲染器创建入口显式推进帧序号；正交视图的 AO 用项目内的 TSL 版 GTAO，实时 GI 在正交视图下回落到工作台；G-buffer 只含不透明几何，工作台用 MSAA、实时 GI 用 TRAA | three 的节点同一帧内只执行一次，帧号只随 rAF 递增：离屏连拍会复用第一张的结果，隐藏标签页里帧号冻结，导出结果也会随渲染器运行时长变化；`GTAONode`、`SSGINode` 只按透视相机编写；TRAA 要求关闭 MSAA |
| 2026-10-21 | R0 结论并入设计（修订 v2）：WebGL2 后端照常渲染实时 GI，不按渲染能力认领；截图和导出统一用「画到画布后立刻 `toDataURL`」；工作台的 G-buffer 用不透明预通道；选中描边用反向外壳；阴影用 PCF 半径 1；SSGI fork 进项目；所有档位一次渲染，8K 实时 GI 照常提供，丢设备时明确失败；总像素上限放宽到 8192²，4K / 8K 的 `clay`、`lit` 用 JPEG（质量 0.95） | R0 实测（`scene-webgpu-spike` 的 `discovery/research/summary.md`）：完整 GI 组合在 WebGL2 后端运行正常；WebGL2 的异步读回在后台标签页卡住，画布路径两个后端都可用；单 pass MRT 的法线会被透明物体写坏；实时 GI 无法分块，降内部分辨率不省显存；PNG 大小由噪点决定，8K 实时 GI 达 105 MB。8K 与媒体上限的方案由 owner 选定；owner 补充：视口按窗口的实际尺寸渲染，4K / 8K 只用于最终出图，8K 实时 GI 实在难以实现时可以先只支持到 4K |
| 2026-10-21 | 修订 v3（R1 起草时）：更正「渲染管线组成」，材质预览与白模、最终渲染一样有 AO，不与线框归为一类 | 迁移前的材质预览经 `SceneRenderer`，AO 默认开启（`Viewport.tsx` 的 `LookView` 只让线框绕开），原表格记错了现状；R1 是等价迁移，按现状迁移 |
| 2026-10-21 | 修订 v3：`scene-editor-3d` 的 C5c（PBR 贴图与 HDRI）排在 R1 之后；C5b、C7、C8 与渲染无关，可以穿插（design 未决事项 7） | C5c 直接在节点材质上实现，避免先写 GLSL 再迁移一遍（owner） |

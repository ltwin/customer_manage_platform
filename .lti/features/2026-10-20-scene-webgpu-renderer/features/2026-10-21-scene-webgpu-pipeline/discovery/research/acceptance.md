# R1 验收记录（scene-webgpu-pipeline）

R1 把 3D 编辑器的全部渲染迁到 `WebGPURenderer` + TSL，WebGL 写法已删除并由静态检查守住。本页按验收标准逐条给结论和证据，最后列出要 owner 决定的事项、已知限制和实施中的偏差。参考设备：Apple M4 Pro，macOS 26.5，Chromium 145（Playwright，Metal 参数）、Chrome 正式版（后台标签页）、Safari 26.5。

## 逐条结论

| 标准 | 结论 | 证据 |
|---|---|---|
| AC-R1-1 迁移等价 | **大部分通过，3 张图超阈值交 owner** | `parity.md`：六组场景 × clay / line / lit（dof 两台摄像机）+ 正交白模共 27 张，24 张在收紧后的阈值内。line 全部逐像素级一致（平均差 ≤ 0.001）。超出的是 noon、materials 的 lit（混凝土气孔硬边，1.35%、1.12%）和 materials 的正交白模（窄缝 AO，2.91%） |
| AC-R1-2 全部走新渲染器 | 通过 | 静态检查 `scripts/creative-scene-shading.test.ts`（AST，含违规样例和注释误报样例；临时放入 `frontend/src` 的违规文件被报出）；e2e 断言视口、离屏的后端日志来自创建入口；缩略图、资产 3D 预览经同一入口（`C6 save to library`、`C6-model-preview` 通过） |
| AC-R1-3 结果确定 | 通过 | e2e「determinism」：真实 Chrome 后台标签页（rAF 0 次/秒），材质板 3 台摄像机 × 3 种方式 9 张，后台两次与前台逐张 SHA-256 相同、9 张互不相同；WebGL2 后端在后台也两次相同。途中修掉两处：降噪噪声用 `Math.random`、WebGL2 预编译在后台挂起 |
| AC-R1-4 退回 WebGL2 | **画面：2 张超阈值交 owner**；功能：通过 | 画面见 `parity.md`：`forceWebGL` 导出与 WebGPU 比，21 张中 19 张通过，noon lit 1.29% 超上限、materials lit 0.97% 超收紧值，同为混凝土气孔。功能：SwiftShader 下视口与离屏都是 webgl2，能编辑、导出、无原始错误；两种都没有的浏览器显示「当前浏览器无法显示 3D 场景」且不认领 |
| AC-R1-5 设备丢失 | 通过（残余窗口已由 owner 接受为已知限制） | e2e「device loss:」四条：视口重建后画面、选中、视角、在途编辑都在，10 秒内第 3 次提示刷新；`render_view` 与 `export_shots`（第 2 张后丢失）不上报、一张不上传、回队后完成；手动导出提示并可重试、画布无图；卡片缩略图换设备重画。执行器、提交点、launcher 暂停另有单测 |
| AC-R1-6 编辑器辅助与显示模式 | 待 owner 看图；定向用例全部通过 | `look/`：三组场景 × 四种模式（含正交白模）左迁移前、右迁移后，数据 `look/look.json`。已知差异：迁移前正交视图把 TransformControls 的平面画成黑方块（新管线没有）；摄像机线框图标颜色更接近设定值。定向 e2e 结果见下「回归」 |
| AC-R1-7 性能 | **帧时间通过；加灯、删灯和部分导出耗时略高于基线，交 owner** | `perf.md`：四种模式都在 120 Hz 上限（R0 材质预览 15.2 ms、最终渲染 19.8 ms）；加灯最长一帧 150 ms（R0 120 ms），删灯 266 ms（R0 136 ms）；切到最终渲染第一帧约 0.25 s，灯光 0.4–0.65 s 亮起（owner 反馈后修正，原先 7–10 s）；导出 noon、dof 不高于基线，其余高 25–300 ms；48 张连续导出纹理数不增长，反复加灯、撤销、切换模式后渲染器资源数不增长 |
| AC-R1-8 兼容模式与 Safari | 兼容模式：已知限制（模拟通过）；Safari：导出通过，人工打开编辑器待 owner | 本机拿不到兼容模式适配器；用 `forceCompatibility` 走 SMAA 分支，与 MSAA 平均差 ≤ 0.17、差 > 8 ≤ 0.5%（`parity.md`）。Safari 26.5 里导出材质板走 WebGPU，对 R0 的差与 Chrome 相同（`safari/`） |

## 要 owner 决定的事项

1. **混凝土气孔**（AC-R1-1 两张、AC-R1-4 两张）：Metal 上 WGSL 浮点差异让气孔边缘像素翻转，位置不变。接受，还是给气孔边缘加抗锯齿（会改变预设外观）？
2. **正交视图窄缝 AO**（AC-R1-1 一张）：材质板方块间窄缝比迁移前深。接受，还是继续调降噪逼近？
3. **加灯、删灯与切换**（AC-R1-7）：加灯最长一帧 150 ms（R0 120 ms）、删灯 266 ms（R0 136 ms），是否接受？上一版的「加灯卡 2.8 s」是切换时逐盏编译遗留的编译串，并非加灯本身，已随切换卡顿一起修正。切到最终渲染：浏览器已缓存着色器时第一帧约 0.25 s、灯光 0.4–0.65 s 亮起；全新着色器的首次切换第一帧 1.7 s、灯光 3.7 s，第二次 2.2 s，之后 0.5 s 内（`perf.md`「切到最终渲染」）。
4. **导出耗时**（AC-R1-7）：dusk、room、cornell 高 25–120 ms，materials 高约 300 ms（单次测量）。是否接受？
5. **AC-R1-6 看图**：`look/` 的并排图是否「外观与迁移前一致」。
6. **Safari 人工检查**：按 AC-R1-8，验收前在 Safari 26.5 打开编辑器、导出一次（脚本化导出已通过）。

## 已知限制

- 提交点之后到上传之前有毫秒级窗口可能漏掉设备丢失，结果是一批空白图被交出（方案评审时 owner 已接受）。
- 兼容模式设备未实测，只验证了工作台的兼容分支。
- WebGL2 后端在后台标签页里不预编译，首张图同步编译（更慢，结果不变）。
- 视口在设备丢失重建时，正在拖、还没提交的变换随旧画布取消（等同按 Esc）。

## 回归

- 单测：`make check-frontend` 通过（lint、build、全部前端单测）；creative-scene 相关 218 个。
- 定向 e2e（SwiftShader，WebGL2 后端）：导出、guides、AC-6、C5 校准、参考场景、AC-5、AC-1、AC-2（预设、砖墙、金属）、移动工具、景深预览、摄像机、C6 存入资产库、设备丢失四条、退回两条、确定性（真实 Chrome）、资产 3D 预览、画布页不加载 3D 引擎。结果记在 tasks 9.4。

## 实施中的偏差（详见 tasks.md 各条）

- GTAO fork 换回 GTAOShader 的地平线搜索与积分（r186 新模型接触阴影浅一半）；守护单测比对「换回上游块后与上游一致」。
- AO 预通道用覆盖材质画几何法线（与 GTAOPass 一致），天空移到 ASIDE 图层。
- 天空在 `sky.ts` 里用 TS 写，没有 fork `SkyMesh.js`。
- three r186 的 `ViewportTextureNode` 两个问题在入口补上：克隆共享 source、克隆不释放（玻璃场景导出报错、每张多留纹理）。
- `probeRender` 放进不依赖 three 的 `render/probe.ts`。
- 降噪噪声改固定种子；`SceneGPU.compile` 统一预编译（WebGPU 按各 pass 格式编译替身场景，WebGL2 在后台跳过）。
- owner 验收反馈切到最终渲染卡顿后：同一次提交挂上的灯合并预编译；替身按代保留与释放（修掉预编译的资源泄漏）；预编译改用克隆的 1×1 目标（线框直切最终渲染时不再报管线错误）。详见 tasks 9.5。
- 静态检查放行三个不含着色器的粗线几何模块。
- e2e `open()` 等渲染器异步创建完成再交给用例。

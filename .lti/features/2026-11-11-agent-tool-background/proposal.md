## Why

助手调用耗时工具时，超过各自的等待上限（生成 150 秒、图片压缩 90 秒）就会带着 `running` 结果离开，任务本身继续跑，但助手再也收不到它的结果，只能半途收尾。等待不该有短上限；该由助手决定要不要等，摄影师也可以随时让它不再等。参照 Claude Code 的后台任务。

## What Changes

- **前台等待取消短上限**：`generate_node`、`compress_image` 改为与场景客户端任务相同的停靠方式：等待期间运行停靠、释放会话槽位，任务终态时运行自动继续。等待只受任务自身的执行时限和运行的 6 小时上限约束，去掉 150 秒和 90 秒的上限。`search_web`（30 秒）和 `read_webpage`（60 秒）的上限是外部请求防挂死，保持不变。
- **助手可选后台运行**：`generate_node`、`compress_image`、`write_model`、`export_shots` 增加可选参数 `run_in_background`。为 `true` 时工具立即返回后台任务句柄，助手接着做别的事；省略时等到结果，即前台等待。`render_view` 不支持后台：截图本来就是给助手当场看的，放到后台只会让通知里再带一次图片。
- **场景任务需要编辑器在线**：`write_model`、`export_shots` 由打开着的创意空间页面领取执行，转到后台也一样。工具卡片在后台状态下提示「需要保持创意空间页面打开」；页面一直没打开时，任务按现有执行时限过期，通知内容为过期结果。
- **完成通知**：后台任务到达终态（成功、失败、被取消、过期）时，向所在对话写入一条完成通知，内容与前台等待拿到的结果相同，另附句柄。通知在对话里显示为一行系统提示。前台和后台的结果状态统一：生成被取消时，两边的 `state` 都是 `cancelled`（现在前台把取消报成 `failed`）。
  - 对话中有运行正在执行：在下一次调用模型前送进这一轮，不打断当前工具调用。
  - 对话空闲：自动开一轮新运行来处理通知（按用量扣积分），沿用发起该任务的那次运行的模型和 Skill。最后一条通知到达后静默 2 秒没有新通知就开始；从第一条通知算起最多等 10 秒。期间完成的、模型和 Skill 都相同的通知合并到同一轮；配置不同的按配置分别开轮，依次进行。
  - 不自动唤醒、只写通知的情况：以下任一成立时，通知照常写入对话，等摄影师下次发消息时一并送达，不自动开轮。
    - 发起任务的那一轮被摄影师停止；
    - 发起任务的那一轮以失败结束；
    - 对话里已连续自动开了 5 轮、期间摄影师没有发过消息（连锁上限：自动开的一轮发起的后台任务，完成后照常可以再自动开轮；摄影师发一条消息就重新计数）；
    - 账号没有当前有效的外发同意（未同意、已撤回或说明版本已变）；
    - 积分不足以开新运行。
  - 运行在等摄影师补充（`waiting_input`）：不唤醒，通知随摄影师的补充一起送达。
- **摄影师手动转后台**：聊天里前台等待中的工具卡片显示「转后台」按钮。点击后，这次工具调用立即以「已转后台，句柄 X」作为结果交还助手，运行继续；任务照常进行，完成时按完成通知处理。
- **后台任务卡片**：转后台或以后台方式发起的工具卡片持续显示任务状态，完成后更新为结果。进行中的卡片可以「取消」：生成走画布已有的 `cancel_execution`，场景客户端任务置为 `cancelled`。
- **停止语义**：后台任务独立于运行。停止对话只停助手，已在后台的任务继续进行，完成时照常写通知，但不自动开轮（摄影师点停止就是不想助手再自己动），通知随摄影师下次发消息送达；要连任务一起停，就在任务卡片上取消。前台等待中的任务仍按现有规则处理：已交给生成服务的生成跑完并计费，还没发出的撤回；场景客户端任务随运行取消。

## Acceptance Criteria

**前台等待**

- WHEN 助手前台调用 `generate_node`，这次生成用了 5 分钟 THEN 工具在生成完成且结果采用有结论后才返回，结果的 `state` 为 `succeeded` 或 `failed`，不会是 `running`；等待期间运行状态为 `waiting_client`，会话槽位已释放。
- WHEN 前台等待期间运行到达 6 小时上限 THEN 运行按现有规则以 `creative_run_deadline_exceeded` 结束；生成继续在画布上完成。
- WHEN 前台等待期间 worker 进程重启 THEN 任务终态后运行照样继续，拿到的结果与不重启时相同，工具不会被重复执行。
- WHEN 助手调用 `search_web`，外部搜索超过 30 秒无响应 THEN 行为与现在相同（返回超时）。

**助手选择后台**

- WHEN 助手以 `run_in_background: true` 调用 `generate_node` THEN 工具在 1 秒内返回，结果包含句柄和 `state: running`；运行不停靠，直接进入下一次模型调用。
- WHEN 助手以 `run_in_background: true` 调用一个不支持后台的工具（如 `search_web`） THEN 调用按参数错误被拒，不执行。
- WHEN 后台生成成功、运行仍在执行另一个工具 THEN 这个工具不被打断；下一次调用模型时，模型输入里有这条完成通知，内容含 `apply_state` 和 `content_revision_ids`。
- WHEN 后台生成在对话空闲时完成，账号有有效的外发同意 THEN 对话里出现一行完成提示，2 秒后自动开始一轮新运行，模型、Skill 与发起任务的那次运行相同；助手的回复跟在提示后面。
- WHEN 3 个由同一模型和 Skill 发起的后台生成先后完成，相邻两次间隔不超过 2 秒、对话空闲 THEN 只开一轮新运行，这一轮的模型输入里有 3 条通知。
- WHEN 后台生成每隔 1 秒完成一个、持续不断 THEN 从第一条通知起 10 秒内开始新运行，之后到达的通知按「运行进行中」送进这一轮或留给下一轮。
- WHEN 2 个后台生成分别来自模型不同的两轮、在同一时间完成、对话空闲 THEN 按配置各开一轮，依次进行，每轮只含自己配置的通知。
- WHEN 一轮自动开始的运行又以后台方式发起了生成，生成在对话空闲时完成，连续自动运行不到 5 轮 THEN 照常再自动开一轮。
- WHEN 对话已连续自动开了 5 轮、期间摄影师没有发消息，第 5 轮发起的后台生成在对话空闲时完成 THEN 只写完成提示，不再自动开轮；摄影师发消息后计数归零，这条通知随消息一起送达。
- WHEN 发起后台任务的那一轮以失败结束（如模型服务报错），之后任务在对话空闲时完成 THEN 只写完成提示，不自动开轮；摄影师下次发消息时，这条通知随消息一起送达。
- WHEN 后台任务完成时账号的外发同意已撤回或说明版本已变 THEN 不开运行，完成提示照常写入；摄影师重新同意并发消息后，通知随消息一起送达。
- WHEN 后台任务完成时积分不足以开新运行 THEN 不开运行，完成提示照常写入对话；摄影师下次发消息时，这条通知随消息一起送达。
- WHEN 后台任务完成时对话处于 `waiting_input` THEN 不开新运行；摄影师补充后，下一次模型调用的输入里同时有补充和通知。
- WHEN 后台任务完成时项目已归档或对话已删除 THEN 不写通知、不开运行；任务结果按现有归档写保护处理，落到已归档的画布或场景上可能被拒绝，此时任务结果为失败。
- WHEN 后台任务失败（如生成服务报错、场景任务过期） THEN 通知照常送达，内容为与前台等待相同的失败结果。

**摄影师转后台**

- WHEN 工具正在前台等待，摄影师点卡片上的「转后台」 THEN 同一帧里卡片变为后台样式；助手的下一次模型调用拿到「已转后台」结果和句柄，不等任务完成。
- WHEN 摄影师点「转后台」时任务恰好已经完成 THEN 助手拿到的是真实结果而不是「已转后台」，卡片显示结果，不再发完成通知。
- WHEN 「转后台」请求失败 THEN 卡片恢复为前台等待样式，并提示没有成功，可以重试。
- WHEN 同一个工具调用被重复点「转后台」 THEN 只生效一次，助手只收到一个「已转后台」结果。

**停止与取消**

- WHEN 有 2 个后台生成在进行，摄影师停止当前运行 THEN 运行立即停止；2 个生成继续，完成后各自写入完成提示，但不自动开轮；摄影师下次发消息时，两条通知随消息一起送达。
- WHEN 前台调用 `generate_node`，摄影师在画布上取消了这次生成 THEN 工具结果的 `state` 为 `cancelled`，与后台任务被取消时的通知一致。
- WHEN 摄影师在后台任务卡片上点「取消」 THEN 生成被取消（与在画布上取消相同），卡片显示已取消；完成通知照常送达，内容为 `cancelled`。
- WHEN 前台等待中的生成所在运行被停止 THEN 行为与现在相同：已交给生成服务的跑完，还没发出的撤回，不产生完成通知。
- WHEN 摄影师在另一个账号下请求转后台或取消某个句柄 THEN 被拒，任务不受影响。

**场景任务与截图**

- WHEN 助手以 `run_in_background: true` 调用 `render_view` THEN 调用按参数错误被拒，不执行。
- WHEN 后台的 `write_model` 进行中、摄影师关掉了创意空间页面 THEN 卡片提示需要保持页面打开；页面一直没再打开时，任务按执行时限过期，完成通知内容为过期结果。

## Impact

- 代码：`backend/internal/creativeagent/`（`generate_node` / `compress_image` 改为停靠，后台参数，完成通知送达与空闲唤醒，转后台控制，取消路径分支）；`backend/internal/creativegeneration/`、`backend/internal/creativeimageedit/`（任务终态时通知关联运行，替代轮询）；`backend/internal/creativescene/`（后台任务不随运行取消，完成时的准入复查改为按对话而非按运行）；`frontend/src/creative-canvas/editor/`（工具卡片的转后台、取消、后台状态，完成提示）。
- 契约：`api/openapi.yaml` 新增转后台、取消后台任务两个接口，运行事件新增后台任务状态与完成通知，均为新增字段；助手工具结果 `AgentGenerationResult.state` 新增 `cancelled`（前台取消原来报 `failed`，模型侧语义变化，需写进 data/api 契约）；`data` 契约新增后台任务的持久化（新表或扩展现有表，design 定）、`creative_scene_jobs` 的取消规则修订；glossary 新增「后台任务」。产品与开发文档同步：`docs/product/creative-canvas-system/modules/harness.md`、`docs/dev/creative-agent.md`。
- 外部：无。

## Risk Notes

- 并发：完成通知可能与摄影师消息、排队消息的自动发出、另一条通知、停止同时到达，同一对话只能有一个运行，唤醒必须和摄影师发消息抢同一个会话槽位，并且不重复开运行、不丢通知。「转后台」与任务完成存在竞态，必须由同一事务决定助手拿到的是哪一个。生成和压缩现在没有终态回调（`creativegeneration/agent.go` 每 2 秒轮询），改为停靠需要从生成执行和压缩候选的终态通知到运行，涉及跨模块事务顺序。
- 数据迁移：需要持久化后台任务（句柄、来源运行和工具调用、状态、通知是否已送达）和完成通知消息，具体结构由 design 定。场景客户端任务现在在取消运行的同一事务里被取消，完成时按关联运行做准入复查；后台任务要改为不随运行取消、按对话复查，这是对 `data: 场景客户端任务` 的修订。
- 信任边界：空闲唤醒是第一条不由摄影师发消息触发的建运行路径，必须走与发消息相同的准入：账号隔离、积分预留、账号外发同意（`egress-consent-account-level` 已于 2026-11-14 结案，说明版本已写明「后台任务完成后助手可能自动回复并计费」）、Skill 可用、项目未归档。转后台和取消接口按句柄操作，必须限定在本账号。
- 计费连锁：后台任务的生命周期比运行长，每轮自动运行又拿到一份新的生成预算，现有按运行计的预算挡不住「自动运行 → 后台任务 → 再自动运行」的循环。本提案照 Claude Code 的做法封住：自动运行可以连锁，但对话里连续 5 轮自动运行、期间没有摄影师消息就停止自动唤醒；发起任务的那一轮被停止或失败时也不唤醒。摄影师不在场时最多连续 5 轮自动回复。
- 与「消息排队」（`agent-message-queue`，已合入 `develop` 并结案）的关系：现有插队与补充已通过持久化输入批次在模型调用前送达。design 阶段沿用这一送达时机与持久化机制，明确如何区分系统完成通知和摄影师消息，以及运行结束时尚未送达的通知如何保留给下一轮。
- 排期：依赖 `egress-consent-account-level` 的账号外发同意，该 Feature 已结案，待合入 `develop`；design 基于合入后的读取规则修订（通知里的产物如何被当前运行读到）。
- 范围：What Changes 有 7 组，处在 Feature 的上限附近。owner 于 2026-11-15 决定不拆期，7 组在本 Feature 内一起交付和验收。

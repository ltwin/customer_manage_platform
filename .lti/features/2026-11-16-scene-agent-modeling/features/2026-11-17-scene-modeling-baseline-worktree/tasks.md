# M0 实施清单

## 1. 冻结评测输入

- [ ] 1.1 编写 `discovery/research/protocol.md` 和 `cases.json`，核对 12 个建模与摆放任务、4 个修改任务。每题都有可重复创建的初态、输入文本、预期尺寸与允差、评分描述及固定机位。
- [ ] 1.2 在 `discovery/research/fixtures/` 准备合成场景和独立几何真值，验证正例、反例、不可判例、校准集和留出集。压力输入通过现行静态预检，同摘要变形样例能由独立脚本认出顶点差异。

## 2. 跑通采集和故障原型

- [ ] 2.1 编写 `discovery/research/run.mjs` 和运行索引格式，先用本地合成运行验证固定目录、运行身份、匿名图、终态与证据索引。模拟缺产物、路由不符和预算不足，核对失败行和剩余计划可追溯。
- [ ] 2.2 在 `discovery/research/prototype/` 接上可终止 Worker 和素模拼图，验证四项检查的适用性及独立真值。记录不同模型规模下的覆盖率、主线程、额外内存、图片与阶段耗时，逐项核对留出样例。
- [ ] 2.3 用现有场景浏览器场景和 API 时延路径验证必要上传与完成的计时。对原型分别注入超时、Worker 终止和可选上传失败，核对必要产物仍提交一次并留下可读的降级证据。

## 3. 执行并复核评测

- [ ] 3.1 按设计使用两个本地隔离实例和账号。先核对配置中的批次预算，逐个试跑确认实际模型路由、可用工具、预留与结算、材料外发范围及结果采集，然后冻结运行配置。
- [ ] 3.2 串行完成现状基线、指定重复与缺陷样例对照。为每次运行保留配对键、费用、耗时、停机原因和匿名视图；预算耗尽时登记未执行项，按设计复核矩阵覆盖和证据缺口。
- [ ] 3.3 用代表样例验证圆角、扫掠、隔板与斜面支撑的适用范围，保留后续同摘要变形对比证据。整理匿名评分表供 owner 评分，登记最终评分和量测，确认后解盲。
- [ ] 3.4 交付 `discovery/research/findings.md`。依据可复核结果推荐 M1 诊断项、适用范围、时间和内存预算、附图策略及验收阈值，说明限制和后续最晚决定时点，供 Epic 修订审阅。

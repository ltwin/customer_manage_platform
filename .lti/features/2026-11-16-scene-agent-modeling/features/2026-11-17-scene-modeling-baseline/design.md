# M0 执行设计

## 继承的设计

本次绑定 `scene-agent-modeling` v1 的「评测与验证」「关键机制」「未决事项」。沿用场景工具、几何模块、客户端任务和现行外发准入。压力样例以现行 `patterns: 几何模块契约` 和 `data: 模型内容` 的 200 万三角形、200 MiB 为限。M0 交付可复跑的评测及原型证据，M1 的正式接口和阈值经 Epic 修订确定。[Epic 设计](../../design.md) · [M0 提案](proposal.md)

## 评测对象与流程

1. 冻结协议、任务、输入、判分器版本、助手模型和预算。每题用独立测试场景及对话执行。复跑时从相同种子的初始状态重新创建场景，用任务 ID、输入摘要、协议版本、模型路由和重复序号识别结果。
2. 基线在隔离本地实例经现有助手和场景命令执行。评测脚本采集首个可用产物和最终产物。助手按原工具准入工作，文字模型仍可使用原有读取和写入工具。模型版本、路由或推理设定变化时中止对应分组，恢复冻结条件后再跑，已发生的调用与费用保留在明细里。
3. 独立运行几何扫描、拼图和故障原型，记录输入摘要及阶段时长。再把同一缺陷场景复制给不同反馈组，用相同的问题和初始对话。实验反馈放入同一位置的合成补充消息，数值以固定格式附上，拼图走现有图片附件。这个对照测信息能否帮助修复，正式工具回执、完成通知和外部读取的交付效果留给 M1 验证。
4. 匿名化视图后由 owner 评分。评分表定稿后再展开模型与组别映射。将结果与支持域、费用、资源和失败记录合并，给出 M1 决策建议并记录后续批次的风险证据。

协议为每题记录以 m 表达的目标、允差和有意交叠名单。草案默认尺寸允差为 `max(1 mm, 目标尺寸 × 1%)`，角度 2°，支撑间隙或陷入 2 mm，水平落点 5 mm。圆角尺寸采用 1 mm 绝对允差。需要更严或更松的任务逐题明示并在首轮前冻结。图像用夹具预先指定的正、侧、顶与斜视机位，固定投影、比例、场景帧和照明；取景基于任务参考范围，所有组使用同一机位。

对每个任务记录关键量测通过数与总数、结构和比例及细节各 0–2 分，以及按现象和位置去重的缺陷条目。0 表示缺失或显著失真，1 表示基本成形但有可见缺陷，2 表示满足本题评分描述。用脚本核验尺寸、姿态及支撑距离，用盲评判定外观与设计意图。未完成、环境退出、超预算或无有效产物的结果保留原始原因，并纳入任务完成率的分母。几何准确率只采用独立真值和有效量测，逐项报告这些分母及缺测数。记录每个模型的配对差和实际样本量，小样本百分比附计数。

## 分组与运行预算

| 用途 | 每种模型的运行数 | 条件 |
|---|---|---|
| 路由与采集试跑 | 各 1 | 用合成场景验证实际路由、外发、预算预留、模型事实与产物采集 |
| 现状基线 | 各 16 + 2 | 全题一遍，预先指定 B01 和 B10 各重复一次 |
| 缺陷修订对照 | 看图 12，纯文本 8 | 四个固定缺陷样例分别覆盖偏移、绕序冲突、内翻和近共面重叠。看图跑三组，纯文本跑两组 |

最多 **58 次助手运行**，包含试跑和重复。单次上限 8 分钟。基线允许首写和最多一轮修订，缺陷对照最多一轮修订。含多个物件的任务以同一提交计划定义该轮涉及的目标集合，逐条登记调用；越界时按已有停止能力收尾，并记录预算失败。计时、工具重试、后台未完成的写入与迟到回执均按实际运行记录。

建议选择仓库目录配置中支持图片的 `claude-sonnet-5-5`（优先验证 `4router/api/claude-sonnet-5-5`，图片输入按实测路由确认），以及纯文本 `deepseek-v4-pro`（`deepseek/api/v4-pro`，当前配置关闭思考）。记录请求模型、实际回传模型、部署键、推理设置和定价版本。试跑前检查本地凭证和路由可用性，仅记录判定结果。有备用路由的模型只把固定路由的结果纳入对照。确需更换部署时，在正式样本开始前记录并重新冻结，正式运行中发生切换时作废该次质量样本并保留其预算支出。

建议整批费用上限 **20 美元**，看图组 15 美元，纯文本组 5 美元，包含试跑、重试和未结算预留。两个模型各用独立的本地测试实例及账号，按模型上限设置已有 `CREATIVE_LLM_MONTHLY_LIMIT_MICROS`，运行在同一结算期内。每次派发前由 Gateway 做既有预留，脚本在分组切换时核对已结算金额与未结算预留；额度不足时停止并保留未运行任务清单。试跑核对实际路由、定价快照、预留额和结算路径。费用上限是本地 Gateway 的计量上限，实际供应商账单以其计量为准。试跑测得预算无法满足完整矩阵时，保留现行上限并把缩小样本或追加预算交 owner 决定。

## 真值、原型与故障

- 由几何构造公式和独立标注生成真值，先固化 `positive`、`negative`、`indeterminate` 或 `not_applicable`，再运行检查器。同一家族用不同几何、尺寸及变换分别做校准和留出，按文件摘要识别。覆盖镜像、绕序正常及单面翻转、合法接缝、开曲面、薄片、闭壳内外层语义未知、正常邻接和实际重叠。报告以已确认结果区分误报、漏报和预算未完成，完整阴性要求走完相应检查。
- Worker 读通过预检的 GLB，扫描只生产本地评测结果。对照普通样本和一个 180–200 万三角形且通过现行预检的单模型压力样本，优先借用已有参数化压力生成方法。普通样本以 1 秒、压力样本以 3 秒作为首轮原型探针，超时由宿主终止并记录；数值用于找资源边界，M1 的最终预算取决于实际编译、上传和提交耗时。测主线程长任务、Worker 搬运字节、可计量的额外内存、图片大小、GPU 读回和上传耗时。浏览器无法提供的内存读数标为不可测，记录可独立核验的缓冲区分配量。
- 浏览器内的故障对照使用同一必要产物，依次耗尽检查预算、显式终止 Worker、模拟可选图上传失败，记录必要提交是否完成、次数及剩余时间。用现有场景助手浏览器脚本和真实 API 时延脚本分别取执行器与上传的对照证据，原型的故障窗口与现有完成链路的真实记录分开呈现。
- 用 B01 和 B03 比较圆角及轮廓、弯臂的受限扫掠候选。用 B10 和 B12 收集隔板多层命中、斜面与父级变换的支撑证据。记录同 AABB、同面数的 E04 改形夹具的实际顶点差。后续算子、落位接口和部件指纹定义由各子项确定。

## 契约与验证

本批沿用产品 API、数据结构、沙箱权限与部署默认值，评测文件只供本地复跑。源协议和夹具留可读文本，体积较大的产物通过大小、SHA-256 和本地证据位置索引。禁止将凭证、生产场景和实际素材写入评测记录。

先执行任务索引、真值、预算门槛和故障分支的试跑，再串行运行整批。浏览器和设备固定，冷、热缓存分开计时，运行中观察 CPU 和内存，持续高负载时停下并缩小受影响用例。压力、构建、容器和真实模型任务分时执行。验证以本地评测入口、必要的现有助手浏览器场景和沙箱用例为范围。M0 结果清楚区分实测、原型、未覆盖和后继决策，归档只保留可检查的结果及来源。[项目 attention](../../../../memory/attention.md#测试)

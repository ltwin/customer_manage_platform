# Roadmap

## 子项

按 `policy: serial` 交付。前一项结案并完成集成后，后一项才进入实施；后续子项可以提前准备设计。M0 先建立评测和判定依据。M1 先贯通数值反馈与修订闭环。M2 到 M4 分别改变建模、落位和已有模型的修改方式。

| 批次 / 子项 | 本批成立的场景 | 依赖和目标契约 | 交付证据 |
|---|---|---|---|
| M0 `scene-modeling-baseline-worktree` | 固定任务、独立真值和运行办法；两个模型完成基线；用有界原型作出 M1 所需决定 | 无产品契约。结论写入 discovery，随后经 Epic 修订进入验收与共享设计 | 任务集、评分表、基线数据、原型输入输出、风险与阈值建议 |
| M1 `scene-model-feedback` | 助手写入模型，拿到数值诊断和模型默认材质回执，并据此修改。可用时附图；回看可按原机位取局部图 | M0；与 `creative-mcp-server` 协调任务及完成条目。交付 `data: 模型检查报告`、`api: 助手场景工具的输入与写入结果`，以及经修订绑定的任务与回看条目 | AC-3、AC-4、AC-5、AC-9、AC-10；模型级 AC-1 对照；内置前后台与 MCP 数值回执对照 |
| M2 `scene-lib-v2` | 助手用发布的新算子做出更细的部件；模型能重新打开和改参；已有库版本的模型可正常重烘焙 | M1；实施前补 `patterns: 几何模块契约`、`data: 模型内容`、`api: 场景模型命令`、库版本涉及的任务条目，并同步 OpenAPI 与两端生成物 | AC-6；硬表面任务和人物尺度道具的 AC-2 对照；跨版本任务、写入、关闭入口后的重烘焙 |
| M3 `scene-relational-placement` | 助手指定地面、支撑区域或位置挂点，求出可验证的落点后原子应用；并发编辑可识别过期解；场景诊断对纯文本助手可用 | M2；实施前补只读求解、原子应用、带场景帧的检查回执。对齐参考点和姿态契约 | AC-7；场景级 AC-1 对照；隔板、斜面、父级变换、快照失效和无法求解样例 |
| M4 `scene-model-patch` | 助手读取已有代码，提交小补丁并核对实际变化；不确定的部件有明确提示 | M3；实施前补来源、互斥与版本校验、变化回执。面分配沿用现有命令 | AC-8；相同 AABB 与面数但几何变化的反例；整体验收 AC-1 至 AC-11 |

### M0 的交付物

1. **评测协议**。计划 12–15 个首次任务，覆盖硬表面道具、家具、建筑构件和带摆放的小场景，另设 3–4 个基于已有模型的修改任务。给出任务意图、关键尺寸与容差、允许的有意分离或交叠、固定对照视图、每维评分和失败分类。冻结助手模型标识、推理强度、可用工具、最大修订次数、运行预算及设备。选定关键样例做重复运行。收费调用前列明每组运行数、单任务和整批花费上限，按上限停止并记录未完成样本。任何推理强度实验单列。
2. **最终质量基线**。至少一个有视觉能力和一个纯文本模型，保存每任务的最终 GLB 或场景修订、生成代码、固定视图、运行指标及人工标注。不同实验组由 owner 按匿名顺序评分。计算每个模型的配对差异，并分别记录未完成或无可用产物的任务。人工质量分始终基于同一标注和量测办法。
3. **独立检查真值与预算原型**。正例、反例与不可判例独立标注。最低覆盖镜像变换、UV 或材质接缝、故意离散部件、开曲面与薄片、一个闭壳包含另一闭壳且不交面、正常邻接和真实近共面重叠、尺度相差大的几何。用留出样例复查容差。测普通模型和接近 200 万三角形的合法模型，记录检查覆盖率、误报与漏报、不可判和预算耗尽率、主线程用时以及峰值内存。至少验证可终止 Worker 和可选反馈失败时仍有时间提交必要产物的机制。
4. **图像增益对照**。在选定缺陷样例与任务子集上，用同一首写产物和任务上下文对比现状、数值反馈、数值加拼图。各组有相同的调用与修订机会；现状组保留该模型原有的回看能力。观察助手能否正确定位问题并修订，并与从头执行的最终质量基线分开报告。量测图片大小、token、GPU 与上传耗时，据此决定默认附图还是按需附图。若预算不足以交付拼图，作为范围修订提出。纯文本模型只跑适用组。
5. **后续风险穿刺**。只原型验证高不确定项。M2 用有代表性的硬表面任务比较基础圆角、轮廓倒角和典型扫掠的收益与预算；候选网格算子逐项定稿留给 M2。M3 用隔板、斜面和父级变换确认支撑选择与快照绑定可行；M4 保留同包围盒同面数却改变几何的反例，供后续指纹验证。原型留在子项 discovery，作为设计证据。
6. **回填和批准**。M0 给出 AC-1、AC-2、AC-3、AC-7、AC-8、AC-10 的指标定义、样例范围、阈值或最晚决定时点。可用基线和探索原型校准阈值；用于判定交付的复测开始前锁定相应阈值，保留校准和验收所用样例的区别。M1 实施前定稿诊断代码、预算、默认附图策略和客户端能力契约。M2 至 M4 保留未决证据及对应决策时点。

### 落地责任

- M0 的任务代表性、质量评分、预算和最低收益由 owner 审阅。对数值和拼图的比较同时给出质量差异与成本，支持选择默认策略。
- 各子项按自己的可验证结果实施与验收。交付的目标契约从对应的批准基线绑定；同一现行条目分批修改时，下一批基于前一批已交付的正文修订并重新绑定。
- M4 完成后，统一按 proposal 的 AC-1 至 AC-11 复测及整体验收，补齐内置前台、后台终态和外部 MCP 三种入口的证据。
- 日常验证按项目影响面执行。M1 跑几何、沙箱、任务和浏览器故障场景，M2 更新 OpenAPI 时跑生成并做漂移检查。收费模型评测用固定脚本串行执行，运行证据单独留存。

## 与其他 Epic 的关系

- **`creative-mcp-server`** 的 C3 `mcp-scene-skill` 负责接入外部助手的场景客户端任务。本 Epic 在 C3 相关契约交付后补齐 M1 所需的请求、结果、能力和完成协议；M0 不依赖 C3。外部助手现有的授权、连接、任务等待、普通回看和镜头卡语义继续沿用其契约。
- **`scene-editor-3d`** 已交付几何模块、沙箱、材质、场景工具。本 Epic 使用现行面分配规则；M3 在定稿时核对参考点能力，且显式把参考点和几何支撑位置区分开。
- **`scene-pose-system`** 涉及场景文档、模型内容及模型命令。M2、M3 和 M4 在补目标契约前核对最新批准与交付范围，协调同名条目的写入权。M3 使用按帧求值的既有姿态。
- **`scene-traced-lighting`** 与 **`scene-performance`** 提供出图与资源预算的背景。M0 可复用压力模型；反馈几何分析有独立的执行预算。
- **AI 3D 生成、贴花和烘焙** 各自推进。模型来源扩展后可评估复用诊断结构，首轮以本 Epic 的代码模型为验收范围。

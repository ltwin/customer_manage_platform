# 探索记录：助手建模能力

2026-11-16。来源是 2026-11-15 对 3D 编辑器渲染质量和助手建模质量的整体诊断（`docs/research/scene-render-and-modeling-diagnosis.md`），以及建模助手在一次硬表面建模后自己总结的 8 条反馈（诊断报告第 4 节）。渲染侧已另立 Epic `scene-traced-lighting`；这里只记建模侧。

## 起因

owner 的反馈：助手默认建出来的模型不够精细，还经常出错。

## 诊断结论

助手是这样建模的：写一段 ES 模块代码，在浏览器沙箱里用 three.js 和平台的建模库 `lib@1` 生成 GLB；摆放靠 `edit_scene` 写坐标；回看靠 `render_view`。

**为什么容易出错**：

| 问题 | 证据 |
|---|---|
| `write_model` 只返回包围盒、面数、槽位、部件和挂点，不带图 | `backend/internal/creativecontent/model_facts.go` |
| 没有几何检查：穿插、悬空、翻面、近共面、原点偏移都没人查 | `frontend/src/creative-scene/sandbox/inspect.ts` 只查 GLB 结构和上限 |
| `render_view` 一次一张、长边固定 1024，只对支持图片输入的模型开放 | `creativeagent/scene_tools.go`、`tool_registry.go`；DeepSeek V4 Pro 不支持图片输入 |
| 摆放坐标由模型手算；`mount` 只在手动拖放时用来吸附 | `frontend/src/creative-scene/placement/snap.ts` |
| 改模型要重写整段代码 | `write_model` 的来源只有整段代码，或基线修订加参数 |

**为什么不够精细**：

| 问题 | 证据 |
|---|---|
| `lib@1` 只有布尔、挤出（倒角固定 2 段）、旋转体、线性和环形阵列 | `sandbox/lib.ts` |
| 沙箱里不能 import，three 的扩展（圆角盒、细分、合并顶点等）用不了 | `sandbox/compile.ts` |
| 提示词只有单位、朝向、命名约定和一句「先粗后细」，没有建模方法 | `creativeagent/instructions/base.md`「搭建场景」 |
| 推理强度固定为 medium | `platform/llmgateway/catalog_4router.go` |
| 材质提示（hint）命中预设后，代码里写的颜色被忽略，结果里不说明 | `materials/resolve.ts` |
| 内置模型只有男、女两个素体 | `backend/internal/creativescene/models.json` |

## 建模助手自己的反馈里与本 Epic 有关的部分

- 缺硬表面的高层操作：倒角、加权法线、抽壳、布尔后的清理（第 5 条）；
- 缺几何检查：非流形、穿插、错误法线、零厚度、近共面（第 4、5 条）；
- 部件可以标识，但不能局部修改，改一处要重写整个模型（第 6 条）；
- 回看能力不足：固定 1024、没有局部区域和部件独显（第 8 条）；
- 材质预设哪些参数实际生效没有回执（第 7 条的一部分）。

它的其余反馈另行处理：面光源阴影条纹（缺陷修复，以及 `scene-traced-lighting`）、渲染调试通道、分层材质与贴花、工业材质与 HDRI（`scene-editor-3d` 的 `scene-hdri` 已在准备）。

## 外部做法（2026-11-15 调研，来源见诊断报告第 7 节）

| 结论 | 来源 |
|---|---|
| 写码—渲染—检查的闭环比单次生成明显更好：BlenderGym 上提升 35.32% | VIGA（arXiv 2601.11109） |
| 只看图解决不了尺寸错误；用几何内核做精确量测加独立评审后，中位 IoU 从 0.81 升到 0.96 | CADSmith（arXiv 2603.26512） |
| 大模型的空间推理很弱：MMSI-Bench 上 GPT-5 约 40%，人类 97% | MMSI-Bench（arXiv 2505.23764） |
| 摆放让模型只说物体之间的关系，由求解器算坐标，优于直接给坐标 | Holodeck（arXiv 2312.09067） |
| 模型擅长语义和相对关系，不擅长绝对数值；用关系算子代替绝对坐标 | aDSL（arXiv 2608.17975） |
| 把常用的形状沉淀成可复用的函数库 | ShapeLib（arXiv 2502.08884）、SceneCraft（arXiv 2403.01248） |

## 方向

1. **先给反馈，再给能力。** 助手现在看不到自己做错了什么。检查报告和拼图是所有后续改进的前提，也最容易量化。
2. **数值检查优先于看图。** 数值报告对所有模型都有效，包括不支持图片输入的；图片只作补充。
3. **检查是反馈，不是闸门。** 沿用 owner「Agent 能力优先于权限控制」的取向：有缺陷的模型照样写入，报告随结果返回，由助手决定改不改。
4. **不让助手手算坐标。** 摆放说关系，部件拼装对挂点。
5. **建模库按版本扩充。** `lib@1` 已发布的行为不变，新能力进 `lib@2`。
6. **先有评测集，再谈改进。** 没有固定的任务集和基线，「更精细、更少出错」无法验收。

## 考虑过、不放进本 Epic 的方向

| 方向 | 理由 |
|---|---|
| AI 3D 生成（Tripo、Meshy 等）接入 | 有许可阻断项（`docs/research/tripo3d-modeling.md`），是另一条产品线；本 Epic 先把代码建模做好 |
| 贴花、遮罩混合、AO 与曲率烘焙 | 主要是材质和渲染的工作，要改材质的数据契约和三条渲染路径，建议另立 Epic |
| 渲染调试通道（法线、粗糙度、直接光、间接光） | 服务于调材质和打光，不是建模；会和 `scene-traced-lighting` 同时改实时 GI 管线 |
| 点、边、面级的网格编辑工具 | owner 已否决（AI 原生，不做 DCC 网格编辑）；网格内部交给代码 |
| 内置道具库 | 资产要逐个制作和审核，是内容工作；等建模能力提升后可以由助手批量产出再精选 |

## 未决（进入 design 的未决事项）

- 评测集选哪些任务、用哪几个模型跑基线；
- 任意网格的按角度倒角在没有几何内核的情况下能不能做；
- 稳健布尔（manifold-3d）要在沙箱里跑 WASM，会改沙箱的 CSP；
- 关系式摆放在服务端按包围盒和挂点算，还是在渲染端按真实几何算；
- 建模时要不要提高推理强度（涉及成本）。

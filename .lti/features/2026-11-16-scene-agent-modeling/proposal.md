# Epic: scene-agent-modeling — 助手建模能力

永久需求文档。整体方案见 [design.md](design.md)，目标契约见 [contracts.md](contracts.md)，交付见 [roadmap.md](roadmap.md)。当前已交付能力以项目 `.lti/contracts/` 为准。问题来源见 [探索记录](discovery/brainstorm.md)和[建模诊断](../../../docs/research/scene-render-and-modeling-diagnosis.md)。

## 目标

摄影师用助手搭建出图参考时，常遇到部件悬空、翻面或穿插、物件落位不准、整体比例失真、硬表面缺少细节等问题。改一个零件也容易牵动其他部件。现有工具已经能写入几何模块和回看场景，但助手拿到的写入回执不足以定位具体几何问题，摆放和修改又依赖手算坐标与整段改码。

完成后，助手能：

1. **根据反馈修订模型**。拿到按部件组织、带单位和检查覆盖情况的数值报告。支持图片输入时可补看素模拼图，也可按原机位局部回看。材质默认解析回执说明槽位预设与被覆盖的模型常量。
2. **构建更准确的形体**。用版本化建模库完成圆角、轮廓和扫掠等常用工序，按建模指导先定尺寸、再分件、最后加细节。
3. **按关系摆放**。明确地面、某个支撑区域或挂点后，由程序求出落位。场景级检查报告按帧指出有证据的间隙、陷入和相交；没有足够证据时说明检查范围。
4. **小步修改并核对影响**。只提交需要替换的源码片段，收到新增、删除、改变或无法比较的部件及尺寸差；已有面分配按现行规则处理并单独回执。
5. **看清质量与成本的变化**。固定任务和评分口径，分别度量摄影师拿到的最终结果、检查器的准确性，以及额外花费的时间和 token。

报告是可选反馈。出现诊断项、检查未运行或反馈失败时，模型写入继续按已有规则完成。助手根据反馈决定后续操作。

## 范围与非目标

- **评测**：固定任务、独立几何真值、基线和复测证据。覆盖首次建模、场景摆放和修改已有模型。
- **写入与回看反馈**：几何诊断、模型默认材质解析回执、可选素模拼图、`render_view` 局部区域、独显和分辨率。实例的实际材质受面分配、实例覆盖和渲染上下文影响，首版回执采用模型默认解析口径。
- **建模库与指导**：发布兼容 `lib@1` 调用的 `lib@2`，首批覆盖圆角基础体、二维轮廓倒角、受限扫掠和按挂点拼装。其他算子按任务收益与预算决定。建模方法放入版本化内置 Skill。
- **落位与修改**：首版支持地面、明确指定的支撑区域和位置挂点。源码补丁走既有烘焙流程，部件级差异基于新旧产物给出。
- **非目标**：引入新的推理模型或 AI 3D 生成供应商、内置道具库、贴花和烘焙、渲染调试通道、手工网格编辑、通用约束系统、自动修复。正式材质扩展与 HDRI 仍由对应 Epic 维护。严格限制任意代码只能改动指定部件，需要独立的受限编辑能力。

## 接口约定

`contracts.md` 定义 M1 的两条目标契约：模型检查报告的数据形状，以及 `write_model@1` 的增量回执。M0 结束时定检查代码、量测和阈值，M1 实施前完成客户端任务及回看接口的契约修订。

M2 发布前补齐几何模块、模型内容、模型命令、任务和 OpenAPI 中受版本变化影响的条目。M3 的只读求解与原子应用接口、M4 的补丁来源与变化回执，在各自实施前修订。现行契约归属及交付顺序见 roadmap。

## 验收标准

M0 先冻结任务、判分口径、每项的验收统计和执行预算，再生成基线。至少选两个助手模型，其中一个只支持文本输入。以基线和技术原型确定阈值，记录适用任务和设备，批准后用于后续对照。不同实验组按相同条件运行和判分，失败与未获反馈要计入结果。

- **AC-1 最终缺陷减少**。WHEN 同一助手模型用固定预算重跑任务 THEN 每个模型的最终结果按同一人工标注规则计数，配对改善达到 M0 阈值。分别呈现模型内缺陷、场景落位缺陷和任务失败率。检查报告条数不进入缺陷分。
- **AC-2 精细度和尺寸改善**。WHEN owner 按统一视图和尺度盲评基线与新结果 THEN 结构、比例、细节的评分改善达到阈值，任务指定的关键尺寸、可见倒角与轮廓质量达到各任务口径。确有设计要求的锐边应保留。
- **AC-3 几何反馈准确**。WHEN 对检查器运行独立 GLB 真值集 THEN 对证据明确的原点、绕序、封闭壳体内翻、近共面重叠返回可定位的量测。负例与不可判例分别验证误报、漏报及未检查率。截断或未完成可从结果辨认。
- **AC-4 写入可靠**。WHEN 注入检查超时、Worker 中止、GPU 丢失、拼图上传失败、旧宿主；再覆盖编译失败、预检失败、冲突、取消与租约丢失 THEN 已有写入条件满足时，同一任务正常提交一次并返回写入修订；已有拒绝、重试和取消语义照常成立。可选反馈失败有可辨认的状态，合法的其他反馈可独立返回。
- **AC-5 回看有效**。WHEN 支持图片输入的助手请求或按策略获得拼图，或调用 `render_view` 指定裁切、独显、分辨率 THEN 有可用图时回执才声明附图。拼图能辨认视角及尺寸；裁切连同独显时仍按原快照、帧和投影取景。纯文本助手得到可用的数值反馈。
- **AC-6 建模库可用**。WHEN 用 `lib@2` 写入、重新打开和改参烘焙，另以固定环境重烘焙 `lib@1` 参照模型 THEN 实际使用的版本与持久化版本一致；新算子满足几何、材质分组和资源上限用例；`lib@1` 参照产物与基线逐字节一致。混合部署和关闭新写入时已有模型仍可按其版本重烘焙。
- **AC-7 落位正确**。WHEN 指定地面、书架隔板、椅座或位置挂点，另覆盖斜面、父级变换、求解后支撑物被改的场景 THEN 有效落点的间隙和陷入在阈值内，朝向按输入保留或应用。无有效支撑及快照失效时返回可处理的结果并保持批次原子性。场景检查量测带物件 ID、帧和修订。
- **AC-8 修改影响可核对**。WHEN 从已有模型的指定源码修订提交小补丁 THEN 精确应用一次，源码过期、匹配不唯一或补丁重叠时可据回执修正。能识别包围盒、面数相同但表面已变的部件；身份不确定时标为无法比较。面分配保留或作废沿用已有规则。匹配任务的补丁字节量和工具成本与整段替换对照。
- **AC-9 安全边界**。WHEN 运行已有沙箱样例，并注入超预算网格、指令形态 ID、伪造报告和不匹配图片 THEN 沙箱仍满足现行契约。服务端按账号、任务与产物范围校验附件，诊断内容按不可信数据处理。生成文本不作为说明或图面标注，机器标识仅用于定位。
- **AC-10 成本有界**。WHEN 助手写入、回看与手动烘焙在固定设备和样例上复测 THEN 分别满足 CPU、主线程阻塞、内存、写入延迟、图像与工具结果预算。测常见模型和接近上限的合法模型；预算耗尽可降级。手动路径不启用新增反馈阶段。
- **AC-11 内外一致**。WHEN 内置与外部助手使用同等授权及能力执行同一场景操作 THEN 共享数值回执的字段、版本、语义以及产物归属。前台、后台终态和 MCP 任务等待都能读取。图片按该调用的能力与授权交付。

## 交付路线

M0 固定基线和完成有界原型。M1 贯通数值反馈与回看。M2 交付建模库版本链路和指导。M3 交付落位和场景检查。M4 交付局部补丁、变化回执和整体验收。具体拆分及批准责任见 roadmap。

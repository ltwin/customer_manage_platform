# 本次交付

## Why

Epic `scene-pose-system`（批准基线 v3）的子项 2。Epic 的主体是带骨骼的人形角色，账号要能导入自己的资产（proposal「目标」、验收 A3）；蒙皮在子项 3。本次先打通**静态、带贴图**的导入：浏览器换算、服务端复核、进资产库、放进场景。这样子项 3 只需在同一条链路上加蒙皮子集和骨骼映射。

本次还要消除 roadmap 列出的三项不确定性：
- 现有贴图字段覆盖不到的 glTF 用法。owner 已在修订 v3 定了处理方式，本次实现并验证。
- 单场景 64 张图片的上限是否够用。
- 导入后的画面与 Blender 是否一致。

## What Changes

交付 Epic 目标契约 `data: MODIFY 场景文档`、`data: MODIFY 模型内容`、`data: MODIFY 模型资产`、`api: ADD 导入模型到资产库`（`epic bind --deliver`）。

**导入**
- 入口有三处：资产库页面和资产库抽屉（「导入」按钮，也可以把 `.glb` 拖进去）、编辑器资产面板的「导入模型」、编辑器「添加 > 导入模型…」。最后一个导入后直接放进场景。
- 只收资源全部内嵌的 `.glb`：图片在 BIN 块里或是 `data:` URL；引用外部文件的拒绝。浏览器按 Epic 设计「导入的材质换算」换算：
  - 解压 Draco、meshopt，反量化量化几何。
  - 拆出图片，材质换成槽位分配。
  - 贴图变换烘进 UV。
  - 可选把原点移到底面中心。
- 导入对话框列出换算结果：槽位、贴图张数，以及忽略或换算过的项。摄影师填标题、来源与授权说明（用文件里的版权信息预填）、来源页面，确认后上传。
- 拒绝的情况在对话框里说明原因：引用外部资源、带骨骼蒙皮、KTX2 贴图、超过 32 个材质、超过 64 张图片、超出静态子集预算。
- 新接口 `POST /creative/assets/from-glb`：校验后一个事务里写模型、贴图持有关系和资产。
- **提交边界**：导入分三个阶段。
  - **提交前**（换算、上传、缩略图）：可以取消，取消时丢弃已上传的暂存文件。
  - **提交中**（请求已发出、还没收到明确结果）：不能取消。网络错误、超时、5xx 时用**同一操作 ID 和同一请求体**重试，服务端按幂等回执返回首次的结果，不会建出第二份；这期间不丢弃上传。
  - **结束**：收到 201 是成功；收到 4xx 是明确失败，此时丢弃上传。
  - 关闭页面时如果仍在提交中，结果可能是资产已建好，也可能是暂存文件 7 天后过期回收，两种情况都不会重复。

**导入的模型**
- `generator = {language: "imported", mount}`，带 `model.import`。
- 编辑器属性栏和资产查看浮窗显示「导入的模型」、原文件名、来源与授权说明，不显示参数和代码。
- 放进场景后可以换材质、做面级材质分配，这些改动都分叉出场景自己的模型，资产不受影响。
- 助手：
  - `search_assets` 标出 `imported`，`read_asset` 返回来源信息。
  - `write_model` 和以它为基础的烘焙任务被拒绝，提示只能换材质或摆放。

**材质能力**（对所有原理化材质生效，不限导入的模型）
- 材质槽加第六种贴图「自发光」：属性栏可以选图。材质预览、最终渲染、`render_view`、`lit` 导出和实时 GI 的追踪层都体现。
- `principled@1` 加「顶点色」开关：打开时基础色乘模型的顶点色，追踪层同样体现。

**不做**
- 蒙皮、骨骼映射、VRM 扩展（子项 3）。
- 导入后修改来源与授权说明。
- 原文件保存与重新换算。
- FBX、OBJ 等其他格式。
- 导入查重。

## Acceptance Criteria

- **AC-1 导入带贴图的道具**：WHEN 导入一个带基础色、ORM、法线、自发光贴图和透明裁切的静态 GLB，THEN：
  - 资产库出现一个模型资产，缩略图带材质。
  - 放进场景后，分别检查三处：视口的材质预览、最终渲染（含实时 GI）里的镜面反射与间接光、`lit` 导出。三处的贴图、发光和挖空都正确。
  - 与同一文件在 Blender 里的效果对照，由 owner 判断一致。对照条件固定：同一相机位置与焦距、同一组灯光（一盏太阳加均匀环境光）、手动曝光、色彩管理统一为 AgX 视图变换（与本项目最终渲染相同，Look 为 None）。
- **AC-2 换算结果看得见**：WHEN 文件里有第二套 UV 的贴图、形态键、动画、unlit 材质或清漆贴图，THEN 导入对话框逐项列出被忽略或换算的内容，导入照常完成。
- **AC-3 压缩与量化文件**：WHEN 导入 Draco 压缩、meshopt 压缩、`KHR_mesh_quantization` 量化（整数位置、归一化 UV，缩放放在节点上）的 GLB 各一个，THEN 都能通过前端预检和服务端复核，画面与未压缩版本一致。
- **AC-4 拒绝并说明**：WHEN 导入引用外部图片或外部缓冲、带蒙皮、带 KTX2 贴图、超过 32 个材质、超过 64 张图片或超过 30 万三角形的文件，THEN 对话框说明是哪一项、怎么处理。不上传任何文件，资产库不变。
- **AC-5 贴图变换**：WHEN 文件里一个材质的贴图都带同一个 `KHR_texture_transform`（平移、缩放、旋转），THEN 导入后的贴图位置与 Blender 一致。
- **AC-5b 寻址方式**：
  - WHEN 一张贴图是镜像或钳制寻址，用它的 UV 全部在 [0, 1] 内，THEN 导入后外观不变，不提示。
  - WHEN UV 跨出 [0, 1]，THEN 对话框逐项提示「原本是镜像 / 钳制寻址，导入后按重复显示」，导入照常完成。
- **AC-6 顶点色**：WHEN 导入一个只用顶点色上色、没有贴图的低多边形模型，THEN 场景里显示顶点色；在材质槽里关掉「顶点色」后变为纯色。
- **AC-7 自发光贴图对所有材质可用**：WHEN 给场景里一个基础体的原理化材质配一张自发光贴图，并把自发光颜色设为白色，THEN 贴图部分发光；`emissive` 为黑色时贴图不起作用。撤销后回到原样。
- **AC-8 原点**：WHEN 导入一个原点在几何中心的道具，不勾「原点移到底面中心」与勾上各导入一次，并分别从资产库拖进场景，THEN 前者按原点贴地（一半陷进地面），后者底面贴地。
- **AC-9 来源记录**：WHEN 导入一个 `asset.copyright` 不为空的文件，THEN：
  - 对话框里的授权说明已预填。
  - 导入后，资产查看浮窗和场景属性栏显示原文件名、授权说明和来源页面。
  - 属性栏不显示参数和代码。
- **AC-10 放进场景后分叉**：WHEN 在场景里给导入的模型做面级材质分配，THEN 场景里的模型变化，资产库里的资产和它的缩略图不变；撤销照常。
- **AC-11 助手**：WHEN 助手搜索到一个导入的模型，THEN：
  - 它看到 `imported` 和来源信息，可以把它放进场景并换材质。
  - 它对这个模型调用 `write_model` 时得到「导入的模型没有代码」的错误，场景不变。
- **AC-12 提交前取消或明确失败**：
  - WHEN 在上传或渲染缩略图时取消，或接口返回 4xx，THEN 资产库不变，已上传的暂存文件被丢弃。
  - WHEN 修正后再导入，THEN 是一次新的导入。
- **AC-12b 响应丢失**：WHEN 服务端已经建好资产，但响应在网络上丢失（测试里让第一次请求的响应失败），THEN 浏览器用同一操作 ID 重试，拿到同一个资产。资产库里只有一份，暂存文件没有被丢弃。
- **AC-12c 提交中不能取消**：WHEN 请求已发出、结果还没回来，THEN 对话框的取消按钮不可用，显示「正在保存到资产库」；结果回来后才结束。
- **AC-12d 超限的透明图片**：WHEN 导入一张超过上传上限、带透明通道的 WebP 基础色贴图（透明裁切的叶片），THEN 它被缩小并编码为 PNG，导入后叶片照常挖空；超限的法线贴图同样编码为 PNG。
- **AC-13 旧数据不变**：WHEN 打开本次上线前的场景、代码模型资产和材质资产，THEN 画面、参数和过时状态不变。
- **AC-14 图片上限实测**：WHEN 把一个带贴图的角色素材（用静态版本）和一套带贴图的布景放进同一个场景，THEN 记录不同图片的张数，由 owner 决定 64 张的上限是否调整。结论写回 Epic 未决事项。

## Impact

- **后端**：
  - `backend/internal/creativescene`：导入接口、`imported` 生成器的读写与派生、库副本规则改为按 `materials` 判断、`write_model` 与烘焙任务的拒绝、`maps.emissive` 校验。
  - `creativecontent`：模型要点。
  - `creativeagent`：`read_asset` 的来源信息。
  - `materials.json`：`vertex_color` 参数。
  - `platform/httpapi`：路由与错误映射。
  - `api/openapi.yaml`：生成物两份。
- **前端**：
  - `frontend/src/creative-scene/import/`：新增，解析、换算、导出、上传。
  - 材质渲染：`materials/`、`render/trace/`。
  - 面板：`panels/TextureFields.tsx`、属性栏、资产面板、添加菜单。
  - 资产库：`creative-canvas/assets/`。
  - 依赖：three 自带的 Draco 解码器文件随前端发布；meshopt 解码器来自已有的 `meshoptimizer` 依赖。
- **规格**：`creative/library` 新增「导入外部模型」；`creative/scene` 修改「材质贴图」（自发光贴图、顶点色）。

## Risk Notes

- **信任边界**：原文件只在浏览器里解析，服务端只接收换算后的 GLB 和图片，并由 worker 按现有的静态子集和图片流程复核。不信任客户端的 manifest，接口只用暂存修订里服务端算出的那份。来源与授权说明只是文本，不核实。
- **契约破坏**：OpenAPI 的 `CreativeModelGenerator` 按 `language` 区分两种结构，所有读 `generator.params`、`code` 的前端代码都要先判断 `language`。前后端同一版本上线，回滚只做前向修复（Epic「验证与交付」）。
- **广影响**：自发光贴图和顶点色改动了原理化材质的着色路径，包括视口、材质预览、最终渲染和追踪层。没配这两项的槽位必须与修改前逐像素相同，用现有的材质截图对照验证（[[render-quality-over-performance]]）。
- **大文件**：原文件可能上百 MB。解析和换算在浏览器里进行，期间对话框显示进度；换算后超过 16 MiB 时拒绝。导入期间不阻塞编辑器其他操作，具体做法在 design 里定。

# 姿态系统与分镜时间线：探索记录

## 原始诉求

- **2026-10-27**：分镜制作中要能精准控制主体的动作，因此引入姿态系统。
  - 骨骼绑定和权重绘制；**至少**要能导入外部已经绑定好的资产。
  - 建立姿态库，姿态可以复用。
  - 助手可以参考资产库里已有的姿态，做出新的姿态。
- **2026-10-28 扩展**：每个分镜对应时间线上的一帧，为以后的关键帧动画打基础。
  - 一帧记录物件的变化（主体的姿态是其中一项，以后的场景变化也一样）和摄像机的变化（焦距、对焦点、光圈、曝光、位置、画幅等）。
  - 组合起来就能做出位置不同、相机参数不同、姿态不同的分镜。

## 事实依据

### 代码与契约（2026-10-27/28 核实）

- **模型内容只接受静态 GLB 子集**：不允许 `JOINTS_*`、`WEIGHTS_*`、`targets`，也不允许 `skins`、`animations`、`images`、`textures`（`.lti/contracts/data.md:286`、`:288`）。几何模块契约要求「没有形变、骨骼、动画」（`.lti/contracts/patterns.md:69`）。
- **外部导入的位置已预留**：契约预留了 `generator.language = "imported"`、没有 `code`（data 契约「生命周期与演进」）。
- **贴图还没做**：C5c `scene-pbr-textures` 未开工。
- **资产库已支持 `model`**：C6 已归档，资产带材质分配、不带变换。
- **摄像机参数都在摄像机物件上**：焦距、传感器、画幅、景深、光圈、对焦距离和对焦物件在 `objects[].camera`（`.lti/contracts/data.md:184`）；曝光模式、补偿、ISO、快门也在摄像机上（`.lti/contracts/data.md:501`–`507`）。导出总是通过场景摄像机。
- **单元**：场景的单元有 `environment`、`render`、`objects`；每个物件还有摆放 `object:<id>` 和内容 `object:<id>:content` 两个单元（`.lti/contracts/data.md:185`）。每次保存都存完整快照。
- **导出按摄像机列出**：`export_shots` 的请求是 `camera_object_ids`。导出图记录来源，场景改动后会提示过时。
- **渲染管线假定几何是静态的**：
  - 同材质的 part 合并成一个几何（`frontend/src/creative-scene/models/merge.ts`）。
  - GI 和路径追踪按几何建 BVH，并按几何的键缓存（`frontend/src/creative-scene/render/trace/build.worker.ts`）。
  - 包围盒用 manifest 里的静态包围盒。
- **渲染引擎**：现有工作台和实时 GI 两种，路径追踪已列入规划，但还不能选择（`frontend/src/creative-scene/render/engines.ts:7`）。实时 GI 画面外的追踪层只带顶点颜色和材质常量（`render/trace/build.worker.ts:88`），没有贴图。
- **C5c 的现状**：`scene-pbr-textures` 是 Epic `scene-editor-3d` 的后续子项，未开工，开工前要修订 Epic。它的范围是：PBR 贴图（基础色、法线、糙度、金属度、AO）接到原理化 BSDF 的同名参数上，三平面投影支持图片和法线贴图，加上内置 HDRI 天空。材质用的是 `MeshPhysicalMaterial`，参数名与 glTF PBR 一致（Epic design 「材质」一行）。
- **平台级内容的先例**：内置 Skill 放在仓库的 `deploy/creative-skills/`，服务启动时同步进平台存储，所有账号可用（`docs/dev/creative-skill-import.md`）。内置基础体是仓库里的 JSON（data 契约「场景内置基础体」）。
- **既有取向**：交互按 Blender 惯例（[[audience-includes-pro-creators]]）；助手不手算四元数（C4 的 `look_at`）；不为方便而加闸门（[[agent-capability-over-permission]]）。

### Blender 调研（2026-10-28，Blender 5.2 LTS 手册）

- **骨骼姿态能存成形态键，但存的是网格烘焙结果**（[修改器概述](https://docs.blender.org/manual/en/latest/modeling/modifiers/introduction.html)）：
  - 骨架修改器属于形变修改器，菜单里有 *Save as Shape Key*（把修改器的结果存成一个新的相对形态键，保留修改器）和 *Apply as Shape Key*（存成形态键后删除修改器）。
  - 存下来的是**这一个网格的顶点偏移**，不是骨骼姿态。
  - 它不能再用骨骼编辑，换一个角色（拓扑不同）就套不上。
  - 挂在手骨上的道具不会跟着动，也不能打骨骼关键帧。
  - 与骨架同时生效时，形变会叠两次。
  - 它在 Blender 里的正经用途是修正形态键（例如修肘部弯曲时的塌陷），以及导出烘焙。
  - **结论：不适合用来存档姿态。**
- **Blender 存档动作、快速切换用的是姿态库**（[Pose Library](https://docs.blender.org/manual/en/latest/animation/armatures/posing/editing/pose_library.html)）：
  - **存储**：姿态资产是一个只含一帧的动作（action），标记为资产，存在当前文件或资产库文件里。
  - **创建**：在姿态模式里选中要收录的骨骼，执行 Create Pose Asset。资产记录这些骨骼当前的位置、旋转、缩放，不管角色有没有动画。
  - **缩略图**：用场景的当前摄像机、Workbench 渲染器渲染，可以重新生成。
  - **套用**：3D 视口底部的资产架（Asset Shelf）单击即套用，方向键也能选中套用。有骨骼被选中时，只改选中的骨骼。
  - **混合**：在资产架上左右拖动缩略图，把姿态按比例混合进当前姿态。往左拖是减去这个姿态；Tab 在原姿态和混合结果之间切换对比；E 外推超过 100%；按住 Ctrl 混合镜像后的姿态。右键或 Esc 取消，左键或回车确认。
  - **镜像**：Apply Pose Flipped 左右镜像后套用。
  - **修改已有姿态**：Adjust Pose、Replace、Add、Remove，用选中的骨骼改写姿态资产。

## 分镜时间线模型（已确认的方向）

- **基础值与关键帧**：物件和摄像机现有的字段是基础值。属性有关键帧时，每一帧的值由关键帧求出；没有关键帧的属性所有分镜共用，布景因此天然一致。
- **按属性通道记录**：改一次布景不必在每个分镜里重做；以后做动画插值也要用通道；冲突粒度更细。
- **分镜 = 时间线上的标记**：标记包括帧号、绑定的摄像机和名称。
  - 静态分镜只渲染标记所在的帧。
  - 以后做动画，一个标记到下一个标记之间就是这个镜头的帧段。
  - 摄像机参数也能打关键帧：每个分镜可以用不同的摄像机，也可以一台摄像机贯穿多个分镜。
- **可打关键帧的属性按白名单开放，分两类插值**：
  - 连续值（位置、旋转、缩放、骨骼旋转、焦距、光圈、对焦距离、曝光补偿、ISO、快门）以后按曲线插值。
  - 离散值（画幅、对焦物件、曝光模式、景深开关、可见性）阶跃，保持到下一个关键帧。
  - 以后的「场景变化」只需把字段加进白名单。
  - 结构（增删物件、改父级、换模型、材质槽分配）不打关键帧。出现或消失用可见性关键帧。
- **编辑语义**（Blender 原样）：
  - 自动关键帧开关、I 插入关键帧、Alt+I 删除关键帧。
  - 改没有关键帧的属性就是改基础值，所有分镜都变。
  - 改有关键帧的属性但没插帧时，显示「已改未记录」，切到别的帧后改动丢失。
- **助手语义**：
  - 写入要说明是哪个分镜；不带分镜就写基础值。
  - 不带分镜去改有关键帧的属性时直接报错，提示指定分镜或删掉动画。
  - 读取、回看和导出都能按分镜进行。

### 对现有系统的影响

- **场景文档**：
  - 新增时间线部分：帧率、标记、每个物件的通道和关键帧。
  - 新增每个物件一个动画单元，外加一个时间线单元。
  - 静态分镜的数据量小，全文快照可以承受。以后的密集动画到时再拆存储（与 C7 相关）。
- **导出**：
  - 按分镜导出，每个分镜先求值再渲染。
  - 过时判定按这一镜求值后的状态计算：只改别的分镜的关键帧，这一镜不会过时。
  - 旧场景兼容：每台摄像机自动对应一个分镜，或者没有标记时退回按摄像机导出（在子项里定）。
- **渲染**：
  - 各分镜状态不同，GI 和路径追踪的加速结构、探针要按分镜重建或重新收敛，多分镜导出会变慢。
  - 同一状态的多个机位可以共享这些结果。
  - 这与当前 GI 收敛方面的问题（`scene-gi-stalls` 等）相关。
- **视口**：底部加时间线面板。切分镜就是跳到标记所在的帧，并切到它绑定的摄像机。

## 姿态库的交互（工作假设，照搬 Blender 姿态库）

- **姿态架**：姿态模式下视口底部是姿态架（Blender 的资产架），列出资产库里的姿态资产，包括内置的和账号自己的，可按分组和标签筛选。
- **套用**：单击即把姿态套到选中的人偶，只改选中的骨骼，没有选中骨骼时改全身。
  - 套用遵守时间线的编辑语义：没插帧也没开自动关键帧时，只是「已改未记录」，用来快速切换观察；满意了按 I 记录。
- **混合与对比**：
  - 拖动缩略图按比例混合，Tab 在原姿态和混合结果之间切换对比。
  - 按住 Ctrl 混合镜像后的姿态。
  - Esc 或右键取消。
- **存档**：选中骨骼后「存为姿态」，生成姿态资产。
  - 资产里按标准人形骨骼存旋转（另存骨盆的位移）。
  - 缩略图用当前摄像机的白模渲染。
  - 修改已有姿态用「用选中的骨骼替换」等操作。
- **存在哪里**：只存资产库，不另设「本场景姿态」。理由是只有一处存储，跨场景复用本来就要资产库。Blender 的 Current File 姿态库，等资产库里姿态多到难找时再加。
- **形态键**：骨架修改器的 Save as Shape Key 不做。以后做表情和修正形态键时，形态键作为网格的通道单独设计。

## 资产与素体（工作假设，依据 owner 决定推出）

- **内部资产是平台级内容**：所有账号可见、只读，仿内置 Skill 在启动时同步进平台存储。账号隔离（ADR-001）要求业务表带 `account_id`，平台级内容走平台目录，具体做法在骨骼导入子项里定。
- **两个默认素体**：一男一女，平台内置，账号不能改素体本身，也不能改默认设置。
  - 放进场景后的实例可以摆姿态、打关键帧，可以换材质槽（材质槽分配属于场景实例，不改模型）。
  - 助手按角色性别选素体，判断不出时先问创作者。
- **普通账号导入 GLB**：
  - 服务端要放宽到「静态子集 + 蒙皮子集」并做校验。
  - 导入时自动识别常见的骨骼命名（VRM humanoid、Mixamo 等），映射到标准人形骨骼；识别不了时，由创作者手动指定映射。
  - 非人形资产也能导入并摆姿态，但姿态只能在同一套骨骼上复用。
- **标准人形骨骼**：参照 VRM 1.0 humanoid 的骨骼定义（必需骨骼加可选的手指等），在骨骼导入子项定版。
- **内置入门姿态**（owner 决定）：平台随素体提供一组入门姿态（站、坐、走、回头等），内容由 owner 在姿态模式里制作。功能上只要求内置资产的同步能收录姿态资产。

## 其他工作假设

- 首版只做静态分镜，不做播放、曲线编辑器和视频导出。关键帧记录插值方式（按属性类型取默认值），以后加贝塞尔手柄只是追加功能。
- 姿态编辑按 Blender 的姿态模式：Ctrl+Tab 进入，R 旋转骨骼（可锁轴），FK 加四肢 IK，复制姿态和镜像粘贴，Alt+R 清除旋转。
- 助手写姿态用按关节语义的角度，带关节活动范围；可以让手或脚对准物件或挂点，由 IK 求解。
- 套到体型不同的角色时，接触点会有偏差，需要用 IK 修正（已知局限）。
- 姿态定下后，把蒙皮结果算成静态几何，供 GI、路径追踪、包围盒和导出使用。拖动骨骼时，视口直接画蒙皮网格。

## 贴图的前置关系（分析结论）

- **贴图功能就是 C5c**，归属保持在 `scene-editor-3d`：那里已经登记了这项，开工前修订那个 Epic，不在本 Epic 另起一份。
- **本 Epic 的「外部 GLB 导入」依赖 C5c 归档**。时间线子项与贴图无关，可以与 C5c 并行，也可以先后做，由 owner 排期。
- **C5c 修订时要一并覆盖导入的需要**，否则导入时还得返工：
  - glTF 的贴图语义：基础色、金属度与糙度共用一张图（G 通道为糙度，B 通道为金属度）、法线（切线空间，缺 `TANGENT` 时生成）、AO（R 通道）、自发光；贴图坐标组和 `KHR_texture_transform`；sRGB 与线性的区分。
  - 透明模式 `alphaMode` 的 `MASK` / `BLEND`：二次元角色的头发大量用 alpha 裁切。
  - 服务端校验图片：格式白名单、解码后的尺寸上限，防止解压炸弹。
  - 预算：带贴图的角色常常超过现在 16 MiB 的 GLB 上限。贴图是留在 GLB 里，还是拆成单独的图片内容（可以去重、走媒体票据加载），在 C5c 的设计里定。
  - 实时 GI 的追踪层要能取到贴图颜色。如果用近似（例如按三角形取平均色），要先给 owner 看对比图（[[render-quality-over-performance]]）。以后的路径追踪从一开始就要支持贴图。
- **导入后的材质**：把 glTF 材质换算成原理化 BSDF 加贴图引用，作为模型槽位的默认材质；场景实例仍然可以改分配。

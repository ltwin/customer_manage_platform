# Epic: scene-pose-system — 分镜时间线与角色姿态

永久需求文档：本 Epic 的目标、边界和交付计划。整体方案见 design.md，目标契约见 contracts.md。项目 `.lti/contracts/` 记录当前已交付事实。探索记录见 `discovery/brainstorm.md`。

## 目标

在同一个布景里做出一组分镜，每个分镜的主体位置、姿态和相机参数可以各不相同，并且能精准控制主体的动作：

- **分镜是时间线上的一帧。** 物件和摄像机的变化按属性通道记成关键帧；没有关键帧的属性所有分镜共用，布景天然一致。这也是以后做关键帧动画的基础。
- **主体是带骨骼的人形角色。** 平台内置一男一女两个素体，所有账号都能用；账号也可以导入自己绑定好、带贴图的 GLB。
- **姿态可以精准编辑、跨角色复用。** 姿态模式按 Blender 的习惯操作，姿态记在骨骼通道上。姿态库按一套标准人形骨骼存储，任何人形角色都能套用。
- **助手能摆姿态。** 助手知道默认用哪个素体，参考姿态库写出新的姿态，按分镜回看自检。

## 范围与非目标

- **范围**：
  - 时间线与分镜标记：属性通道关键帧、按分镜求值、按分镜导出与过时判断、时间线面板，以及助手按分镜读写和回看。
  - 外部 GLB 导入：静态模型和蒙皮模型；拆出贴图，把 glTF 材质换算成槽位分配；服务端校验；账号导入后进资产库。
  - 蒙皮渲染：视口、材质预览、最终渲染、实时 GI 和导出都按当前姿态显示。
  - 标准人形骨骼：导入时自动识别常见命名并映射，识别不了时手动指定。
  - 平台内置资产：两个默认素体和内置姿态，所有账号可见、只读。
  - 姿态模式：FK、四肢 IK、镜像、清除，骨骼通道关键帧。
  - 姿态库：姿态资产、视口姿态架、套用、混合、镜像、跨角色换算。
  - 助手摆姿态：选素体、按关节语义写姿态、参考姿态库、按分镜搭镜头。
- **非目标**：
  - 动画播放、曲线编辑器、视频导出。数据上为它们留了位置，但本 Epic 不做。
  - 编辑器内的自动绑定和权重绘制：owner 2026-10-28 定为下一期。
  - 形态键（表情、修正形态键）：以后作为网格的通道单独设计。
  - GLB 以外的格式（FBX、PMX、`.vrm` 扩展名）：在 Blender 里转成 GLB 再导入；VRM 和 Mixamo 的骨骼命名能识别。
  - 从参考照片估计姿态：发布规划 CP-19 的候选，需要先做技术验证，不在本 Epic。
  - 账号修改内置素体，或者修改默认素体的设置。

## 验收标准

全部子项完成后由 owner 按场景走查。技术检查通过不等于验收通过。

- **A1 一个布景，多个分镜**：WHEN 摄影师在一个场景里放内置女素体、建 6 个分镜，每个分镜的主体位置、姿态、焦距和光圈各不相同，THEN 按分镜导出的 6 组图各自对应它那一帧，布景在 6 组图里一致。
- **A2 分镜互不影响，按分镜判断过时**：
  - WHEN 改一个没有关键帧的布景物件，THEN 6 个分镜的导出图都提示「场景已更新」。
  - WHEN 只改分镜 3 那一帧的关键帧，THEN 只有分镜 3 的导出图提示。
  - **先建镜头、后加动画**：WHEN 6 个分镜都建好以后，主体的位置第一次在分镜 3 里被改动（摄影师或助手），THEN 只有分镜 3 的主体移动，其他 5 个分镜的画面和导出图都不变。
  - **后加入人片**：WHEN 6 个分镜都建好以后，在分镜 3 里放入一张只属于这个分镜的人片，THEN 它只出现在分镜 3，其他分镜的画面和导出图都不变；WHEN 之后新建、挪动或删除别的分镜，THEN 人片仍然只在分镜 3。
  - WHEN 把分镜 3 换绑到另一台摄像机，THEN 分镜 3 的导出图提示过时，即使两台摄像机的参数完全相同。
- **A3 导入带贴图的角色**：WHEN 普通账号导入一个按 VRM 或 Mixamo 命名、带贴图的绑定 GLB，THEN 骨骼自动映射到标准人形骨骼，贴图和透明方式在材质预览、最终渲染（含实时 GI）和 `lit` 导出里正确。
- **A4 内置素体**：WHEN 任意账号打开场景编辑器，THEN 能直接放入内置的男、女素体；素体本身不能修改，场景里的实例可以缩放、换材质、摆姿态。
- **A5 精准摆姿态**：WHEN 在姿态模式里用 FK 旋转骨骼、用 IK 拖动手脚、镜像粘贴姿态，再给骨骼打关键帧，THEN 在分镜之间切换时，姿态按关键帧变化。在角色贴近墙面、镜面反射、肢体自遮挡三种场景下分别检查：
  - **几何正确**：拖动中任何时刻，画面（含反射和屏幕外的间接光）都没有旧姿态的残影。
  - **光照收敛**：松手后若干帧内，视口与导出图一致。
- **A6 姿态库跨角色复用**：WHEN 把女素体上的一个姿态存进姿态库，再单击套到男素体和一个导入角色上，THEN 两个角色摆出同一个动作；拖动可以按比例混合，Tab 可以对比原姿态，按住 Ctrl 混合镜像姿态，Esc 取消。体型不同造成的接触点偏差可以用 IK 修正。
- **A7 助手摆姿态**：WHEN 摄影师要求「女性角色回头看镜头，右手扶剑」的一个分镜，THEN 助手选女素体，参考姿态库写出姿态，按分镜回看并自检；WHEN 助手判断不出角色性别，THEN 先问摄影师。**质量由 owner 判断**，样例每例至少跑两次。
- **A8 旧场景不受影响**：WHEN 打开本 Epic 之前建的场景，THEN 画面和已有导出图的过时状态都不变；没有分镜标记时，导出仍然按摄像机进行。

## 决策记录

| 日期 | 决定 | 为什么 |
|---|---|---|
| 2026-10-27 | 姿态按标准人形骨骼存储，跨角色复用 | 只有这样姿态库才能真正复用，助手也有统一的骨骼名可用 |
| 2026-10-28 | 分镜 = 时间线上的一帧，物件和摄像机的变化按属性通道记成关键帧 | 位置、相机参数、姿态不同的分镜用同一套机制表达，也为以后的关键帧动画打基础；按通道记录，改一次布景不必在每个分镜里重做 |
| 2026-10-28 | 不做「人偶挂多个具名姿态」；姿态记在骨骼通道上，复用走姿态库，交互照搬 Blender 的姿态库；「形态键」留给表情 | Blender 的 Save as Shape Key 存的是网格烘焙结果，不能再用骨骼编辑，也套不到别的角色上。「存档动作、快速切换观察」由姿态库的单击套用、拖动混合和 Tab 对比提供 |
| 2026-10-28 | 时间线是第一个子项 | 它是场景编辑器的通用底座，单独就能交付「同一布景、物件位置和相机参数不同的分镜」，骨骼通道之后只是新增一类通道 |
| 2026-10-28 | 内部资产是所有账号初始可用的平台资产；普通账号也能导入 GLB | 平台面向专业创作者，需要导入自己的角色 |
| 2026-10-28 | 默认素体两个，一男一女，账号不能修改；助手判断不出性别时先问 | 素体是分镜主体的统一基准 |
| 2026-10-28 | 编辑器内的自动绑定和权重绘制移到下一期 | 内置素体和导入资产都在外部绑好、刷好权重 |
| 2026-10-28 | 导入的 GLB 要支持贴图；内置入门姿态由 owner 制作，不是功能项 | 导入角色带贴图是常态；入门姿态只要求内置资产机制能收录姿态 |
| 2026-11-05 | C5c 已交付，导入还需要补的贴图能力在本 Epic 里规划 | C5c 已经提供贴图种类、ORM 通道、UV 映射、透明方式和 GI 读贴图 |
| 2026-11-05 | 分镜导出以关键帧为准。一个分镜占一帧，帧号不重复；人片在哪些分镜出现用可见性关键帧表达，不做「人片绑定摄像机」 | 只保留一套机制。同一瞬间的多个机位是相邻的两帧，可见性关键帧因此总能区分分镜 |
| 2026-11-05 | 有通道的属性在每个分镜帧上都必须有关键帧，服务端检查；首次创建通道时，其他分镜写入修改前的值（方案评审） | Blender 的第一个关键帧会让整条时间线都取这个值，「只改分镜 3」就会改动所有分镜，违反 A2。由服务端检查，编辑器和助手写漏时直接被拒，而不是悄悄改到别的分镜 |
| 2026-11-08 | 修订 v2（子项 1 方案评审）：基础值是有通道属性的默认状态；新建分镜取默认状态（S2a），复制分镜取被复制分镜（S2b）；只属于某个分镜的物件默认隐藏；首次插帧在任意帧都补齐分镜帧，编辑器记录修改前的值作为基线 | 「新建保持当前画面」与「只属于当前分镜」冲突，且没有地方记录专属意图；自动关键帧关闭时按 I 拿不到修改前的值；在非分镜帧首次插帧会被 P8 拒绝 |
| 2026-11-05 | 分镜换绑另一台摄像机算过时（方案评审） | 现有指纹计入摄像机 ID；沿用这一点，旧导出图的指纹才能保持不变 |
| 2026-11-05 | 骨骼身份是「模型修订 + 节点下标」，名称只用于显示；人形骨骼经映射寻址；跨角色换算在子项 3 冻结骨架数据前先做穿刺（方案评审） | glTF 节点名可以缺省、不唯一；VRM 的映射本来就按节点下标；不同的静止姿势、局部轴和辅助骨会让「按静止姿势偏差换算」失效，必须先验证 |
| 2026-11-05 | 拖动骨骼时追踪层不能用旧姿态的几何：跟不上就暂时剔除，不保留旧姿态（方案评审） | 旧几何参与间接光和反射，会让预览和最终结果不一致；宁可暂缺，不可错位 |

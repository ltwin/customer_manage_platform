# Epic 技术方案

> 实时 GI 在屏幕追踪之后补一层世界空间追踪：
> - **光追底座**：渲染端把场景打包成两级 BVH 和材质表，跨导出图复用。
> - **反射**：SSR 没命中的采样，以及屏幕边缘淡出带里的采样，沿同一方向改用 BVH 补追，在重投影之前并入 SSR 的原始输出，和 SSR 共用一条降噪链。
> - **漫反射**：以摄像机为中心分级的 DDGI 式辐照度探针，替换合成里材质的环境贴图辐照度那一份。
> - **复杂场景，画质优先**（修订 v2）：
>   - 探针光线追误差受控的简化代理，锐利反射追原始几何；
>   - BVH 和代理在 Worker 里构建，并按模型修订缓存；
>   - 编辑时增量打包，上传量只与改动的几何成正比。
>
> 这一层只在满足上限的 WebGPU 设备上运行，其余情况退回现在的屏幕空间，现有的标定值不变。不新增场景字段。

## 设计上下文

- 需求与验收见 proposal，共识与 owner 决定见 `discovery/brainstorm.md`。研究文档有两份：
  - `discovery/research/world-space-tracing-options.md`：方案比较、Lumen 分层对照、工作量估计；
  - `discovery/research/complex-scene-scaling.md`：复杂场景下的扩展性和精度分档（修订 v2）。

  设计评审一轮（2026-10-23）的结论已并入本文。S0 技术验证（`scene-trace-spike`）的结论经修订 v3 并入本文，数据和对照图在子项的 `features/2026-10-23-scene-trace-spike/discovery/research/`，汇总见其中的 `summary.md`。
- **采用的方案**：BVH 混合追踪，即屏幕追踪优先，没命中的部分交给 BVH 光追。反射接入 SSR 的原始输出，漫反射用级联的 DDGI 探针。场景变复杂时，不靠牺牲画质来换性能，而是靠以下几项（修订 v2，owner 2026-10-23「以尽可能不牺牲渲染质量为前提」）：
  - 精度分档；
  - 构建移出主线程并缓存；
  - 增量打包。
- **规模目标**（owner 2026-10-23 确认，S0 用压力场景验证）：单个场景的原始几何去重后约 2000 万面，实例约 2000 个。超出时按「能力与容量」分档降级，不失败。上万实例的密集远景不在目标内（research「何时该换方案」）。
- **S0 已验证的假设**（修订 v3，参考设备 M4 Pro）：
  - **吞吐**：每帧十几万条探针光线加上 SSR 没命中部分的反射光线，参考场景不到 1 ms，压力场景约 3–7 ms（`throughput.md`）。
  - **设备上限**：参考场景远在上限之内。压力场景按适配器上限请求时在第 1 档（原始层 894 MiB）；按 WebGPU 默认上限时在第 2 档，第 1 档的门槛约 670 万面（`throughput.md`）。
  - **代理画质**：探针追代理与追原始几何，ε = 3 mm 时超过 2/255 的像素只占 0.26%（`proxy-quality.md`）。
  - **宽度函数**：14 个预设改为宽度函数输入后光栅逐值相同，在 compute 里可以调用，与光栅差 ≤ 0.55 级（`hit-shading.md`）。
  - **编译**：14 个预设全部内联，冷编译 1.3 s（`hit-shading.md`）。
  - **探针**：两级级联 DDGI 相对逐像素参考在 ±10% 以内，薄墙房间 +4% 到 +24%（`probes.md`）。

  有四处原设计在实测下不成立，已按 S0 改写：合成（不乘 SSGI 的 `ao`、`GI_INTENSITY` 取 0）、导出预热（两段）、命中点的阴影（阴影光线），以及库的求交不能从 TSL 直接调用（包装函数）。
- **后续增强，不在本 Epic**：
  - 粗糙反射复用探针；
  - 光线里的透明与透射；
  - 命中点的 PBR 贴图（C5c 之后）；
  - 在烘焙时生成代理和 BVH，随模型内容存储（外部 GLB 导入落地后）；
  - 光栅的 LOD 和 cluster 剔除（另立 Epic，可以与代理共用「派生几何」管线）。
  - 路径追踪复用底座。

## 领域模型与业务规则

本 Epic 不触及业务领域，只增加渲染端的派生状态。术语：

| 术语 | 含义 | 不是什么 |
|---|---|---|
| 世界空间追踪层 | 实时 GI 里在屏幕追踪之后接手的那一层：屏幕外反射加探针 GI | 不是新的渲染器，也不是渲染设置 |
| 光追底座 | 场景的光追数据和函数：两级 BVH、材质表、求交、命中点着色。实时 GI 和将来的路径追踪共用 | 不读场景文档，也不是场景数据 |
| 探针体 | 以摄像机（当前在画的视角）为中心分成三到五级的一组辐照度探针，每个探针保存八面体编码的辐照度和深度矩，逐帧更新 | 不是反射捕获（cube），也不存储 |
| 追踪代理 | 每个几何按绝对误差 ε 简化出的一份网格，只给探针光线用 | 不用于光栅，也不用于锐利反射和路径追踪 |
| 精度档 | 一类光线追哪份几何：探针追代理，反射追原始几何 | 不是界面上的画质设置 |
| 兼容模式 | 沿用界面用语：渲染器运行在 WebGL2 后端 | 不是 WebGPU 的 `compatibility` 功能级别。WebGPU 设备上限不足另称「当前设备不支持」 |

**不变量**：

- **I1 屏幕优先**：世界空间追踪层只补屏幕追踪没覆盖的部分。
  - 反射：只在 SSR 没命中处、屏幕边缘淡出带里接手。
  - 漫反射：探针只替换环境贴图的辐照度那一份，`AmbientLight`（场景字段 `environment.ambient`）那一份保留。
  - 太阳只计一次：太阳由阴影贴图下的直接光计入，环境贴图里没有太阳盘（沿用 C5）。
  - 这一层构建时，漫反射的间接光由探针负责：探针不乘 SSGI 的 `ao`，SSGI 的 `gi` 不再叠加（增益取 0）。S0 实测表明两者叠加会重复计算近处的遮挡和反弹（见「合成的接入点」）。偏差由 AC-3 对照逐像素参考测量。
- **I2 一份材质定义**：
  - 命中点着色和光栅用同一份材质参数和同一个预设函数，以及同一组灯光和预曝光、同一张场景环境贴图。阴影例外：命中点朝灯光发阴影光线，因为产品的太阳阴影按视锥拟合，屏幕外的命中点不在覆盖范围内（修订 v3，见「命中点着色」）。
  - 命中点的光照模型是与光栅等价的另一份实现：three 的光照模型只在材质构建时运行，无法在 compute 里复用。等价由「同一表面、光栅对照命中点着色」的测试把关。
- **I3 结果确定**：世界空间追踪层的随机序列只取帧序号。跨帧状态（探针、反射历史）在每张导出图从帧序号 0 开始时清空。
- **I4 场景不变**：后端和设备能力不同，只影响本机怎么画，不改写场景（G4、E7）。场景字段（包括环境光的颜色和强度）在构建和不构建这一层时含义相同。
- **I5 作用范围不变**：只作用于实时 GI 已经作用的地方，即最终渲染、`lit` 导出和 `render_view` 的 `lit`。
- **I6 标定只随这一层**：为这一层重新标定的常数，只在这一层构建时生效，在 `realtimeGI` 里按管线设置 uniform 或参数。这些常数包括 SSGI 增益 `GI_INTENSITY`（这一层构建时取 0，修订 v3）、环境光填充 `AMBIENT_FILL_GI`、收敛帧数和时限。兼容模式、设备不支持和超出容量时全部保持现值，所以 AC-6 的画面不变。
- **I7 预设外观不变**：预设函数改成「宽度函数」输入后，光栅路径生成的着色与现在相同，已发布的预设不升版本（材质目录的规则）。
- **I8 画质优先的精度分档**（修订 v2）：为了性能做的简化，只能用在画面上看不出差别的地方。
  - **探针光线**追代理，代理按 ε_probe 简化（修订 v3：ε_probe = 3 mm）。探针存的是低频的辐照度，ε 远小于探针间距时差异看不出来。
    - meshoptimizer 的误差是估计值，S0 实测有 1.5%–3.5% 的点超出 ε，最大约为 ε 的 2–4 倍。所以「看不出差别」由出图对照把关（AC-12），不由 ε 本身保证。
  - **反射光线**默认追原始几何。只有原始几何超出设备容量时，才改追代理，并在渲染选项卡说明（见「能力与容量」）。
  - 将来的路径追踪始终追原始几何。
  - 规模变大时，按「代理反射 → 不画这一层」的顺序逐档降级，每一档都在渲染选项卡说明，不悄悄降低画质。
- **I9 就绪后才出图**（修订 v2）：底座在后台构建。视口不等待，就绪前实时 GI 只画屏幕空间并给出轻提示，就绪后自动接上。导出和 `render_view` 一定等底座就绪再开始计帧（I3），等待计入时限，所以结果不受构建快慢的影响。

**数据所有权**：

- BVH、材质表、探针和反射历史都是渲染端的 GPU 派生状态，来源是已挂载的 three 场景图，不是场景文档。
- 底座按渲染设备持有（每个 `SceneGPU` 一份，修订 v4），跨导出图复用，随设备释放。不跨标签页共享。导出为每张图新建 `SceneRenderer`（`host/render.ts`），挂在它上面就不能跨图复用。
- 反射历史属于每条管线。探针在导出和 `render_view` 里属于每张图，每张图清空（I3）；视口的探针由视口的 `SceneRenderer` 持有，按代理层的身份做键，管线重建时保留（修订 v5：切景深、换档都会重建管线，每次冷启动画面会暗一下）。
- **几何缓存**（修订 v2）：原始几何和代理按 GPU 格式打好的区段（基址为 0，修订 v4）存进本机 IndexedDB。
  - 键是「几何身份（模型内容修订或内置基础体参数的哈希）+ 构建算法版本」，算法或 ε 变化时版本号随之变化。
  - 缓存只是加速用的派生数据：随时可以清除或读取失败，失败就重建，从不作为事实来源，也不上传。
  - 容量上限 2 GiB，按模型修订做 LRU 淘汰，写入前用 `navigator.storage.estimate()` 检查配额（修订 v3）。压力场景约 440 MB（每面约 22 B）。
  - 键里包含构建参数（SAH、叶子大小、深度上限、ε）和构建器版本；原始几何与代理分开缓存，改 ε 时不重建原始几何的 BVH。

## 架构设计

```mermaid
flowchart LR
  SG[three 场景图<br/>网格·材质·灯光·环境贴图] --> TS[光追底座 render/trace<br/>每个渲染设备一份]
  SR[SceneRenderer] --> TS
  TS <--> WK[构建 Worker<br/>BVH·代理简化]
  WK <--> DB[(本机几何缓存<br/>IndexedDB)]
  SR --> RG[realtimeGI 管线<br/>每张导出图新建]
  RG --> SSR[SSR（fork）<br/>没命中/边缘带 → 补追]
  RG --> SSGI[SSGI]
  RG --> PV[探针体]
  TS --> SSR
  TS --> PV
  SSR --> DN[specular 重投影·降噪]
  SSGI --> C[合成 composite]
  DN --> C
  PV --> C
  C --> F[雾·辅助对象·TRAA·累积]
  TS -.将来.-> PT[路径追踪渲染器]
```

**职责与非职责**：

- **光追底座**（新建 `frontend/src/creative-scene/render/trace/`）：
  - **收集**：自己遍历场景图，选出参与追踪的网格，规则同光栅的不透明预通道：可见、在渲染图层里、不是辅助对象，透明和透射材质不参与。不依赖 `three-mesh-bvh` 的收集，因为它会带上子孙物件，也不看图层。
  - **构建与缓存**：在 Worker 里为每个几何构建原始 BVH，以及追踪代理和它的 BVH，结果按几何身份缓存（I8、I9，见「一次性开销与缓存」）。
  - **打包与同步**：增量打包两份底层几何（原始与代理）、顶层和材质表，每帧比对变化并按需更新（见「场景同步」）。
  - **提供函数**：TSL 的求交函数（按精度档选原始或代理，经包装模块调用库的求交，见「使用要点」）和命中点着色函数。
  - **打包移出主线程**：压力场景的原始层在主线程上打包要 0.64–0.74 s（S0），改为由 Worker 写好基址为 0 的区段，主线程只改基址并分帧提交（修订 v4）；写缓存放到回传之后。
  - **报告状态**：能力和容量（见「能力与容量」）。
  - 不负责：降噪、合成、帧推进和任何场景数据。
- **世界空间追踪层**（`realtimeGI` 管线内部）：
  - 反射：在项目内 fork 的 SSR 里接入补追；
  - 探针体：布置、每帧更新、给像素插值；
  - 合成：改动见「合成的接入点」；
  - 按 I6 设置这一层专用的标定值。
  - 不负责：改材质、改灯光，或改实时 GI 之外的渲染器。
- **渲染器创建入口**（`render/gpu.ts`）：
  - 在适配器上限之内，额外请求底座需要的存储上限：`maxStorageBufferBindingSize` 和 `maxBufferSize` 按适配器上限请求。现在只请求了 `maxTextureDimension2D` 和 `maxBufferSize`（`gpu.ts:280`）。不请求时绑定上限是 128 MiB，原始几何超过约 670 万面的场景就会退到第 2 档（S0）。
  - 能力按设备的实际 limits 判断，不按适配器。
  - 继续报告 `{backend, maxTextureSize}`，另加光追能力。
- **渲染选项卡**：读取本机能力和底座的容量状态，在「渲染后端」旁说明未绘制的部分。

**依赖方向**：`realtimeGI` → `render/trace` → `three-mesh-bvh/webgpu` 和材质的 TSL 函数（`materials/`）。底座不依赖 `realtimeGI`，将来路径追踪以同样方式依赖底座。

**失败与恢复**：

- 设备丢失：沿用现有恢复流程，底座随渲染器重建。
- 打包、编译失败，或运行中超出上限：本机不画这一层，记日志，渲染选项卡给出一般性提示，不暴露原始错误（沿用「部署错误不暴露给用户」），实时 GI 退回屏幕空间和现有标定值（I6）。

## 技术选型

| 项 | 选择 | 理由与边界 |
|---|---|---|
| BVH 与求交 | `three-mesh-bvh` 0.9.15（已是 npm 依赖，锁定版本）的 `three-mesh-bvh/webgpu` | 路径追踪 Epic 已选定它（`scene-webgpu-renderer` proposal）。遍历是 WGSL（`wgslTagFn`），作为 `patterns` 的例外接受；它以 npm 依赖的形式使用，不拷进仓库（见下文「使用要点」）。整套 API 上游标为不稳定。在 r186 上从 TSL 调用它的求交，需要一个很小的 WGSL 包装函数，例外范围扩大到 `render/trace/` 里这一个包装模块（修订 v3），同时向上游提 PR |
| 漫反射 | DDGI：以摄像机为中心的两级级联、八面体辐照度、Chebyshev 可见性（深度矩）、探针挪位与停用、读上一帧探针实现多次反弹（Majercik 等，JCGT 2019「Dynamic Diffuse Global Illumination with Ray-Traced Irradiance Fields」） | 比 Lumen 的 Screen Probe 加 Radiance Cache 简单得多，天然支持多次反弹。级联让探针数与场景范围无关，近处比均匀网格更密（修订 v2）。漏光是它的已知弱点，用挪位、停用和深度矩来压（S2）。S0 原型的方向见「探针体」（修订 v3） |
| 追踪代理 | `meshoptimizer`（改为直接依赖，锁定版本）的 `MeshoptSimplifier.simplify`，用 `ErrorAbsolute` 按米指定误差，用 `LockBorder` 防止部件之间出现裂缝，并检查返回的实际误差 | 误差可以指定，也可以逐个模型检查，I8 才能写成可验证的上限。它的误差是二次误差的估计，不是严格的豪斯多夫距离（S0 实测有 1.5%–3.5% 的点超出 ε），所以由出图对照把关（AC-12；research「误差怎么受控」） |
| 构建与缓存 | 多个普通模块 Worker（核数减一），按几何分给各个 Worker；Worker 产出按 GPU 格式打好的区段，缓存存区段（修订 v4）；本机 IndexedDB | 一次性开销移出主线程，同一个模型修订在同一台设备上只构建一次；热启动只拷贝和改基址，不反序列化、也不在主线程打包。首版不改契约；烘焙时生成并随模型内容存储，留到外部 GLB 导入之后。不用 `ParallelMeshBVHWorker`（修订 v3）：它依赖 `SharedArrayBuffer`，页面要开启跨源隔离，而几何多时按几何分配已经能用满所有核（S0 `throughput.md`） |
| 反射 | 在项目内 fork 的 `SSRNode` 里，对没命中和边缘淡出的采样沿同一 GGX 方向补追，命中点直接着色（hit lighting） | 和 SSR 同方向、同权重，才能共用现有的重投影、降噪和多次反弹回灌，不另建一条降噪链。fork 按 `patterns` 的 fork 规则在文件头注明上游版本和改动的行 |
| 没命中时的光 | 场景环境贴图（`scene.environment`，`objects/Lighting.tsx` 生成的 PMREM） | 和材质的环境光照同一来源，天空类型（物理天空、夜空、纯色）自动一致（I2），不各自接入大气 LUT |
| 命中点的阴影 | 朝太阳和灯光发阴影光线（求交到灯光距离为止）（修订 v3） | 产品的太阳阴影已改为按视锥拟合的级联阴影（`f8b2f34e`），屏幕外的命中点不在任何一级的覆盖范围内。阴影光线比不相干光线快 2.5–4 倍（S0 `hit-shading.md`），在反射补追里约占四成耗时 |
| 着色 | TSL：compute（`Fn().compute()`）和 `RenderPipeline` 的节点，配存储缓冲与存储纹理 | 项目代码不写 WGSL 字符串，`render/trace/` 的包装模块除外；静态检查加禁 `wgslFn` 和 `wgslTagFn`，对包装模块放行（S1） |
| three r186 在 compute 里的限制 | `render/trace/` 里一个限定范围的补丁模块（修订 v3），同时向上游提 issue 或 PR，上游修复后删除 | 四处（S0 `hit-shading.md`）：`TextureNode.grad()` 和深度比较采样只在片元阶段生成；PMREM 的环境旋转在 compute 里读到空材质；TSL 的 `Switch` 紧跟 `If` 时会接成 `else`，库的 `mat4x4f` 类型名不被识别。补丁只改 compute 阶段原本报错的分支，光栅着色器不受影响；后两条在写法上绕开 |
| 不采用 | Mesh SDF、Global SDF、Surface Cache、Screen Probe、体素锥追踪、硬件 RT、`three-gpu-pathtracer` | SDF 能让追踪开销与面数脱钩，但薄结构会漏光，反射细节也不足，与 I8 冲突，路径追踪也用不上。复杂场景下的比较见 research `complex-scene-scaling.md`，其余见 `world-space-tracing-options.md`「Lumen 的分层」和 `scene-webgpu-renderer` 的决策记录 |

**`three-mesh-bvh/webgpu` 的使用要点**（评审核对 0.9.15 源码）：

- **结构**：
  - 顶层是 `ClusteredBVH`，底层每个几何一棵 `MeshBVH`。底层在 Worker 里按 SAH 构建，不复用放置功能的 `geometry.boundsTree`：那棵树在主线程上按 CENTER 策略建，只有拖动过的网格才有（修订 v4）。
  - **顶层一个根一项**（修订 v3）：构建 `ClusteredBVH` 时传 `shouldCluster: () => true`。库的默认做法把普通网格拆成不到 64 面一簇，压力场景的顶层会有约 1400 万项。
  - 网格有多个 group 时，每个 group 是一个根，在顶层各占一项、各占一个变换槽；预留空间按根数算。多槽位模型的材质索引因此可以按「实例 + 槽位」写进各自的变换槽。
  - 每个变换槽存正矩阵、逆矩阵和可见标志。
- **求交**：`fns.raycastFirstHit` 在 r186 上不能从 TSL 直接调用（结果要经 `ptr<function>` 传出，临时变量要在模块作用域），所以经 `render/trace/` 里的 WGSL 包装函数调用（修订 v3，S0 `integration.md`）。返回变换槽、三角形索引、重心坐标和世界空间法线。
- **双面求交**：库的求交不分正反面，光栅按材质的 `side` 剔除背面。材质表要记下 `side`，命中单面材质的背面时按材质跳过或另行处理（S1）。
- **材质索引**：写进变换槽里上游预留的对齐字段（覆写 `writeTransformData`）。S0 已确认可行。
- **更新**：只改变换时**不用**库的 `updateTransforms()`，它每次整体上传节点缓冲（压力场景每帧 232 MB）；增删物件或改几何时也**不用** `update()`，它会整体重新打包和上传。改为增量打包（见「场景同步」）：子类扩展 `BVHComputeData`，覆写 `update()` 和 `updateTransforms()`，不 fork 库的文件（修订 v3）。
  - 依赖的非公开接口：`three-mesh-bvh/src/*` 深路径导入的 `ClusteredBVH` 和 5 个打包辅助函数、私有方法 `_getTransformMap` 和 `writeTransformData`、存储缓冲的命名约定（S0 `throughput.md`）。
  - 版本锁定；S1 加一个升级时必跑的对照用例（主光线命中与光栅逐像素对照）。
- **属性**：默认只有 `position`；带顶点色的模型要加 `color`，以后有 UV 时再加。法线编码进 `position.w`，每顶点从 32 B 降到 16 B，默认上限下第 1 档的门槛从 670 万面提到 890 万面（修订 v3）。库的求交只读 `position.xyz`。
- **一个内核只绑一层**：每层占 4 个存储缓冲，两层同时绑定会超出默认的每阶段 8 个。探针内核只绑代理层，反射内核只绑原始层。
- **单例**：`raycastFirstHit` 用 `Math.random()` 生成着色器里的变量名，所以每个渲染器只建一个 `BVHComputeData` 实例，避免每次重编译。
- **栈深**：BVH 遍历栈深为 60，超出时会抛错，计入容量判定。压力场景的遍历深度是 38，按每多一倍实例加一层估算，2 万个实例最坏约 58（S0）。

## 关键机制

### 合成的接入点

**现行合成**（`render/realtimeGI.ts:91-103`）：

```text
kd     = base.rgb · (1 − base.a)
direct = output − ambient − envSpec
shaded = direct · contact' + ambient · ao + envSpec · ao · (1 − cover) + reflection · split + kd · gi
```

- `ambient` 是材质完整的 `indirectDiffuse`（`giSplit.ts`），由两部分组成：环境贴图的辐照度，加上 `AmbientLight`。后者的强度为 `environment.ambient.intensity × ambientFill(engine)`，见 `Lighting.tsx`；物理天空下没有这一项。两部分都已经乘过材质的能量补偿系数，即 three 的 `PhysicalLightingModel` 里的 1 − 镜面散射。
- `cover` 是本帧 SSR 原始采样是否命中。
- `gi` 已乘 SSGI 增益 `GI_INTENSITY = 5`。这约是能量中性值 2.5 的两倍，是为了替补缺失的屏幕外光和多次反弹而有意调亮的（`engines.ts`）。

**目标合成**（`world` 表示这一层已构建；修订 v3 按 S0 改写，修订 v5 改写各项的取得方式）：

```text
ambient = A_env + A_light                      // 都含能量补偿系数 c_E；giSplit 在 ambient 的 alpha 里写 c_E
A_light = kd · c_E · L_amb / π                 // L_amb：AmbientLight 的颜色 × 强度之和，一个 uniform
A_env   = ambient − A_light
shaded  = direct · contact'
        + (world ? mix(A_env · ao, kd · c_E · E_probe / π, coverage) : A_env · ao) + A_light · ao   // 只换环境贴图那一份；探针不乘 ao
        + envSpec · ao · (1 − cover') + reflection · split           // cover'：SSR 命中或补追命中
        + kd · gi                                                    // world 时 gi 的增益为 0（I6）
```

- **`E_probe`**：像素处插值得到的探针辐照度（W/m²，所以要除以 π）。`coverage` 是探针在这一点的覆盖与成熟度。细的一级覆盖不到或不成熟时，先混入更粗的一级；所有启用的级都覆盖不到时，才退回 `A_env · ao`（修订 v5，S2 design「采样」）。
- **`c_E`**：和材质对环境贴图辐照度、对 `AmbientLight` 乘的是同一个系数（three 的 `PhysicalLightingModel`，电介质的单次加多次散射）。`A_light` 保留，所以环境光的颜色和强度在两种情况下含义相同（I4）。
- **各项的取得方式**（修订 v5）：
  - 原写法是 giSplit 拆成两个输出。但光照 pass 的四个输出已占满 WebGPU 默认的每像素 32 字节（`maxColorAttachmentBytesPerSample`），再加一个 RGBA16F 输出就超了。
  - 改为 giSplit 在 `ambient` 的 alpha 里写 c_E 乘材质 AO，`A_light` 由 uniform 算出。c_E 直接调用 three 的 `computeMultiscattering` 求出，与材质一致；乘上材质 AO 后，`A_light` 与 `ambient` 严格一致。
  - 不构建时，alpha 只用来判断「是否拆开」（> 0），这一项不改变画面。
  - `base` 改为 sRGB 编码的 8 位格式：`kd` 来自 `base`，探针那一份承担了主要的间接光，8 位线性在暗色上误差太大。它不占额外的每像素预算，但会让不构建时的画面有量化上的差别，按现有阈值（R2 的一级以内）判定（AC-6）。
- **探针不乘 `ao`，`gi` 不叠加**（修订 v3）：
  - 修订 v2 假设探针只替换「未被遮挡的那部分」，被遮挡的方向由 SSGI 的 `gi` 负责。S0 实测不成立：探针辐照度已经包含近处遮挡物（例如红墙）的反弹光，也已经按探针的尺度算过遮挡。
  - 乘 `ao` 会把这部分遮挡扣两次，`gi` 又把近处的反弹加一次。按 v2 的写法，各区域相对逐像素参考偏差 −44% 到 +104%，最佳的 `gi` 增益因场景而异（1 到 5 都有）。
  - 探针单独用时，三个参考场景整图平均差 3.4–4.8 级（v2 写法 7.6–18.5 级），区域在 ±10% 以内，薄墙房间 +4% 到 +24%（S0 `probes.md`）。
  - 小于探针间距的接触阴影，S2 可以试短半径的 AO，按对照图决定是否加上。
- **`GI_INTENSITY`**：`world` 时取 0（I6）。SSGI 在 `world` 时对漫反射不再有贡献，S2 可以省掉它的漫反射部分。
- **`AMBIENT_FILL_GI`**：只影响 `A_light`，`world` 时按需重新标定，不改兼容模式的值（I6）。

### 屏幕外反射

现行的 SSR 采样（`SSRNode.js`）：

- 原始采样 = 命中颜色 × 该 GGX 采样方向的权重，并写入命中距离；
- 没命中时 rgb 为 0，距离为 `ENV_RAY_LENGTH`。项目没有给它 `environmentNode`，环境反射由合成里的 `envSpec` 补上。
- 默认 `screenEdgeFadeBlack = false`：屏幕边缘附近的命中会向环境反射淡出，而这里的环境反射是 0，所以这些像素虽然 `cover = 1`，反射却被压暗。

目标：

- **补追的采样**：fork `SSRNode`，对两类采样沿**同一个**采样方向补追：
  - SSR 没命中的采样；
  - 边缘淡出带里的采样，按 (1 − 边缘因子) 混入补追结果。
  - 糙度低于阈值 `r_max`（U3）、不是透明或透射材质时才补追。
- **写回**：补追得到的原始采样 = 命中点着色 × 同一个权重，并写入命中距离。之后照常进入 specular 重投影和降噪（`realtimeGI.ts`），降噪结果照旧回灌给 SSR 做多次反弹。
- **`cover'`**：SSR 命中、补追命中或边缘带混合时为 1。只有两者都没命中（光线射向天空）时为 0，这时由材质的 `envSpec` 补上。
- **在哪里追**（修订 v3，U3）：直接在 fork 的 SSR 片元着色里调用求交（做法 A）。
  - S0 比较了 A 和「fork 输出方向和权重，由 compute pass 追完后在重投影之前合并」（做法 B）：两者出图相同，A 每帧便宜 0.3–0.8 ms，改动集中在 fork 的一个文件里（`reflections.md`）。
  - A 在片元阶段要绑 5 个存储缓冲（BVH 4 个加材质表）。core 设备满足；compatibility 设备按 U4 的「质量层」规则不构建这一层，不必为它走 B。
- **`r_max`**（U3）：视口取 0.5，导出取 1.0。
  - 视口：0.5 时参考场景每帧只多 0.1–0.9 ms；1.0 时粗糙表面多的场景每帧多 4.5–6 ms。
  - 导出有收敛帧数和时限，取 1.0 能得到封闭空间里粗糙表面来自屏幕外的高光。S2 接入探针后，导出是否仍取 1.0，由 S2 对照决定。
- **GGX 采样的 NaN**：three 的 `ggxReflectionSample` 在视空间法线恰好为 `(0, 0, 1)` 时返回 NaN 方向，NaN 方向的光线会遍历整棵树（`cornell` 一帧从 9.6 ms 涨到 115 ms）。fork 带上修好的采样函数，只补追方向有限的光线，并向上游报告。

### 命中点着色

- **材质**：命中后取出变换槽和三角形，用逆矩阵得到对象空间的位置和法线，再按材质表调用同一个材质函数（原理化 BSDF 或预设的 TSL `Fn`），得到 `{albedo, roughness, metalness, emission}`。命中点不做凹凸（凹凸在预设函数之外由 `height` 求导得到），用几何法线。
- **宽度函数**（I7）：
  - 预设函数体里现在直接调用 `fwidth`（`materials/patterns.ts` 的 `aaStep`、`joint` 和若干预设体），`instances.ts` 的 `footprint` 也由 `fwidth` 算出。WGSL 的导数函数只能在片元阶段使用，而且命中点之间不连续，导数没有意义。
  - 预设函数改为接收一个宽度函数输入：光栅路径传 `fwidth`，生成的着色与现在相同；命中点由光线锥合成光线微分，再对预设的输入取有限差分（修订 v3：S0 实测与光栅差 ≤ 0.55 级；取 0 在 `tile@1`、`fabric@1` 上超标，16 帧累积后仍差 2.0–2.3 级，不采用）。
  - 像素尺度同样按光线锥在命中距离处的宽度估计：锥在像素处的宽度为像素角乘以视距，之后每米加宽「像素角 + 2 × 粗糙度²」，落到表面时沿光线方向按 1/cosθ 拉长。
  - **TSL 的写法要求**：材质函数的输入在 `Switch` 之前存成变量。各分支共享的表达式，TSL 会在第一次构建它的分支里存成变量，其他分支读到的是未赋值的值（S0 在 `fabric@1` 上得到 NaN）。
- **直接光**：太阳、点光和聚光按现有的预曝光强度计算，阴影朝灯光发阴影光线，距离截到灯光处（修订 v3）。自发光直接计入。
- **间接光**：
  - S1 与材质的现有规则相同：环境贴图辐照度全量，加上 `AmbientLight × ambientFill`（物理天空下没有后者）。
  - S2 改为环境贴图那一份取上一帧的探针，`AmbientLight` 那一份不变，由此得到多次反弹。
- **没命中**：按光线方向采样场景环境贴图。
  - 反射取最清晰的一级。
  - 探针取糙度 0.5 的一级（修订 v5，S2 design D7）：探针本身在做余弦积分，取漫反射卷积的一级等于卷积两次；取最清晰的一级，64 条光线噪声大。
- **透明与透射**：不进 BVH，光线直接穿过（proposal 非目标）。

### 场景同步

`SceneRenderer` 只在显示方式或尺寸变化时重建管线（`sceneRenderer.ts`），没有场景内容的变化检测。底座自己每帧比对。原则是**编辑的代价只与改动成正比**（修订 v2）：

| 变化 | 底座的动作 |
|---|---|
| 新几何（新模型修订、内置基础体的新参数） | 先查缓存，没有就交给 Worker 构建原始 BVH 和代理。完成后把它的节点、索引和属性追加写进底层缓冲的空闲区段，只上传这一段；再重建顶层 |
| 物件增删（几何已在缓冲里） | 只重建顶层（只含实例，千级），并更新变换槽和材质表。压力场景两层各 13–14 ms；可选优化是两层共用一棵顶层（原始几何的包围盒外扩 ε） |
| 几何不再被任何实例引用 | 它的区段标为空闲，之后复用。碎片率超过阈值时，在空闲帧整理一次 |
| 只有变换变化（拖动、旋转） | 按区间上传：只上传顶层节点和被移动物件的变换槽。压力场景每帧 256 KB，主线程 3–9 ms，帧时间与静止时相当，不需要降频（修订 v3）。库自带的整体上传每帧 232 MB，最长帧接近 300 ms，不用 |
| 材质槽、材质参数变化 | 只更新材质表 |
| 灯光、天空、曝光变化 | 底座不变；命中点着色读同一组 uniform 和环境贴图 |

- 底层缓冲按容量预分配并留出余量，超出时扩容一次再整体上传。扩容是唯一一种整体上传，频率按指数扩容来控制。
- 导出时每张图新建 `realtimeGI` 管线（`realtimeGI.ts` 的 MRT 注释），底座挂在渲染设备（`SceneGPU`）上，跨图复用，不随管线重建 BVH 或重新编译（修订 v4）。

### 一次性开销与缓存

| 开销 | 何时发生 | 处理 |
|---|---|---|
| 原始 BVH 构建（SAH） | 每个新几何 | 在 Worker 池里构建并打包成区段，存入本机几何缓存（修订 v4）。压力场景 11 个 Worker 墙钟 4.4–5.7 s；30 万面的几何在一个 Worker 里 0.38–0.41 s |
| 代理简化和代理 BVH | 每个新几何 | 在 Worker 里用 `meshoptimizer`，按 ε_probe 简化（目标面数 0，`ErrorAbsolute`、`LockBorder`）。简化不掉时（例如重合顶点被锁住），代理就是原始几何，不放宽误差（I8）。内置基础体的盒子每个面各有一组顶点，边全是边界，代理与原始相同 |
| 上传 GPU | 打开场景，或新几何就绪 | 按几何分段上传，不阻塞编辑 |
| 着色器编译 | 每个渲染器第一次 | 材质表是数据驱动的，场景内容变化不会触发重编译。编译时间计入 `lookBudgetMs` |
| 探针冷启动 | 每张导出图 | 预热帧 `M` = 64（见下文），每帧约 7 ms，约 0.45 s |

- **就绪**：所有当前可见实例的几何都已上传，才算底座就绪（I9）。
- **视口**：就绪前只画屏幕空间，渲染选项卡显示「正在准备屏幕外光照」。
- **导出和 `render_view`**：认领后先等底座就绪，再从帧序号 0 开始。等待时间计入时限，`shotBudgetMs` 和 `viewBudgetMs` 由 S1 按冷启动的实测加上余量。S0 实测压力场景冷启动 7–9 s、热启动约 2 s，等待上限 15 s（AC-11）。

### 精度分档

```text
探针光线    → 代理 BLAS（误差 ≤ ε_probe）
反射光线    → 原始 BLAS；只有原始几何超出设备容量时才改用代理 BLAS（见「能力与容量」）
命中后的着色 → 始终取原物件的材质（材质表按实例和槽位，与几何精度无关）
```

两份 BLAS 共用同一套顶层实例和材质表，求交函数按光线类型选择用哪一份。代理与原始几何的三角形没有一一对应关系，所以命中代理时，材质按「实例 + 槽位」查表，不依赖三角形编号。简化时保留槽位边界，也就是按槽位分别简化，或者用 `LockBorder` 锁住槽位之间的边。S0 的场景每个几何只有一个槽位，多槽位的简化由 S1 验证。

### 探针体

修订 v3 按 S0 原型写下方向（数据见 S0 `probes.md`）。修订 v5 写入 S2 定下的取值，U2 已决，细节见 S2 design「探针体」「关键机制」：

- **级联**（修订 v5）：三到五级，每级 16 × 16 × 16 个探针，间距 0.25 m 起逐级翻倍（0.25、0.5、1、2、4 m），前方分别覆盖约 3、6、12、24、48 m。
  - **级数**：按场景大小自动取（owner 2026-10-26），加到盖住「摄像机到场景包围盒最远角」的距离为止，最少三级。包围盒不含内置地面。
  - **「摄像机」**：指当前在画的视角，包括视口的自由视角，探针每帧跟着它放置。
  - **为什么不是两级**：S0 原型是两级（0.25 m 和 0.5 m，大房间 0.4 m 和 0.8 m）。参考场景的摄像机离主体 2–9 m，两级只覆盖前方约 6 m；封闭的大室内，超出范围的地方会退回穿墙的环境光，远处变亮。
  - **为什么不用全场景的均匀网格**：探针数会随场景体积增长，30 × 20 × 4 m 的大厅按 0.25 m 间距要 15 万个探针。
  - 第 1 级的间距不宜大于 0.5–0.8 m（S0），这种取法满足这一点。
  - 细的一级覆盖不到或不成熟时，先用更粗的一级；所有启用的级都覆盖不到时，才退回环境贴图的辐照度（见「合成的接入点」的 `coverage`）。
  - 每一级的原点只在这一级被更新的那一帧移动；探针按「未曝光值 × s_env」存储，避免物理天空下超出 fp16（S2 design P4）。
- **放置**（修订 v5）：
  - 水平方向前方 3/4、后方 1/4。S0 原型是近面贴着摄像机，改动的原因是反射的命中点常在摄像机背后，要读探针；
  - 竖直方向以摄像机为中心。16 × 8 × 16 不够：眼高的摄像机即使放在级高的 3/4 处，地面也正好落在盒底，进不了第 0 级；
  - 各级对齐到自己的网格，摄像机移动时探针不滑动；
  - 环形寻址：移出盒子的探针从另一侧进入并重置，其余保留历史。
- **滞后与重定位**（修订 v5）：
  - 滞后按探针的年龄取，编辑跟随和导出预热是同一个公式的两组参数（见「收敛、帧推进与导出」）；
  - 探针重定位只在刚放下或几何变化后的前几次更新里进行，之后冻结。
- **视口分摊**（修订 v5）：视口按顶层规模分档轮转更新各级，远处的级更新得更少；导出每帧更新全部。
- **显存**（修订 v5）：每级约 31 MB，视口按五级预留约 154 MB，不计入底座的 1 GiB 预算（预算是给场景几何的）。
- **过渡**：在第 0 级最后一格内交叉淡化。混合带上两级相差 1.8%–4.2%，图上看不到接缝。混合时要先保证两级都有限：`mix(b, a, 0)` 在 `a` 为 NaN 时仍是 NaN。
- **存储**：辐照度 8 × 8，深度矩 16 × 16。深度矩用 8 × 8 时，薄墙外被阳光照亮的探针成片漏进来（区域偏亮 +12% 到 +48%）；16 × 16 时剩下墙体接缝处的细亮线。辐照度按「余弦加权平均 × π」存（只做余弦加权平均得到的是 E/π）。
- **光线**：每个探针每帧 64 条，方向取球面 Fibonacci 点集，每帧随机旋转。128 条只降低噪声，不降低偏差。
- **停用**：超过 1/4 的光线命中背面的探针停用（在物体内部）。
- **滞后**：稳态取 0.93。DDGI 默认的 0.97 对多次反弹为主的房间太慢：每帧只多传一次反弹，滞后又把每次反弹拖慢 1/(1 − α) 倍，薄墙房间 96 帧都回不到 10%。
- **薄墙漏光**：2 cm 薄墙接缝处的细亮线，S2 用探针重定位（把贴在墙外侧的探针挪开）处理，或者由 owner 接受放宽薄墙场景的阈值（AC-3）。
- **耗时**：8192 个探针一帧约 10 ms（光线 3–4 ms，更新 3 ms，全分辨率采样 3.5 ms），超出 AC-7 的预算。S2 要分摊：每帧只更新一部分探针（轮转）、半分辨率采样后上采样、优化深度矩的更新。轮转会拉长 AC-4 的跟上帧数，两者一起定。

### 收敛、帧推进与导出

- **视口**：沿用按需渲染。启用这一层后，`convergeFrames` 按探针的收敛重新标定（S2，I6）。
  - 编辑后探针先整体替换若干帧（滞后 0），再回到稳态的 0.93。S0 实测「12 帧整体替换，之后 0.93」2–21 帧回到 10% 以内，但跟随期间每帧闪烁 4%–15%；改用滞后 0.5 时闪烁减半，薄墙房间要 28–52 帧。由 S2 按观感取舍（AC-4）。修订 v5：S2 缺省按「12 帧整体替换」实现，录拖动的对照视频交 owner 看。
  - 最后一次编辑后，探针区域平均值逐帧变化小于 1% 时停止重绘（AC-4）。
- **导出与 `render_view`**：
  - 帧序号从 0 开始，探针和反射历史一律清空（I3）。
  - 先跑 `M` 帧只更新探针的预热帧，再跑现有的 `convergeFrames + K` 帧。预热分两段（修订 v3）：前 32 帧每帧整体替换（滞后 0，每帧多传一次反弹），之后做均值累积。`M` = 64，各区域都在收敛值的 ±2% 以内。修订 v5：两段预热和视口的编辑跟随写成同一个按探针年龄取滞后的公式，参数分开（S2 design「更新」）。
    - 修订 v2 写的「从第一帧起做均值」不可用：前几帧的反弹还没传过来，偏暗的估计被永远平均在结果里，薄墙房间 96 帧只到收敛值的 61%–76%（S0 `probes.md`）。
  - three 的帧编号只随动画循环前进，导出的帧循环不经过它时，每帧要显式推进 `nodeFrame`，否则 pass 和噪声会复用上一帧（S0 `reflections.md`）。
  - `drawnFrames` 计入 `M`；`estimateMs` 按实测更新，单张时限和 `render_view` 时限随之更新（S1、S2 各自标定，只在构建这一层时生效）。
- **编译**：首张图要把 14 个预设内联进命中点着色器，编译时间计入 `lookBudgetMs`（60 s，`engines.ts`）。S0 实测冷编译 1.3 s。

### 能力与容量

```text
能力   = WebGPU 后端 且 设备 limits ≥ 底座最低要求（入口已在适配器上限内请求）
容量_1 = 原始层加代理层（加余量）≤ 1 GiB 显存预算 且 每个缓冲 ≤ 设备的绑定上限 且 BVH 深度 ≤ 遍历栈深
容量_2 = 代理层 ≤ 绑定上限 且 BVH 深度 ≤ 遍历栈深

渲染器为实时 GI 且是透视视图时：
  WebGL2 后端       → 不构建；渲染选项卡：「兼容模式：未绘制屏幕外的光照与反射」
  WebGPU 但能力不足 → 不构建；「当前设备不支持屏幕外的光照与反射」
  满足容量_1        → 完整构建（反射追原始几何）
  只满足容量_2      → 构建，但反射也追代理；「场景较大：屏幕外的反射使用简化几何」
  两者都不满足      → 不构建；「场景过大：未绘制屏幕外的光照与反射」
不构建时：合成与全部标定值保持现状（I6）
```

- 降级按档逐级进行，每一档都在渲染选项卡说明（I8），档位只取决于本机设备和场景，不改写场景（I4）。
- **门槛**（修订 v3，S0 `throughput.md`）：
  - WebGPU 查不到显存大小，所以显存预算是产品定的固定值：原始层加 25% 余量后 ≤ 1 GiB。压力场景是 894 MiB，法线编码进 `position.w` 后约 700 MiB。
  - 按适配器上限请求时，绑定上限不是约束，门槛由显存预算决定。
  - 只有 WebGPU 默认上限（128 MiB）时，第 1 档的门槛约 670 万面，法线编码后约 890 万面。
  - 代理只有原始的 0.4%–2%，所以第 2 档的容量远大于第 1 档。

- 客户端任务不按能力路由（U4，owner 2026-10-23）：这一层属于「只支持 WebGPU 的统一规则」里的「质量层」（`scene-world-environment` 修订 v7），各渲染端按本机能力出图。
- 手动导出时，渲染选项卡的提示同样可见。

### 场景与导出

- 不新增场景字段。
- 实时 GI 的 `lit` 指纹连同世界空间追踪的版本号（S2 起为 1）一起计入，后端实现在 `backend/internal/creativescene/fingerprint.go`。S2 上线后，已有的实时 GI `lit` 导出各提示一次「场景已更新」（U7）。
  - 指纹版本前缀 `v1:` 不升级，所以 `clay`、`line` 和工作台的 `lit` 不受影响。
  - 兼容模式下重新导出得到的画面不变，这是接受的误报。
- 同一场景在 WebGPU 后端和兼容模式下画面不同，`scene-webgpu-renderer` 里「两个后端的实时 GI 画面一致」的口径对这一层不再适用。

## 验证与交付

- **参考场景与设备**：沿用 `scene-webgpu-renderer` R0 确定的参考设备和场景集，S0 另加三个参考场景和一个压力场景（proposal「验收标准」）。S0 记录本 Epic 之前实时 GI 的基线图、区域亮度和帧时间，作为 AC-2、AC-3、AC-6、AC-7、AC-9 和 AC-11 的对照。
- **画质对照**（I8）：同一场景分别让探针追代理和追原始几何，比较两张图的差异，作为 AC-12 的依据；S1、S2 改了简化参数或 ε 时都要重跑。
- **性能用例**：用墙钟（提交到 GPU 完成），至少 30 帧取中位数，重复 3 次。three 的时间戳在嵌套 pass 里归属不准，参考场景两次运行之间的中位数可相差 1.6 倍（S0）。
- **自动检查**：
  - 底座：收集、打包、同步和材质表的单测；
  - 合成：`composite` 在纯数值上的单测，沿用现有写法；
  - 命中点着色和光栅在同一表面的对照（I2）；
  - 增量打包的对照：主光线命中距离与光栅逐像素对照，`three-mesh-bvh` 升级时必跑（S0 组 2 的做法）；
  - 预设改为宽度函数之后，光栅出图与基线逐像素相同（AC-9，S1）；
  - 隐藏标签页里两次导出逐像素相同（AC-5，S1 和 S2 都要过，只在 WebGPU 后端）；
  - 兼容模式的输出与基线一致（AC-6）；
  - 静态检查：项目代码里不出现 `wgslFn` 和 `wgslTagFn`，`render/trace/` 的包装模块除外。
- **人工验收**：反射观感、漏光、重绘对照由 owner 判断（roadmap「验收责任」）。
- **回退**：这一层在合成里是开关式接入，出问题时可以在本机关闭它（开发者开关，不进界面），回到现状和现有标定值，不影响场景数据。
- **验证门禁**：按 `AGENTS.md`「验证范式」，日常用 `make check-frontend`，e2e 只跑定向用例；合回 `develop` 用 `make check-merge`。

> 状态：PRD 草稿 v0.1（2026-10-29）。先细化需求，不开工；需求讨论完成后再规划 Epic。讨论依据见 `discovery/brainstorm.md`。
>
> 标记：〔事实〕能在代码或已拍板文档核实；〔决定〕owner 拍板，带日期；〔建议〕本 PRD 的提议，待 owner 确认；〔假设〕未验证；Q 编号见末节未决问题。
>
> 与已有文档的分工：策划文档本身（章节、确认、版本、助手协作）以 V6-079/080/081 和 `.codestable/features/2026-10-15-shoot-plan-document/` 为准；3D 编辑器以 Epic `scene-editor-3d`、`scene-webgpu-renderer` 为准；姿态与时间线以 `.lti/features/2026-10-27-scene-pose-system/` 为准。本 PRD 只定跨阶段的部分。

## 问题与目标

### 现状〔事实〕

- **CRM**：
  - 有客户、订单、套系、档期和提醒。
  - 订单状态是：咨询 / 定档 / 已拍摄 / 已选片 / 精修中 / 已交付 / 完结 / 取消。
  - 套系记录拍摄类型、时长、拍摄张数范围、底片数和精修张数。
  - 订单只快照渠道和拍摄类型，不快照套系的交付数量。
- **创意空间**：
  - 有画布、资产库和助手。
  - 拍摄策划有文档和画布节点（V6-079，原型 `docs/prototypes/creative-workspace/v6/plan.html`）。
  - cosplay 策划 Skill（V6-081）固定使用 2+4+3 交付阵列。
- **3D 场景编辑器**：
  - 有场景节点和多摄像机，按摄像机导出到画布。
  - 渲染器有工作台和实时 GI 两种，路径追踪在规划中。
  - 姿态系统还在探索，第一个子项是「时间线与分镜」。
- **旧 CRM 侧拍摄策划**：客户链接、现场执行等能力已冻结为只读兼容，不再扩展。

### 问题

面向 cosplay 摄影师，合成片最突出，也面向使用创意空间的专业创作者。

1. **订单和策划割裂。** 约定在订单里，创意在策划里，状态要在两边分别手动改。策划里看不到约定拍几张、哪天拍、给谁拍。
2. **合成片不可控。**
   - 直接生成的分镜之间场景不一致。
   - 机位和光向只是文字，现场照着分镜拍，到后期才发现透视、光向、脚下接触点和背景对不上。
3. **策划离现场太远。** 策划文档在电脑上，现场需要的却是按灯位排好的拍摄顺序、每个镜头的参数和动作参考。
4. **coser 拿不到方案。** 大部分准备（假发、服装、道具、美瞳）在 coser 那边，现在只能截图转述。

### 目标

- **G1 订单和策划连成一条线**：从订单开始的策划自动带上约定，创作进度能在订单上看到，摄影师不在两边重复录入。
- **G2 合成片可控**：
  - 场景、机位、光位和姿态在 3D 里确定。
  - 同一份策划的分镜共用一个场景。
  - 这些数字可以直接拿到现场和后期用。
- **G3 策划在现场被用上。**
- **G4 coser 拿到一份能照着准备的方案（PDF）。**

### 为什么现在做

- **避免两边重复定义分镜。** 姿态系统正要定「分镜 = 时间线上的一帧」，策划里也有「镜头」。两边如果各自定义分镜，之后要返工。应该先定跨阶段的镜头模型，再开姿态 Epic（见 Q12）。
- **串联的条件已经具备。** 3D 编辑器和 WebGPU 渲染已有出图基础，策划 Skill 和文档原型也已成形，缺的是把它们串起来。

## 用户与核心场景

### 角色

- **摄影师（账号）**：主用户。
  - 做 cosplay 方向，接付费约拍、互勉和商单。
  - 后期主要在 PS 里做。
  - 平台也面向专业创作者，交互按 Blender 惯例〔决定 2026-10-20〕。
- **coser（客户）**：不登录系统，通过摄影师导出的 PDF 看方案〔决定 2026-10-29〕。
- **助手**：贯穿各个阶段的协作者，先写入、后由摄影师审核〔决定 2026-10-15〕。
- **不作为系统角色**：妆娘、助理、后期外包〔建议〕。

### 端到端场景（以合成片为主线）

例子沿用原型：芙宁娜合成片，coser 通过 QQ 约拍。

| 阶段 | 摄影师与系统 | 订单状态 |
|---|---|---|
| S1 前期沟通 | 摄影师建客户和订单（套系「合成片」）并定档。在订单上点「开始策划」：选择或新建创意项目，再新建策划。作品、角色、拍摄日期、约定数量、coser 身高（如果有）自动预填 | 咨询 → 定档 |
| S2 拍摄策划 | 按 V6-079 的章节推进：<br>• 视觉设定里，场景是一个 3D 场景，人设是 AI 三视图或导入的角色模型<br>• 每个镜头绑定 3D 场景里的一帧，渲染后重绘成分镜图<br>• 镜头自动带上现场参数 | 定档 |
| S3 发给 coser | 导出 PDF，摄影师发到 QQ 或微信 | 定档 |
| S4 前期拍摄 | 现场模式：<br>• 按灯位组排序<br>• 每个镜头显示分镜图、现场参数和姿态参考<br>• 摄影师勾选已拍或跳过<br>全部处理完后，提示把订单改为「已拍摄」 | 已拍摄 |
| S5 后期 | 选中的照片按镜头归位。合成片在 3D 里把机位对齐这张照片，渲染背景板以及深度、阴影图层，交给 PS。成片回传后归到对应镜头 | 已选片 → 精修中 |
| S6 交付 | 成片按镜头排好，默认九宫格顺序，导出交付，并提示把订单改为「已交付」。成片可以收入资产库，拍后回访提醒照旧 | 已交付 |

外景片和普通棚拍的差别：S2 默认不用 3D，S5 没有背景板。

### 关键业务规则

- **BR-01 策划与订单**〔决定 2026-10-29，已写入术语表〕：
  - 一份策划最多挂一笔订单。
  - 一笔订单可以有多份策划，用于团片或一次拍多套服装。
  - 个人创作的策划不挂订单。
  - 创意项目本身不关联订单。
- **BR-02 镜头目标数**〔决定 2026-10-29〕：
  - 没挂订单时，按策划类型的默认分镜数（cosplay 是 2+4+3，共 9 个）。
  - 来自订单时，读取 CRM 里约定的数量来规划。
  - 这条修订了 V6-081「首版不允许改模板」：方法论不变，数量随订单变。读哪个字段、怎么分到三组，见 Q1。
- **BR-03 状态分工**〔建议〕：
  - 经营进度以订单为准，创作进度以策划和镜头为准。
  - 创作侧的事实只提示订单改状态，不自动改。这条沿用旧需求「经营变更由摄影师显式确认」。
- **BR-04 镜头贯穿全流程**〔建议〕：
  - 镜头的稳定 ID 从策划一直沿用到交付。
  - 一个镜头依次关联：分镜图 → 现场素材 → 选中照片 → 成片。
  - 各阶段都是同一批镜头的不同视图，不另建一串文档。
- **BR-05 coser 版 PDF**：
  - 导出 PDF 给 coser〔决定 2026-10-29〕。
  - PDF 不含价格、成本和经营信息〔建议，沿用旧需求「客户侧始终不显示价格」〕。
- **BR-06 两条出分镜的路径**〔建议〕：
  - 精控路径：3D 场景 → 渲染 → 重绘。
  - 快速路径：直接生图。
  - 默认值按拍摄形式定：合成片默认走精控；外景片、普通棚拍和特写默认走快速。
- **BR-07 意图与现场参数**〔建议〕：
  - 镜头里的动作、构图、光线仍然是文字，表达意图。
  - 3D 侧自动派生只读的现场参数：机位高度、俯仰、等效焦距、拍摄距离、主光方位与高度、色温。
  - 系统不从 3D 反写文字，两边一致由助手负责。
- **BR-08 比例真实**〔建议〕：
  - 素体按 coser 的实际身高缩放。
  - 摄像机传感器按摄影师的机身设置。
  - 否则现场参数不能直接拿去用。
- **BR-09 过时链**：
  - 分镜记录它基于哪一版设定〔决定 2026-10-15〕。
  - 建议扩展到场景和姿态：人设、场景、姿态任何一项改了，都提示受影响的分镜。判断按单个镜头求值后的状态。
- **BR-10 合成以 3D 为几何基准，PSD 始终带人片**〔决定 2026-11-01，修订原建议〕：
  - 人片（抠出的人物）放进 3D，前后穿插和阴影由 3D 决定。
  - AI 重绘溶图的结果本身可以交付；是否只重绘背景由摄影师选择。
  - gpt-image 重绘一定会改动人物细节、降低分辨率，所以 PSD 始终带原分辨率的人片图层，细节修复交给主创。
  - 机位匹配只是可选增强，不作为绝对参考。
  - 细节见 Epic `cg-composite`。

### 非目标

- 精修与修图工具本身（在 PS 里做）、RAW 管理、联机拍摄。
- 客户账号、在线协作、分享链接：先只做 PDF。

- 外景片强制使用 3D。

## 成功标准

### 交付验收

验收靠场景走查，由摄影师判断。

- **A1** 一笔合成片订单从「开始策划」走到「已交付」，作品、角色、日期、数量都不需要手抄；订单页能看到策划进度。
- **A2** 同一份策划的所有分镜共用一个场景，机位、光向和现场参数一致（逐张核对）。
- **A3** 摄影师按现场参数架机位、布主光，拍出的照片合成到背景板上时，不需要大幅修正透视。
- **A4** coser 拿到的 PDF 不含价格，能看到分镜、姿态参考和自己负责的准备项。

### 上线后观察

目前没有基线，也不设目标值。由 owner 和种子摄影师负责观察以下指标：

- 挂订单的策划占比；
- 进入现场模式的策划占比，以及其中镜头的处理率；
- PDF 导出次数；
- 合成片背景板被直接采用的比例；
- 分镜的重新生成次数，用来反映摄影师不满意的程度。

1. **M1 合成片策划 ↔ 3D**：CP-10 到 CP-14。

## 约束、假设与未决问题

### 约束

- **账号隔离**：遵守 ADR-001，客户端不传 `account_id`。
- **渲染在前端**：3D 渲染在前端完成，页面关闭时助手不能渲染〔决定 2026-10-15〕。批量出分镜和出背景板时，页面需要开着。
- **不用 ControlNet**：生图走 gpt-image 系列〔决定 2026-10-15〕，重绘后几何会漂移。
- **联网**：cosplay Skill 以联网为前提〔决定 2026-10-15〕。
- **素材授权**：
  - 原作设定图可以作为生成参考〔决定 2026-10-15〕。
  - 导入的角色模型要记录来源和授权，官方模型普遍禁止商用。
- **不复用旧实现**：旧 CRM 侧策划已冻结；现场模式不复用旧的实现，只借鉴〔假设，对文档的同类决定见 2026-10-15〕。
- **订单不快照交付数量**〔事实〕：套系改了，旧订单读到的数量也会跟着变（见 Q1）。
- **内容归属**〔决定 2026-10-07〕：节点持有不可变修订，不反查来源。成片归到哪个镜头记录在策划内，不靠资产反查。

### 假设

- **H1** 种子摄影师里合成片的占比足以支撑在 3D 上的投入。
- **H2** 摄影师愿意在现场用平板或手机看策划。
- **H3** 「3D 出图 + 重绘」得到的分镜，一致性可以接受。已有的 Skill 走查没有覆盖这条路径。
- **H4** coser 主要通过 QQ 和微信收文件，PDF 可以接受。
